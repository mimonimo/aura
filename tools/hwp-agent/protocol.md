# 한글 편집 명령 계약 (thin JSON protocol)

한글 실시간 편집 에이전트와 서버 사이의 얇은 명령 계약이다. 같은 명령이
두 실행 경로에 공존한다.

- **경로 ① hwpx-plugin (서버측, 기본)** — 한컴 없이 python-hwpx로 HWPX를 직접
  편집한다. 화면 동기화가 필요 없는 대부분의 작업.
- **경로 ② COM 에이전트 (이 디렉터리, Windows 전용)** — 실행 중인 한글 창을
  COM으로 조작해 **화면에 실시간 반영**한다. "지시 → 눈앞의 한글이 바뀜"이
  필요할 때만.

명령 집합을 최소로 유지해 두 경로가 같은 계약을 해석할 수 있게 한다.

## 명령 봉투

```json
{ "id": "cmd-8f3a", "op": "insert_text", "args": { "text": "..." } }
```

- `id` — 명령 식별자(결과 매칭용).
- `op` — 아래 op 중 하나.
- `args` — op별 인자.

## 결과 봉투

```json
{ "id": "cmd-8f3a", "ok": true, "result": { ... } }
{ "id": "cmd-8f3a", "ok": false, "error": "설명" }
```

## op 목록 (얇은 집합)

| op | args | 뜻 |
|---|---|---|
| `ping` | — | 생존·버전 확인 |
| `open` | `{ "path": "...", "format": "hwpx\|hwp" }` | 문서 열기(경로) |
| `find` | `{ "text": "...", "nth": 1 }` | n번째 일치로 캐럿 이동·선택 |
| `insert_text` | `{ "text": "..." }` | 캐럿 위치에 텍스트 삽입 |
| `replace` | `{ "find": "...", "replace": "...", "all": true }` | 찾아 바꾸기 |
| `insert_table` | `{ "rows": n, "cols": n }` | 표 삽입(캐럿 위치) |
| `get_text` | `{ "scope": "all\|selection" }` | 텍스트 읽기(라운드트립 검증용) |
| `save` | `{}` | 현재 경로에 저장 |
| `save_as` | `{ "path": "...", "format": "hwpx\|hwp\|pdf" }` | 다른 경로·형식 저장 |

원칙: 수치·서식은 명령에 담지 않는다. 텍스트 편집과 위치 지정만 담는다.
값은 서버(검색·검증 통과분)에서 생성해 넣는다.

## 전송 (롱폴, 아웃바운드)

Windows 에이전트는 **바깥 방향으로만** 서버에 연결한다(PC 방화벽 개방 불필요).
서버 엔드포인트는 서버측 담당이며, 계약은 다음을 전제한다.

1. 등록: `POST /hwp/agent/register` → `{ "session": "...", "poll_after": 0 }`
   (사용자 인증 컨텍스트에 에이전트를 묶는다 — 그 사용자 문서만 편집)
2. 명령 수신: `GET /hwp/agent/commands?session=...&after=<cursor>` (롱폴)
   → `{ "commands": [봉투...], "cursor": <다음 커서> }`
3. 결과 회신: `POST /hwp/agent/result` (결과 봉투)

명령은 해당 사용자 세션으로만 라우팅된다. 서버는 세척·검증을 거친 값만
명령에 실어 보낸다(내부 정보 유출 경계는 서버가 책임진다).

## 안전

- 에이전트는 op 화이트리스트 밖의 명령을 거부한다.
- `--confirm` 모드에서 편집성 op(insert/replace/save)는 콘솔 확인 후 실행.
- 실패는 결과 봉투에 사유를 담아 회신하고, 문서를 임의로 닫거나 저장하지 않는다.
