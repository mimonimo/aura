그 방식이 성립하지 않는다.

요청 내용:
1. 운영 DB(`data/platform/platform.db`)의 현재 조각으로 **질의·정답 세트**를 만든다.
   합성 질의는 `scripts/51_synth_queries.py` 가 있으니 재사용하거나 대체안을 제시하라.
   정답은 사람이 붙이지 않아도 되게, 조각 자신에서 유도하는 방식을 쓰되 그 방식의
   한계를 기록하라.
2. Recall@1·Recall@5·MRR 을 재고, **변경 전후를 비교할 수 있게** 결과를 파일로 남긴다.
   (`data/eval/` 아래. `data/` 는 커밋하지 않는다.)
3. 하한선 환경변수(`ZZAIMY_DENSE_FLOOR_K`, `ZZAIMY_RERANK_MIN`)를 바꿔 가며 재고,
   어느 값이 잡음을 걷으면서 정상 검색을 지키는지 **수치로** 보고하라.

검증 기준: 같은 명령을 두 번 돌리면 같은 수치가 나올 것. 수치는 전부 기계 산출물에서
오고, 확인하지 못한 것은 미확인으로 적을 것. 운영 서버는 재처리가 끝난 뒤에만 쓰고,
배포·재시작은 하지 말 것.

막히거나 범위를 바꾸고 싶으면 `codex.md` 에 요청 ID 와 함께 남겨 달라.

## K-20260920-17 — ZZAIMY-Embed 1차 학습본: 채택 보류 (근거 기록)

토르 GPU 대조학습(MNR + 헷갈리는 오답 4개, 2 에폭, `98_train_embed_on_thor.sh`)으로
`zzaimy-embed-v1` 을 만들었다. 학습은 성공했지만 **운영 색인에는 넣지 않는다.**

  상황 질의는 R@1 0.571 그대로, MRR 0.699→0.681.
- 같은 모델로 **운영 경로(하이브리드 = Kiwi 어휘 + 조밀 + RRF)** 를 다시 재니 이득이 사라졌다
  (질의 150건, 조각 4003, 오늘 같은 표본):

  | 질의 | 지표 | 운영 KURE-v1 | 학습본 |
  |---|---|---|---|
  | 정확한 질문 | R@1 / R@5 / R@10 / MRR | 0.633 / 0.800 / 0.833 / 0.704 | 0.633 / 0.787 / 0.820 / 0.696 |
  | 상황 질문 | R@1 / R@5 / R@10 / MRR | 0.400 / 0.647 / 0.707 / 0.504 | 0.407 / 0.653 / 0.693 / 0.508 |

- 해석: 임베딩이 더 잘 찾게 된 건들은 어휘 검색이 이미 잡고 있던 것이라 RRF 뒤에는 차이가 남지 않는다.
  조밀 검색 단독 지표만 보고 채택하면 운영 성능은 그대로인데 색인 전체를 다시 만드는 비용만 든다.
