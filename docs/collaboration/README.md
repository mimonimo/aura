사용자 요청(2026-09-19)에 따라 같은 저장소에서 작업 내용과 연결 정보를 공유한다.
공통 지침 원본은 `CLAUDE.md`, 인프라 현황은 `docs/HANDOFF.md`, 우선순위는

## 작업 주고받기

Codex는 `codex.md`, Claude는 `claude.md`에 자신의 기록을 작성한다.
시작할 때 상대 기록과 `git status --short`를 읽고, 작업 목적·수정할 파일·상태를
자기 기록에 먼저 남긴다. 상대가 맡은 파일이나 출처를 모르는 기존 수정과 겹치면
편집을 시작하지 않고 요청을 남겨 담당을 조정한다. 문서 기록은 파일 잠금이 아니므로
수정 직전에도 변경 여부를 확인한다.

작업을 마치면 변경 파일·검증 명령과 결과·남은 문제·상대에게 요청할 일을 기록한다.
상대 기록은 읽기만 하고 답변은 자기 파일에 요청 ID와 함께 쓴다.
요청 상태는 요청/확인/진행/완료/막힘으로 구분하고, 상대가 실제 응답하기 전에는
확인이나 합의로 표시하지 않는다. 한 요청의 담당자가 결과를 통합한다.

스테이징은 자신이 맡은 파일만 명시해서 수행한다. 공동 작업 트리에서 `git add -A`나
`git add .`로 전체 변경을 담지 않는다. 커밋은 요청별 통합 담당자가 맡고,
직전 `git diff --cached`로 상대의 미완성 변경이 섞이지 않았는지 확인한다.
동일 파일을 병렬로 고쳐야 하면 별도 worktree에서 진행하되, 기존 미커밋 수정은
자동으로 옮겨지지 않으므로 필요한 작업 기준을 먼저 합의한다.

운영 배포·서비스 재시작·계정 변경은 동시에 하지 않는다. 수행 전에 담당과 범위를
기록하고 상대 작업과 겹치지 않는지 확인한다. 사용자 요청 범위와 기존 배포 규칙을 따른다.

## 접속·계정 정보

서버 주소·로그인 계정·접속 전제는 `docs/HANDOFF.md`를 참조한다.
문서의 과거 기록을 현재 접속 성공으로 간주하지 않는다. 확인 날짜·환경·성공 여부만
작업 기록에 남기고, 비밀번호·API 키·세션 쿠키·SSH 개인 키는 남기지 않는다.

기존 보관 위치는 다음과 같다. 실제 값은 필요한 작업에서만 해당 환경에서 사용한다.

| 용도 | 기존 보관 위치 또는 설정 경로 |
|---|---|
| 운영 환경변수 | 운영 VM `~/zzaimy-capstone/.env.local` |
| 플랫폼 계정 | 해당 환경 `data/platform/accounts.json` |
| LLM 서버 연결·발급 키 | 해당 환경 `data/platform/llm_connections.json`, `/dev/train` |
| NAS 연결 | 해당 환경 `data/platform/nas_sources.json`, `/dev/nas` |
| 학습 도구 계정·연결 | `/dev/train` 도구 카드, `scripts/68_labelstudio_token.sh` |

보관 위치 공유가 자격 증명 존재나 사용 권한을 보장하지 않는다. 비밀값은 새 문서나
명령 인수에 복사하지 않는다. `data/`, `.env*`, `secrets/`의 실제 값은 Git에 넣지 않는다.
이미 추적된 문서에 평문 비밀이 발견되면 값을 인용하지 말고 위치만 알린다.
