# 파일럿 계획

> 착수 단계(2026-09-01)에 쓴 설계 문서다. 범위는 최근 3~5년 유사 유형 사업의 계획서 20~30건과 대응 결과보고서로
> 고정한다. 수만 장 전체로 시작하지 않는다(절대 규칙 7).

현재 상태: 교내 실문서는 사업별로 DGX에서 처리하고 있다. 실문서를 받기 전에는 공개 국고사업 문서와 교내 공개 문서로
파이프라인·검색·학습 과정을 검증했다. 반입 건수와 파일럿 목록의 확정 여부는 반입 대장을 기준으로 하며, 이 문서에서는
미확인으로 둔다.

## 1. 대상 선정 기준

구체 사업명은 담당 부서가 정한다. 이 문서는 선정 기준만 정한다.

1. 대응하는 결과보고서가 있을 것. 실적 카드의 원천이다(③ 계열이 가장 중요하다).
2. 최근 3~5년 안의 문서일 것. 양식과 용어가 현재와 맞아야 한다.
3. 목차 구조가 비슷한 사업 유형으로 묶을 것. Writer의 절 대응 난이도를 낮춘다.
4. 선정·미선정 여부가 섞여 있으면 표시할 것. 평가셋 설계에 쓴다.
5. HWP 원본이 있는지 표시할 것. 파서 경로가 갈린다.

## 2. 마일스톤과 성공 기준 (capstone-plan §3)

| 시점 | 마일스톤 | 성공 기준 |
|---|---|---|
| W2 | 파일럿 목록 확정, 표본 30~50쪽 수령 | 파서 비교 실행 완료, 파서 확정 ADR |
| W3~W5 | 파일럿 전량 파싱·색인 | 전 문서 색인 적재, 개인정보 감사 로그 무결, 평가셋 v1 동결 |
| W6~W8 | 실적 카드 DB와 베이스라인 | 검수 승인 카드 수백 건, 베이스라인 보고서 확정 |
| W9~W10 | 실제 공고 1건 처음부터 끝까지 | 출처 주석 초안 1건과 배점 커버리지 보고서 출력 |
| W11~W12 | 모델 4종 개선폭 | 베이스 대비 재현 가능한 측정 완료 |

마일스톤에 못 미치면 모델 반복 횟수 축소 → Writer 비교군 축소 → (최후) Extract를 교사 모델 운용으로 대체하는 순서로
범위를 줄인다. 베이스라인 측정과 평가셋 동결은 줄이지 않는다.

## 3. 수직 슬라이스

- 범위: 공고 1건, 문서 5~10건, 절 1개를 처음부터 끝까지 관통한다.
- 품질보다 경로가 우선이다. 각 단계는 임시 구현이어도 되지만 검증기 3종의 인터페이스는 실제대로 설계한다.
- 명령 한 줄로 공고에서 출처 주석이 붙은 문단 1개가 나오면 성공이다(`scripts/90_slice_demo.py`).
- 발표회에서 전체 시스템을 보이지 못하더라도 이 슬라이스로 시연할 수 있다.

## 4. 발표회용 비식별 데모 세트 (capstone-plan §1.2)

- 대상 사업과 연도는 파일럿 목록과 함께 정한다.
- 비식별화를 통과한 문서만 쓰고, 발표 전 한 번 더 눈으로 검수한다.
- 화면에 띄우는 모든 문서와 수치는 데모 세트에서만 가져온다.
- 학생 노출 기준도 같다. 비식별화 통과본만 보인다.
