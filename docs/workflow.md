## 2. 결정이 갈릴 때

- 리서치 추천과 실측이 다르면 ADR을 쓰고 근거를 남긴다(예: 그래프 도입, 벡터 DB 미도입, NVFP4 채택).
- 교수님 판단이 필요한 건은 ADR 상태를 `제안`으로 두고 주간 미팅에서 올린다.
- 사용자만 아는 정보(문서 실물 구조, 조직 운영)는 추측으로 채우지 않고 묻는다.

## 3. 보고

- 주간 보고는 플랫폼 논문 자료 화면에서 만든다(`docs/weekly/양식.md` 구성, 피드백 반영, md·docx·hwpx).
  교수님 피드백·미팅 결정은 그 화면의 피드백 칸에 붙여 넣는다.
- 단계 게이트: 베이스라인 리포트 확정(Writer 학습 전) → 모델 카드·평가 보고서 4종(발표 전).

## 4. 브랜치·커밋

- `main` 은 항상 동작하는 상태. 운영 배포(`scripts/99_deploy.sh`)는 `main` 에서만.
- 커밋에 넣지 않는 것: 실제 문서·파싱 결과·실적 카드(`.gitignore`), 비밀번호·키(`.env.local`).
  `git add` 전에 `git status` 를 본다.
- Codex·Claude 가 같이 작업할 때의 파일 소유·스테이징 규칙은 `docs/collaboration/README.md`.
