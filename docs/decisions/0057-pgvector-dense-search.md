# ADR-0057: 의미 검색 벡터는 pgvector 로(배열 파일 대신)

- 상태: 채택
- 날짜: 2026-10-06
- 관련: ADR-0049(사업 문서 색인), ADR-0053(RAG 공간), 절대 규칙 4(열람 등급은 검색 단계에)

## 맥락

사업 문서 조각의 임베딩은 NumPy 배열 파일(grant_embeddings.npz)에 들어 있었다. 크기는 5.4GB이고 직전본도 같은 크기로 하나 더 있다.
앱은 질문마다 이 배열 전체를 메모리에 올려 곱했고, 색인 갱신은 파일 전체를 다시 썼다. 10/4 VM 메모리 부족의 원인이었고,
문서가 늘면 같이 커진다.

## 대결(scripts/178·173, 2026-10-06)

- 벡터만 비교(같은 131.9만 개, 질의 200, HNSW m=16·ef_construction=64): ef_search 300 에서 recall@10 0.915, @50 0.963,
  질의 15ms. 정확 계산은 89ms다.
- RAG 실제 결과(고정 질문 80, 조밀 검색만 바꿈):

  | 방식 | 문서 적중 | 같은 계열 | 사업 적중 | 검색 시간 |
  |---|---|---|---|---|
  | 배열 | 0.688 | 0.988 | 1.0 | 3.49초 |
  | pgvector | 0.675 | 0.988 | 1.0 | 1.85초 |

  문서 적중 차이는 80문 중 1문이다.

## 결정

1. 조밀 검색은 PostgreSQL 의 grant_vec(chunk_id, doc_id, emb halfvec(1024)) + HNSW(halfvec_ip_ops) 로 한다. ef_search 는 300 이다.
   권한·부서(RAG 공간)·범위(사업 문서)·범위 밖 갈래는 같은 SQL 에서 거른다(iterative_scan relaxed_order).
2. 색인 갱신(170 --index)은 표만 본다. 살아 있는 조각 중 표에 없는 것을 임베딩해 넣고, 사라진 조각은 뺀다.
   메타(grant_embeddings.json)는 그대로 적는다.
3. 배열 파일(grant_embeddings.npz·.prev.npz)은 지운다. SQLite(개발 환경)는 배열 경로가 그대로 남는다.
4. 확장은 앱 스키마(aura_app_c129_live)에 둔다. 앱 계정에는 확장 생성 권한이 없어 관리자가 만들었다.

## 결과

- 앱 메모리에서 벡터 배열(5GB 넘음)이 빠진다. 디스크는 표·색인 6.3GB 다.
- 되돌리려면 ZZAIMY_DENSE_BACKEND=numpy 로 두고 배열을 다시 만든다(170 --index 가 배열 경로로 처음부터 쌓는다).
