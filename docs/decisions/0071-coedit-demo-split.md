# 0071. 공동 편집 시연은 관리자 세션 하나에서 칸마다 시연 계정으로 판정한다

- **상태**: 확정(서버 판정·시험). 실브라우저 세 칸 동시 편집은 미확인
- **날짜**: 2026-10-24
- **관련**: ADR-0070(칸 단위 공동 편집), `app/webhwp_demo.py`, `app/webhwp_routes.py`(_depts), `templates/coedit_demo.html`·`hwp_edit.html`, `tests/test_webhwp_demo.py`

## 맥락

칸 단위 공동 편집(ADR-0070)을 보여 주려면 같은 문서를 여러 사람이 동시에 연 화면이 필요하다. 로컬 시험은 호스트 이름을
`a.localhost`·`b.localhost` 처럼 나눠 쿠키를 따로 심었는데, 운영은 주소가 하나라 한 브라우저에서 세 사람의 세션을 동시에 가질 수 없다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 호스트 이름을 나눠 쿠키 분리 | 앱 변경 없음 | 운영 주소 하나에서는 불가 |
| B. 시연 계정에 비밀번호를 주고 창마다 따로 로그인 | 실제 로그인과 같다 | 한 브라우저 세 창이 쿠키 하나를 나눠 써서 안 된다, 로그인 가능한 계정이 늘어난다 |
| C. 관리자 세션 그대로, 칸 표시를 단 편집 요청만 시연 계정으로 판정 | 한 화면에서 된다, 로그인 길이 늘지 않는다 | 편집 화면이 모든 요청에 표시를 붙여야 한다 |

## 결정

C. 관리자 화면 `/dev/coedit-demo`(업무 화면 사이드바 아래 「테스트 보기」 옆 「공동 편집 시연」)에 같은 문서를 세 칸(iframe)으로 연다.

- 시연 계정: `demo_a`·`demo_b`·`demo_c`(시연 김가람·이나래·박다온). 「새 시연 문서」 때 계정 장부에 만든다(있으면 그대로). 비활성·비밀번호 없음·`demo` 표시라
  로그인할 수 없다. 같은 아이디의 실제 계정이 있으면 덮지 않고 그 칸을 쓰지 않는다.
- 시연 문서: 기안기 문서함의 시연 뿌리 `~시연`(「내 폴더」 꼴이라 부서 목록에 끼지 않고, 관리자만 연다). 칸이 4개 이상인 잠긴 공통 양식 가운데
  칸이 가장 적은 것을 복사한다. 「문서 비우기」는 같은 양식으로 새 사본을 만들고 앞 사본은 시연 휴지통으로.
- 판정: 인증 단계(main.check_auth)가 `webhwp_demo.apply` 를 부른다. 실제 로그인한 사람이 관리자이고, 칸 표시(머리 `X-Aura-Demo`, 머리를 못 붙이는
  알림 흐름·sendBeacon 은 주소 `demo=`)가 시연 계정이고, 주소가 기안기 편집 화면(`/webhwpctrl/aura-edit`)이나 편집·공동 편집 경로
  (`/hwp/{id}/` file·save·state·presence·live·lock·unlock·coedit·events·ops·lease·leave·conflicts·page-setup·cmd)일 때만 그 요청의 사람을 시연 계정(교직원, 부서 없음)으로 바꾼다.
  그 밖의 요청은 표시를 무시한다(관리자가 아니면 자기 권한 그대로, 편집 경로 밖이면 관리자 그대로).
- 시연 계정으로 판정한 요청은 열 수 있는 곳이 시연 뿌리 하나다(webhwp_routes._depts) — 공통 양식·부서 문서·자기 내 폴더도 404.
- 편집 화면은 시연 칸으로 그릴 때만 맨 앞에 짧은 스크립트를 넣는다: 같은 주소로 가는 fetch·XHR 에 머리, EventSource·sendBeacon 주소에 `demo=`,
  세 칸이 함께 쓰는 세션·로컬 저장소와 IndexedDB 는 칸마다 이름을 나눈다(창 번호·보낼 줄이 섞이지 않게). 표시가 없으면 편집 화면 출력은 예전과 같다.

## 근거

- 표시는 권한을 좁히기만 한다: 관리자만 쓸 수 있고, 결과는 시연 폴더만 여는 교직원이다. 관리자가 아닌 사람이 표시를 달아도 바뀌지 않는다.
- 시험(`tests/test_webhwp_demo.py`, 임시 DB): 관리자만 화면·만들기, 세 칸 iframe, 계정은 비활성·비밀번호 없음·다시 눌러도 그대로, 편집 화면 「나」 가 칸 계정,
  편집 경로 밖·관리자 아닌 사람의 표시는 무시, 시연 계정은 부서 문서·공통 양식을 편집 화면·공동 편집 경로 모두 404, 세 칸은 같이 보는 사람 셋·임대·칸 글
  주인이 각 시연 계정, sendBeacon 꼴(주소 demo=)으로 그 창만 빠짐, 비우기는 같은 양식 새 사본.
- 앞 스크립트는 node 에서 가짜 브라우저 객체로 돌려 확인: fetch·XHR 머리, EventSource·sendBeacon 주소, 저장소 키·IndexedDB 이름이 칸마다 나뉨, 다른 주소는 그대로.
- 미확인: 실브라우저에서 기안기 서버 세션 쿠키(/webhwpctrl)를 세 칸이 함께 쓸 때 편집기 셋이 서로 간섭하지 않는지.

## 결과와 되돌리기 비용

- 시연 계정 셋이 계정 장부에 비활성으로 보인다(사용자·계정 화면). 지우려면 장부 줄과 `~시연` 폴더를 지우면 된다.
- 판정 경로 목록은 `webhwp_demo._EDITOR` 하나다. 편집 화면이 새 경로를 부르면 여기에 넣어야 그 요청도 시연 계정이 된다(빠지면 관리자 권한으로 돈다).
- 되돌리기: main 의 apply 호출 한 줄과 라우터 포함, 편집 화면의 조건부 스크립트를 빼면 된다.
- 시연 계정 표시 이름은 「김가람」 처럼(칸 위에만 「시연」) — 「시연 …」 이면 머리 글자가 모두 「시」 였다. 시연 문서는 1쪽 요약 보고서 양식을 먼저, 편집 화면의 시연 폴더 이름은 「공동 편집 시연」.
- 시연 화면 머리줄 다듬음: 돌아가기·제목·문서 고르기(파일 이름 대신 제목)·오른쪽 버튼, 칸마다 흰 머리(아바타와 같은 색 동그라미·이름·「시연 계정」).
