# 0008. 외부 참조 이그레스 게이트웨이 — 내부 정보 유출 차단

- **상태**: 제안
- **날짜**: 2026-09-08
- **관련**: `PROJECT_BRIEF.md` §5.3(수치 인출)·11장(금지사항), ADR-0007, 미해결 질문 #11(개인정보)

## 맥락

문서 작성 중 외부 일반 지식(국고사업 절차, 규정 상식 등)이 필요할 때 외부
Claude API에 질의할 수 있게 한다. 단 **학교명·인명·개인정보 등 내부 정보가
외부로 나가면 절대 안 된다**(사용자 강제약, 2026-09-08). 모든 외부 참조는
빠짐없이 기록되고, 현황은 /dev에서 자동 집계·확인 가능해야 한다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 외부 참조 미지원 | 유출 위험 0 | 작성 시 외부 지식 활용 불가 |
| B. 자유 질의 + 사후 로깅 | 편함 | 유출은 이미 일어난 뒤 — 되돌릴 수 없음. **채택 불가** |
| C. 이그레스 게이트웨이(세척→분류→감사→전송) | 유출을 구조로 차단, 완전 감사 | 구현·운영 부담, 세척 한계 존재 |

## 결정

**C.** 외부로 나가는 모든 질의는 단일 관문(egress gateway) 하나만 통과한다.
로그 없이 외부로 나가는 경로는 존재하지 않는다. 관문의 처리:

1. **세척(scrub)** — PiiMasker(Presidio 한국어) 재사용 + 기관 식별자 데니리스트
   (영남이공대학교/YNC/짜이미/부서명 등)를 일반화("한 전문대학" 등)로 치환.
2. **분류(classify) — fail-closed 3분기**
   - `safe`: 세척 후 잔여 내부정보 없음 → 자동 전송
   - `review`: 잔여 위험이 애매(미상 고유명사 등) → **사람 승인 대기 큐**
     (클로드 보안 필터링처럼 담당자가 세척본을 보고 승인해야 나감)
   - `blocked`: 세척으로도 안전 보증 불가 → 자동 차단
   - 애매하면 나가지 않는 것이 기본값. 안전 > 편의.
3. **감사(audit)** — 매 건: 시각·계정·세척본(실제 나간 문구)·제거 내역·
   응답·판정·승인자. 이 기록이 모니터링 데이터.
4. **모니터링** — /dev(개발자·관리자 전용)에서 자동 집계 표시.

외부 호출 자체는 설정(ZZAIMY_EXTERNAL_ENABLED + API 키 + 아웃바운드 허용)이
갖춰지기 전까지 비활성. 인프라 의존성: 서버가 api.anthropic.com **한 곳으로만**
나가는 통제된 아웃바운드가 필요(현재 VM은 인터넷 차단 — 관리자 개방 요청 대상).

## 근거

유출은 사후 조치가 불가능한 종류의 사고다(한 번 나가면 회수 불가). 따라서
"나가기 전에 막는" 구조만 유효하다. 세척은 100%를 보장할 수 없으므로
(미상 고유명사·문맥 의존 정보), 확신 못 하는 건은 자동 차단하거나 사람 승인을
거치게 해 잔여 위험을 사람이 최종 판단한다. 데니리스트 방식은 하드코딩 금지
원칙과 무관하다 — 이것은 인식 성능이 아니라 **보호 대상 목록**이며, 보안에서
명시적 데니리스트는 정공법이다.

## 결과와 되돌리기 비용

- 잠그는 것: 외부 통신 경로가 게이트웨이 하나로 고정된다. 이후 다른 외부
  연동을 추가해도 반드시 이 관문을 지나야 한다(설계 불변식).
- 되돌리기: 기능 자체는 설정 플래그로 끌 수 있어 저비용. 단 감사 테이블
  스키마는 한 번 정하면 마이그레이션 필요.
