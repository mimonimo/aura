# 0025. KURE-v2 다중 벡터 검색 경로 — 같은 질의로 재고 채택하지 않는다 (0022 의 조건 이행)

- **상태**: 확정
- **날짜**: 2026-09-22
- **관련**: ADR-0022(보류 조건), ADR-0021(Embed v2), ADR-0020(Rerank v1), `scripts/128`·`129`, `src/zzaimy/eval/retrieval_eval.py`

## 맥락

ADR-0022 는 공개 KURE-v2 가 단일 벡터가 아니라 다중 벡터(PyLate ColBERT) 모델이라 "바꾼다면 같은
질의 세트에서 후보 진입률·R@1 을 운영과 나란히 재고, 색인 크기·질의 시간을 적는다"는 조건으로 보류했다.
사용자가 이 조건을 이행하라고 했다(2026-09-22 "ㅇㅋ 작업 시작해").

## 무엇을 만들었나

- 색인(128): PyLate 의 인코딩을 pylate 없이 옮겼다(젯슨 컨테이너에 pylate 를 깔면 sentence-transformers 가
  통째로 바뀐다). 질의 = `<cls> [Q] … <sep>` + `<mask>` 로 64토큰 확장, 문서 = `<cls> [D] … <sep>`, 구두점
  토큰 제외, Dense 3층(잔차) → 토큰별 128차원 정규화. 조각 4,284개 → 토큰 846K, fp16 780MB, 토르 03 GPU 33초.
- 서비스(129): 색인 전체를 GPU 에 두고 질의 토큰 × 조각 토큰 MaxSim. 질의당 50~70ms, 컨테이너 1.8GB.
- 측정(53): `ZZAIMY_ALT_DENSE_URL` 이 있으면 다중 벡터 단독 · 어휘+다중벡터 · 같은 표본 리랭커 행과
  후보 진입률(R@20)을 운영 행과 나란히 낸다.

## 결정

**채택하지 않는다 — 운영은 Embed v2 그대로.** 학습 전 공개 모델이 우리 학습본에 근접한 것은 인상적이지만
(단독 R@1 −0.010), 운영 경로에서는 후보 진입률이 낮고(0.919 < 0.935) 어휘와의 융합이 더 나빠지며
(−0.039), 리랭커까지 거친 최종 값은 표본 오차 안(+0.007, 300건 중 2건)이다. ADR-0021 의 채택 기준
"운영 경로 위의 개선"을 만족하지 않는다.

경로(128·129·53 대안 축)는 비교용으로 남긴다. 다시 볼 조건 두 가지: ① 교내 실물 문서·골드셋으로
재측정할 때 ② KURE-v2 를 우리 자료로 학습(PyLate 학습 경로 필요)해 학습본끼리 견줄 때. 그 전까지
서비스 8017 은 내려도 되고 색인은 33초면 다시 만든다.

## 근거·주의

- 같은 날 운영 구성 행이 0.737 로 전날(0.763)보다 낮은 것은 표본이 아니라 코퍼스 차이다 — 문서 422 재처리로
  조각이 4,254 → 4,284 로 늘었는데 색인은 4,254 그대로였다(30조각 미색인). 재분할 뒤 전부 재색인한다.
- 다중 벡터 색인은 조각당 벡터 하나(1024차원 fp32 4KB)보다 조각당 평균 197토큰 × 128 × 2B ≈ 50KB 로 12배 크다.
  수만 조각이면 GPU 상주 대신 후보 재정렬(/score)로만 쓰는 구조가 된다.
