# ADR-0039 — 실문서 학습쌍: 양식 × 완성본에서 절 작성·표 채우기 쌍을 만든다

날짜: 2026-09-29 · 상태: 채택 · 관련: ADR-0029(채팅 에이전트), ADR-0035(서식 보존 채우기), model-plan §2(정제 규칙), 브리프 규칙 1·8

## 배경

Label Studio 「ZZAIMY 검수」 의 태스크는 검토 지시 + 접수 문서 글을 입력으로, 모델의 맥락 분석 요약을 출력으로 둔 것이라
무엇을 판정하라는 것인지 알 수 없었고(사용자 지적 2026-09-29), 그 출력은 우리가 학습시키려는 능력(양식 절 작성)과도 무관했다.
사용자 지시: 제공한 실문서(작성서식 ver5 = 양식, 사업계획서 Ver.3.3 = 완성본, 공고·기본계획·평가편람 = 근거)를 라벨해 학습에
쓸 수 있게 만들 것, 품질이 좋아야 할 것.

## 결정

1. 학습쌍은 서빙 때 에이전트가 보는 프롬프트와 같은 꼴로 만든다(`gdocs_agent._PROMPT` 를 그대로 씀). 입력 = 양식 절의
   작성방법 + 평가지표·공고·기본계획 근거 조각(운영 검색 `find_relevant`) + 그 절의 사실 목록 + 양식 표 격자(독스 격자와 같은
   docx 좌표). 출력 = 완성본의 그 절을 편집 계획 JSON 으로 옮긴 것(insert 문단·table 새 표·fill 양식 표 칸·figure 도식).
   학습 입력과 운영 입력이 같아야 학습이 곧 능력이 된다.
2. 사실 목록: 완성본 절의 수치·명칭을 앞뒤 낱말과 함께(표 값은 '행 이름 · 열 머리: 값') 입력에 준다. 모델은 사실을 양식에 맞게
   구성하는 능력을 배우고 지식(수치)은 자료가 준다(규칙 8). 출력의 수치가 입력 어디에도 없으면 그 쌍은 폐기한다(규칙 1).
3. 표 채우기(fill)의 좌표는 양식 격자를 독스와 같은 docx 변환에서 읽어 정한다. 완성본 표와의 대응은 일반 기법으로만:
   머리 행은 완성본에서 세어 양식에 물려주고(짧은 이름표이거나 양식 위쪽 글과 겹치는 행), 열은 머리 이름·순서로(1차년도↔2026년),
   행은 이름 칸 글(세로 병합 이름은 아래 행에 물려줌)로, 칸은 열 범위 겹침으로 고른다. 양식의 '(예시)·000백만원·○○○' 은
   빈 칸이다. 완성본 자료 행의 절반도 못 옮기면(견본 몇 줄뿐인 명단표) 채우기 대신 새 표(table)로 낸다.
4. 그림 판독 조각('글자:' 줄)은 도식 명세(figure: 상자 제목 + 요점)로 바꿔 출력에 넣는다 — 완성본에서 인포그래픽이던 자리를
   에이전트가 figure 로 내도록 가르치는 재료. 그림 파일명 조각·띠 표(칸 하나둘의 꾸민 소제목)는 표가 아니라 글줄로 다룬다.
   마지막 절은 부록(증빙자료·별첨) 앞에서 끝난다.
5. 산출(`scripts/152_build_real_sft.py`, VM 에서 .env.local 과 함께): `data/training/real_pairs.jsonl`(검수용 원쌍, meta.shown 에
   읽히는 글), `real_sft.jsonl`(messages 형식, `scripts/83 --data`), `real_dpo.jsonl`(prompt·chosen·rejected — rejected 는
   `drafting_episodes.jsonl` 의 같은 절 초안), `real_report.md`(절별 통계·폐기 사유). Label Studio 는 새 프로젝트
   「ZZAIMY 실문서 절 작성」에 검수 설정(입력·읽히는 출력·채택/수정/폐기·수정본)으로 올린다(`--push --replace`).
6. 반입 조각 상한 400 을 2000 으로(`pipeline.MAX_CHUNKS`, 환경변수 `ZZAIMY_MAX_CHUNKS`). 400 은 73쪽 사업계획서(표 112개)를
   Ⅴ장 중간에서 잘라 Ⅵ장(재정투자)이 통째로 빠져 있었다. 문서 562 는 재반입(백업 `data/backup/doc562_chunks_2026-09-29.json`).

## 실측 (2026-09-29, VM, 양식 557 × 완성본 562, 근거 14건 539조각)

- 양식 절 33개 중 완성본과 맞춘 절 24개(상위 제목 9개는 본문 없음). 절 작성 24쌍 + 표 채우기 4쌍 = 28건, DPO 15쌍, 폐기 0.
- 양식 표 채움: 핵심 성과지표 총괄표 21칸(기준값·1차·2차년도 — 행마다 병합 폭이 달라 열 번호가 어긋나는 표), 세부계획표 9칸,
  재정투자 실적·계획표 50칸, 타 재정지원사업 연계표 14칸, 자율 성과지표 표 10칸. 총 사업비·비목별 집행표·거버넌스 명단은
  형식 차이(항목 행 이름이 양식에 없음·견본 몇 줄)로 새 표로 나간다.
- 입력 길이 4천~1만9천 자(사실 목록이 긴 예산 절). 학습은 `scripts/83 --seq-len 16384` 로 돌려야 한다(기본 4096 은 잘린다).

## 보완 (2026-09-29 저녁, 아스트라 C-134 검토 반영)

- 사실 목록에 수치 구절만이 아니라 완성본 절의 문장 전부를(글머리·번호를 떼고, 정해진 순서로 섞어) 넣는다 — 수치 없는 사실(기관·프로그램·
  행동)도 입력에 있어야 출력이 입력에서 풀린다. 섞는 것은 양식 순서로 재구성하는 능력을 배우게 하려는 것이다.
- 수치 규칙은 `fact_numbers`: 단위가 붙은 수(9명·27건·1,250백만원)는 자릿수와 상관없이 사실, 절 번호꼴(1.2·2.1.1)은 구조 표기.
- 검수 화면은 담당자 지시 / 출력 / 재료(접힘) / 원문 입력 전체(접힘, 시스템 지침 포함)로 나눈다(meta.view).

## 품질 관문 연결 (2026-09-29 밤, 아스트라 C-135)

- 쌍마다 `program_id`(docset:양식:완성본)·`node_path`(사업 → 부 → 절)·`evidence_records`(입력에 보이는 줄마다 문서·조각·턴)를 단다
  (`dataset/provenance.py`). 줄의 글이 실제로 든 조각을 찾아 잇고, 칸을 이어 만든 표 사실은 만든 자리에서 아는 표 조각 id 를 쓴다.
  못 이은 줄은 기록하지 않는다 — 그 줄의 수치는 관문에서 보류된다. 검수 판정(review)은 사람이 남긴다.
- 표 맨 위의 '(단위: 백만원)' 같은 설명 줄은 열 이름으로 쓰지 않는다. 답의 안내 문장에서 셈(문단 몇 건·몇 칸)을 뺐다.
- `scripts/audit_sft_quality.py` 실측: 28건 모두 남은 문제는 `review_incomplete` 하나(근거·수치·턴 구조 통과). 학습 가능 건수는 검수 뒤에 생긴다.

## 한계·다음

- 한 문서 쌍이라 24절·28건이다. 같은 양식의 다른 대학 계획서나 다음 판본이 오면 `--form/--done` 으로 쌓는다(문서 id 만 다르다).
- 도식 명세는 그림 판독(OCR) 글의 품질에 매인다 — 글머리 없는 판독은 상자 제목만 남는다.
- 새 표로 나간 예산표·명단표는 양식 표 좌표 학습에는 쓰이지 않는다. 항목 행을 순서로 맞추는 대응은 다음.
- 검수에서 '수정' 한 글은 편집 계획 JSON 이 아니라 읽히는 글이다 — 되받을 때 insert 한 건으로 바꾸는 변환은 아직 없다.
