# 0060. 문서 양식은 Writer(27B)가 고르고, 양식 모양과 품질 관문은 코드가 맡는다

- **상태**: 확정
- **날짜**: 2026-10-11
- **관련**: ADR-0058(공통 양식·초안 흐름), ADR-0059(실제 서식 모양), `src/zzaimy/app/form_choice.py`, `src/zzaimy/ingest/doc_quality.py`

## 맥락

초안 요청이 들어오면 어떤 양식으로 쓸지를 코드 규칙이 정했다(서류 갈래 낱말 → 공통 양식, 프로젝트에 서식이 있으면 담당자에게 되묻기).
학습 뒤에는 Writer 가 요청·대화·프로젝트 자료를 보고 쓸 양식을 스스로 가져와 작업해야 한다는 방향이 정해졌다(2026-10-11 사용자).
같은 날 실제 대화 시험에서 규칙만으로는 「위 목차대로 써 줘」(대화에서 정한 목차)를 놓치고 공통 양식을 까는 일이 반복됐다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 규칙 유지(갈래 낱말·되묻기) | 결정론, 빠름 | 대화 맥락(정한 목차·공고 서식)을 못 읽음, 학습 재료가 쌓이지 않음 |
| B. Writer 가 후보 안에서 고름, 규칙은 물러날 자리 | 맥락 판단, 고른 기록이 학습 재료 | 모델 호출 1회 추가, 후보 밖 응답 처리 필요 |
| C. Writer 가 양식 모양까지 생성 | 유연 | 표·병합·지침 모양을 27B 가 못 챙김(10/9 시험), 품질 흔들림 |

## 결정

B. 코드는 후보(프로젝트 작성 서식, 대화에서 정한 목차, 공통 양식 5종)만 모으고 Writer 가 하나를 고른다. 고름이 후보 밖이거나 실패하면
규칙(목차 지칭 → 목차, 맞는 서식 → 서식, 서류 갈래 → 공통 양식)으로 물러난다. 고른 양식으로 바로 문서를 만들어 쓰고, 다른 후보는 안내 문구로 알린다.
양식의 모양(표·병합·지침·목차 들여쓰기)과 쓰고 난 뒤의 품질 관문(넘친 표·반복 줄·목차·근거 없는 수치 가리기)은 코드가 맡는다.

## 근거

- 10/11 대화 24: 목차 후보가 없을 때 Writer 가 「목차를 따르라고 했으나 후보에 없어 공통 양식」이라고 이유를 정확히 적었다 — 후보만 바르게 주면 판단은 된다.
- 양식 모양을 모델에 맡긴 시험(10/9)은 표가 모두 같고 병합·지침이 깨졌다(ADR-0059 근거).
- 고른 기록(`data/platform/form_choice_episodes.jsonl`: 요청·후보·모델 고름·규칙 고름·이유)은 학습 재료다. 데이터셋으로 만드는 일은 아스트라 담당.

## 결과와 되돌리기 비용

초안 첫 요청마다 짧은 모델 호출(최대 200토큰)이 하나 는다. 되돌리려면 `form_choice.decide` 에 client 를 넘기지 않으면 규칙만 쓴다(코드 한 줄).
후보 목록의 모양(id·label·note)이 학습 입력 형식이 되므로 바꿀 때는 기록 형식과 함께 바꾼다.
