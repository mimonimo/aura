# 0030. 문서 저장 구조 — DB 가 원본, 디스크는 종류별로 정리된 폴더

- 상태: 채택
- 날짜: 2026-09-23
- 관련: ADR-0018(NAS 가져오기), ADR-0028(드라이브 원천), 브리프 저장소 규칙

## 배경

원본 파일이 `data/platform/inbox/` 한 폴더에 임의 이름(uuid)으로 쌓여 292건이 됐고, 사람이 디스크만 보고는 어느
파일이 어느 문서인지 알 수 없었다. 추출 그림·복원 파일·대화 첨부·주간 보고도 제각각의 자리에 있었다. 실물 문서가
들어오면 이대로는 관리가 되지 않는다는 사용자 지적(2026-09-23)이 있었다.

## 결정

1. DB 가 원본이다. 파일의 이름·유형·부서·등급·갈래·접수번호·소속(문서·대화)은 DB 에 있고, 디스크는 DB 를 그대로
   비추는 정리된 폴더다. 디스크의 모든 파일은 `files` 표(종류·경로·소속·크기·시각)에 있어야 한다.
2. 종류별 디렉터리를 나눈다.
   - 반입: `documents/반입/<연도>/<유형>/<접수번호> <제목>/원본.<확장자>` (+ `원본_imgs/` 추출 그림). 유형 폴더는 접수번호
     코드(국고·채용·입학·행정·기준·추출)와 같다.
   - 첨부: `documents/첨부/<연도>/대화-<번호>/<시각> <파일명>`.
   - 생성: `documents/생성/<연도>/<접수번호|대화-번호>/<시각> <종류>.<확장자>` (초안·OCR·복원·추출결과 내보내기 사본).
   - 보고: `documents/보고/주간/<월요일>.md`.
3. 부서·열람 등급·갈래는 폴더가 아니라 DB 로 관리한다(나중에 바뀌어도 파일이 움직이지 않는다). 접수번호는 한 번
   쓰면 다시 쓰지 않으므로 폴더 열쇠로 쓴다. 반입 뒤 제목이 본문 제목으로 바뀌면 폴더 이름도 따라간다.
4. 반입 경로(업로드·기준 등록·문서 추출·공유 폴더·드라이브)는 전부 `storage.adopt_original` 하나를 거친다. 삭제는
   문서 폴더째 지운다. 기존 파일은 `scripts/138_layout_migrate.py` 로 옮긴다(DB 백업 뒤).
5. 재생성 가능한 캐시(복원 PDF `restored/`, 쪽 그림 `pagecache/`, 색인 npz)는 장부 대상이 아니다.

## 근거

- 합성 검증(`tests/test_storage.py`): 업로드·기준·추출·첨부·삭제·제목 따라가기·생성 사본·이관 6건.
- 운영 이관 결과는 dev-now 최근 작업에 적는다.

## 되돌리기

`storage.adopt_original` 호출을 빼면 예전처럼 inbox 에 남는다. 이관 전 DB 는 `backup/platform-<시각>-before138.db`.
