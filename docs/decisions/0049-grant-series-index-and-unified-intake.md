# ADR-0049: 사업 문서 계열 검색 색인과 들어오는 길 하나로 묶기

- 상태: 채택
- 날짜: 2026-10-02
- 관련: ADR-0031(데이터 세 층), ADR-0047(원본 보관 DGX·색인 VM), ADR-0048(온톨로지 v3), 절대 규칙 4·6

## 맥락

DGX 원본 보관소에 사업 문서가 계속 들어온다(10/2 기준 125,012건). 사용자: "플랫폼에 첨부한 문서들도 RAG·온톨로지·지식그래프에
실시간으로 동기화, 반입 문서와 동일하게 수집·저장, VM 에는 캐시, 원본은 업로드", "제각각이면 안 된다". 그런데 대화 RAG 는
규정 계열(regulation_chunks)만 보고, 사업 문서 조각은 문서함(doc_chunks)과 초안 맥락에만 있었다. 그래프는 손으로 돌릴 때만
갱신됐고, 플랫폼 업로드 원본은 DGX 에 없었다.

## 결정

1. 사업 문서 계열 색인을 규정과 따로 둔다(절대 규칙 6) — `app/grant_search.py`, 임베딩 `knowledge/index/grant_embeddings.npz`
   (Embed v2, 질의와 같은 모델). 검색: 그래프(graph/retrieve)로 사업·연차를 좁힘 → 어휘(Kiwi)·임베딩 RRF → 사업 > 연차 > 문서 경로.
   열람 범위는 검색 단계에서 거른다(절대 규칙 4). 대화 응답기는 규정 근거와 사업 문서 근거를 따로 표시해 건넨다.
2. 들어오는 길을 하나로 — DGX 원본 동기화·DGX 가벼운 처리·문서함 업로드·채팅 첨부 모두 같은 문서함(documents)·같은 처리기.
   처리기가 끝날 때 `.kg-dirty` 를 남기고, 1분 주기(`zz_quick` → `170 --quick`)가 업로드 원본 DGX 사본(`~/zzaimy_uploads`, 쓰기 전용 키)·
   원본 목록 장부(같은 사업 분류)·그래프(157 --full)·양식·사업 문서 색인(새 조각만)을 맞춘다. 10분 주기(`zz_sync` → `170`)는 DGX
   원본 전체를 훑어 장부를 차이로 동기화(새로·바뀜·옮김·없어짐)하고 새 뼈대를 반입한다.
3. 원본은 DGX, VM 에는 캐시 — 문서함 원본 사본은 보기용 캐시이고 DGX 사본이 보관본이다. DGX 원본 중 뼈대 밖 문서는 DGX 에서
   가볍게 처리(167, 검토 의견 LLM·비전 없음)해 글·조각만 VM 에 'DGX 보관 문서'(stored_path `dgx://`)로 둔다.

## 결과

- 대화 에이전트가 사업 문서를 근거로 답한다(사업·연차·문서 경로와 함께).
- 새 문서는 들어온 길과 상관없이 1~10분 안에 장부·그래프·색인에 반영된다(처리 시간 별도).
- 비용: 색인 첫 구축은 조각 수에 비례(토르 임베딩 서비스, 회차마다 2만 조각). 그래프는 회차마다 전체 재구축(수십 초).
- 남은 것: 재정렬기(Rerank v1)를 사업 문서 후보에도 — 측정 뒤. 성과지표 노드(목표↔달성 값).
