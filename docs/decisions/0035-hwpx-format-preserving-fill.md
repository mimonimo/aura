# ADR-0035 — 최종 한글본은 원본 서식(hwpx)에 작업본 내용을 서식 보존으로 넣어 만든다

날짜: 2026-09-28 · 상태: 채택 · 관련: ADR-0029(독스 편집 에이전트)·ADR-0033(kordoc 어댑터)·ADR-0034(COM 에이전트 폐기)

## 배경

작업 공간은 구글독스(실시간 다중 인원·에이전트 편집)이고, 제출본은 공고가 준 한글 서식 그대로여야 한다. 사용자 확정(2026-09-28):
"여러 사람이 참조·작업하려고 구글독스를 쓰는 것이고 어쨌든 최종본은 원본 서식에 채우면 된다." 그래서 독스 작업본 → 원본 hwpx 로
내용을 옮기는 "서식 보존 채우기"가 필요하다. 후보를 실측했다.

- kordoc `patch`(마크다운 편집 → 원본 in-place): 글 바꾸기·표 행 추가는 되지만 새 문단·표 블록 추가는 "미지원(v1)"(9/28 실측, 557 서식
  본문 제목 뒤 삽입 시도). 빈 서식에 절 본문을 넣는 우리 일에는 못 쓴다.
- kordoc `fill`(누름틀·라벨 옆 칸 채우기): 신청서의 칸 채우기용. 절 본문에는 해당 없다.
- kordoc `generate`(md → 새 hwpx): 서식을 새로 만드는 것이라 원본 서식 보존이 아니다.

사용자 지시는 kordoc 의 흐름을 그대로 따르는 것이 아니라 "원본 서식을 보존하면서 내용을 채우는 핵심 원리·기술을 우리 것에 맞춰 흡수"하는
것이다.

## 결정

1. 최종 한글본은 서버의 `ingest/hwpx_fill.py` 가 만든다 — 작업본의 절 본문(`gdocs.section_bodies`: 글·표, 안내 상자 제외)을 원본 hwpx 의
   절 제목 문단(그 뒤에 【작성방법】 상자가 있으면 상자) 뒤에 끼워 넣는다. 절 제목은 번호·제목 글자로 맞춘다(`section_context` 와 같은 잣대,
   같은 번호가 여러 구역에 있어도 제목으로 가른다). 못 찾은 절은 건너뛰고 답에 적는다.
2. kordoc(`roundtrip/patcher.ts`·`source-map.ts`·`zip-patch.ts`·`table-insert.ts`)에서 흡수한 기술:
   - 구역 XML 을 다시 직렬화하지 않고 글자열 위치에 끼워 넣는다(바이트 보존). 손대지 않은 문단·구역은 한 글자도 안 바뀐다.
   - 글이 바뀐 구역은 줄 배치 캐시(`hp:linesegarray`)를 전부 지운다 — 한글이 다시 계산하고, 변조 경고·옛 줄배치 렌더를 막는다.
   - ZIP 은 원본 항목 순서·압축 방식을 그대로 두고 바뀐 항목만 다시 쓴다(mimetype 첫 항목·무압축이 자동 보존, 안 바뀐 항목은 CRC 동일).
   - 새 표의 id 는 문서 전체 숫자 id 최댓값 다음부터. 표 테두리는 그 구역의 본문 표(안내 상자 제외)가 가장 많이 쓰는 네 변 실선
     borderFill 을 승계하고, 없으면 실선 하나를 header 에 추가(itemCnt 갱신)한다.
   - 문단·글자 모양은 서식의 기본 스타일('바탕글', style 0) 참조를 빌린다 — 특정 서식에 맞춘 값이 없다.
3. 채팅 명령 "한글 파일로 내보내 줘"(`_edit_linked_doc`)가 이를 부른다. 원본 서식은 작업본의 장부(files google → doc_id)에서, 없으면
   프로젝트의 양식 문서(하나뿐일 때) 또는 지목한 문서(`_working_copy_source`, 작업본 새로 만들기와 공용). 결과는 `생성/` 폴더에
   보관(files 장부 generated)하고 프로젝트 드라이브 `작성/` 에 올려 링크를 답한다. "안내 상자 없이" 또는 "제출본" 이면 【작성방법】·
   【증빙자료】 상자를 뺀다.
4. 원본이 .hwp(옛 형식)면 채우지 않고 hwpx 로 저장한 서식의 반입을 안내한다 — hwp 바이너리를 다시 쓰는 경로는 만들지 않는다(kordoc
   patch 도 블록 추가가 안 되는 같은 한계, LibreOffice 는 hwpx 를 못 읽고 hwp 를 쓰지 못한다).
5. 이것은 정답을 코드에 넣어 문서를 찍는 것이 아니다. 내용은 에이전트·담당자가 독스 작업본에 쓴 것이고, 이 층은 그 내용을 서식에 옮길 뿐이다.

## 첫 실물 실행에서 배운 것 (2026-09-29, 대화 18 작업본)

작업본은 서식의 변환본이라 서식 자체의 글·표가 그대로 들어 있고, 옮기기(migrate)로 같은 표가 두 벌인 절도 있었다. 처음 결과는 표 63→110 개.
그래서 "작업본 내용을 서식과 견줘 넣는" 일반 규칙을 더했다(모듈 머리말 참조): 서식에 있는 문단·표는 다시 넣지 않고 그 자리를 지나 이어 쓰고,
서식 표를 고쳐 썼으면 칸에 써 넣고, 서식에 없는 소제목('1) 강점(S)')은 앞 절 본문으로 잇는다(그래서 본문이 빈 절도 차례에 둔다), 글상자·
목차처럼 독스가 여러 문단을 한 칸으로 합친 것은 이어진 문단을 붙여 견준다, XML 엔티티는 풀어서 견준다. 다시 실행: 표 63→63(새 표는 에이전트가
만든 1개), 문단 108개, 서식 것 152건 유지, 소제목 11개 이어 넣기. 작업본에 같은 문단이 두 절에 있던 7건은 작업본 쪽을 정리했다(대표과제 절).

## 서식 표 칸 채우기 (2026-09-29 오후)

작업본에서 채운 양식 표(총괄표)를 완성본에 옮길 때, 독스는 병합 표를 잘게 나눈 격자(서식 6열 → 14열)로 내므로 칸 대응이 안 돼 깨진 새 표가
들어갔다. 작업본의 열 너비(section_bodies 가 함께 냄)로 값 칸의 x 위치를 재고, 서식 표의 격자(표 폭을 다 덮는 행 기준, colAddr 별 x)와 맞춰
원래 칸에 써 넣는다. 실측: 총괄표 24칸이 원본 표 모양 그대로 들어갔다.

## 실측 (2026-09-28, 557 작성서식 ver5 hwpx)

| 항목 | 결과 |

| 채운 절 | 1.1(문단 3·표 1)·2.1·3.1·"1. 사업추진체계"(같은 번호 1 이 세 구역에 있어도 제목으로 골라 section4 에) |
| ZIP | 19 항목 순서·압축 방식 동일, 17 항목 CRC 동일(바뀐 것은 section1·section4 뿐) |
| 줄 배치 캐시 | 바뀐 두 구역에서 1,604개 제거, 남은 것 0 |
| kordoc validate | 구조 검증 통과(엔트리 19) |
| kordoc parse | 넣은 글·표가 절 자리에 그대로(없는 절 "9.9" 은 들어가지 않음) |
| 우리 변환기 → LibreOffice PDF | 원본 64쪽 → 채운 것 64쪽, 넣은 내용 18~19쪽, 새 표는 본문 표의 실선 테두리 |

한글(HWP) 프로그램에서 직접 열어 보는 확인은 아직 하지 않았다(맥·VM 에 한글이 없다) — 담당자 PC 에서 첫 실물 제출 전에 확인할 것.

## 되돌리기

`hwpx_fill.py` 와 채팅 분기만 빼면 된다. 독스 작업본·변환기는 이 결정과 무관하다.
