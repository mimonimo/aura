# ADR-0033 — kordoc 을 한글 읽기 어댑터로 채택하고 포크를 보관한다

날짜: 2026-09-28 · 상태: 채택(옛 hwp 읽기), 후보(hwpx 읽기·열람 렌더·lint·신구대조표·서식 보존 패치)

## 배경

chrisryugj/kordoc(MIT, TypeScript, 2.2k★)은 한글(hwp 3/5·hwpx)·pdf·xlsx·docx 를 자체 파서로 읽어 마크다운·JSON·RAG 청크로 내고,
마크다운 → HWPX 생성·서식 보존 채우기/패치·신구대조표·공문서 lint·레이아웃 렌더를 갖춘다. 우리 실물 세 건 실측
(`docs/notes/2026-09-28-kordoc-comparison.md`): 옛 hwp 30MB 읽기 1초(우리 pyhwp 경로 3분), 글자 양 동등, 표는 중첩·병합 보존,
서식 6쪽 렌더가 원본 배치 그대로. 사용자 지시: 좋은 사례를 우리 플랫폼·목적에 맞춰 흡수하되 실물 문서는 우리 기준으로,
작업 공간은 구글독스(실시간 다중 인원), 한글은 최종 산출만. 업데이트를 잘 반영하고 지원 종료도 대비해 우리 GitHub 에 보관.

## 결정

1. 옛 hwp 읽기는 kordoc 이 1순위다. `ingest/parsers/kordoc.py` 가 CLI(`--format json --image-refs`)를 불러 우리 ParseResult
   (문단·제목·표 좌표·그림)로 옮기고, 그 뒤 마스킹·조각·색인·판독은 우리 것 그대로. kordoc 이 없거나 실패하면 pyhwp 경로로
   돌아간다(`pipeline._parse_hwp_structured`). hwpx 는 우리 파서 유지 — 독스 변환(docx)에 같은 XML 을 쓰고 이미 빠르다.
2. 판을 고정한다. VM 설치 판은 `~/opt/kordoc/node_modules/kordoc/package.json`(지금 4.15.7)이고 반입 기록(parse_note)에 판이 남는다.
   판을 올릴 때는 `scripts/147_kordoc_parity.py`(우리 파서 대 kordoc: 시간·글자·표·그림)와 145·144 를 다시 돌려 통과한 뒤에만.
3. 포크를 보관한다. `github.com/mimonimo/kordoc`(2026-09-28 포크). 우리에 맞춘 수정은 포크의 `zzaimy` 가지에서 하고, 상류가 멈추면
   포크에서 이어간다. 설치는 npm 판을 쓰되 포크 판으로 바꿀 수 있게 어댑터 뒤에만 둔다.
4. 내장 OCR(PP-OCRv5)은 쓰지 않는다(모델 4종 규칙 9). `KORDOC_OFFLINE=1` 로 자원 내려받기를 막는다. 판독은 Writer.
5. 유출 통제를 전제로 한다(우리 운용은 인터넷은 되지만 중요 정보가 밖으로 안 나가는 것). kordoc 은 VM 안에서만 돌고 문서 내용을
   외부로 보내지 않으며, `KORDOC_OFFLINE=1` 로 자원 내려받기를 막는다. 재설치 묶음(`~/opt/dist/`)은 인터넷이 막힌 상황의 예비일 뿐이다.
6. 가져오는 범위는 좁다. 채택은 대조 수치로 확인된 것만(지금은 옛 hwp 읽기), 나머지는 후보로 두고 하나씩 비교·검토한다.
7. 본받아 우리 것으로 만드는 것(순서): 청크 제목 계층(breadcrumb) → 열람 렌더(SVG) 화질 비교 뒤 교체 여부 → 규정 판본 신구대조표 →
   마무리 단계 공문서 lint → 최종 한글 산출은 독스 → 마크다운 → 원본 서식 보존 패치(윈도우 COM 에이전트 ADR-0014 대체 후보).

## 근거

속도(3분 → 1초)와 표 충실도가 반입 지연과 재료 품질에 바로 닿는다. 어댑터 한 겹이면 교체·회귀가 쉽고, 포크로 지원 종료 위험을 줄인다.

## 되돌리기

`ZZAIMY_KORDOC_OFF=1` 이면 어댑터를 건너뛰어 pyhwp 경로만 쓴다. 파일·조각 형식은 바뀌지 않는다.
