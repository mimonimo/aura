# ADR-0040 — 문서 구조 단계 문답(CoT): 사업명 → 개요 → 목차 → 부 → 절의 항목 → 절의 뼈대

날짜: 2026-09-29 · 상태: 채택 · 관련: ADR-0039(실문서 학습쌍), ADR-0029(채팅 에이전트), 브리프 규칙 1·8

## 배경

사용자 지시(2026-09-29): 실문서 절 작성 쌍은 문답이 길고 지저분하다. 사업에 대한 문답을 사슬처럼 잇는 CoT 형식으로 — "AID 사업이
뭐야?" 에는 개요가 정답이고, 목차가 1·2·3… 이면 단계별로 내려간다. 사업 문서는 어느 것이든 개요와 목차가 있으니 그 공통 구조를
먼저 잡고 해당 사업의 정확한 구조를 파악하는 것이 핵심이다. 파인튜닝된 모델이 사업의 구조를 먼저 쓰고, 검색(RAG)·추가 문서의
근거를 그 구조에 채운다. 참고로 준 글 둘: daddynkidsmakers(2025-06, instruction·input·output 의 output 에 "[N단계: …]" 추론 뒤
최종 답), alchera(질문–생각의 사슬–답의 삼중 구조, 단계는 논리적으로 이어지고 사실이 정확해야 하며 길이는 문제 복잡도에 비례,
외부 근거를 추론에 통합, 반자동 생성 + 사람 검수, 패턴 암기 주의).

## 결정

1. 단계(사슬): ① 사업명 → 개요 ② 개요 → 목차(부·절) ②′ 목차 → 한 부의 절 구성 ③ 절 → 그 절이 다룰 항목 ④ 절 → 뼈대(소제목·표 머리·
   도식 자리, 내용 없음). 뼈대의 칸을 채우는 능력은 ADR-0039 의 절 작성 쌍이 맡는다.
2. 출력 형식: `[1단계: 질문 파악] … [2단계: 근거 확인] … [3단계: 구조 도출|항목화|뼈대 배치] …` 뒤 `[답]`. 추론 단계는 입력의 근거를
   따옴표로 인용한다(평가영역 'Ⅰ. 사업추진 목표(15)', 착안점 첫 구절, 요구 항목 1) — 검증 가능성. 표현은 절마다 세 가지로 바꿔
   같은 문장 패턴이 되풀이되지 않게 한다(패턴 암기 방지).
3. 입력은 짧다: 머리말 한 줄 + 근거 조각(공고·기본계획의 목적·개요, 평가편람의 영역·착안점) + 앞 단계의 답(사슬) + 질문. 지식은 입력의
   근거에서만 오고(규칙 8), 답의 사실 수치(세 자리 이상·백분율·소수)가 입력에 없으면 폐기한다(규칙 1). 절 번호(1.2·2.1.1)와 두 자리
   이하 수('3-Tier'·'5쪽 이내')는 구조 표기로 본다.
4. 재료: 양식(작성서식 557)의 절 목록과 작성방법 상자 → 목차·요구 항목, 완성본(562)의 같은 절 → 뼈대(소제목·표 머리·도식 제목),
   공고(561)·기본계획(560) → 개요 근거, 평가편람(564) → 영역·착안점 근거(운영 검색 `find_relevant`). 부 제목은 완성본 차례의 'Ⅰ. …' 줄.
5. 산출(`scripts/153_build_tree_cot.py`, VM): `data/training/tree_cot_pairs.jsonl`(검수용), `tree_cot_sft.jsonl`(messages — 단발형 +
   단계를 누적한 대화형), `tree_cot_alpaca.jsonl`(instruction·input·output, 단발형), `tree_cot_report.md`. Label Studio 「ZZAIMY 문서
   구조 문답」에 `--push --replace`. 반자동 방식이다 — 생성은 규칙, 판정은 사람.
6. 학습은 ADR-0039 의 절 작성 쌍과 섞어 한 어댑터로(구조 세우기 + 채우기). 순서: 베이스라인 측정 → SFT(`scripts/83 --data` 에 두 파일을
   이은 jsonl, `--seq-len 16384`) → DPO.

## 실측 (2026-09-29, VM)

- 사업명 "2026학년도 AID 전환 중점 전문대학 지원사업", 부 4개(Ⅰ 사업추진 목표 / Ⅱ 사업추진 실적 및 계획 / Ⅲ 사업추진체계 및 성과관리 /
  Ⅳ 재정관리 계획), 절 33개.
- 단발형 48건(1단계 3·2단계 3·부 4·3단계 22·4단계 16) + 대화형 15건 = 63건, 폐기 3건(뼈대에 수치가 든 절, 작성방법에 연도가 든 절).

## 보완 (2026-09-29 저녁, 아스트라 C-134 검토 반영)

- ③ 절의 항목 단계는 입력에 양식의 작성방법 상자도 근거로 준다(답이 입력에서 풀리게). 착안점 근거가 없으면 단정하지 않고 쌍을 내지 않는다.
- 수치 규칙은 `real_pairs.fact_numbers`(단위 붙은 수는 사실). 근거 설명의 '부 4개·항목 3개' 같은 셈은 답 자체가 근거라 제외.
- 대화형은 검증을 통과한 단계만으로 잇는다. "[N단계]" 줄은 모델이 실제로 한 생각이 아니라 검증 가능한 근거 설명이다 — 그렇게 부른다.
- 검수 화면은 질문 / 근거 설명 / 답 / 근거·사슬(접힘) / 원문 입력(접힘)으로 나눈다. 재실측: 단발 42 + 대화형 9 = 51건, 폐기 9(뼈대에
  '’27년' 같은 연차 표기나 표 값이 든 절 — 입력에 없는 사실로 본다).

## 한계·다음

- 한 사업의 문서 세트라 구조가 하나다. 다른 사업(공고·양식·계획서)이 오면 `--form/--done/--notice/--basic/--manual` 로 쌓아
  구조의 다양성을 만든다 — 이것이 "공통 구조를 먼저 잡고 사업마다 정확한 구조를 파악"하는 데 필요한 재료다.
- 추론 단계는 규칙 생성이라 사람이 쓴 것보다 단조롭다. 27B 가 초안을 쓰고 사람이 고치는 반자동 경로는 다음.
- 뼈대는 완성본의 소제목·표 머리에서 왔으므로 완성본이 없는 절(상위 제목)은 뼈대 쌍이 없다.
