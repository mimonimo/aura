# ADR-0048: 온톨로지 v3 — 절 단위 조각과 근거·기준이 달린 사업 그래프

상태: 제안 · 날짜: 2026-10-01 · 관련: ADR-0009·0010(v1·v2), ADR-0015, ADR-0033 7항(조각 제목 경로), ADR-0047

## 맥락

사용자(2026-10-01): "그래프랑 온톨로지는 보강해야 할 듯 — 그래프 디자인도 그렇고, 온톨로지도 문맥을 뭘 기준으로 잘라서 엮어놨는지."
진단:
- 조각: 처리한 글을 빈 줄 문단으로 자른다(40자 미만 버림, 2,000자 끊음, `pipeline._split_chunks`). 절 경계를 따르지 않고, 소속 절은
  저장하지 않고 읽을 때 앞선 제목 줄로 추정한다(`chunk_path`).
- 그래프: 노드는 문서 통째·프로젝트·개체(사업·기관·법령). 문서끼리는 임베딩 상위 2개(0.75↑)·같은 사업·같은 법령·개체 언급으로 잇는다
  (`graph/build.py`, 요청 때마다 다시 만든다). 문서 안의 절·지표·예산·연차가 없어 "1차년도 계획의 지표 ↔ 3차년도 실적" 같은 연결이 없다.

## 결정(제안)

0. 사업 분류가 먼저(사용자 2026-10-01: "각 사업별 분류도 잘 되어야 함"): 사업 카드(정식 명칭·다른 이름·기간·연차·주관 부서)를 데이터로
   두고 — 다른 이름은 공고·기본계획·표지 등 문서에서 뽑아 쌓는다(코드에 넣지 않음) — 문서마다 폴더 경로(DGX 원본은 사업별 폴더)·제목·
   표지 사업명·본문 앞부분 세 근거로 사업·연차·문서 갈래를 정한다. 근거가 맞으면 자동, 엇갈리거나 약하면 검토 대기. 결과마다 근거를
   남긴다. 이 분류 하나를 문서함(사업별 프로젝트·거르기), RAG(사업 범위 검색), 온톨로지(사업·연차 노드), 데이터셋(program_id)이 같이 쓴다.
1. 조각은 절 단위: 처리본의 목차 노드 경계를 넘지 않는다. 긴 절만 문단으로 나누고, 표는 머리 행을 붙여 따로. 조각마다 소속 절 id·제목 경로를
   저장한다. 검색 결과는 절 단위로 묶어 컨텍스트를 만든다.
2. 노드: 사업(program) → 연차(program_year) → 문서(계획서·실적보고서·평가·공고·서식·지침) → 절(section, node_path) → 조각(chunk).
   개체: 성과지표(이름·단위·연도별 목표값·실적값), 예산 항목(비목·금액·연도), 세부과제, 조직·위원회, 규정 조항.
3. 관계마다 기준과 근거: 기준 = 구조(목차·소속) / 식별자 일치(같은 지표명·과제명·비목) / 추출(27B, 근거 문장 필수) / 유사도(추정, 따로 표시).
   근거 = 문서·절·문장 위치. 근거를 댈 수 없는 관계는 만들지 않는다(v1 원칙 유지).
4. 주요 관계: contains(구조), plans↔reports(같은 과제·지표의 계획과 실적), evaluates(평가 의견 → 대상 연차·절), target↔actual(지표 연도별),
   funds(예산 → 과제), mentions(절 → 개체, 근거 문장), similar(절↔절, 추정).
5. 저장: PostgreSQL 노드·관계 표(요청 때마다 다시 만들지 않음). id 는 사람이 읽는 고정 값 — 예) program:linc3, year:linc3:2024,
   doc:linc3:2024:report, section:linc3:2024:report:2.1.3, kpi:linc3:취업률. 아스트라 provenance(program_id·node_path)가 같은 값을 쓴다.
6. 화면: 사업 하나 중심 — 연차별 열 × (계획·실적·평가) 행. 관계를 누르면 기준과 근거 문장. 유사도 관계는 점선·접힘.

## 검증

LINC3.0 1~3차년도 계획·실적·평가 9건으로 먼저: 절 노드 수·조각 경계(절을 넘는 조각 0), 지표 목표↔실적 대응을 원문과 대조, 화면에서
연결 기준이 보이는지. 그 뒤 AID 7건에 같은 규칙.
