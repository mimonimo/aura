# 0011. 학습·데이터 도구 — 기성 오픈소스 통합

- **상태**: 제안 (교수님 확인 후 채택)
- **날짜**: 2026-09-08
- **관련**: ADR-0001(학습 스택), 데이터 공방(dataset/build.py), 2주차 미팅
  (SFT+DPO+RAG), 사용자 요청(2026-09-08)

## 맥락

학습 모니터링·실행 UI·데이터 라벨링을 지금은 자체 제작했거나(데이터 공방)
아직 없다. 사용자 요청: W&B·TensorBoard 같은 학습 모니터링, LLaMA-Factory·
HF AutoTrain 같은 학습 UI, Label Studio 같은 데이터 관리 대시보드를 오픈소스로
끌어다 플랫폼에 붙이자. 자체 재발명 대신 검증된 도구를 쓰는 것이 맞다.

제약: 온프레미스·오프라인(외부 API 불가), 실제 학습은 DGX 확보 후. 이 도구
대부분은 GPU/학습 로그가 있어야 의미가 있다.

## 결정 (도구별)

### 학습 모니터링 — TensorBoard (채택 권장)
- W&B 대신 TensorBoard. 완전 오픈소스·오프라인 동작(W&B는 SaaS 기본,
  오프라인 모드는 있으나 서버 별도)이라 우리 환경에 맞다.
- LLaMA-Factory가 `report_to: tensorboard`로 학습 로그를 쓰면 TensorBoard가
  손실·학습률·평가지표를 그래프로 낸다.
- 플랫폼 통합: /dev/train에 TensorBoard(기본 6006 포트)를 iframe 임베드,
  또는 리버스 프록시. 별도 웹앱을 우리가 만들지 않는다.

### 학습 실행 UI — LLaMA-Factory의 LLaMA Board (채택 권장)
- 이미 학습 엔진으로 정한 LLaMA-Factory에 Gradio 웹UI(LLaMA Board)가 내장.
  데이터셋 선택·하이퍼파라미터·학습 시작·미리보기를 UI로. 별도 제작 불필요.
- HF AutoTrain은 대안이나, 스택 일관성(이미 LLaMA-Factory 채택)과 오프라인
  적합성에서 LLaMA Board 우선.
- 플랫폼 통합: /dev/train에서 LLaMA Board(기본 7860)로 링크·임베드. DGX에서
  구동, 맥·VM에서 접근.

### 데이터 라벨링·관리 — Label Studio (채택 권장, GPU 불필요)
- 오픈소스. 학습 쌍 검수, 실적 카드 추출 정답 라벨, DPO 선호쌍(A/B 선택)을
  사람이 다루는 표준 도구.
- 데이터 공방과의 역할 분담: 공방은 기록→후보 쌍 자동 생성(수치 검증 필터),
  Label Studio는 사람 검수·정답 확정. 공방이 Label Studio 태스크 형식으로
  내보내고(JSON), 검수 결과를 다시 받아 골드/학습 세트로.
- GPU 불필요 — DGX 전에 지금 착수 가능한 유일한 도구.

### RAG — 자체 구현 유지
- 현재 KURE+Kiwi+RRF+리랭커가 도메인에 맞고 실측 성능이 나온다(R@1 0.62).
  기성 프레임워크(LlamaIndex 등)로 갈아탈 이득이 비용을 넘지 않는다. 유지.

## 통합 원칙

- 도구는 각자의 프로세스로 돌리고 플랫폼은 **연결·임베드**만 한다. 우리
  코드로 재구현하지 않는다(모니터링 그래프·라벨링 UI 등).
- 오프라인: 전부 학내망에서 자립 동작해야 한다. 설치는 프록시 역터널로 1회.
- 접근 통제: /dev 하위(개발자 전용)로. 라벨링은 담당자도 쓸 수 있게 별도
  검토 후 권한 설계.
- 데이터는 장비 밖으로 안 나간다 — Label Studio·TensorBoard 모두 로컬 인스턴스.

## 단계

1. (지금) 이 ADR + /dev에 "모델 학습" 섹션 골격(각 도구 연결 지점, 미가동
   표시). Label Studio 데이터 연동 규격을 데이터 공방에 추가(내보내기·되받기).
2. (Label Studio 구동 후) 실제 라벨링 워크플로 — 공방 후보 → 검수 → 골드.
3. (DGX 후) LLaMA-Factory 학습 + TensorBoard 모니터링 + LLaMA Board를
   /dev/train에서 접근. 베이스라인 측정 먼저(순서 원칙).

## 되돌리기 비용

- 임베드·연동 방식이라 결합도 낮음. 특정 도구를 바꿔도 플랫폼 코어 영향 적음.
- Label Studio 내보내기 형식만 계약으로 고정하면 라벨링 도구 교체도 가능.
