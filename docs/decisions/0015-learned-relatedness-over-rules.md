# 0015. 연관·반영 판정은 학습된 의미 표현으로 한다 (규칙·키워드 짜맞추기 폐기)

- 상태: 확정 (사용자 지시 2026-09-14: "실제 연관 있고 중요한 키워드를 찾아 묶는 능력이 되어야 한다. RAG 생성도 무식하게 하면 안 된다")
- 날짜: 2026-09-14
- 관련: ADR-0009(그래프 온톨로지), ADR-0010(개체 계층), `docs/context/working-notes.md` 하드코딩 금지, `src/zzaimy/graph/build.py`, `src/zzaimy/verify/coverage.py`, `src/zzaimy/app/drafter.py`

## 맥락

지식 그래프가 문서를 "개체 하나라도 겹치면" 이었다. 한국장학재단이 언급됐다는 이유로
개인정보 동의 절차 문서가 기부장학금 사업계획과 연관으로 떴다. 이를 고치려고 시도한
두 가지가 모두 사례 짜맞추기로 흘렀다.

- 개체 벡터(IDF 가중) 코사인: 잡음이 줄긴 했으나(123→9 간선) 동의 절차 문서가 장학금
  이름 6개를 나열해 여전히 사업 문서와 엮였다(코사인 .703).
- 문서 역할을 제목 규칙으로 나눠 같은 역할끼리만 잇기: "업무처리기준"이 든 사업계획이
  규정으로 오분류되고, 정작 문제의 간선은 안 잘렸다.

같은 성격의 문제가 초안 생성(RAG)에도 있었다. 섹션 근거로 넣는 접수 자료가 문서
앞 6조각 고정(예산 섹션이든 추진체계 섹션이든 같은 재료)이었고, 배점 커버리지는
항목 키워드의 문자열 포함 여부만 봤다(키워드가 없으면 다뤘어도 누락, 있으면 안
다뤘어도 반영).

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 규칙·키워드 정교화(역할 사전, 불용어, 임계값 조정) | GPU 불필요, 설명 쉬움 | 문서마다 예외가 생겨 규칙이 끝없이 늘고, 새 문서에서 다시 틀린다(실측으로 확인) |
| B. 학습된 임베딩(KURE-v1)의 의미 유사로 판정 | 규칙 없이 내용으로 묶임, 이미 검색 스택에 있어 추가 비용 없음, CPU로 동작 | 절대 임계값은 모델 척도에 묶여 보정이 필요 |
| C. 크로스인코더(리랭커)로 항목↔문단 관련도 판정 | 검색 리랭킹에선 검증된 도구 | 짧은 항목 문구를 질의로 주면 로짓이 0 근처로 눌려 판별값이 안 나옴(실측) |

## 결정

B. 세 곳 모두 학습된 임베딩을 판단 근거로 바꿨다.

1. 그래프 문서↔문서 연관 = 임베딩 유사(similar) 간선을 주 신호로 기본 표시. 개체
   공출현·규칙 기반 연관은 제거. 개체 노드는 탐색용으로 남기되 기본 숨김.
2. 초안 섹션 재료 = 섹션 질의와 접수 자료 조각의 임베딩 코사인 상위 6개(문서 1건당
   벡터 1회 계산). 후보 풀은 앞 10조각에서 40조각으로 넓힘.
3. 배점 커버리지 = 1차 키워드(결정론) + 2차 의미 판정. 의미 판정은 절대 임계값이
   아니라 돋보임 규칙: 항목별 최고 문단 코사인 − 문단 평균 ≥ 0.10 이고 최고 ≥ 0.40,
   문단 4개 이상일 때만. 판정 근거("키워드"/"의미 +0.12")를 리포트에 남긴다.

임베딩 함수는 `embed_fn`으로 주입한다. `verify/`가 `app/`을 모르게 하고, 모델이
없으면 세 곳 모두 기존 규칙 동작으로 조용히 내려간다.

## 근거

실측(운영 VM, KURE-v1 CPU, 2026-09-14).

- 그래프: 임베딩 유사는 개인정보 동의 절차끼리(.862), 장학 사업끼리(.842, .865),
  IACF 규정끼리(.905), 편성표 연도끼리(.92~.96) 묶였고 절차↔사업은 안 엮였다. 개체
  코사인은 절차↔사업을 .703으로 엮었다.
- 커버리지 절대값: 항목↔문단 코사인이 관련 .464~.625, 무관 최대 .473으로 겹친다.
  0.62 임계값은 전부 누락으로 찍었다.
- 커버리지 돋보임: 최고−평균이 관련 .134~.181, 무관(초안에 없는 항목) .061. 실제
  판정에서 관련 항목 +0.11~+0.13, 무관 항목 누락. 키워드만이면 0/55점이던 표본이
  45/55점.
- 크로스인코더: 같은 그리드에서 시그모이드 .500~.534, 무관 항목과 구분 불가.
- 재료 선별: 예산 섹션에 예산 조각, 추진체계 섹션에 체계 조각이 1순위로 옴.

미확인: 돋보임 폭 0.10은 합성 문단 표본으로 정했다. 실제 생성 초안·공고 쌍에서의
보정은 아직 없다(관련 항목 폭이 하한에 가깝다, 재보정 대상).

## 결과와 되돌리기 비용

- 판단 품질이 임베딩 모델에 묶인다. ZZAIMY-Embed(도메인 파인튜닝) 완성 시 세 곳이
  같이 좋아지고, 반대로 모델을 바꾸면 돋보임 폭·바닥값을 다시 재야 한다.
- 규칙으로 되돌리는 비용은 낮다(embed_fn 미주입 = 기존 동작). 다만 그렇게 하면
  이 ADR의 맥락에 적힌 오분류가 그대로 돌아온다.
- 운영 VM은 아웃바운드가 막혀 있어 모델 로더가 허브 갱신 확인에서 멈추는 함정이
  있었다. `embed_search`·`rerank` 로더에 HF 오프라인 기본값을 넣어 서비스 밖
  스크립트·테스트도 같은 함정에 안 빠지게 했다.
