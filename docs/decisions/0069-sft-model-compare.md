# 0069. SFT 학습 모델로 바꿀지는 같은 시험으로 오픈 모델과 비교해 정한다

- **상태**: 확정 (이번 SFT 병합본 writer-sft-v1 은 채택하지 않았다 — 플랫폼 문서 작업 에이전트가 동작하지 않음, 토르 02 는 10-24 오픈 모델로 되돌림. 비교 절차는 다음 판 v2 에도 그대로 쓴다)
- **날짜**: 2026-10-24
- **관련**: ADR-0052(SFT 범위), ADR-0067·0068(문서 작성 시나리오 202), 절대 규칙 1(수치는 인출만)·2(베이스라인 먼저)

## 맥락

아스트라가 학습한 Writer SFT(LoRA r32, BF16 바탕, 2에폭, 학습 4,434쌍)가 나왔다. 운영에 넣는 꼴은 어댑터를 바탕에 합친 뒤
운영과 같은 NVFP4 혼합 양자화로 다시 줄인 병합본(`writer-sft-merged`)이다. 바꾸는 것은 모델 하나뿐이고 질문·플랫폼 코드·설정·생성 설정·채점 모델은 그대로 둔다.
기존 비교 도구(195·201·202·203)는 장부에 등록한 연결만 받았고, 학습셋 시험 문항으로 두 모델을 나란히 재는 도구는 없었다.

## 결정

1. 비교는 네 묶음으로 한다. 모든 묶음에서 비교 대상마다 같은 요청을 보낸다(온도 0.2, 최대 2,048토큰, 생각 끔).
   - 시험 문항 220개(학습셋에서 따로 떼어 둔 test, scripts/210): 문항마다 학습 꼴 그대로(시스템·앞 대화·질문)로 생성.
     채점 모델(토르 03 운영 Writer)이 두 답을 보고 나은 쪽을 고른다 — 순서를 바꿔 두 번 묻고 두 판정을 더한다(자리 치우침 상쇄).
     정답은 채점 모델에 보여 주지 않는다(정답 꼴을 익힌 쪽에 기울지 않게). 같은 채점 모델이 답 하나씩 여섯 항목
     (지시 충실·맥락 이해·형식·근거 충실·문체·완결성)을 1~5점으로도 매긴다. 코드가 세는 지표: 정답 겹침(chrF·ROUGE-L), 질문에 없는 숫자,
     표·정답 형식·「확인 필요」 표시, 잘림, 길이, 시간·토큰.
   - 맥락 이해 30문항(scripts/211): 여러 번 주고받은 값 이어 쓰기(절반은 둘째 질문에서 예산을 바꿈), 공개 공고·기본계획 약 1.16만 토큰 속
     사실 한 문장 찾기(일부는 자료에 없는 것을 물음), 다섯 칸 표에서 자료에 없는 칸을 「확인 필요」로 두기. 가상 값이라 개인정보가 없고 채점은 코드.
   - 문서 작성(scripts/202 noforms, 모델마다 2회): 양식 없이 시작해 11번 주고받으며 양식 만들기·절 쓰기·고쳐 쓰기·디자인까지.
     SFT 쪽은 답변·검토 용도를 모두 후보로 돌린다(운영 교체 뒤 모습과 같게). 채점은 운영 연결로 고정.
   - 속도: 시험 문항 20개를 한 번에 하나씩 흘려 받아 첫 글자까지 시간·초당 토큰.
2. 결과 파일은 비교 대상 이름(open-nvfp4·sft-merged·sft-lora)으로 남긴다. 운영 서버를 병합본으로 바꾼 뒤 같은 서빙 이름(zzaimy-writer)으로
   다시 재도 앞 결과와 섞이지 않는다. 답 하나씩 매기는 항목 점수는 다른 모델 답을 보지 않으므로 나중에 더한 대상과도 그대로 비교된다.
3. 장부에 없는 교내 서버는 `--candidate-url`(ZZAIMY_LLM_TRY_URL)로 장부를 고치지 않고 잰다(195·201·202·203). 등록된 외부 서버 주소는 거절한다.
   202 는 장부 사본(ZZAIMY_EVAL_CONN)에 후보 연결을 더해 돌릴 수도 있다 — 운영 llm_connections.json 은 건드리지 않는다.
4. 결과는 scripts/212 가 `data/eval/model_compare/<run-id>/`(summary·samples·docs.json, 한글 결과 파일)에 모으고 관리자 화면이 읽는다.
   대표 문항은 사람 이름·연락처를 가린다. 서버 주소는 남기지 않는다.
5. 생성 비교 전에 두 가지를 먼저 본다: 학습이 서빙에 들어갔는가(정답 로그확률, 210 goldlp), 학습셋 틀이 플랫폼 꼴 요청에 새는가(213).
6. 채택 기준(제안): 시험 문항 220개의 나은 답 점수 95% 구간 아래 끝이 0.5 이상이고, 맥락 이해·문서 작성에서 오픈 모델보다 떨어진 항목이 없으며
   (지어낸 숫자 0 유지), 문서 작성 시나리오에서 작업본을 끝까지 만들고, 평범한 질문에 학습셋 틀이 나오지 않으며(0/45),
   속도가 운영 허용 범위(첫 글자 1초 안팎, 초당 20토큰 이상)일 때 바꾼다.

## 결과(10-24, 운영 VM, run-id sft-compare-20261024)

### 가장 큰 문제 — SFT 병합본에서 플랫폼 문서 작업 에이전트가 동작하지 않는다

운영 토르 02 를 병합본(/models/writer-sft-v1-merged-nvfp4)으로 바꾼 상태에서 문서 작성 시나리오(202, 2회)를 돌렸다.
- 두 회차 모두 작업본을 만들지 못했다(오픈 모델 2/2 → 병합본 0/2, 쓴 절 6.5 → 0). 11턴 가운데 묻기만 하고 끝난 턴 82%(오픈 14%),
  에이전트 단계 출력을 읽지 못해 멈춘 턴(stop=format) 18%(오픈 0%). 디자인 요청도 반영 0.
- 작업 메모(chat_memory)에 학습셋 틀이 그대로 들어갔다 — 「근거 설명: … 검색 계획: {…} 답변: …」(1회차 11/11턴).
- 평범한 업무 질문 15개(213)에서도 학습셋 틀(줄머리 「답변:」)이 나왔다: 지시 없음 11/15, 플랫폼 답변 지시(responder._SYSTEM) 15/15,
  학습셋 지시 13/15. 오픈 모델은 세 판 모두 0/15.
- 원인: 학습쌍이 「한 줄 시스템 지시 + 질문 → 근거 설명·답변 틀」 하나의 꼴뿐이라, 플랫폼이 실제로 보내는 꼴(에이전트 단계 JSON, 작업 메모 갱신,
  채팅 답, 절 쓰기·고쳐 쓰기 지시)에도 그 틀을 쓴다. 학습 데이터에 서빙 꼴을 넣거나, 플랫폼이 쓰는 시스템 지시로 학습해야 한다.

### 측정 경위와 어댑터 대조군

SFT 병합본 측정 경위: 토르 02 에 운영과 나란히 :8002 로 띄우려 했으나 CUDA 그래프 준비 중 메모리 부족(137)으로 멈췄다(10-24 02시대).
운영 :8001 을 병합본으로 바꾼 뒤(04:28) 같은 시험을 돌렸다(VM ~/ops/sft_eval/drive4.sh). 채점 모델(토르 03)은 그대로 오픈 모델이다.

SFT 어댑터(writer-sft, 토르 02 :8001 에서 LoRA 로 얹음): 서빙에서 효과가 없었다.
- 첫 토큰 상위 5개 로그확률(온도 0, 3문항)과 정답 토큰당 평균 로그확률(40문항, -1.845 · 첫 토큰 -3.46)이 오픈 모델과 소수 다섯째 자리까지 같다.
- 생성 결과 56문항 중 21개가 글자까지 같고, 나머지 차이는 오픈 모델을 같은 seed 로 다시 돌렸을 때의 차이(6/6 다름)와 같은 크기다 — 서빙 비결정성(배치·MTP).
- 학습은 됐다(손실 1.43 → 0.92). 토르 02 기동 기록에는 어댑터를 읽었다고 나오고 visual.* 만 무시했다고 나온다. 어댑터 키 접두
  `base_model.model.model.layers.N` 이 서빙 모델(Qwen3_5ForConditionalGeneration)의 `model.language_model.layers.N` 에 맞지 않아
  어디에도 붙지 않은 것으로 본다(서빙 담당 확인).
- 그래서 이 대상은 「같은 모델을 두 번 돌린」 대조군으로만 쓴다 — 둘 중 나은 답 고르기의 잡음 크기를 본다.
  대조군 결과(220문항): 이김 49 · 비김 129 · 짐 42, 점수 0.516(95% 구간 0.475~0.559). 같은 모델끼리도 41% 문항에서 한쪽을 골랐고,
  두 순서 판정이 엇갈린 문항 23%, 채점 모델이 A 자리를 고른 비율 0.364(뒤 자리를 더 고름). 그러므로 병합본의 점수가 이 구간(대략 0.47~0.56) 안이면 차이가 없다고 본다.
- 결정 보탬: 어댑터·병합본이 서빙에 실제로 들어갔는지는 생성 비교 전에 정답 로그확률(210 goldlp)로 먼저 확인한다. 샘플링 잡음이 없어 몇 분이면 갈린다.
