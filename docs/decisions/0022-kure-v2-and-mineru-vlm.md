# 0022. 임베딩 베이스 KURE-v2와 MinerU의 GPU 판독 백엔드를 보류한다

- 상태: 제안 (KURE-v2 항목은 교수님 판단이 필요하다)
- 날짜: 2026-09-21
- 관련: ADR-0021(임베딩 v2 채택), ADR-0025(KURE-v2 측정)

## 배경

사용자가 두 가지를 물었다. KURE도 v2를 쓰면 되지 않는가, MinerU도 토르로 옮겨 OCR을 강화할 수
있지 않은가. 둘 다 같은 날 실측했다.

## KURE-v2

공개된 KURE-v2를 토르 03에 받아 구조를 보니 단일 벡터 모델이 아니었다. PyLate로 만든 ColBERT
계열의 다중 벡터 모델이라 토큰마다 벡터를 낸다. 지금 검색은 조각당 벡터 하나를 코사인으로
견주고 질의 임베딩도 같은 방식이다. KURE-v2를 쓰려면 색인 형식, 임베딩 서비스, 점수 계산을 통째로
바꿔야 한다. 계획 문서의 임베딩 베이스는 KURE-v1 단일 벡터다.

보류한다. 베이스 교체가 아니라 검색 구조 변경이므로 별도 결정이 필요하다. 바꾼다면 같은 질의
세트에서 후보 진입률과 R@1을 지금 운영과 나란히 재고, 다중 벡터 색인의 크기와 질의 시간을 함께
적는 것이 조건이다. 그 전까지는 KURE-v1의 학습본(v2)을 유지한다. 이 조건은 다음 날 ADR-0025로
이행했다.

## MinerU의 GPU 판독 백엔드

MinerU 3.4.5의 원격 판독 방식으로 토르 03의 vLLM에 MinerU 전용 1.2B 모델을 올려 문서 두 쪽을
넣었다. 25~33초로 빨랐지만 결과가 잡음이었다. 한자 잡음과 같은 날짜 줄이 반복됐다. MinerU의
로짓 처리기를 붙여도, 한국어 옵션을 줘도 같았다. 젯슨의 vLLM 빌드와 이 모델의 궁합 문제로
본다. MinerU가 지정한 vLLM 판을 젯슨용으로 맞추는 일이 먼저다.

보류한다. PDF 구조 추출은 운영 서버의 MinerU 파이프라인으로 두고, 스캔본과 글자층이 깨진
문서는 27B 판독으로 간다.

## 이후

27B 양자화 판의 적재 실패와 두 토르 분담은 ADR-0023으로 옮겼다. 규칙대로 옛 기록에 덧붙이지
않는다.
