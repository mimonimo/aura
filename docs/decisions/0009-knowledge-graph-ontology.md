# 0009. 지식 그래프 — 경량 온톨로지와 단계 도입

- **상태**: 채택
- **날짜**: 2026-09-08
- **관련**: ADR-0002(에이전트 계층), `research` 그래프 A/B(원안에서 삭감 → 사용자 지시로 부활), 사용자 확정(2026-09-08): 최종 형태 = 하이브리드 검색 + 지식 그래프 + 파인튜닝

## 맥락

"이 공고에 내세울 우리 실적은?" 같은 질문은 유사도 검색만으로 풀리지 않는다.
공고→사업→과년도 문서→실적으로 건너가는 다리가 필요하며, 이것이 그래프의
역할이다. 사용자는 옵시디언 그래프 뷰 수준의 시각화(채팅·기준문서 페이지 진입)도
요구했다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. OWL/RDF 정식 온톨로지 | 논리 추론, 표준 교환 | 설계에만 수 주. 13주 일정에 정당화 불가 |
| B. 전용 그래프 DB(Neo4j 등) | 그래프 질의 언어 | 운영 스택 추가. 현 규모(문서 수십~수백)에 과함 |
| C. 경량 온톨로지 + 기존 SQLite 관계에서 그래프 생성 | 추가 인프라 0, 즉시 가동 | 대규모 그래프 질의엔 한계 |

## 결정

**C.** 유형 정의(경량 온톨로지)만 명시하고, 그래프는 기존 DB 관계에서 매번
생성한다(`src/zzaimy/graph/build.py`). 규모가 커져 생성 비용이 문제가 되면
그때 사전 계산·전용 저장소로 이관한다.

온톨로지 v1:

- 노드 — criteria(기준 문서: 규정·지침·공고), intake(접수 문서), project(프로젝트)
- 간선 — refers(접수→기준 근거), belongs(문서→프로젝트), uses(프로젝트→기준),
  cites(기준→기준 조문 참조: 제목 언급 스캔), similar(기준↔기준: 임베딩 코사인)

도입 단계:

1. **구조 그래프(이번)** — 위 관계만. GPU·LLM 불필요. `/graph` 뷰 + `/graph.json`
2. **개체 그래프(LLM 후)** — 문서에서 사업·부서·연도·실적 항목 개체를 추출해
   노드로 추가. 온톨로지에 개체 유형을 증보(v2)하고 ADR로 남긴다
3. **검색 결합** — 검색 결과에서 그래프를 1~2걸음 확장해 근거 후보를 보강
   (GraphRAG). 확장 폭·기여도는 평가 하네스로 측정 후 반영

## 근거

그래프의 당면 용도는 검색 확장과 시각화이지 논리 추론이 아니다. cites를
제목 언급 스캔으로 잇는 것은 특정 사례 짜맞추기가 아니라 일반 메커니즘이다
(모든 기준 제목에 동일 적용). 유사 간선은 이미 있는 사전 계산 임베딩을
재사용하므로 추가 비용이 없다.

## 결과와 되돌리기 비용

- 잠그는 것: 노드·간선 유형 이름(`/graph.json` 계약). 뷰·검색 확장이 여기 의존.
- 되돌리기: 생성식 그래프라 저장소 마이그레이션이 없다. 유형 추가는 자유,
  유형 변경·삭제만 뷰와 동시 수정 필요 — 저비용.
