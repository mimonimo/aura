# 0029. 구글 독스를 화면 안에서 에이전트와 함께 고친다 — 쓰기는 담당자가 누른 것만, 가리고, 기록한다

- 상태: 채택
- 날짜: 2026-09-22
- 관련: ADR-0028(드라이브 읽기 전용 원천), ADR-0008(외부 참조 관문), ADR-0024(공개 문서 판독 예외), 브리프 절대 규칙 3

## 배경

사용자는 구글 독스 문서를 플랫폼 화면 안(iframe)에 띄우고 옆의 에이전트가 바로 붙기를 바란다. 우리 화면은
iframe 안을 읽을 수 없으므로 에이전트는 구글 독스 API(`documents.get`·`documents.batchUpdate`)로 같은 문서를 읽고
고친다. 문제는 방향이다. 읽기는 드라이브 원천과 같지만, 쓰기는 교내 내용이 구글로 나가는 외부 전송이다.

## 결정

1. 읽기: 담당자가 문서 작업 화면에 연 문서의 본문·제목 구조를 에이전트가 읽어 근거 검색·검토·초안의 재료로 쓴다.
   읽은 본문은 대화 첨부와 같은 취급이다(저장하지 않고 그 요청에만 쓴다).
2. 쓰기는 세 가지 제한을 둔다.
   - 담당자가 화면에서 누른 삽입(절 아래에 넣기)·치환만 보낸다. 에이전트가 스스로 문서를 고치지 않는다.
   - 보내는 글은 개인정보 검사기(접수 문서 마스킹과 같은 것)를 한 번 더 거친다. 검색 근거 조각의 원문은 넣지 않고
     에이전트가 쓴 글만 넣는다.
   - 모든 쓰기는 `data/platform/gdocs_audit.jsonl` 에 시각·계정·문서·절·글자 수로 남고 원천 관리 화면에 보인다.
3. 허용 범위는 drive.readonly 에 documents 를 더한다. 기존 허용 계정은 다시 허용받아야 한다(화면이 안내).
4. 제안 모드(추적 변경)는 API 가 지원하지 않으므로 직접 편집이다. 검토 성격의 제안은 화면의 답변으로 보여 주고
   담당자가 넣을지 고른다.

## 근거

- 구글 독스 API 개요(사용자 확인 2026-09-22): 읽기 `documents.get`, 쓰기 `documents.batchUpdate`(원자적 일괄 갱신).
- iframe 편집기는 실시간 동기화라 API 로 넣은 글이 담당자 화면에 바로 보인다. 서드파티 쿠키를 막는 브라우저에서는
  iframe 로그인이 안 되므로 화면에 "새 창에서 열기"를 같이 둔다.
- 가짜 독스 API 로 구조 읽기·절 삽입·치환·감사 기록을 검증했다(`tests/test_gdocs.py`).

## 되돌리기

문서 작업 경로(`/gdocs/*`)를 빼고 허용 범위에서 documents 를 지우면 1단계(읽기 전용 원천)만 남는다.
