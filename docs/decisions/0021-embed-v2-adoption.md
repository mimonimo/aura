# 0021. 조밀 검색 모델을 학습본(ZZAIMY-Embed v2)으로 바꾼다

- 상태: 확정
- 날짜: 2026-09-20
- 관련: `docs/model-cards/zzaimy-embed-v2.md`, ADR-0020(리랭커), 절대규칙 2·8

## 맥락

같은 날 오전에 만든 임베딩 학습본 v1 은 조밀 단독 지표가 올랐는데도 운영 하이브리드에서 이득이
없어 보류했다. 원인을 따져 보니 오답을 조밀 검색 상위에서만 뽑아, 어휘 검색이 이미 잡아 주던
건들만 좋아진 것이었다. 한편 축별 진단에서 상황으로 묻는 질의는 조밀 축이 거의 전부를 짊어지고
(상위 20 기준 조밀만 0.420 · 어휘만 0.047), 두 축 모두 못 찾는 22.7% 가 천장으로 남았다.
리랭커·후보 수로는 이 천장을 넘을 수 없다 — 조밀 축을 고쳐야 했다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. KURE-v1 유지 | 손대지 않음 | 천장 그대로 |
| B. v1 채택 | 이미 만들어 둠 | 하이브리드 이득 0 — 색인만 다시 만드는 비용 |
| C. 오답을 융합 후 후보에서 뽑아 재학습(v2) | 어휘가 못 걸러 준 경쟁자를 배운다 | 색인 전체 재계산 + 질의 모델 동시 교체 필요 |
| D. 조각에 질문을 붙여 보조 축 추가(doc2query) | 말이 다른 질의에 직접 대응 | 생성물 관리·색인 축 추가. C 와 배타적이지 않다 |

## 결정

C 를 택해 v2 를 운영에 적용했다(색인 4,003개 재계산, 질의 임베딩 서비스 8016). 베이스 KURE-v1 은
8014 에 그대로 두어 비교에 쓴다. D(doc2query)는 별도로 준비 중이며 v2 위에 얹어 측정한다.

## 근거

학습에 쓰지 않은 21개 문서의 질의로만, 운영 경로(어휘+조밀 → 후보 20 → 리랭커) 그대로 측정.

| 홀드아웃 질의 | 임베딩 | 후보 진입률 | R@1 | R@5 | MRR@10 |
|---|---|---|---|---|---|
| 정확한 질문 90건 | KURE-v1 | 0.889 | 0.811 | 0.856 | 0.837 |
| 정확한 질문 90건 | v2 | 0.933 | 0.856 | 0.911 | 0.884 |
| 상황 질문 14건 | KURE-v1 | 0.929 | 0.714 | 0.929 | 0.821 |
| 상황 질문 14건 | v2 | 0.929 | 0.714 | 0.929 | 0.809 |

조밀 단독으로는 1위 정확도가 내려간다(합성 R@1 0.567→0.522). 그래도 최종 지표가 오르는 이유는
조밀의 일이 "정답을 후보에 들여놓기"이고 순서는 리랭커가 잡기 때문이다(R@20 0.844→0.900).

## 결과와 되돌리기 비용

- 되돌리기: 백업 색인(`data/platform/backup/chunk_embeddings-<stamp>.npz`)을 되돌리고
  `ZZAIMY_EMBED_URL` 을 8014(KURE-v1)로 바꾼 뒤 서비스를 재시작한다. 5분 안에 가능하다.
- 잠기는 것: 색인과 질의 모델은 한 짝이다. 한쪽만 바꾸면 벡터 공간이 어긋나 검색이 조용히
  망가진다(오류가 아니라 엉뚱한 결과로 나타난다). 그래서 색인 메타에 모델 이름을 적고
  `scripts/110_serving_check.sh` 가 서비스와 설정을 함께 본다.
- 조각을 다시 나누거나 문서를 다시 반입하면 색인을 이 모델로 다시 만들어야 한다
  (`MODEL=/models/zzaimy-embed-v2 bash scripts/96_embed_on_thor.sh --apply`).
