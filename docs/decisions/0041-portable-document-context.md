# ADR-0041: 이식 가능한 문서 맥락 계약

상태: 채택 (순수 코어 구현, 운영 연결은 별도)

## 배경

문서의 고정 길이 분할과 제목 번호 추정만으로는 표 주석, 제외 조건, 상위 항목을
보존할 수 없다. SFT와 RAG가 다른 방식으로 맥락을 만들면 검수 기준도 달라진다.
사용자는 다른 환경으로 옮길 수 있는 모듈화를 요청했다.

## 결정

- `zzaimy.document_context`는 표준 라이브러리만 사용한다. DB, UI, 검색 엔진,
  LLM, Label Studio를 가져오지 않으며 네트워크/파일 쓰기를 하지 않는다.
- 문서 식별자는 사업·문서·개정판을 포함한다. 실제 원문 순서는 `order`로 제공하고
  인쇄 쪽 번호는 위치 정보로만 사용한다. 표·본문 문자열을 임의 절단하지 않는다.
- 명시적으로 제공된 목차 노드(parent)와 근거 관계(requires)를 검증한다.
  주석/예외의 의미 관계를 자동 발견했다고 주장하지 않는다. 검증 안 된 구조는
  `needs_review`로 표시한다.
- 검색 결과 ID로부터 부모와 필요한 연결 근거를 펼친다. 호출자는 요청자의
  접근 가능 ID 집합을 반드시 전달한다. 사업 경계를 넘는 자동 확장은 금지한다.
- 근거가 없거나 권한 때문에 제외되거나 길이 예산을 넘으면 `complete=False`를
  반환한다. 누락된 원문 내용을 채우거나 조용히 잘라서 완전한 답변으로 전달하지 않는다.
- 문답/이전 대화의 자동 생성이나 개인정보 마스킹은 코어의 책임이 아니다.
  권한, 가명화, 검수 승인, SFT export는 별도 계층에서 처리한다.

## 결과와 한계

새 문서 파서/기존 DB는 이 계약으로 변환하는 어댑터가 필요하다. 실제 제목 관계와
표 주석 링크는 파서 또는 검수자가 공급한다. 코어가 승인한 구조라고 해서
사실 정확성/문서 전체 커버리지/개인정보 검수가 끝난 것은 아니다.
운영 교체 전 7개 실문서의 검수 구조와 대조하고 RAG 권한/누락 회귀를 수행한다.
