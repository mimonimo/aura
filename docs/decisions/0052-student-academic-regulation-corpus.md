# ADR-0052: 학생은 학사 규정 RAG 만 — 교직원 자료와 분리

- 상태: 채택
- 날짜: 2026-10-06
- 관련: 절대 규칙 4(열람 등급은 검색 단계에), 절대 규칙 6(문서 계열을 단일 색인으로 합치지 않는다), `docs/notes/2026-09-22-access-controlled-knowledge-base.md`

## 맥락

지금 들어 있는 자료(사업 문서·규정·문서함·그래프)는 교직원·교수용이다. 사용자: "추후에 학생도 추가할건데 학생은 학사관련 규정 RAG 만
참조 가능하도록 할거야. 그러니 지금 있는 RAG 랑 분리 되어야함."
학생 역할(student)은 이미 일부 있었지만 점검해 보니 두 군데가 열려 있었다(학생 계정은 아직 없어 실제 노출은 없었다).
1. 학생 대화가 사업 문서 검색을 불렀다. 학생 범위에는 사용자 값이 없는데, 사업 문서 검색은 사용자가 없으면 권한 필터를 걸지 않는다.
2. 화면 차단은 /dev 뿐이었다. 학생도 문서함·원본 보관소·그래프·프로젝트 화면에 들어갈 수 있었다.

## 결정

1. 학생용 말뭉치. 규정 문서마다 공개 대상(documents.audience: staff 기본, student)을 둔다. 학생 검색은 학생 공개로 지정한 규정의
   공개 조각만 후보로 들인다. 걸러내기는 검색 SQL 에서 한다(`list_regulation_chunks(levels=("student",))`, `access_guard.search_scope`).
2. 학생 질문에는 사업 문서 검색·그래프·프로젝트 맥락·연결 문서·외부 검색·모델 지식 모드를 쓰지 않는다(`responder`·`_answer_task_impl`).
3. 학생 화면은 허용 목록으로 연다. 대화(보내기·읽기·다시·지우기)와 학생 공개 규정 읽기(원문·쪽 그림)만 허용하고, 첫 화면은 대화다.
   허용 목록이라 앞으로 생기는 화면도 저절로 막힌다. 문서 경로의 열람 판정(`access_policy.visible`)은 학생에게 학생 공개 규정만 보인다.
4. 학생 공개 지정은 규정 문서 화면의 「학생 공개하기」로 한다. 관리자나 그 문서를 올린 사람만 할 수 있고, 규정이 아닌 문서는 지정할 수 없다.
   자동으로 켜지 않는다 — 어떤 규정이 학사 규정인지는 담당자가 정한다.

## 결과

- 학생이 추가되기 전에 할 일이 둘 있다. 학사 규정을 문서함에 들이고 학생 공개로 지정해야 하고, 학생 로그인 방식(학교 계정 연동 등)을 정해야 한다.
- 시험(`tests/test_student_corpus.py`)이 검색 범위·답변 경로·화면 13개 경로·지정 권한을 지킨다.
- 대화 화면의 답변 방식 선택(외부 검색·모델 지식)은 학생에게도 보이지만 서버에서 무시한다. 화면에서 숨기는 일은 화면 담당과 맞춘다.
