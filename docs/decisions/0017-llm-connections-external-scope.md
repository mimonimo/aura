# 0017. LLM 연결 관리 — 교내 GPU 서버와 외부 기관 GPU 서버, 상용 클라우드 API 불사용

- 상태: 확정
- 날짜: 2026-09-17
- 관련: ADR-0004(vLLM 서빙), ADR-0008(외부 참조 이그레스 게이트웨이), 브리프 11장(문서 외부 반출 금지)

## 배경

교내 GPU 서버 외에, 협약을 맺은 다른 기관의 GPU 서버(개발 키를 발급받아 OpenAI 호환 규격 API 로 접속)를
쓸 수 있어야 한다. 반면 OpenAI·Anthropic 같은 상용 클라우드 API 는 개인정보와 문서 반출 문제로 쓸 수 없다.
교내 행정 문서는 개인정보 마스킹을 거치더라도 외부로 내보내지 않는 것이 브리프의 전제이므로, 외부 기관 서버에
문서 작업을 맡기는 것은 기관 간 협약과 개인정보 검토가 확인된 경우로 한정한다.

## 결정

1. 플랫폼에 LLM 연결 목록을 둔다(`src/zzaimy/generate/llm_connections.py`,
   저장은 `data/platform/llm_connections.json` 0600). 연결 종류는 두 가지뿐이다.
   - 교내 GPU 서버(vLLM, OpenAI 호환 규격)
   - 외부 기관 GPU 서버(OpenAI 호환 규격, https 필수, 발급받은 개발 키)
   상용 클라우드 API 종류는 두지 않는다. 키는 파일에만 있고 화면에는 끝 4자리만 보인다.
2. 용도
   - 문서 작업 기본(채팅·검토 의견·초안·요약·파이프라인): 교내 서버는 바로 지정한다. 외부 기관 서버는
     "해당 기관과의 이용 협약과 개인정보 검토를 거쳤음"을 확인(체크)해야 지정되며, 확인 시각을 기록한다.
   - 외부 AI 참조용(이그레스 게이트웨이, ADR-0008): 외부 기관 서버 연결만 지정할 수 있고, `egress._send_external`
     만 그 자격으로 호출한다. 예전의 Anthropic 경로(환경변수 키)는 제거했다.
3. 우선순위: 지정된 연결 > 화면 설정(`llm_base_url`·`llm_model`) > 환경변수(`VLLM_BASE_URL`·`VLLM_MODEL`) > 서버 첫 모델.
4. vLLM 전용 요청 옵션(`chat_template_kwargs.enable_thinking`)은 교내 서버 연결에만 보낸다.
5. 호환성은 OpenAI 호환 규약의 공통 부분에만 맞춘다(Bearer 키, `/v1/models`, `/v1/chat/completions`,
   401/403·404·429·5xx 의 뜻). 특정 기관 허브의 전용 헤더나 부가 엔드포인트(임베딩·리랭크)에는 맞추지 않는다 —
   교내 GPU 서버와 기관 서버를 같은 코드로 써야 하기 때문이다. 요청 시간 제한과 429/5xx 백오프 재시도는 SDK 옵션으로
   두고(환경변수 `ZZAIMY_LLM_TIMEOUT`·`ZZAIMY_LLM_RETRIES`), 응답의 usage 는 날짜·연결·모델별로 누적해
   기관 키의 일 한도 관리에 쓴다(`data/platform/llm_usage.json`).

## 결과

- 개발자는 모델 학습 화면의 "LLM 연결" 카드에서 연결을 추가·수정·확인(모델 목록 조회)·삭제하고 용도를 지정한다.
- 담당자 화면(사이드바)은 문서 작업 기본 연결의 상태만 보인다.
- 외부 전송 자체는 `ZZAIMY_EXTERNAL_ENABLED` 와 관리자 측 아웃바운드 개방(해당 기관 주소)이 있어야 켜진다.
