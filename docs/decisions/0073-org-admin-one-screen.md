# 0073. 조직 관리 한 화면과 여러 단계 부서 트리

- **상태**: 확정
- **날짜**: 2026-10-26
- **관련**: ADR-0066(부서 단위와 등급), `app/org_routes.py`, `app/user_admin.py`, `static/org-chart.js`

## 맥락

같은 부서를 세 곳에서 다뤘다. 사용자·계정(/dev/users)의 부서 표와 사용자 표, 조직·구성원(/team)의 구성원 탭, 같은 화면의 조직도 다이어그램 탭이다. 부서 하나를 정리하려면 세 화면을 오가야 했고, 부서 80여 개가 한 줄씩 늘어선 표와 좌우로 퍼지는 다이어그램은 부서가 늘면 다루기 어려웠다. 조직도는 처·단 → 팀·센터 두 단계만 받았다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 세 화면 유지, 표마다 찾기·접기 덧붙임 | 고칠 곳이 적다 | 같은 부서를 여전히 세 곳에서 다룬다 |
| B. /team 한 화면 — 왼쪽 부서 트리, 오른쪽 상세(구성원·부서 설정 / 전체 사용자) | 부서·사람·계정을 한 자리에서. 트리는 단계 수와 부서 수가 늘어도 접어서 본다 | 화면 코드를 새로 짠다 |

## 결정

B. /team 「조직 관리」 한 화면으로 합친다.

- 왼쪽: 부서 트리(세로 들여쓰기, 찾기, ＋/－ 펼치기, 끌어다 놓아 옮기기). 맨 위 「전체 사용자」 는 관리자에게만.
- 오른쪽: 부서를 고르면 「구성원」(체크 → 작업 줄: 옮기기·등급 바꾸기·빼기, 사람 추가)과 「부서 설정」(총괄 책임자·부서 RAG 문서 수·최소 등급·이름 바꾸기·상위 부서 옮기기·하위 부서 추가·지우기·부서 드라이브). 「전체 사용자」 는 계정 목록(찾기·거르기·쪽 나누기, 체크 → 역할·부서 옮기기·사용 중지, 계정 추가·편집).
- 부서 위계의 단계 수 제한(두 단계)을 푼다. 순환만 막는다. 권한 판정(grades.covered_depts)은 원래 하위 부서를 끝까지 따라가므로 바뀌지 않는다.
- 부서를 지울 때 아래 부서는 고른다 — 지운 부서의 자리로 올리기(기본) 또는 함께 지우기. 소속 사람이 있는 부서가 하나라도 걸리면 아무것도 지우지 않는다.
- /dev/users 에는 구글 앱 등록과 학교 계정 연결 현황만 남긴다. 옛 주소(/team?tab=org, /dev/users#depts)는 새 화면으로 온다.
  (10-27 갱신) 구글 앱 등록·학교 계정 연결 현황도 조직 관리 아래 관리자 칸(_team_google.html, #google-links)으로 옮기고 /dev/users 화면과 개발 메뉴 줄은 지웠다.

## 근거

권한 규칙은 ADR-0066 그대로다. 관리자는 전부, 총괄 책임자는 맡은 처·단 아래, 사업 책임자는 자기 부서 일반 직원의 추가 권한만 바꾼다. 서버가 매번 다시 본다(/api/org/members 의 op 마다). 사람 옮기기·빼기·사람 추가는 계정 편집과 같은 저장 함수(_save_one)를 거쳐 RAG 추가 권한·겸직 등급이 같이 맞춰진다.

## 결과와 되돌리기 비용

조직도 다이어그램(확대·끌어 보기)과 /dev/users 부서·사용자 표는 없어졌다. 단계 제한을 다시 걸려면 org_routes._check_parent 에 검사를 되돌리고, 이미 세 단계 이상으로 둔 부서를 옮겨야 한다.
