# 0026. 실적 추출도 Writer(27B) 하나로 — 소형 Extract 모델은 처리량이 문제될 때만

- 상태: 제안 (교수님 확인 필요 — 브리프 7.4는 3~7B급 소형 추출 모델을 두라고 했다)
- 날짜: 2026-09-22
- 관련: ADR-0023(두 토르 NVFP4 서빙), 브리프 7장, model-plan

## 배경

계획은 모델 넷이었고 그 가운데 실적 추출(Extract)은 Qwen3-4B 같은 소형 모델로 두었다. 이유는 수만 장을
배치로 추출할 때 대형 모델은 처리 시간이 감당되지 않는다는 것이었다. 그 뒤 구성이 바뀌었다. 27B를 NVFP4로
두 토르에 올려 요청 하나에 초당 10토큰 남짓이 나오고, 이미지 판독과 반입 검토, 대화, 초안을 모두 이 한
모델이 맡는다. 사용자는 "27B 하나로 다 되면 전부 그것으로" 하자고 했고 장비를 뒤죽박죽 쓰지 않는 것이
원칙이다.

## 결정

실적 카드 추출은 Writer(27B)가 맡는다. 추출 형식은 vLLM의 스키마 강제(xgrammar)로 보장하고 추출값의 원문
대조로 내용을 보장하는 것은 그대로다. 학습 트랙에서는 27B 어댑터 하나가 섹션 생성과 추출을 함께 배우거나,
추출 전용 어댑터를 같은 베이스 위에 얹는다. 어느 쪽이든 서빙은 같은 모델이다.

소형 모델(Qwen3-4B)은 처리량이 실제로 문제가 될 때만 후보로 되살린다. 조건은 실측이다. 파일럿 규모(계획서
20~30건과 결과보고서)를 27B로 추출했을 때 문서당 시간과 필드 정확도를 재고, 전체 문서(수만 장)로 늘렸을 때
한 대로 감당이 안 되는 것이 수치로 보이면 그때 4B 증류를 대결로 잰다.

## 근거

- 처리량 추정: 결과보고서 한 건의 실적 카드 추출은 출력 500토큰 안팎이라 27B NVFP4로 문서당 1분 남짓이다.
  파일럿 30건은 30분, 1,000건은 하루다. 토르 두 대로 나누면 절반이다. 캡스톤 범위(파일럿)에서는 충분하다.
- 품질: 추출은 표와 문맥을 읽는 일이라 큰 모델이 유리하고, 판독까지 같은 모델이면 스캔 결과보고서를
  이미지에서 바로 추출하는 경로도 하나로 이어진다.
- 단순함: 학습·양자화·이관 경로(83 → 병합 → NVFP4 → 116)가 하나다. 모델이 하나 줄면 모델 카드·평가·서빙
  자리도 하나 준다.

## 되돌리기

소형 모델이 필요해지면 model-plan의 Extract 절(교사 추출 → 검수 → SFT)을 그대로 살리면 된다. 검수된 실적
카드가 곧 학습 데이터이므로 27B로 먼저 뽑아 검수해 둔 것이 낭비가 되지 않는다.
