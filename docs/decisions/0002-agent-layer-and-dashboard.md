# 0002. 에이전트 오케스트레이션 계층과 검수 대시보드 추가

- 상태: 제안
- 날짜: 2026-09-01
- 관련: `PROJECT_BRIEF.md` §2(70% 초안·사람 검수), `docs/capstone-plan.md` §1.1(실사용 요구), `docs/architecture.md` §9

## 맥락

브리프의 산출물 목록(3장)에는 UI와 오케스트레이션 계층이 없다. 그러나
① 이 시스템은 발표 후 실제 행정에 투입될 예정이고(실사용), ② "70% 초안 +
사람 검수" 원칙은 검수할 화면이 있어야 성립하며, ③ 새 문서의 반입 →
인제스트 → 인덱스 갱신은 사람이 매번 명령을 치는 방식으로는 운영되지 않는다.
지도교수 미팅(2026-09-01)에서 대시보드와 에이전트 운영이 언급되었다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 설계에 포함, 구현은 후반 최소 기능 (제안) | 실사용·시연 요구 충족, 모델 트랙(논문 본체) 일정 보호 | W12 전후 UI 작업 부담 |
| B. 이번 학기 제외, 논문 향후 과제로만 | 일정 단순 | 검수 워크플로(UC-5)가 CLI로 남아 실사용 전환 지연 |
| C. 조기 구현 (W3~) | 시연 품질 | 모델 4종 일정 잠식 — 축 B 위험 |

## 결정 (제안)

A안. 아키텍처에 두 계층을 정식 포함하되:

- 에이전트 계층은 파이프라인 단계의 얇은 래퍼로 한정 — 로직은 라이브러리에,
  프레임워크 종속 배제. 문서 반입 폴더 감시 → 인제스트 트리거가 1순위.
- 대시보드는 수직 슬라이스(TASK-08) 검증 후, UC-5(실적 카드 검수) 최소 화면부터.
  UC-1(초안 검토)·UC-3(짜임새 점검)은 시간이 허락하는 범위에서.
- "70% 초안 · 사람 검수 전제" 경고문을 UI에 명문화 (capstone-plan §1.1-3).

## 근거

검수 화면은 Extract 학습 데이터 생산(UC-5 = 검수 = 라벨링)과 직결되어
축 B에도 기여한다. 시연의 얼굴이 되는 부수 효과도 있다. 반면 조기 구현(C)은
논문 본체를 잠식한다 — 순서로 위험을 통제한다.

## 결과와 되돌리기 비용

산출물 목록이 늘어난다(승인 필요). 후반 일정 압박 시 대시보드가 첫 축소
대상이 되며, 그 경우에도 에이전트 계층(반입 자동화)은 유지를 권장한다 —
실사용 전환의 최소 요건이기 때문이다.
