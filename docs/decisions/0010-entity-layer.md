# 0010. 개체 계층 — 온톨로지 v2와 결정론 1차 추출

- **상태**: 채택
- **날짜**: 2026-09-08
- **관련**: ADR-0009(온톨로지 v1), 2주차 미팅(온톨로지 고려 데이터·학습,
  docs/notes/meeting-w2-20260908.md), 사용자 방침(정답지 축적)

## 맥락

구조 그래프(v1)는 문서 사이의 명시적 관계만 잇는다. "이 공고에 맞는 우리
실적"처럼 내용으로 이어지는 다리를 놓으려면 문서 안의 개체(사업·기관·연도)를
노드로 올려야 한다. GPU·LLM은 아직 없다.

## 결정

온톨로지 v2 — v1에 개체 유형을 증보한다.

- 노드 추가: entity (하위 유형 program·org·year)
- 간선 추가: mentions (문서→개체, 가중치 = 언급 횟수 기반)
- 저장: entities · doc_entities 테이블. 그래프에는 두 문서 이상을 잇는
  개체만 승격(연결 가치 없는 고아 개체 제외), 검색 확장은 원본 전체 사용

추출은 2패스.

1. **결정론 패스(이번)** — 한국어 행정문서의 일반 형태만 쓴다: 연도
   표기("2026년"), 판별력 있는 기관 복합 접미사(사업단·위원회·재단·진흥원 등),
   명명된 사업류(…지원사업·…전형). 짧고 흔한 접미사(부·과·팀)는 오탐이 많아
   제외하고, 범주 일반어는 개체로 세지 않는다. 멱등 배치
   (scripts/70_extract_entities.py), GPU 불필요.
2. **LLM 정제 패스(후속)** — 별칭 통합("혁신지원사업"="대학혁신지원사업"),
   규칙이 못 잡는 개체 보강, 실적 항목 추출. LLM 연결 후. 사람 검수를 거친
   결과는 Extract 모델의 평가 골드로도 쓴다(정답지 축적 방침).

## 근거

접미사·연도 규칙은 특정 문서 짜맞추기가 아니라 언어 일반 형태다(하드코딩
금지와 무관). 결정론 패스를 먼저 두는 이유: 재실행 가능하고, LLM 패스의
품질을 잴 기준선이 되며, GPU 없이 지금 그래프 가치를 낸다.

## 결과와 되돌리기 비용

- 잠그는 것: entity 노드·mentions 간선 유형(/graph.json 계약), 두 테이블.
- 되돌리기: 추출은 멱등 교체라 규칙 개선 시 재실행이면 끝. 테이블 스키마
  변경만 마이그레이션 필요 — 저비용.
