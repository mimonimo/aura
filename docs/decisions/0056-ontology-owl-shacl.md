# ADR-0056: 온톨로지를 표준 형식(OWL·RDF)으로 내보내고 SHACL 로 검사한다

- 상태: 채택
- 날짜: 2026-10-06
- 관련: ADR-0048(온톨로지 v3), ADR-0055(기관 노드·서류 갈래), 절대 규칙 12(관계는 근거가 있을 때만)

## 맥락

온톨로지는 우리 코드(graph/programs.py·kg_store.py)와 장부 JSON 으로만 정의돼 있었다. 다른 도구나 기관이 읽을 표준
설계도가 없었다. 구조 규칙(연차는 사업 하나에만 속한다, 관계에는 근거가 있다 등)도 점검 코드(174) 안에 흩어져 있었다.
사용자가 "온톨로지는 오픈소스가 아닌가"를 물었고, 표준 층을 오픈소스로 더하기로 했다.

## 결정

1. 정본은 PostgreSQL(kg_nodes·kg_edges)로 둔다. 검색·권한은 그대로다.
2. 설계도(OWL)는 rdflib(BSD)로 낸다. 클래스는 노드 종류 8이고, 문서 갈래는 하위 클래스로 둔다. 관계의 정의역·치역은
   실제 그래프에 나온 조합(여럿이면 owl:unionOf)으로 정한다. 속성(연도·차년도·갈래·기간)도 담는다.
   파일은 data/platform/ontology/ontology.ttl 이고, 화면 /graph/explore/ontology.ttl 에서 내려받는다.
   Protégé·WebVOWL 로 열 수 있다.
3. 인스턴스(RDF)는 사업 묶음·사업·기관·연차·문서·성과지표만 낸다. 절·단위과제(수십만)는 규모 때문에 뺀다.
   관계는 근거·기준을 검사할 수 있도록 진술(z:Statement)로도 낸다. 장부에서 온 관계는 z:LedgerStatement 다.
4. 검사 규칙(SHACL)은 src/zzaimy/graph/shapes.ttl 에 둔다. pySHACL(Apache-2.0)이 검사한다. 규칙은 다음과 같다.
   - 사업: 이름이 있고, 주관 부처·전담기관은 기관이다.
   - 연차: 사업 하나에만 속하고, 연도는 1990~2035, 차년도는 1~12다.
   - 문서: 연도는 하나이며 범위 안이고, 갈래는 하나까지이고, 사업이나 연차에 속한다.
   - 기관: 어느 사업과 이어진다.
   - 관계: 출발·도착이 하나씩, 정해진 기준 다섯 중 하나, 근거가 하나 이상이다.
   - 장부 관계: 출처 URL 이 있다.
5. scripts/177 이 내보내기와 검사를 함께 한다. 결과(shacl_report.json)는 온톨로지 보기에 나온다.
   전체 순환(그래프 → 판정 → 온톨로지 점검 → 표준 검사 → RAG 실측)에 넣는다.

## 결과

- 174(우리 점검)와 177(표준 검사)이 함께 돈다. 겹치는 규칙은 표준 쪽으로 옮겨 가고, 174 에는 표준으로 쓰기 어려운
  것(예: 막연한 사업 이름)만 남긴다.
- 작업 현황 「핵심 기술」의 온톨로지 칸에 rdflib·pySHACL 이 들어간다.
