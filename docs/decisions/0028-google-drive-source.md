# 0028. 구글 드라이브를 읽기 전용 원천으로 붙인다 — 쓰기(독스 편집)는 외부 전송 규칙을 정한 뒤

- 상태: 채택(1단계) · 2단계는 제안
- 날짜: 2026-09-22
- 관련: ADR-0018(NAS 읽기 전용 가져오기), ADR-0017(LLM 연결 종류), ADR-0008(외부 참조 관문)

## 배경

담당자들의 문서 일부가 구글 드라이브에 있고, 사용자는 그것을 플랫폼으로 끌어오고 나중에는 구글 독스를 화면 안에서
에이전트와 함께 고치고 싶어 한다. 지금까지 자료 연결 화면에는 구글 드라이브가 "미지원"으로만 있었다.

## 결정

1. 1단계: 구글 드라이브 폴더를 NAS 와 같은 원천 백엔드로 붙인다. 읽기 전용이다(목록·내려받기·내보내기). 인증은 담당자
   본인의 OAuth 허용이고 범위는 drive.readonly 하나다. 클라이언트 비밀과 갱신 토큰은 서버 파일(0600)에만 두고 화면에
   되돌려 보이지 않는다. 가져온 문서는 업로드와 같은 처리 경로를 탄다(부서·등급·마스킹·조각·색인).
2. 구글 클라이언트 라이브러리를 들이지 않고 httpx 로 REST 를 직접 부른다. 오프라인 VM 에 설치할 것이 없고 의존성이
   늘지 않는다.
3. 2단계(독스를 화면 안에서 편집, 에이전트가 API 로 읽고 쓰기)는 교내 내용이 구글로 나가는 외부 전송이므로 외부 AI
   참조 관리와 같은 승인·기록 규칙을 먼저 정한 뒤 만든다. 설계는 `docs/notes/2026-09-22-google-drive-source.md`.

## 근거

- NAS 원천의 계약(확인·목록·읽기)이 이미 있어 백엔드 하나로 끝난다. 반입 규칙(중복·부서·등급·갈래·판본)을 다시 만들지 않는다.
- 운영 VM 에서 googleapis.com 이 열려 있음을 확인했다(2026-09-22).
- 가짜 드라이브 API 로 목록·내보내기·토큰 갱신·원천 등록·허용 경로를 검증했다(`tests/test_gdrive.py`).

## 되돌리기

원천 백엔드 목록에서 gdrive 를 빼고 `gdrive_oauth.json`·`gdrive_tokens.json` 을 지우면 된다. 가져온 문서는 다른
반입분과 같은 문서이므로 그대로 둔다.
