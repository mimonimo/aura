# ADR-0059: 공통 양식은 실제 서식 모양으로 — 병합 칸·서식 격자 허용, 양식은 규칙으로 지키고 27B 는 내용만

- 상태: 확정
- 날짜: 2026-10-10
- 관련: ADR-0058(독스 공통 양식·절 작성 흐름 — 그 가운데 「병합 없는 표」를 이 기록이 대체), 절대 규칙 1·5·10

## 맥락

ADR-0058 의 공통 양식 4종은 표가 깨지지 않게 「1단 머리행·병합 없음·8열 이하」로 짰다. 담당자가 쓸 바탕으로는 모자랐다 — 표가 모두
같은 격자라 서식 같지 않았고, 양식을 받아 독스에서 참고하며 쓰기
어려웠다. 실제 한글 서식다움은 병합에서 나온다 — 「목표값」 아래 연차를 두는 2단 머리행, 구분 칸 세로 병합, 라벨·값이 한 줄에 엇갈린
개요 격자, 합계 행. 독스 API 는 칸 병합(mergeTableCells)을 지원하고, 절 작성 에이전트의 표 읽기(table_grids)는 덮인 칸을 이미 다룬다.

또 27B 에게 양식을 맡기면 모양·구조를 지키지 못했다(지침 문단을 덮어씀, 개요 표 위에 문단을 덧붙임, 위 제목의 자리 표시를 둠,
다른 회의 값을 새 회의록에 옮김).

## 결정

- 표 사양을 세 갈래로: 목록 표(TG — 머리행 여러 줄·병합), 항목 표(KV), 서식 격자(FORM — 라벨 칸 좌표·병합·높은 행).
  사업 개요·과제 개요·성과지표 정의서·SWOT·회의 개요·프로그램 개요는 서식 격자, 성과지표 총괄·현황 지표·계획 대비 실적은 2단 머리행,
  추진 일정은 월별 간트표(14열까지), 예산·집행 표는 합계 행. 계획서·보고서 끝에 제출 문구(날짜·기관장 직인 자리).
- 양식의 모양·구조는 코드 규칙으로 지킨다: 개조식 들여쓰기, 지침 덮어쓰기 막기, 표만 채우는 절, 한 번의 기록 문서(회의록·결과보고서)는
  문서함 검색 재료 금지, 보고서 절은 계획서 짝 절을 재료로, 자리 표시 제목은 좁은 물음으로 채움. 27B 는 내용만 쓴다.
- 못 채운 절은 원인 갈래로 남겨(fill_gaps) 담당자 안내·다음 작성의 맥락에 쓴다.

## 근거

- PDF 로 쪽마다 확인: 5종(17·11·5·5·4쪽) 병합·2단 머리행·간트표·합계 행·제출 문구 정상, 머리행은 쪽마다 반복.
- 27B 시험(실시계획서): 서식 격자 「프로그램 개요」 11칸이 값 칸에만 채워지고 라벨·덮인 칸은 그대로, 본문 문단 덧붙임 없음.
- 회의록 시험: 문서함 재료를 막기 전 지난 회의의 일시·참석자·안건이 옮겨짐 → 막은 뒤 0자·필요 자료 안내.

## 결과와 되돌리기 비용

병합 표는 서식 쪽(사양)에만 있고 에이전트의 채우기 경로는 같다 — 되돌리면 사양만 옛 T·KV 로. Word 로 내보내도 병합이 유지된다.

## 덧붙임 (2026-10-25) — 한글 판(코드로 짠 공통 양식 15종) 생성 규칙 손질

같은 정의로 만드는 한글 양식(`webhwp_templates.build`, 사업 문서 5종·공문 4종·국고 운영 6종)을 풀어 점검했더니 상 등급 문제가 6건이었다.
모두 생성 규칙 한 곳에서 고쳤다(양식 하나만 맞추는 땜질 없음).

- 절 필드: build 가 아는 제목 차례(`slots_of`)를 `webhwp_fields.fieldize(slots=…)` 로 넘겨 잎 절에만 박는다. 글 꼴로 짐작하던 때는
  번호 없는 절(「사업 요약」)·로마 숫자 잎 장(「Ⅵ.」「Ⅶ.」)·붙임에 필드가 빠지고, 아래 절이 있는 위 제목(「1. (추진 과제 1) ○○○○」)에 생겼다.
  라벨·값 격자만 있는 잎 절(「가. 과제 개요」, 독스의 「표만 채운다」 절)은 절 필드 없이 칸 필드로만 쓴다. 학교 실물 서식은 지금처럼 짐작한다.
- 열 폭: 빈 표의 누름틀 안내 글(「… 입력」)을 하한 셈에서 빼고, 합친 칸 글은 덮은 열 수로 나눠 센다(`fit_widths(spans=…)`).
  하한 합이 본문 폭을 넘어 정의 비율이 버려지던 것이다(예산 변경 「사유」(비율 2)가 가장 좁았고, 간트표 1월 칸만 두 배였다).
  98개 표에서 정의 비율과 15% 넘게 다른 표 47 → 11개(남은 것은 머리 낱말을 한 줄에 두는 하한 때문), 가장 벗어난 열 148% → 30%.
  간트 달 칸 하한은 6mm(`TABLE["month_min_mm"]`, 갈래 일정표와 같은 값), 달 칸 음영은 둘째 머리행에서도 찾는다.
- 작성방법: 공문·국고 10종도 같은 헬퍼(H·G)와 수치 규칙(NUM_RULE·BUDGET_RULE), `_with_sources` 를 쓴다. check_spec 이 15종 모두에 돈다.
- 블록: 제출 문구(`sign` — 문구·날짜는 가운데, 셋째 줄부터 기관장 줄 오른쪽 굵게, TYPE `sign`·`sign_org`)를 만들고, 모르는 블록 키는 예외로 막는다.
- 머리줄이 있는 표는 「제목 줄 반복」(repeatHeader)을 켠다 — 학교 실물 표본 20건의 표가 거의 모두 켜 있다(한글 기본값).
  다만 한글은 「제목 칸」(header="1")으로 표시한 행을 되풀이하는데, 기안기가 제목 칸의 굵게를 무시해 우리는 그 표시를 끄고 있다(style_table).
  다음 쪽에서 머리줄이 실제로 되풀이되는지는 한글에서 확인하지 못했다.
- 빈 양식 표: 본문에 표를 쓰면 같은 절의 빈 양식 표를 지운다. 「빈 틀」은 사용자 글이 있는가로 가른다 — build 가 표 칸의 양식 글(머리줄·라벨·행 이름) 문단에
  「양식 틀」 문단 스타일을 붙이고(`mark_form_text`), 그 스타일이 아닌 문단의 글과 누름틀에 쓴 글을 사용자 글로 본다. 스타일은 한글이 저장해도 남고,
  빈 칸에 친 글은 그 칸 문단(바탕글)을 따르므로 사용자 글로 읽힌다. 열 수가 같은 빈 틀이 있으면 그것만 지우고(한 절에 지표 표와 SWOT 격자가 있으면 격자는 남김),
  머리줄 없는 라벨·값 격자와 결재란·확인표(「양식 틀 고정」, 정의의 `keep`)는 지우지 않는다. 학교 서식(표시 없음)은 옛 판정 그대로.
  목록표가 있는 잎 절 69곳에 같은 꼴 표를 써 보면 빈 틀이 남는 절 18 → 0.

중 등급에서 함께 고친 것:
- 사람 칸은 「입력:<라벨>」 필드(정의의 `people`·`keep`) — 신청·보고 일자, 결재란, 대표자(서명), 달성률, 출장자, 회의록 확인. 에이전트는 담당자에게 물어 받은
  값만 `hwp_fill {from_user: true}` 로 넣고, 그 밖의 값은 넣지 않고 묻게 한다(절대 규칙 5 — 달성률을 셈해 넣지 않게). 칸:사업명·칸:담당자 같은 기존 이름은 그대로.
- 짐작으로 필드가 하나도 안 박히던 목록표 8개(2단 머리줄·12자 넘는 머리)는 build 가 아는 머리줄 수·열 이름으로 첫 본문 행에 「표n:<위 머리>/<아래 머리>」.
- 여백은 `house_style.PAGE` 한 곳(좌우 20mm — 실물 표본 다수·독스 판과 같게, 전에는 한글 새 문서 기본 30mm)이고 본문 폭(TEXT_W)을 여기서 셈한다.
  제목이 8개 넘는 여러 쪽 양식에는 아래 가운데 쪽 번호. 양식 만들기(webhwp_form_create)는 쪽 번호를 담당자 디자인 요청으로 넣으므로 붙이지 않는다.
- 편집 도구가 절 필드의 제목 문단을 찾을 때 사이의 작성방법 상자를 건너뛴다(쪽 나누기가 상자 문단에 걸리고, 절 범위가 다음 절 제목까지 먹던 것).

되돌리기: `BUILD` 를 올린 판(13)이라 운영 양식은 새 규칙으로 다시 만들어진다. 되돌리면 build·fieldize 의 새 인자만 빼면 되고, 이미 만든 작업본의 필드 이름은 그대로 남는다.
남은 것: 표 필드 이름을 「표:<절>/<행 라벨>/<열 머리>」 로 바꾸는 일(행 라벨 표의 칸 이름이 뜻과 다른 것), 표지 ○○ 칸 필드, KV 첫 행 머리줄 오인, 결재란 8열 꼴.
