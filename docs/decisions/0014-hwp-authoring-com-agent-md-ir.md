# 0014. 한글 문서 = COM 에이전트 생성 + PDF 미리보기 (rhwp 제거)

- 상태: 확정
- 날짜: 2026-09-08
- 관련: ADR-0013(대체함: rhwp 채택 철회), `tools/hwp-agent`,
  `docs/notes/hwpx-agent-skills.md`, 사용자 확정(2026-09-08)

## 맥락

ADR-0013은 웹 한글 기안기 엔진으로 rhwp(Rust/WASM) 사이드카를 채택했다.
실측 결과 생성·렌더 품질이 실사용에 못 미쳐, 한글 문서의 생성·미리보기·읽기
경로를 다시 정한다.

## 검증 (2026-09-08, 실측)

- rhwp fill(replaceAll): 실제 .hwp 열어 값 교체 시 글자 서식 보존은 확인
  됨(파일 자체는 충실). 그러나 —
- rhwp 렌더(renderPageSvg): 맥에 원본 글꼴(HY중고딕·돋움체 = 한컴 상용)
  부재로 폴백 → 폰트·줄바꿈이 어긋남. 이 환경에선 눈으로 품질 판정 불가.
  함초롬(무료) 문서는 웹폰트 로드로 개선되나, 상용 폰트 문서는 못 고침 + 조판
  자체가 v0.8 미성숙.
- 네이티브 HWP 브라우저 뷰어의 현실: HWP는 한컴 폐쇄 포맷. 변환 없이
  브라우저에서 충실히 그리는 성숙한 오픈소스는 없다(rhwp가 유일 시도, 품질
  한계). 상용 온라인 뷰어(한컴독스 등)는 클라우드라 PII 문서에 못 씀.
- rhwp는 저장소 코드에 미통합(파서=docling/mineru/lattice, rhwp 참조 0).
  실험은 스크래치패드에서만 존재 → 제거 비용 없음.

## 결정

1. 생성·편집 = 한글 COM 에이전트(실제 한글). `tools/hwp-agent`.
   - 중간표현 = Markdown(제목/본문/표/필드). 수치는 RAG 근거 인출(브리프
     §1, 지어내기 금지).
   - 에이전트가 md → 한글 op 변환: 양식 있으면 양식 열어 셀 매핑해 채움
     (못 채운 칸은 비워 사람 검수), 없으면 새 문서에 본문+표 생성.
   - `save_as`로 .hwpx/.hwp/PDF 저장.
2. 미리보기 = 한글이 생성한 PDF를 브라우저(크롬 내장 PDF 뷰어)로 표시.
   - 한글이 원본 글꼴로 직접 그린 PDF라 폰트·조판 100% 충실. 브라우저 무관.
   - 원본 .hwp는 브라우저에서 안 열고 다운로드 → 한글로.
3. rhwp 제거. 생성·렌더·뷰어 어디에도 쓰지 않는다. (스크래치패드 실험
   삭제 완료.)

## 근거

- 초안 품질 = 형식(한글이 그리니 한계 없음) + 내용(LLM+RAG, 70% 초안+사람
  검수). rhwp의 폰트·조판 한계를 회피.
- 미리보기를 PDF로: 네이티브 hwp 웹뷰어가 없다는 현실의 유일한 충실 해법.
  크롬이 PDF를 그리므로 별도 뷰어 불필요.
- md IR은 렌더러 독립 → 향후 엔진 교체 시 내용 생성부 불변.

## 결과와 되돌리기 비용

- 잠그는 것: 생성·PDF미리보기가 한글+Windows 워커 상시 가동에 의존. 무인
  대량 = 전용 한글 워커 PC.
- 사람 1회 개입: 양식별 셀↔md필드 매핑(등록 시 자동추정+확인, 이후 무인).
- 네이티브 .hwp 읽기(인제스트): 해소(2026-09-08). `pyhwp`(+`six`)의
  TextTransform으로 .hwp 본문 텍스트 추출을 실측 확인, `.hwpx`는 ZIP+XML로
  직접 추출. 리더는 `src/zzaimy/ingest/hwp_text.py`(extract_text)로 두고
  pyproject `[parsers]`에 pyhwp·six 추가. 실측: 국고 문서 26/34건 즉시 추출
  OK, 스캔 PDF 0건. 한계: pyhwp 텍스트 변환은 표 셀 내용을 `<표>`로 접는다
 , 표 구조·셀은 인제스트 표 파서(lattice)와 병용. 빈 양식 서식은 텍스트가
  적은 게 정상(양식으로서 가치). 일부 hwpx 변형은 `<hp:t>` 외 구조라 추출기
  보강 필요(후속).
- 되돌리기: rhwp 재도입은 스크래치 재설치뿐(코드 의존 없음).
