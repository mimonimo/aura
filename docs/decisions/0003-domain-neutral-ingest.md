# 0003. 인제스트 공통 계층의 도메인 중립화 — 채용 문서 확장 대비

- **상태**: 제안
- **날짜**: 2026-09-01
- **관련**: `docs/architecture.md` §10, 지도교수 미팅(2026-09-01)

## 맥락

캡스톤의 상위 목표는 "행정업무 자동화를 위한 YNC LLM"이다. 미팅에서 두 번째
적용 사례로 **채용 프로세스**(이력서·학위·경력 서류의 수동 검토 — 외부 상용
서비스는 개인정보 우려로 불가)가 언급되었다. 국고사업(ZZAIMY 브리프)과 채용은
"문서 반입 → 파싱/OCR → PII 처리 → 분류 → 검토/생성"이라는 공통 골격을 공유한다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 공통 계층만 도메인 중립으로 설계, 구현은 국고사업만 (제안) | 추가 비용 ≈ 0 (이미 그렇게 구현됨), 확장 경로 확보 | 채용 도메인 로직은 이번 학기 없음 |
| B. 채용 파이프라인 병행 구현 | 상위 목표 직접 입증 | 13주 일정 파괴 — 기존 삭감 위에 추가 삭감 필요 |
| C. 확장 고려 없이 국고사업 전용으로 | 단순 | 파서·PII·분류에 국고사업 가정이 스며들면 재사용 시 재작업 |

## 결정 (제안)

A안. 경계를 다음과 같이 긋는다:

- **도메인 중립 (공통 계층)**: 파서 인터페이스, PII recognizer, 열람 등급,
  계열 분류 프레임(규칙 세트만 도메인별), 하이브리드 검색 기반.
  W1 구현분(TASK-04·05·06)은 이미 이 기준을 충족한다.
- **국고사업 전용 (도메인 모듈)**: 실적 카드 스키마, 공고 스키마 추출,
  배점 검증기, 예산 로직, ZZAIMY-* 모델 4종.
- 채용 확장은 논문 "향후 과제"와 발표 자료의 확장 비전으로 기술한다.
  이번 학기 구현 범위에 넣지 않는다.

## 근거

공통/전용 경계는 지금 그어야 비용이 0에 수렴한다 — 나중에 전용 가정을
걷어내는 것은 재작업이다. 반면 채용 도메인 구현(B)은 요구 분석부터 새로
필요해 13주에 들어가지 않는다.

## 결과와 되돌리기 비용

이 결정은 아무 산출물도 추가하지 않는다 (설계 규율만 추가). 되돌리기 비용도
사실상 없다. 다음 학기/후속 과제가 채용 파이프라인을 만들 때 인제스트 계층을
그대로 가져가는 것이 이 ADR의 성공 기준이다.
