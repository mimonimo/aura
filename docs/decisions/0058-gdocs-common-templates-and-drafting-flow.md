# ADR-0058: 구글 독스 공통 양식은 독스 API로 직접 짜고, 문서 작성은 서식 우선·절 단위로

- 상태: 채택
- 날짜: 2026-10-09
- 관련: ADR-0035(한글 완성본=서식 보존 채우기), ADR-0049(사업 문서 색인), ADR-0057(pgvector), 절대 규칙 1·10, K-20261008-01

## 맥락

담당자가 사업 자료(공고·기본계획·평가편람·작성 서식·지난 계획서)를 주고 27B 에게 계획서·보고서를 쓰게 한다. 한글 서식을 독스로 옮기면
쪽이 밀리고 표가 깨져, 서식이 없는 사업이나 새 문서를 쓸 바탕이 없었다. 데이터에서 뽑은 공통 뼈대(172)는 「사업 셋 이상에 모두 나오는 절」만
남겨 절 6개로 얇았다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 한글 서식을 변환해 공통 양식으로 | 원본 모양 그대로 | 쪽 밀림·표 깨짐, 사업마다 다름 |
| B. 데이터 교집합 뼈대(172) | 자동 | 절 6개 — 쓸 바탕이 안 됨 |
| C. 독스 API 로 직접 짠 사양 + 실문서 집계로 절·표·분량·근거 위치를 고름 | 독스에서 깨지지 않음, 27B 가 읽을 지침이 절마다 | 사양을 사람이 관리 |

## 결정

C. `ingest/gdocs_templates.py` 의 사양 4종(사업계획서·실적보고서·단위 프로그램 실시계획서·결과보고서)을 독스 API 로 만든다(scripts/180).

- 독스 규칙: 제목 스타일 절, 8열 이하·병합 없는 표(머리행 반복), 머리말 낱말이 꺾이지 않는 칸 폭, 강제 쪽 나눔·글상자 없음.
- 절·표는 실문서 집계에서 여러 사업이 두는 것(계획서 5,732·보고서 2,273·단위 프로그램 1,151건). 지침마다 근거 위치·실문서 분량(중앙값)을 붙인다.
  사업 이름은 넣지 않는다(절대 규칙 10).
- 문서 작성: 프로젝트에 요청 갈래의 작성 서식이 있으면 「서식으로 / 공통 양식으로」 고르게 하고, 「○○ 초안 써 줘」는 절 작성 에이전트로
  빈 절 앞쪽부터(요약 절은 마지막, 이미 다룬 절은 건너뜀). 재료 = 작성방법·문서 전체 규칙·기준 문서·프로젝트 문서·문서함 사업 문서 RAG
  (실적보고서면 같은 연차 계획서도). 넣는 글의 수치·출처는 재료와 대조해 없는 것을 짚는다.
- 내보내기: 서식으로 쓴 문서는 원본 hwpx 에 채운다(ADR-0035, 같은 절 안 같은 모양 서식 표에 채움). 공통 양식 문서는 Word 로(작성 지침은 뺌).
- 묶음 접수·대화 첨부는 판독·색인 뒤 검토 의견·정체 읽기를 뒤로 미룬다(문서는 바로 작성에 쓴다).

## 근거

- 리허설 7회(AID 실물 세트, 임시 DB): 한 글자도 안 쓰던 흐름 → 절이 순서대로 쓰이고 한글 완성본의 서식 표가 제자리에 채워짐(새 표 2 → 0).
- 실데이터 시험(LINC 3.0 가정): 문서함 RAG 재료로 추진 배경 355~560자 → 1,567자(실문서 중앙값 1,800자), 개조식·출처 표기.
- 묶음 접수 5건 977초 → 343초. 동시 처리는 더 느려 채택하지 않음(젯슨 27B 는 동시 요청에도 처리량이 안 늚, MinerU 는 CPU 를 다툼).

## 결과와 되돌리기 비용

사양이 코드에 있어 양식을 바꾸면 scripts/180 으로 다시 만든다(옛 판은 휴지통). 절 작성 규칙(쓸 절·요약 순서·건너뛰기)은 공통 양식과
한글 서식 변환본 모두에 쓰인다 — 바꾸면 두 경로를 리허설로 다시 확인한다.
