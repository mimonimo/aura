# 0074. 라이브러리는 문서 하나, 학교 원본 관리는 개발 메뉴로

- **상태**: 확정
- **날짜**: 2026-10-27
- **관련**: ADR-0062(라이브러리 한 목록·쓰임새 칩, 이 결정이 C 항의 「원본 보관소」 탭을 대체), ADR-0047(원본은 DGX, 색인·분석은 VM), `app/archive_view.py`, `app/dev_nav.py`

## 맥락

라이브러리에 「문서」(등록 문서 — 검색·답변에 쓰임)와 「원본 보관소」(학교 원본 파일 전부 — 처리 상태·정리) 두 탭이 있었다. 사용자는 둘이 무엇이 다르고 왜 나뉘었는지, 어디까지 보면 되는지 헷갈렸다. 원본 보관소에서 교직원이 하는 일은 등록 문서의 원본 파일을 여는 것뿐이었고, 그 일은 이미 문서 줄·문서 화면의 「원본」 으로 할 수 있었다. 처리 상태·정리 카드·처리 실패는 관리자에게만 보였다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 두 탭 유지, 탭 설명만 고침 | 고칠 곳이 적다 | 같은 문서를 두 곳에서 찾는 구조가 그대로 |
| B. 라이브러리는 문서 하나, 원본 관리는 개발 메뉴 한 곳 | 사용자에게는 문서 목록 하나. 원본 장부·처리 상태·정리는 반입을 맡는 관리자 화면에 모인다 | 옛 주소·링크·시험을 함께 옮겨야 한다 |

## 결정

B.

- 교직원: 라이브러리는 문서 한 목록이다(탭 없음, 머리 오른쪽 「지식그래프」). 원본 파일은 목록 줄의 「원본」 과 문서 화면의 「원본 열기」·「내려받기」 › 「원본 파일」 로 연다(/doc/{id}/original — 문서 경로 열람 검사 그대로). 문서 화면 위 학교 원본 위치(사업 › 연도·경로 복사)는 남기고, 원본 관리로 가는 단추는 관리자에게만.
- 관리자: 「원본 관리」(/dev/archive)를 개발 사이드바 「문서 반입·읽기」 의 데이터 현황 옆에 둔다. 정리 카드(정리함으로·남기기·되돌리기), 처리 실패 다시 시도, 사업 → 연도 → 종류 → 처리 상태로 훑는 원본 목록, 원본 파일 열기(/dev/archive/original)가 여기 한 곳이다. /dev 아래라 관리자 검사가 앞단에서 걸린다.
- 옛 주소 /archive 는 관리자면 조건 그대로 /dev/archive 로, 교직원이면 라이브러리로 넘긴다.
- 원본 관리가 관리자 전용이 되어 교직원 열람 범위 거르기(볼 수 없는 문서·부서 폴더 감추기)와 「열람 권한 필요」 표시는 지웠다.

## 근거

아직 문서가 되지 않은 원본(처리 대기·제외·실패)은 교직원이 찾아 쓸 일이 없다 — 검색·답변은 등록 문서만 쓰고, 등록 전 원본은 원래도 관리자만 열 수 있었다. 처리 상태와 정리는 반입 점검(처리 흐름)·데이터 현황과 같은 일이라 같은 메뉴 묶음에 둔다.

## 결과와 되돌리기 비용

라이브러리 탭 partial(_library_tabs.html)과 탭 이름 전역(library_tabs)은 없어졌다. 교직원용 원본 장부 화면이 다시 필요하면 열람 범위 거르기(볼 수 없는 문서·부서 폴더)를 원본 장부 질의에 되살리고 라이브러리 쪽 화면을 새로 두어야 한다.
