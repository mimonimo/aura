# 0067. 맞는 양식이 없으면 27B 가 실물 양식을 참고해 설계하고, 문서 작업은 여러 턴 시나리오로 잰다

- **상태**: 제안 (양식 만들기는 한글 기안기 경로에 구현, 참고 양식·자기 검토는 설정으로 켜고 끔. 기본값은 회차를 더 모은 뒤 담당자 판단)
- **날짜**: 2026-10-23
- **관련**: ADR-0059(공통 양식 모양은 규칙으로), ADR-0060(양식은 Writer 가 고르고 품질 관문은 코드), ADR-0065(작업 메모·서브 맡기기)

## 맥락

- 한글 기안기 에이전트는 양식이 있어야 일을 시작한다. 문서함·공통 양식·공고 서식 가운데 목적에 맞는 것이 없으면(행사 운영 계획, 만족도 조사 결과 보고 같은 문서)
  담당자에게 양식을 구해 오라고 할 수밖에 없었다.
- 평가(scripts/201)는 요청 하나에 답 하나였다. 실제 대화는 두루뭉술하게 시작해 대상·예산·기간이 나중에 나오고, 양식을 고른 뒤 절을 쓰고, 고쳐 쓰고, 모양을 바꾼다.
  목표 이해·고쳐 쓰기·디자인 요청 반영은 잴 수단이 없었다.
- 후보 모델(파인튜닝)이 오면 답변 품질뿐 아니라 문서 작성·양식 만들기도 같은 묶음으로 견줘야 한다.

## 결정

1. **양식 만들기 도구 hwp_form_create**(app/webhwp_form_create.py). 판단은 27B, 모양·관문·기록은 코드.
   - 설계: 메인이 목적·갈래·필수 항목만 주면 같은 모델을 깨끗한 문맥으로 한 번 더 불러 설계 JSON 을 받는다(문서 제목, 표지 여부, 요약 표 칸 라벨,
     절 목록 — 단계·제목·작성방법·분량·표 열 머리와 표 갈래(요약·일정·예산·일반)·도식으로 그릴 것). 작업 메모의 목표·확정 값, 담당자 원문 인용,
     프로젝트 문서 제목, 공고의 작성·평가 항목을 찾은 조각은 코드가 재료로 넣는다. 출력·근거 몫은 문맥 한도 비율(모델 이름·길이를 코드에 두지 않는다).
   - 참고 양식: 문서함의 잠긴 양식(공통 양식·공고 서식)과 열람 범위 안의 반입 양식에서 이름의 갈래 낱말·요청 낱말이 겹치는 실물 2~3개를 골라
     구조만(절 제목, 표 머리, 작성방법 요지 60자, 칸 라벨) 문맥 12% 안에서 준다. 값·본문은 넣지 않는다.
   - 갈래 사전: 실물 양식에서 갈래(서류 이름 끝의 일반 명사)마다 자주 쓰인 절·표 머리를 센 파생 결과물. 입력 지문(양식 목록과 파일 지문)이 바뀌면 다시 만든다.
     「이 갈래는 보통 이런 절」 참고로만 준다.
   - 자기 검토: 관문을 지난 설계를 점검표(빠진 절 — 사전·참고와 대조, 중복, 차례, 안내 구체성, 표·도식 자리, 요약 칸·분량)로 한 번 고친다. 고친 것이
     관문을 못 지나면 처음 설계를 쓴다. 설정 ZZAIMY_FORM_REFS·ZZAIMY_FORM_REVIEW(기본 켬).
   - 관문: 빈 제목, 절 0개·30개 초과, 같은 제목, 단계 건너뛰기, 220자 넘는 안내, 「~작성」「~제출」 처럼 안내 글로 끝나는 제목(기안기가 절로 읽지 못함),
     칸 라벨 꼴(예시 글자·숫자만), 표 열 수·길이. 거절이면 까닭을 붙여 한 번 다시 청한다. 분량 꼴이 아닌 분량은 거절하지 않고 안내 글로 옮긴다.
   - 만들기: 번호는 코드가 학교 서식 꼴(1. → 가. → 1))로 매기고 모델이 붙인 번호는 뗀다. 빌드는 공통 양식과 같은 webhwp_templates.build(표지·절 제목
     모양, 【작성방법】 상자, 학교 표 기본 모양, 누름틀 필드). 아래 절이 있는 위 절은 쓸 자리가 아니라 필드를 뺀다. 표지면 첫 절 앞에서 쪽을 나눈다.
     자가 점검(hwpx_fill.check)을 지나야 작업본으로 열고 대화에 잇는다(문서 패널이 바뀐 작업본을 연다). 설계는 작업본 meta form_design 에 남긴다.
   - 기존 양식 먼저: 이 대화에서 hwp_forms 를 돌린 뒤에만 돈다(관문). 도구 설명도 「맞는 양식이 없을 때」.
   - 화면: 진행 표시 「양식 설계 중 — 참고 양식 찾기 → 설계 → 검토」, 만든 뒤 편집 화면의 AURA 작성 표시(webhwp_activity), 대화에 잇기만 하면 문서 패널이
     바뀐 작업본을 연다(기존 확인 주기). 도구 결과에 「담당자에게는 양식 이름·절 수·여는 곳·확인할 값만 짧게」 를 붙인다.
2. **시나리오 평가 scripts/202**. 임시 DB·운영 연결 설정 복사본(끝나면 지움)·실제 27B 로 11턴 대화(두루뭉술한 시작 → 대상·예산 → 기간·양식 → 절 쓰기 → 계속 →
   고쳐 쓰기 둘 → 디자인 넷)를 문서함에 양식이 있는 판(forms)과 없는 판(noforms)으로 돌린다. 지표는 코드가 센다 — 고른·만든 양식과 그 걸음의 생각,
   만든 양식의 구조 점수(기준표 8항), 작업 메모 「지금 목표」 의 대상·예산·기간, 쓴 절, 준 값 반영, 지어낸 숫자, 표·도식, 작성방법 요구 반영,
   고쳐 쓰기 전후(바뀐 자리·글자·숫자·표), 디자인 요청 반영(실제 XML 값 — landscape, 좌우 여백, 머리줄 칸 음영, pageNum, 디자인 요청 전 값과 견줌),
   서식 깨짐(자가 점검·필드 짝), 턴별 시간과 가장 큰 호출. 글 품질은 review 연결 27B 가 기준표(구체성·논리·문체·근거, 1~5)로 채점하고 지시·기준표를
   결과에 남긴다. 쓰는 모델과 채점 모델이 같아 자기 평가 한계가 있으므로 판·회차 비교에만 쓴다.
3. **양식 만들기 묶음(202 --forms)**: 목적 여덟 가지(사업계획서·결과보고서·회의록·출장 결과 보고·내부결재 기안문·예산 변경 신청·행사 운영 계획·
   만족도 조사 결과 보고)마다 기존 양식을 hwp_forms 목록에서 숨긴 판(참고 양식으로는 읽힘)에서 「참고 없음 / 참고 / 참고+검토」 세 판을 직접 설계로,
   「참고+검토」 는 에이전트 대화 한 턴으로도 돌린다. 채점은 학교 서식에서 흔히 쓰는 절 이름 갈래의 포함률(정답 목록을 채우는 것이 아니다),
   작성방법 덮음·평균 글자·근거 언급률, 분량 안내, 요약 칸, 번호 체계, 빌드·깨짐.
4. **후보 모델 견주기**: 201·202 가 scripts/195 와 같은 방식(--candidate-conn·--candidate-model → ZZAIMY_LLM_TRY_CONN·ZZAIMY_LLM_TRY_MODEL,
   llm_connections.trial_conn)을 따른다(zzaimy.eval.model_trial). 결과에는 모델 정보·연결 이름만, 서버 주소는 남기지 않는다. 채점자는 후보 설정을 빼고
   운영 연결로 고정한다. scripts/203_model_compare.py 가 195·201·202 를 운영·후보로 돌려 한 표(compare.md)로 합친다.

1차에서 본 약점과 2차 고침(모두 일반 규칙):

- 쓰기·고쳐 쓰기 요청에 값이 모자라다며 묻기만 함 → 상태 글에 「쓰기 요청이면 먼저 쓰고 모르는 값은 확인 필요로 남긴 뒤 묻는다」.
- 일정 절이 근거에 없는 달(「12」)로 막힌 뒤 같은 본문을 되풀이 → 관문 거절 글에 막힌 줄과 고치는 법(시작·끝만 날짜, 사이는 단계 이름).
2차에서 본 약점과 3차 고침: 결정 값 찾기 거절 뒤 같은 찾기를 되풀이 → 거절 글에 「쓰기 요청이면 그 값 자리만 확인 필요로 두고 쓴다」,

3차의 실패 1건은 사업계획서 참고+검토 판 — 첫 설계가 12자 넘는 표 열 머리로 거절되고, 다시 청한 답이 JSON 꼴이 아니었다(재료가 길어 출력이 잘린 것으로 본다, 미확인).

해석: 만든 양식은 모두 빌드·자가 점검을 지났고 번호 체계가 맞았다. 참고 양식과 자기 검토는 작성방법 안내를 길고 근거를 밝히게 바꿨지만(근거 언급 0.23 → 0.51)
기준 절 포함률은 2차에서 거의 그대로(0.73 → 0.74), 3차에서 0.65 → 0.71 → 0.75 로 올랐다. 같은 판의 회차 차이(참고 없음 0.73 vs 0.65)가 판 사이 차이만큼 커서
효과를 단정하려면 같은 요청 반복 표본이 더 필요하다. 에이전트 길은 메인이 준 목적이 짧아 포함률이 낮다(0.65·0.67). 검토는 시간을 두 배 넘게 쓴다(25~31초 → 75초).
기본값은 참고·검토 모두 켬으로 두되(만든 양식의 안내가 근거를 밝히고 깨짐 0), 담당자가 결과 양식을 기안기로 본 뒤 정한다. 남은 확인: 같은 요청 반복 표본(판마다 흔들림), 후보 모델 비교(203), 운영 문서함의 실물 양식을 참고로 쓸 때의 효과.

## 되돌리기 비용

도구 하나와 설정 둘이다. ZZAIMY_FORM_REFS=0·ZZAIMY_FORM_REVIEW=0 이면 참고·검토 없이 설계만, 도구 등록 한 줄을 빼면 양식 만들기 전체가 빠진다.
갈래 사전은 설정 form_kind_dict 하나에 담겨 지우면 다음 호출에 다시 만든다. 만든 작업본은 보통 작업본과 같아 따로 정리할 것이 없다.
