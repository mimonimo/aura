# 0068. 고쳐 쓰기는 전용 도구로, 절 쓰기는 개요·자기 점검으로, 같은 값의 단위 바꿈은 같은 값으로

- **상태**: 제안(한글 기안기 경로에 구현·설정으로 켜고 끔, 기본 켬. 기본값 확정은 회차를 더 모으고 결과 문서를 담당자가 본 뒤)
- **날짜**: 2026-10-23
- **관련**: ADR-0065(작업 메모·서브 맡기기), ADR-0067(양식 만들기·시나리오 평가 202), 절대 규칙 1(수치는 인출만)

## 맥락

시나리오 평가(scripts/202, ADR-0067) 세 회차에서 남은 약점:
- 고쳐 쓰기 요청(「2번 절 더 구체적으로」「일정은 표로」) 반영 1/6. 에이전트가 고쳐 쓰기를 hwp_write 다시 쓰기로 처리하면서 지금 글을 다시 보지 않거나,
  값이 모자라다며 찾기·묻기를 되풀이했다.
- 작업 메모 「지금 목표」 가 지금 단계(「일정 표 정리」)로 바뀌어 대상·예산·기간이 빠지는 판이 있었다.
- 채점(같은 모델, 5점) 구체성 2.3~3.7·근거 2.0~3.0. 서브는 절 제목+요지 검색어 하나로만 찾았다.
- 긴 서식(절 47) 채움 29/47, 서브 맡기기를 차례로만 해서 대화 전체 31~39분.
- 「5억 원」 을 「500(백만원)」 처럼 단위만 바꿔 쓴 값이 지어낸 숫자로 잡혔다(평가 스크립트는 표면형만 견줬다).

## 결정

판단은 27B, 코드는 도구·관문·기록이라는 원칙(ADR-0060·0065)을 그대로 둔다. 사례 규칙 없이 일반 메커니즘만.

1. **고쳐 쓰기 도구 hwp_revise {field, instruction}**(app/delegate.Reviser). 서브 호출 둘 — 첫째는 지시의 뜻을 점검표 JSON 으로
   (의도·길이 늘림/줄임/그대로·표·도식 넣음/뺌/그대로·더할 항목·뺄 항목·문체·그 밖·검색어 0~3), 둘째는 지금 글 + 지시 + 점검표 + 그 절의 작성방법 +
   점검표 검색어로 찾은 근거를 깨끗한 문맥으로 주고 절 전체를 다시 받는다. 지금 글은 AURA 가 쓴 본문 기록(작업본 meta body, 마크다운 그대로)이
   작업본 첫 줄과 맞으면 그것, 아니면 작업본 글. 코드 관문은 셀 수 있는 것만 본다 — 바뀌었나, 길이 방향(늘림 1.15배·줄임 0.9배), 표·도식 유무,
   더할 항목 낱말(근거가 없어 확인 필요로 돌린 항목은 지킨 것), 본문 관문(check_body). 어기면 까닭을 붙여 한 번 다시 청하고, 본문 관문을 지나면 쓰고
   못 지킨 점을 메인에 알린다. 상태 글에 「이미 쓴 절을 고쳐 달라고 하면 다시 찾거나 묻지 말고 먼저 hwp_revise」. 비어 있는 절은 거절(먼저 쓰기).
   「N번 절」 은 번호가 하나로 정해질 때만 코드가 잇는다(같은 번호 절이 여럿이면 에이전트가 이름으로 짚는다). 설정 ZZAIMY_REVISE.
2. **서브 절 쓰기 품질**(app/delegate.Delegator, 설정 ZZAIMY_DRAFT_QUALITY):
   - 검색어: 서브가 절 제목·작성방법·작업 메모·요지에서 검색어 2~3개를 먼저 내고, 코드가 절 제목+요지와 그 검색어마다 찾아 같은 조각은 한 번만 모은다.
     근거 머리에 번호와 쪽(조각 장부의 page_no, 모르면 빼고)을 붙인다 — 「[근거 3] 《기본계획》 12쪽」.
   - 개요 → 본문: 같은 호출 안에서 [개요](요지·쓸 근거 번호·표/도식 필요와 까닭·항목 3~6개)를 먼저 쓰고 개요대로 [본문]을 쓴다. 근거 문서에서 온
     문장 끝에 짧은 출처 꼬리 「(출처: 짧은 문서 이름 N쪽)」, 담당자가 알려 준 값에는 달지 않는다.
   - 자기 점검: 쓴 뒤 기준표(구체성 — 대상·방법·시기·수치가 근거·확정 값에서 왔나 / 근거 — 근거·확정 값·담당자 인용과 맞나 / 작성방법 / 개요 반영)로
     한 번 점검하고, 모자라면 같은 호출에서 고친 본문을 받는다. 고친 글이 본문 관문을 못 지나거나 처음 글의 절반보다 짧으면 처음 글을 쓴다.
   - 수치는 근거나 담당자 글에만 — 관문은 그대로.
3. **같은 값의 단위 바꿈**(verify/numbers): 「500(백만원)」 처럼 숫자 바로 뒤 괄호의 금액 단위, 글의 「(단위: 백만원)」 선언을 읽어 그 단위로 환산한 값도
   같은 값으로 본다(초안·근거 양쪽). 5억 = 500,000,000원 = 500백만원 = 500(백만원) = 백만원 단위 표의 500. 앱 관문(check_body·mask_unsupported)과
   평가(202 invented)가 같은 함수를 쓴다. 정말 없는 값(700(백만원), 4,500명)은 그대로 잡는다.
4. **작업 메모 최종 결과물 줄**(app/chat_memory, 설정 ZZAIMY_MEMO_GOAL_LOCK): 메모 맨 앞에 「최종 결과물」(문서 이름·용도·대상·마감 한 줄)을 따로 둔다.
   갱신 지시에 「담당자가 바꾸자고 하지 않으면 지난 줄 그대로, 지금 단계는 적지 않는다」. 코드 관문 keep_final — 담당자 말에 바꾸자는 낱말(바꾸·변경·
   대신·말고·다른 문서)이 없는데 그 줄이 사라지거나 이전 줄 낱말의 절반 넘게 빠지면(단계 이름으로 바뀐 경우) 이전 줄을 지킨다. 더 분명해진 줄은 받는다.
   서브 지시서·양식 설계 재료에도 이 줄을 싣는다.
5. **여러 절 동시 맡기기**: delegate_section 에 sections 목록. 서브 연결 묶음은 검토 연결(review 역할) 위주로 연결별 동시 상한만큼 + 메인 연결 하나
   (메인은 맡기는 동안 기다리므로). 두 역할이 같은 서버·모델이면 그 연결 하나의 상한만큼. 동시 상한은 연결 설정의 parallel(정수), 없으면
   ZZAIMY_DELEGATE_PARALLEL(기본 2), 합 4까지. 모델 호출(검색어·쓰기·점검)만 동시에, 찾기와 파일 쓰기는 차례대로. 상태 글에 동시 상한과,
   빈 절이 넷 이상이거나 남은 문맥이 절반 아래면 묶어 맡기는 편이 낫다는 안내.
6. **평가 202**: --repeat N(같은 요청 N 번), --old(위 설정 넷을 끈 이전 판), 판·판본마다 평균(최소~최대) 표, --rescore(저장된 결과를 같은 잣대로
   다시 센다). 지표 — 고쳐 쓰기 반영(구체: 바뀐 자리 글자 1.15배 넘게, 표: 바뀐 자리에 표가 생김, 0~2), 절 채움, 지어낸 숫자(수치 대조기 기준·표면형),
   목표와 목표 유지(기간·양식 턴 뒤 메모 목표 갈래에 대상·예산·기간이 다 든 턴 비율), 채점 4항목(review 연결 고정), 시간.

## 근거

결과와 확인 절의 실측. 쓰는 모델과 채점 모델이 같은 27B 라 채점은 자기 평가 한계가 있다 — 판끼리 견주는 데만 쓴다.

## 결과와 확인

10-23 운영 VM, 202 noforms(양식 없이 시작 → 양식 만들기 → 절 쓰기 → 고쳐 쓰기 둘 → 디자인 넷), 판마다 3회, 쓰기·채점 모두 Writer 27B(16384).
결과 파일 ~/ops/scenario_eval/cmp. 새판 = 이 결정의 설정 넷 켬, 이전판 = --old.

| 항목 | 새판(3회) | 이전판(3회) |
|---|---|---|
| 쓴 절 | 21/21 | 17/17 |
| 작성방법 요구(표·도식·출처) 반영 | 19/20 | 17/20 |
| 「더 구체적으로」 고쳐 쓰기 반영(1.15배 넘게 늘어남) | 3/3 | 1/3 |
| 지어낸 숫자 | 0 | 0 |
| 디자인 지시(가로·여백·머리줄·쪽 번호) | 12/12 | 12/12 |
| 깨짐(점검·필드) | 0 | 0 |
| 채점 평균 구체성·논리·문체·근거(5점) | 2.94 · 3.39 · 3.89 · 3.33 | 2.83 · 3.19 · 3.89 · 2.70 |
| 걸린 시간 평균(초) | 924 | 782 |
| 모델 호출 평균 | 73 | 62 |

- 고쳐 쓰기 반영과 근거 점수(+0.63)가 가장 크게 나아졌다. 시간·호출은 개요·자기 점검·검색어 여러 개만큼 늘었다(약 18%).
- 「표로 정리해 줘」 는 두 판 모두 0/3 으로 잡혔는데, 원본을 열어 보니 일정 절이 처음부터 작성방법대로 표였다 — 채점이 「표가 새로 생겼나」 만 봐서다.
  202 에 「이미 표」 를 따로 세게 고쳤다(73385438). 이 회차 결과는 옛 잣대라 그 칸을 비교에 쓰지 않는다.
- 목표 유지(메모 목표 갈래에 대상·예산·기간)는 두 판 모두 낮았다(새판 1/9×3, 이전판 0~9/9). 원인은 최종 결과물 줄 고정이 첫 대화의
  막연한 줄(「…미정」)을 끝까지 지킨 것 — 미정 줄은 구체화를 받게 고쳤다(73385438). 다음 회차에서 다시 잰다.
- 결과 문서에서 본문 표 밑에 양식의 빈 표가 겹쳐 남는 것을 찾아, 본문이 표를 들고 오면 같은 절의 빈 양식 표를 지우게 했다(73385438).
- 가장 큰 호출이 한도(16384)에 거의 닿는다(16292~16373) — 근거를 한도까지 채워 넣는 맞춤(create_fitted) 때문이며 잘림은 없었다.

## 되돌리기 비용

설정 넷(ZZAIMY_DRAFT_QUALITY·ZZAIMY_REVISE·ZZAIMY_DELEGATE_PARALLEL·ZZAIMY_MEMO_GOAL_LOCK)을 0 으로 두면 이전 흐름 그대로다(202 --old 와 같다).
수치 대조기의 단위 바꿈 인정은 설정 없이 늘 켜진다 — 같은 값을 다르게 적은 것을 지어낸 숫자로 보지 않는 것이 맞는 판정이라서다.
메모의 최종 결과물 줄은 갈래가 하나 더 늘 뿐이라 옛 메모도 그대로 읽힌다.
