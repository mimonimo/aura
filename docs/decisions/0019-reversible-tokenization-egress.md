# 0019. 외부 처리용 가역 토큰화 (재조립)

상태: 채택 (2026-09-19)

## 배경

외부 모델(협약 GPU·상용)로 처리해야 하는 작업에서 민감정보가 섞일 수 있다. 기존 반출
관문(ADR-0008)의 세척은 단방향이라 원값을 복원할 수 없어, "외부에서 처리한 결과에 실제
값을 되살린다"는 흐름이 안 됐다. 교수님 제안(민감정보를 나눠 처리 후 재조립)의 취지를
살리되, 조각 분산·해시 방식의 원리적 결함(해시는 비가역이라 재조립 불가, 무의미하게 나누면
외부가 처리 불가)을 피하는 정공법이 필요했다.

## 결정

가역 토큰화를 반출 관문에 추가한다(`egress.process_external_tokenized`).

1. 교내에서 개인정보를 되돌릴 수 있는 토큰으로 치환한다(`PiiMasker.tokenize`). 같은 값은
   같은 토큰(`[[ENTITY_N]]`)을 쓴다. 토큰↔원값 대응표(vault)는 교내에만 둔다.
2. 외부 모델에는 토큰본만 보낸다. 시스템 프롬프트로 토큰을 그대로 유지하도록 지시한다.
3. 결과가 오면 교내에서 결정론적 치환으로 원값을 되살린다(`PiiMasker.restore`). 값 복원은
   생성이 아니라 정확 치환이다(수치·식별자 환각 방지, 브리프 절대규칙 1).
4. 반출은 `external_status()`(ZZAIMY_EXTERNAL_ENABLED + 외부 연결 + 키)가 켜져야 시도한다.

## 한계 (명시)

- 보호 범위는 탐지기가 잡은 것까지다. 라벨 없는 성명·주소는 놓친다(NER 도입은 별건).
- 토큰화는 개인정보를 가릴 뿐, 문서 내용(기밀) 자체는 외부에 공유된다. 개인정보 안전 ≠ 기밀 안전.
- 주민번호 등 고유식별정보의 국외 상용 클라우드 전송은 법적으로 취약하다. 상용 사용 여부는 기관 정책.
- 맥락 재식별(직책·연도 등)은 토큰화로 막지 못한다.

## 결과

- 화면 `/dev/egress`에 "외부 처리: 민감정보 토큰화" 카드. 원문 → 토큰본(외부로 나감) → 외부
  결과 → 교내 복원을 한눈에 보인다.
- 대응표·복원 결과는 화면에 한 번 렌더할 뿐 저장하지 않는다.
- 정책상 안 쓰면 카드·라우트·함수만 제거하면 된다(색인·검색 무관).
