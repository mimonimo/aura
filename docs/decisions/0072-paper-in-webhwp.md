# 0072. 논문을 웹 기안기에서 쓰기

- **상태**: 확정(로컬 시험 서버·시험). 운영 배포는 미확인
- **날짜**: 2026-10-24
- **관련**: ADR-0070(칸 단위 공동 편집), `app/paper_hwp.py`, `app/dev_docs_routes.py`(/dev/paper/hwp, /hwp/{id}/paper-toc), `templates/dev_docs.html`, `templates/hwp_edit.html`, `static/paper-toc.js`,
  `scripts/214_paper_write.py`, `tests/test_paper_hwp.py`, `docs/paper/논문-양식-가이드.md`, `docs/paper/논문/`

## 맥락

캡스톤 논문을 우리 플랫폼의 웹 한글 기안기에서 쓴다. 팀원이 같은 문서를 동시에 고치고, 원고(`docs/paper/논문/*.md`)는 Claude 가
공동 편집 참여자로 절마다 넣는다. 형식은 작년 캡스톤 논문집 한 편의 차례와 지면을 따른다(논문 양식 가이드).

## 결정

1. 논문 양식은 코드가 만든다(`paper_hwp.build`). 표지(「2026 사이버보안과 캡스톤디자인 졸업프로젝트 논문」 머리 줄 — 학과는 칸:학과, 기본값 사이버보안과, PROJECT _ n·제목·팀원 [팀명]
   상자) → 목차(세 단계, 점선) → 그림 목차 → 표 목차 → 1~6장 → 참고 문헌 → Abstract → 팀원 소개 → 부록. A4, 머리말 오른쪽 위 줄인 제목과
   아래 선, 꼬리말 「영남이공대학교 사이버보안과」 와 쪽 번호(표지에는 숨김). 장·절·소절 제목은 house_style 의 chapter·h1·h2 모양.
2. 쓸 자리는 절마다 제목 바로 아래 문단 하나의 누름틀 「절:<번호> <제목>」(번호 없는 장은 「절:<제목>」). 제목은 필드 밖이고 장 제목에는
   쓸 자리를 두지 않는다. 표지 값은 칸 필드(칸:학과·칸:프로젝트 번호·칸:논문 제목·칸:팀원·칸:팀명).
3. 차례는 데이터로 둔다. 원고 폴더에 장 파일이 있으면 그 번호 제목에서 읽고(3단계까지), 원고가 아직 없는 장은 기본 차례(`OUTLINE`)로 채운다.
   번호 없는 장·절 제목(「이 장의 그림·표 자리」)은 원고 메모로 보고 넣지 않는다. 부록 안의 숫자 번호는 「부록 」 을 붙여 본문 장과 겹치지 않게 한다.
4. 꾸밈 문단 스타일 여섯(단계 목록·팁 상자·그림 자리·그림 캡션·표 캡션·코드)을 header 에 이름 붙여 둔다. 사람은 기안기 스타일 목록에서 고른다.
5. 논문 문서는 하나. 설정 `paper:hwp_fid` 가 문서 id 이고, 자리는 한글 문서함 「공통/논문」 이다. 공통은 교직원·관리자 모두 열고(학생은 못 연다),
   공통 양식이 아니므로 잠그지 않는다. 개발 현황 → 논문·설계 문서의 「논문 자료」 칸에 「논문 문서 만들기」(POST /dev/paper/hwp, 개발자) 또는
   「논문 작성」(GET /dev/paper/hwp → 기안기 편집 화면)을 둔다. 교직원은 문서함 공통/논문에서 연다.
6. 원고 쓰기는 `scripts/214_paper_write.py`. 참여자 아이디 `claude`(화면 이름 「Claude」, `webhwp.AGENTS`)가 사람·AURA 와 같은 길로 쓴다 —
   임대 잡기 → 같이 보는 사람 표시 → 칸 글을 몇 걸음에 나눠 보내기(보는 사람에게 글이 차오른다) → 놓기 → 한글 파일 써 넣기. 절 사이는 쉰다.
   사람이 쥔 칸, 사람이 쓴 글이 있는 칸(--overwrite 가 아니면)은 건너뛰고 알린다. 그림·표 목차 칸은 원고 캡션에서 채운다.
7. 칸 글은 글만 오가므로 기본 쓰기는 글 꼴로 대신한다: 번호 목록 「1) 」, 글머리 「- 」, 팁 「※ 참고: 」, 그림 자리 「〔그림 자리: …〕」 + 「[그림 n-m] …」,
   표는 「칸 | 칸」 줄 + 「[표 n-m] …」(캡션은 표 아래), 코드는 네 칸 들여쓰기, 깊은 소제목 「■ 」. `--rich` 는 AURA 의 절 쓰기와 같이
   절 필드 뒤에 문단·표·도식을 파일로 넣고 꾸밈 스타일을 입힌다(팁·코드·그림 자리는 바탕 칠한 1칸 표). 이때 열린 편집 화면은 저장 알림으로 새 판을
   다시 부르고, 누가 구조 잠금을 쥐고 있으면 쓰지 않는다.

## 고도화(학과·목차 쪽 번호·그림)

8. 학과는 사이버보안과. 이미 만든 문서는 `paper_hwp.restamp`(scripts/214 `--restamp`)가 필드 밖 학과 글(표지 아래 줄·꼬리말)만 바꾼다 — 칸 글을 먼저
   파일에 써 넣고, 고친 뒤 필드 값이 그대로인지 확인하고, 앞 판을 .판/ 에 남겨 저장한다(열린 화면은 저장 알림으로 새 판). 예전 값은 문서 메타 paper.dept,
   없으면 자리표시 「○○과」. 표지 머리 줄의 학과는 칸이라 `--set 칸:학과=사이버보안과`(칸에 글이 있어도 바꾼다, 쥔 칸은 건너뜀)로 쓴다.
9. 목차 줄은 「들여쓰기 + 제목 + 오른쪽 탭(점선 채움) + 쪽」. 쪽은 편집 화면 「⋯」 → 「목차 쪽 번호 넣기」(논문 문서만, static/paper-toc.js)가 목차 줄마다
   그 절 칸으로 커서를 옮겨 인쇄 쪽 번호를 재고(KeyIndicator), POST /hwp/{id}/paper-toc 가 필드 밖 목차 줄만 다시 쓴다(restamp 와 같은 저장 길). 장 줄은
   그 장 첫 절의 쪽, 목차 줄과 절 필드는 문서 차례대로 짝짓는다(부록 소절처럼 같은 제목이 있어도 갈린다). 예전 꼴(제목 뒤 「····」)도 이 꼴로 바뀐다.
   한글 차례 기능(자동 목차)은 웹 기안기에서 쓸 수 있는지 확인하지 못해 쓰지 않았다.
10. 서식째 쓰기에서 그림·표 목록(그림-표-목록.md)의 「자료」 칸이 저장소 그림 파일(docs/images/…)로 시작하는 그림은 그림 자리 상자 대신 그 그림을 넣는다
    (글자처럼 취급, 가운데, 글 폭에 맞추고 높이 상한, 다음 문단 캡션과 함께). 문단 id 를 쓴 목록에 남겨 다시 쓰면 지우고, 같은 그림 바이트는 BinData 를
    다시 쓴다. 「캡처 필요」·「작성 필요」·「본문 글 상자」 는 자리 상자로 둔다. 부록 그림 번호(「[그림 부록-n]」)도 캡션으로 읽는다.
    글로 먼저 채운 문서는 `--rich --formatted` 로 표·그림·팁·코드·도식·참고 문헌이 있는 절만 서식째로 다시 쓴다(사람이 쓴 칸·쥔 칸은 그대로 건너뛴다).
11. 원고의 `<!-- -->` 는 원고 메모라 넣지 않는다. 「참고: …」 문단은 팁 상자, 「[n] …」 문단은 참고 문헌 스타일(내어쓰기), 그림을 사이에 둔 번호 목록은 번호를 잇는다.
12. Claude 참여자는 절 하나를 쓰는 동안 공동 편집의 절 흘려 쓰기(`webhwp_coedit.SectionStream`)로 임대를 쥐고, 걸음마다 임대를 늘리며 같이 보는 사람 표시를
    그 칸에 둔다(사람 목록 「Claude · 쓰는 중」). 마지막 글을 넣고 놓은 뒤 표시는 칸 없이(문서 보는 중) 둔다. 걸음 수는 글 길이에 따라 4~12.
13. 「논문 문서 만들기」 단추는 답(JSON 의 편집 주소)을 받아 직접 옮겨 간다. 스크립트가 꺼진 화면은 폼 그대로 303.
14. 아래 절만 있고 원고에 제 글이 없는 절(1.4 프로젝트 구성처럼)은 제목만 두고 쓸 자리를 두지 않는다(`headless`) — 빈 칸의 붉은 안내 글 「본문 입력」 이
    보이지 않게. 이미 만든 문서는 `--drop-empty` 가 그 빈 칸 문단을 지운다(파일 값·칸 글 표가 비고 아무도 쥐지 않은 칸만, 다른 칸 값은 그대로인지 확인, 앞 판은 .판/).
    목차의 그 줄은 다음 절의 쪽으로 잰다. 원고가 아직 없는 장의 절은 쓸 자리를 남긴다. 기안기가 저장한 파일은 빈 누름틀에 안내 글(Direction)을 실제 글로
    넣어 두므로, 파일 값이 비었거나 안내 글뿐이면 빈 칸으로 본다. 서식째 쓴 절(메타 written)은 지우지 않는다. 미리 보기(--dry-run)는 남기는 절의 까닭도 보인다.
15. 서식째 쓴 표는 학교 표 모양으로 다시 입힌다(`dress_tables`) — 머리줄 가운데·굵게·음영, 본문 칸 왼쪽 정렬(양쪽 정렬이면 좁은 칸 글이 벌어졌다), 한 열의 본문
    칸이 모두 짧은 값(한글 8자 폭 이하·수)이면 그 열은 가운데, 모두 금액이면 오른쪽. 열마다 한 가지 정렬.
16. 서식째 쓰기는 장마다 묶어 저장 한 번(`write_batch`) — 절마다 저장하면 열린 화면이 절마다 새 판을 불러 첫 쪽으로 돌아갔다. 칸에 hwpx 조각을 넣는 길
    (`webhwp_coedit.put_rich`)은 화면에는 서식째 들어가지만 파일 써 넣기가 아직 글만이라, 화면(조각이 칸 안)과 파일(문단·표가 칸 뒤)의 모양이 갈라진다.
    파일 써 넣기가 조각을 받게 되면 그 길로 옮긴다.
17. 본문 쪽 번호는 「1. 서론」 에서 1 — 쪽 번호 매기기 컨트롤(pageNum)을 서론 제목 문단으로 옮기고 그 자리에 쪽 번호 새로(newNum 1)를 둔다. 쪽 번호는 그 컨트롤이
    있는 쪽부터 찍혀 표지·목차·그림 목차·표 목차에는 번호가 없다(작년 논문집 꼴). 이미 만든 문서는 `--page-numbers`. 「목차 쪽 번호 넣기」 는 인쇄 쪽 번호(KeyIndicator
    prnpageno)를 재므로 목차에 본문 쪽(1부터)이 들어간다.

## 서식째 동기화로 넓히는 최소 변경(제안)

기안기는 필드를 고른 뒤 `SetTextFile(base64 hwpx, 'HWPX', 'insertfile')` 로 hwpx 조각을 그 필드 안에 서식째 넣는다(로컬 시험: 팁 상자·표·
표 캡션이 스타일째 들어가고 다시 넣으면 바뀐다). 지금 서식 동기화(설정 coedit:rich)는 편집 화면이 기안기 JSON 블록을 보내고 받는 꼴이라 서버 쪽
참여자는 서식을 만들 수 없다. 넓히려면 세 곳이다.

- 편집 화면 래퍼(`static/webhwp-wrapper.js` importField): rich 가 `{"fmt":"hwpx","b64":…}` 이면 `SetTextFile(b64, 'HWPX', 'insertfile')`, 아니면 지금처럼 JSON.
- 서버 쪽 참여자: 칸 글 op 에 `rich` 로 그 JSON 을 싣는다(`paper_hwp.fragment` 가 조각 hwpx 를 만든다, 상한 RICH_MAX 2MB 안).
- 한글 파일 써 넣기(`webhwp_coedit.overlay`): 지금은 글만 쓴다. rich 가 hwpx 조각이면 필드 안을 조각의 문단·표로 바꾸는 쓰기(write_section 을 필드 안으로)가 있어야
  다시 열어도 서식이 남는다. 이것이 빠지면 화면에만 서식이 있고 파일에는 글만 남는다.

## 27B 절 쓰기로 넓힘(10-25)

논문에서 쓴 꾸밈 스타일 가운데 행정 문서에도 맞는 둘을 27B 의 절 쓰기(hwp_write·절 맡기기·고쳐 쓰기)에 붙였다(app/webhwp_dress.py).
27B 는 글에 표시만 하고, 모양은 코드가 정한다.

- 「> 」 로 시작하는 줄(이어진 줄은 한 상자): 참고 상자. 연한 파랑 바탕 1칸 표에 「팁 상자」 스타일.
- 표 바로 윗줄(또는 아랫줄)의 「<표> 제목」·「<표 3> 제목」·「[표 3] 제목」: 가운데·굵게 표 제목(「표 캡션」). 번호를 안 적으면 다른 절에 이미 있는
  <표 N> 다음 번호. 표에 붙지 않은 문장 속 「<표 3> 에서 보듯」 은 글로 둔다.
- 개조식 번호(1) 가) (1))·표 모양·도식은 예전대로 양식의 문단 모양과 학교 표 기본을 따른다(논문의 「단계 목록」 같은 꾸밈은 행정 양식과 겹쳐 넣지 않았다).
- 실제 27B 시나리오(scripts/202, 10-25 시험 DB)에서 참고 상자 1개·표 제목 6개를 썼다. 절이 표 제목으로 시작하면 제목이 칸 첫 문단에 들어가 꾸밈이 빠졌고(3개),
  27B 가 번호를 직접 적어 <표 2> 가 둘이었다 — 칸 첫 문단도 꾸미고, 쓸 때마다 「표 캡션」 문단의 번호를 문서 차례대로 다시 매긴다(webhwp_dress.renumber).
- 목차 쪽 번호(점선 탭·쪽 재기)는 아직 논문 문서만이다. 긴 행정 보고서에 목차가 있는 양식이 들어오면 같은 길로 넓힌다.

## 한계

- 목차 쪽 번호는 서버가 셀 수 없어(글자 배치는 기안기만 한다) 편집 화면의 「목차 쪽 번호 넣기」 를 눌러야 들어간다. 그림 목차·표 목차 칸은 쪽 번호 없이 캡션만이다.
- 그림은 그림·표 목록에서 파일을 정해 둔 것만 넣는다(서식째 쓰기). 「캡처 필요」 인 그림은 자리 상자로 남는다.
- 원고 차례가 바뀌면(절이 늘거나 이름이 바뀌면) 문서의 필드는 따라오지 않는다. 쓰기는 번호가 같고 제목이 비슷한 필드에만 넣고, 맞는 필드가 없는 절은 알린다.
- 장 머리 글(장 제목과 첫 절 사이)은 쓸 자리가 없어 건너뛴다.
- 쓰기 스크립트는 DB 와 파일을 직접 쓴다. 파일 써 넣기 잠금은 프로세스 안 잠금이라 서버와 같은 때 써 넣으면 나중 것이 이긴다(두 쪽 다 칸 글 표 전체를
  덮어 쓰므로 칸 글은 잃지 않는다).
- 편집 화면의 왼쪽 여백 이름표는 시험 화면 갈무리에서 보이지 않았다(같이 있는 사람 목록·풀이말에는 「Claude · 쓰는 중 · 칸 이름」).
- 목차 쪽 번호는 넣은 때의 쪽이다. 본문이 늘어 쪽이 밀리면 다시 눌러야 맞는다(장 줄은 그 장 첫 절의 쪽, 제목이 쪽 끝에 홀로 걸리면 한 쪽 어긋날 수 있다).
