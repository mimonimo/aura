# ADR-0034 — 윈도우 COM 한글 에이전트(exe)를 폐기하고, 한글 에이전트가 필요하면 MCP 방식으로 만든다

날짜: 2026-09-28 · 상태: 채택 · 대체: ADR-0014(한글 생성 = COM 에이전트 + md IR)

## 배경

사용자 판단(2026-09-28): 담당자 PC 에 exe 를 설치해 한글(HWP) 프로그램을 COM 으로 조종하는 방식은 쓰기에 너무 번거롭다. 작업 공간은
구글독스(실시간 다중 인원)이고 한글은 최종 산출에만 필요하다. kordoc(ADR-0033)은 MCP 서버(17 도구: 파싱·채우기·비교·렌더 등)를
제공하므로, 한글 에이전트가 필요하면 그 방식(도구 서버)을 참조해 우리 플랫폼에 맞춰 만드는 편이 낫다.

## 결정

1. `tools/` 의 윈도우 COM 에이전트와 설치 프로그램(installer)은 폐기한다. 화면의 "한글로 내보내기(에이전트)" 진입은 뺀다.
   코드는 한 판 동안 저장소에 두되 새 기능을 붙이지 않고, 다음 정리 때 지운다.
2. 최종 한글(HWPX) 산출은 서버에서 한다 — 우리 hwpx 변환기의 역방향(독스/docx 본문을 원본 서식 XML 에 넣기) 또는 kordoc 의
   기입란 채우기(fillForm)·생성(generate) 중 실측으로 고른다(kordoc patch 는 새 문단 추가가 안 돼 제외, 2026-09-28 실측).
3. 담당자 PC 쪽 조작이 꼭 필요해지면 exe 가 아니라 MCP 도구 서버로 만든다(kordoc-mcp 참조, 도구 이름·입출력을 우리 것으로).

## 되돌리기

ADR-0014 경로는 저장소 기록에 남는다. 이 결정을 되돌리려면 installer 배포와 화면 진입을 복구하면 된다.
