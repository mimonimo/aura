# 1~2주차 작업 계획 (2026-09-01 ~ 09-14)

목표: 장비에서 서빙·학습 스택이 실제로 도는지 확인하고, 문서 파서를 정하고, 설계를 문서로 굳힌다.
선행 문서: `CLAUDE.md`, `PROJECT_BRIEF.md`.

## 진행 원칙

- 한 작업은 한 브랜치에서 끝내고, `main` 은 늘 통과 상태로 둔다.
- 작업마다 완료 기준을 확인하고, 못 맞추면 그 이유를 남긴다.
- 판단이 갈리는 지점은 `docs/decisions/` 에 `상태: 제안` ADR 로 남긴다.
- 검증하지 않은 값은 「미확인」으로 적는다.

## 순서

```
TASK-01 ─┬─ TASK-02 ─┐
         └─ TASK-03 ─┴─ TASK-08
TASK-04 ─── (표본 도착 후 실행) ─── TASK-09
TASK-05 ─── TASK-06
TASK-07 (병행 가능)
```

TASK-01~03, 05~07 은 외부 입력 없이 시작할 수 있다. TASK-04 는 코드까지 만들고 실행은 표본 문서를 기다린다.

## TASK-02 · 서빙 스택 스모크 테스트

브랜치 `feat/serving-smoke` · 선행 TASK-01 · 참고 `research/01-J-llm-serving.md`

aarch64 + Blackwell 조합은 조사 단계에서 위험 요소로 꼽힌 지점이라 먼저 확인한다.

- vLLM 을 aarch64 에서 구동한다. 컨테이너 이미지 우선, 소스 빌드는 차선
- 동작하는 이미지 태그·커밋 해시를 고정해 기록한다(`latest` 금지)
- 소형 모델(Qwen3-4B 급)을 올려 OpenAI 호환 엔드포인트 응답 확인
- 처리량(토큰/초, 첫 토큰 지연)을 측정 조건(배치, 컨텍스트 길이)과 함께 기록
- 기동 파라미터는 `configs/serving.yaml`

완료 기준: 엔드포인트 응답, 고정 이미지와 재현 절차를 담은 ADR. 실패하면 원인과 시도한 우회 경로를 ADR 에 남긴다.

## TASK-08 · 수직 슬라이스 골격

브랜치 `feat/vertical-slice` · 선행 TASK-02, TASK-03

발표 시연의 예비이자 통합 위험을 일찍 찾는 장치다. 품질보다 경로를 먼저 연다.

- `scripts/90_slice_demo.py`: 공고 파일 1개로 `공고 파싱 → 스키마 추출 → 검색(스텁) → 절 1개 생성 → 검증기 3종 → 출처 주석` 통과
- 단계 내부는 스텁 허용, 검증기 3종(수치 대조, 배점 커버리지, 예산 계산)의 인터페이스는 실제로 설계

완료 기준: 명령 한 줄로 끝까지 통과해 출처 달린 문단 하나가 나오고, 실패 지점이 로그에 남는다.
