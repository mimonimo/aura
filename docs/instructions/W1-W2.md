# 작업 지시서 — W1~W2 (2026-09-01 ~ 09-14)

> 대상: 클로드 코드 · 선행 필독: `CLAUDE.md`, `PROJECT_BRIEF.md`
> 목표: **환경이 실제로 도는지 확인하고, 파서를 확정하고, 설계를 문서로 굳힌다.**

## 작업 방식

- **한 태스크 = 한 브랜치 = 한 PR.** 브랜치명은 각 태스크에 적힌 것을 쓴다
- `main`을 깨진 상태로 두지 않는다
- 태스크마다 완료 기준을 만족했는지 스스로 확인하고, 못 만족하면 왜인지 적는다
- **막히면 멈추고 묻는다.** 추측으로 채우지 않는다 (브리프 0장)
- 판단이 갈리면 임의 결정하지 말고 `docs/decisions/`에 `상태: 제안`으로 ADR을 쓴다
- 검증 안 된 값은 "미확인"으로 표기한다. 그럴듯한 수치를 지어내지 않는다

## 실행 순서

```
TASK-01 ─┬─ TASK-02 ─┐
         └─ TASK-03 ─┴─ TASK-08
TASK-04 ─── (표본 도착 후 실행) ─── TASK-09
TASK-05 ─── TASK-06
TASK-07 (병행 가능)
```

TASK-01~03, 05~07은 **외부 입력 없이 지금 시작할 수 있다.**
TASK-04는 코드까지 작성하고 실행은 표본 문서를 기다린다.

## TASK-02 · 서빙 스택 스모크 테스트

**브랜치**: `feat/serving-smoke` · **선행**: TASK-01

`research/01-J-llm-serving.md` 참조. **여기서 터질 문제라면 지금 알아야 한다.**
aarch64 + Blackwell 조합은 리서치가 위험 2번으로 지목한 지점이다.

**할 일**

- vLLM을 aarch64에서 구동. 컨테이너 이미지 우선, 소스 빌드는 차선
- **동작하는 이미지 태그/커밋 해시를 고정하고 기록한다.** "latest"를 쓰지 않는다
- 소형 모델(예: Qwen3-4B 급) 하나를 올려 OpenAI 호환 엔드포인트로 응답을 받는다
- 간단한 처리량 측정 — 토큰/초, 첫 토큰 지연. 측정 조건(배치 크기, 컨텍스트 길이)을 함께 적는다

**완료 기준**

- 엔드포인트가 실제 응답을 반환한다
- **ADR 작성** — 고정한 이미지 태그와 그 근거, 재현 절차
- 실패했다면 실패도 완료다. 무엇이 왜 안 되는지, 시도한 우회 경로를 ADR에 기록하고 보고

**막히면**: 소스 빌드로 넘어가기 전에 보고한다. 시간을 많이 먹는 경로다.

## TASK-08 · 수직 슬라이스 골격

**브랜치**: `feat/vertical-slice` · **선행**: TASK-02, TASK-03

발표 시연의 백업이자 통합 위험의 조기 발견 장치.
**품질보다 경로를 먼저 뚫는다.** 각 단계는 스텁이어도 된다.

**할 일**

- `scripts/90_slice_demo.py` — 공고 파일 1개를 받아 아래를 통과시킨다
  ```
  공고 파싱 → 스키마 추출 → 검색(스텁) → 섹션 1개 생성 → 검증기 3종 → 출처 주석 출력
  ```
- 각 단계는 인터페이스만 맞추고 내부는 하드코딩/스텁 허용
- 단, **검증기 3종의 인터페이스는 진짜로 설계한다** — 수치 대조, 배점 커버리지, 예산 계산.
  나중에 끼워 넣기 어려운 지점이다
- 예산 계산에 LLM을 쓰지 않는다. 결정론적 함수로

**완료 기준**

- 명령 한 줄로 끝까지 통과하고, 출처가 달린 문단 하나가 나온다
- 실패 지점이 명확히 로그에 남는다
