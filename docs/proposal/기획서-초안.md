# 행정업무 자동화를 위한 YNC LLM 모델 개발 — 기획서 (초안)

캡스톤디자인 · 2026-09-01 작성

## 1. 배경

학교 행정 부서에는 문서를 읽고 정리하는 일이 끊이지 않는다. 국고사업 공고가
나오면 담당자는 과거 문서 수만 장을 뒤져 계획서를 처음부터 쓰고, 채용 공고가
나가면 접수된 서류를 한 장씩 열어 확인한다. 전결이나 결재 같은 절차는 기존
업무 포털이 이미 처리해 주지만, 문서를 읽고 이해하고 정리하는 일 자체는 여전히
사람 몫이다.

이런 문서에는 개인정보와 기관 내부 정보가 들어 있어 ChatGPT 같은 외부 상용
서비스에 올릴 수 없다. 그래서 이 프로젝트는 교내 장비(NVIDIA DGX Spark)에서
로컬 LLM으로 같은 일을 하는 시스템을 만든다.

## 2. 목표

에이전트가 업무 문서를 이해해서, 사람이 일일이 검토하지 않아도 되게 만드는
것이 목표다. 문서를 대신 읽고 요약하고, 확인이 필요한 부분을 짚어주고, 초안을
만들어 주는 방식으로 담당자의 의사결정을 돕는다. 시스템이 판단을 대신하는 것이
아니라 판단에 필요한 재료를 갖춰 주는 것이고, 최종 결정은 항상 사람이 한다.

적용 업무는 두 가지로 시작한다.

- 국고사업: 공고를 분석해 요구사항과 배점을 뽑고, 교내 실적 문서에서 근거를
  찾아 계획서 초안을 만든다. 초안의 모든 수치에는 출처가 달리고, 근거가 없는
  수치는 지어내는 대신 빈칸으로 남긴다.
- 채용: 접수 서류를 읽어 학력·경력·자격을 정리하고, 누락 서류나 확인이 필요한
  항목을 짚어 준다. 지원자를 평가하거나 서열화하지 않는다.

같은 파이프라인(문서 반입, 파싱과 OCR, 개인정보 마스킹, 검토와 생성)을 쓰기
때문에 다른 행정 업무로도 넓힐 수 있다.

## 3. 시스템 구성

- 검토 플랫폼(웹 대시보드): 담당자가 문서를 올리고, 에이전트의 검토 의견을
  확인하고, 피드백을 남기는 화면. 업무 섹터(국고사업, 채용, 일반 행정)별 탭으로
  나뉜다. 교내 시스템(LMS)과 같은 디자인 계열로 맞췄다.
- 처리 파이프라인: 문서를 올리면 파싱(스캔본은 OCR), 개인정보 자동 마스킹,
  문서 분류를 거쳐 로컬 LLM이 검토 의견을 만든다. 개인정보는 마스킹된 뒤에야
  모델에 전달된다.
- 피드백 루프: 담당자가 "재검토 요청"에 의견을 남기면 에이전트가 그 의견을
  반영해 다시 검토한다. 이렇게 쌓이는 피드백이 이후 모델 개선(파인튜닝)의
  학습 재료가 된다.
- 검증 장치: 생성된 초안의 수치가 근거 문서에 실제로 있는지 기계적으로 대조하고,
  공고의 배점 항목이 빠짐없이 반영됐는지 검사한다. 예산 계산에는 LLM을 쓰지
  않고 결정론적 로직을 쓴다. 행정 문서에서 잘못된 숫자는 단순 오류가 아니라
  사고이기 때문이다.

## 4. 추진 방식

빠르게 돌아가는 시스템을 먼저 올리고, 그 위에서 점진적으로 고도화한다.

1단계(완료): 기반 구축. 장비 검증, 파서 선정 체계, 개인정보 마스킹, 로컬 모델
서빙, 검토 플랫폼 가동까지. 현재 대시보드가 실제로 동작하며, 문서를 올리면
검토 의견이 나오고 공고에서 계획서 초안이 생성된다.

2단계: 실제 문서 투입. 개인정보 부서 협의를 거쳐 실물 국고사업 문서를 파일럿
범위(계획서 20~30건과 결과보고서)로 처리하고, 검색 인덱스와 실적 카드 DB를
구축한다. 평가 기준선을 이때 측정해 둔다.

3단계: 모델 고도화. 쌓인 문서와 피드백으로 교내 도메인에 맞춘 모델 4종(검색
임베딩, 리랭커, 초안 생성기, 실적 추출기)을 지도 파인튜닝(SFT)하고, 기준선
대비 개선 폭을 측정한다. 베이스는 오픈웨이트 모델(Qwen 계열)을 쓴다.

## 5. 현재까지의 결과 (2026-09-02 기준, 전부 실측)

- DGX Spark(aarch64, GB10) 환경에서 파싱·학습·서빙 스택이 전부 동작함을 확인
- 로컬 LLM 서빙: Qwen3.5-35B-A3B(MoE), 첫 토큰 87ms, 초당 30.8토큰.
  같은 조건에서 소형 dense 모델(Qwen3-4B, 23.0토큰/초)보다 빠르면서 품질은 상위 —
  대역폭 제약 장비에 MoE가 유리하다는 설계 판단을 실측으로 확인
- 기준 문서 저장소: 학칙, 교육부 재정지원사업 매뉴얼, 산학협력단 규정 8종,
  채용공고 등 12건을 582개 조각으로 등록. 검토와 채팅이 해당 조항을 인용해 답변
- 검색 성능(합성 질의 1,737건 기준): 형태소·임베딩 하이브리드가 Recall@1 0.748,
  MRR 0.809 — 네 가지 방식을 비교 측정해 최적 조합을 채택
- 개인정보 마스킹: 주민등록번호·전화·이메일·계좌·사업자번호·성명 6종, 체크섬 검증 포함
- 공고 PDF에서 출처 달린 계획서 초안까지 자동 생성되는 전체 경로 관통
- 검토 플랫폼 웹 대시보드 가동: 업무 섹터별 문서함, 접수번호 체계, 에이전트 채팅
  (파일 첨부 검토·기준 선택), 판정 피드백 루프
- 테스트 97건 자동화, 주요 결정 기록(ADR) 5건 문서화

## 6. 기대 효과

- 계획서 초안 작성 기간 단축 (기존 2주 수준에서 2~3일 목표)
- 채용 서류 정리·확인의 반복 작업 제거
- 사람이 자주 놓치는 배점 항목 누락을 기계가 잡아 주는 품질 향상
- 외부 서비스 없이 교내에서 처리하므로 개인정보 유출 경로 원천 차단
- 문서가 쌓일수록 좋아지는 구조: 처리한 문서와 담당자 피드백이 곧 다음 모델의
  학습 데이터가 된다

## 7. 남은 확인 사항

- 개인정보 부서의 처리 승인 절차와 시점 (실물 문서 투입의 전제)
- 실물 문서 표본 확보 시점 (파서 최종 선정에 필요)
- 문서 열람 등급 체계 확정 (검색 권한 필터에 반영)
