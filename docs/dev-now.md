- 어느 OpenAI 호환 서버든 같은 규약으로 다루도록 호출부를 손봤습니다. 요청 시간 제한과 한도 초과·일시 장애 때의 백오프 재시도를 두고, 응답의 토큰 사용량을 날짜·연결·모델별로 기록해 LLM 연결 카드에 오늘 요청 수와 토큰을 보입니다. 키 거부, 모델 없음, 한도 초과, 서버 일시 불가는 각각 다른 안내로 나옵니다. 특정 기관 허브 전용 항목에는 맞추지 않았습니다.
- 연결마다 모델 목록을 가지고 고르게 했습니다. 허브의 공개 카탈로그나 모델 API 에서 받아 저장하고, 나가는 통신이 막힌 서버는 목록 파일을 올려 씁니다. 수정 창의 모델·비전 모델 칸이 사용 가능 여부가 표시된 선택 상자로 바뀌었습니다.
- 경북 Open AI Service Hub(open.hasa.re.kr, OpenAI 호환 API)를 외부 기관 GPU 서버 연결로 등록했습니다. 개발 키는 화면에서 넣고, 운영 서버의 아웃바운드 개방이 있어야 실제 호출이 됩니다. 텍스트 모델과 문서 이미지 판독용 비전 모델을 따로 지정할 수 있습니다.
- LLM 연결 관리를 넣었습니다. 교내 GPU 서버와 협약 기관의 GPU 서버(발급받은 개발 키)를 등록하고 확인·수정·삭제하며, 키는 서버 파일에만 두고 화면에는 끝 4자리만 보입니다. 상용 클라우드 API 는 쓰지 않습니다. 외부 기관 서버를 문서 작업 기본으로 쓰려면 기관 승인 확인이 필요하고, 외부 AI 참조(민감정보 제거 후 일반 지식 질의)도 외부 기관 서버 연결만 씁니다(ADR-0017).
- 모델 서버와 모델을 화면에서 고를 수 있습니다. 모델 학습 화면의 모델 서버 카드에서 주소를 넣으면 서버의 모델 목록을 받아 선택하고, 저장 즉시 채팅·검토 의견·초안·문서 요약이 같은 설정을 씁니다. 설정이 없으면 환경변수(VLLM_BASE_URL, VLLM_MODEL), 그것도 없으면 서버의 첫 모델을 씁니다.
- 문서 화면의 계획서 초안을 마크다운 렌더(제목·표·굵게)로 보이고, 초안 항목 지정·재작성은 초안 카드 안의 접이식 영역으로 옮겼습니다. 삭제 버튼은 머리 줄 오른쪽으로, 추출 결과 머리의 내려받기 버튼은 줄바꿈되도록 했습니다. 문서 요약·채팅의 실패 문구에서 예외 이름(APIConnectionError)을 없애고 상태 문장으로 바꿨습니다.
- 채팅 화면에서 작업 패널이 열려 있을 때 말풍선이 잘리던 문제(음수 여백)를 고치고, 적용 기준 목록은 8건까지만 보인 뒤 전체 건수 링크로 잇습니다. 로그인·데이터 공방 단계 배지·한글 에이전트 내려받기 버튼을 새 버튼 체계에 맞췄고, 외부 AI 참조 관리의 숫자 타일 8개는 한 줄 칩으로 바꿨습니다.
- 데이터 공방 1단계에 원천별 미리보기를 넣었습니다. 검토 의견·초안·대화 각각 기록 수, 생성 가능한 예시 수, 수치 검증·내용 빈약 탈락 수를 실제 변환기를 돌려 보이고, 첫 예시를 열어 볼 수 있습니다. 문서함의 처리 현황 타일을 누르면 안내 문장 없이 목록만 보입니다.
- 데이터 열람을 문서 중심 탐색기로 다시 만들었습니다. 문서를 고르면 개요, 마스킹 기록(유형·건수), 추출 조각과 검색 단위(임베딩 유무), 지식 그래프 연관을 보고, 규정·국고 코퍼스·채팅 기록은 탭으로 봅니다. 행과 열을 그대로 뿌리던 표는 없앴습니다.
- 논문·설계 문서 목록과 열람 화면, 변경 이력의 가독성을 높였습니다. 목록은 종류별 카드에 상태·날짜, 열람은 본문 폭·행간·목차, 변경 이력은 날짜별 작업 기록과 접이식 커밋 목록입니다.
- 한글 에이전트 화면에 Windows 에서 만든 setup.exe 를 올려 배포하는 기능을 넣었습니다. 확장자·실행 파일 서명·크기를 검사하고, 담당자는 /hwp/setup.exe 에서 내려받습니다.
- 모델 학습 화면을 다시 구성했습니다. 데이터 공방, Label Studio, LLaMA Board, TensorBoard를 같은 크기의 도구 카드로 두고, Label Studio 계정·비밀번호 재설정과 GPU 도구 주소는 각 카드의 설정 창에서 다룹니다. 데이터 공방 진입 버튼은 이 화면에 하나만 남겼습니다.
- 화면 전반의 설명 문장을 핵심만 남기고 줄였습니다. 공통 안내(교내 장비 처리, 개인정보 자동 마스킹)는 화면마다 적지 않고 사이드바 하단 한 줄로 옮겼습니다. 개발 현황의 진행 현황은 최신 날짜 작업만 보이고 전체 작업 기록은 변경 이력에서 봅니다.
- 배포 후 실동작 점검 스크립트를 만들어 화면 22개, 규정 검색 6개 질의, 개인정보 마스킹 자가 점검(19개 항목 통과)과 잔여 검사(0건), Label Studio 연결을 한 번에 확인합니다.
- Label Studio 연결을 스크립트 한 번으로 맺도록 바꿨습니다(접속 키 생성, 서비스 반영, 검증). 토큰을 붙여 넣거나 파일을 주고받는 단계는 없앴습니다.
- 접수번호 규칙을 고쳤습니다. 이전에는 문서를 지우면 번호가 겹칠 수 있었고, 이제는 기존 최대 번호 다음 번호를 씁니다.
- 지식 그래프에 프로젝트 목록과 선택 상세 패널, 검색 결과 목록을 넣었고, 프로젝트와 문서를 의미 유사도로 잇는 추정 연관을 추가했습니다. 프로젝트 이름과 지침이 실제 내용이어야 연관이 잡힙니다.
- 화면 전반의 표현을 다듬었습니다(외부 참조 관문을 외부 AI 참조 관리로, 세척을 민감정보 제거로, 영문 키 노출 제거). 용어집은 docs/notes/ui-glossary.md에 있습니다.
- 개발 현황의 중복 요소를 정리했습니다. 규모 타일은 데이터 열람과 같은 원천을 쓰고, 근거 없는 영역별 퍼센트는 기능 상태에서 계산한 완료 비율로 바꿨습니다.
- 논문 자료 여섯 편의 사실 관계와 수치 출처를 맞췄습니다. 출처가 없는 수치는 지우거나 미확인으로 표시했습니다. 프로젝트 정식 명칭, 팀 구성, 발표 일자, 검색 가중치(0.3 또는 0.4)는 확인이 필요합니다.
- 문서 추출을 고도화했습니다. 표는 평문으로도 저장해 검색과 초안 근거로 쓰이고, 그림 속 글자는 tesseract로 읽으며, 한글 파일(hwp, hwpx)은 표 구조를 살려 읽습니다. 검증 중에 운영 서버에 pyhwp가 없어 한글 접수 문서가 빈 채로 처리되던 문제, 서식 표의 성명·학번이 마스킹되지 않던 문제, 그림 파일 접수가 실패하던 문제를 찾아 고쳤습니다.
- 작성 모델의 베이스가 Qwen3.8-27B dense임을 문서에 맞췄습니다. QLoRA와 DPO는 dense 모델에서 검증된 경로이고, MoE 모델은 예비로만 둡니다.
