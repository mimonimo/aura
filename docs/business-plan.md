## 2. 추진 배경

### 2.1 기관 현황 — 자산은 쌓였지만 쓰이지 못한다

- 국고사업(정부 재정지원 사업) 관련 문서가 **수만 장 규모 PDF**로 파일 서버에 축적되어 있으나, 검색·재활용 수단이 없어 사실상 사장된 자산이다.
- 새 공고가 나올 때마다 담당자가 과거 문서를 수동으로 뒤져 계획서를 처음부터 다시 작성하며, 초안 1건에 **약 2주**가 소요된다.
- 실적 수치·보유 자산·과거 표현이 담당자 개인의 기억과 폴더 구조에 의존한다. **담당자 교체 = 조직 지식 유실**이라는 구조적 위험이 상존한다.
- 계획서 평가에서 가장 흔한 감점 요인인 **배점 항목 누락**을 사람 눈으로 전수 점검하기 어렵다.

### 2.2 전문대학의 재정 구조 — 국고사업 대응력이 곧 경쟁력

학령인구 감소와 등록금 동결 장기화로 전문대학 재정에서 정부 재정지원 사업의 비중은 구조적으로 커지고 있다. 계획서의 질과 작성 속도가 기관 재정에 직결되는 환경에서, 계획서 작성은 더 이상 개인기가 아니라 **기관 차원의 시스템으로 뒷받침해야 할 핵심 역량**이다.

### 2.3 정책·기술 환경 — 지금이 적기인 이유

- **정부가 "행정문서 초안 AI"를 표준화하고 있다**: 2025년 11월 범정부 AI 공통기반이 행정 내부망에서 개시되었고, 양대 공통 기능이 정보 검색과 **행정문서 초안 작성**이다. 2026년 국가 AI 예산은 10.1조 원, 공공기관 경영평가에 AI 가점이 신설되었다. 문서 작성 AI는 실험이 아니라 공공부문의 기본 인프라가 되는 중이다.
- **대학 대상 재원이 열려 있다**: 교육부 'AI·디지털(AID) 전환 중점 전문대학' 사업(2026년 24개교 내외, 교당 최대 10억 원), 과기정통부 AI중심대학(교당 연 30억 원) 등 대학 AI 전환 재정지원이 본격화되었고, 연구개발혁신법 시행령 개정으로 **AI 서비스 비용의 간접비 집행이 허용**(2026.4.)되었다. 본 사업의 성과는 이들 사업 대응의 실증 자료가 된다.
- **기술 성숙**: 문서 파싱(MinerU·Docling), 하이브리드 검색(Qdrant), 구조화 추출(xgrammar), 서빙(vLLM), 한국어 오픈웨이트 모델이 모두 온프레미스에서 실용 수준에 도달했다(Phase 0 검증 완료).
- **하드웨어 보유**: NVIDIA DGX Spark(128GB 통합 메모리)를 개발 1대 + 배치·학습 최대 20대 규모로 활용 가능 — 신규 GPU 서버 투자 없이 구축 단계 전체를 소화할 수 있다.
- **선행 사례 부재의 기회**: Phase 0 조사 결과, 국고사업 계획서 도메인 전체(공고 파싱→근거 인출→검증→예산)를 커버하는 오픈소스·상용 솔루션은 국내외에 존재하지 않는다(`research/01-N-prior-art.md`). 요소 기술을 조립해 도메인 로직만 직접 구현하면 **선점 가능한 영역**이다.

### 3.4 시사점

1. **용도의 수렴**: 국내외 공히 챗봇을 넘어 **문서 초안 작성**(계획서·보고서·조서·심사의견·제안서)이 도입 목적의 중심이 되었다. KIST의 "연구개발계획서 초안"과 범정부의 "행정문서 초안"은 짜이미의 유즈케이스가 이미 공공부문에서 정당성을 확보했음을 보여준다.
2. **보안 요건 = 구축형**: 민감 문서를 다루는 기관(중앙은행·원전·수사·국방·금융)은 예외 없이 폐쇄망 온프레미스 구축을 선택했다. "외부 API 전송 불가"라는 본 사업의 전제는 특수한 제약이 아니라 검증된 표준 패턴이다.
3. **사업 범주의 검증**: "과거 실적 문서로 제안서를 쓰는 AI"는 해외에서 GovDash(수주 $5B)·AutogenAI(시간 70% 단축)가 정량 성과로 입증한 범주다. 짜이미의 목표치(2주→2~3일, 약 75~80% 단축)는 이 범주의 검증된 성과와 정합한다.
4. **선점 가능한 공백**: 국내 대학의 도입은 멀티 LLM SaaS 플랫폼(교육 중심)에 집중되어 있고, **온프레미스 RAG+sLLM으로 국고사업 계획서 초안을 지원하는 대학 사례는 확인되지 않는다**(2026.8. 기준). 전문대학에서는 더욱 그렇다 — 성공 시 확산·선도 위치를 점할 수 있는 공백 영역이다.

## 4. 필요성

### 4.1 왜 해야 하는가 — 문제의 비용

| 문제 | 현재 비용 | 방치 시 |
|---|---|---|
| 초안 작성 2주 소요 | 공고당 담당자 약 10영업일 점유 | 대응 가능 공고 수의 상한 = 기회 손실 |
| 배점 항목 누락 | 감점 → 탈락 위험 | 선정률 하락이 재정에 직결 |
| 실적 수치 수작업 발굴 | 문서 재탐색 반복, 오기재 위험 | **허위 기재 시 사업 취소·환수·제재 사유** |
| 지식의 개인 의존 | 담당자 교체 시 노하우 소실 | 조직 역량이 축적되지 않음 |

### 4.2 왜 자체 구축인가 — 대안 비교

| 대안 | 판정 | 근거 |
|---|---|---|
| 상용 SaaS (ChatGPT·클라우드 AI 등) | **불가** | 문서에 개인정보·기관 내부정보 포함 — 외부 API 전송 원칙적 불가. 배점 대조·출처 추적 등 도메인 기능 부재 |
| 외주 SI 구축 | 부적합 | 도메인 지식(국고사업 문서 구조) 전수 비용 큼, 구축 후 모델 개선 사이클을 내재화할 수 없음, 비용 대비 산출물 통제 어려움 |
| **자체 구축 (오픈소스 조립 + 도메인 로직 직접 구현)** | **채택** | 보안 요건 충족, 보유 하드웨어 활용, 모델·데이터 자산 내재화, Phase 0에서 전 구간 오픈소스 검증 완료 |
| 미도입 (현행 유지) | 배제 | §4.1의 비용 지속 + 축적 문서 자산 계속 사장 |

### 4.3 왜 지금인가

1. 온프레미스에서 실용 품질이 나오는 한국어 오픈웨이트 모델·도구가 2025~2026년에 갖춰졌다 (Phase 0 검증).
2. 구축에 필요한 하드웨어를 이미 보유하고 있다 — 한계비용이 낮다.
3. 보유 문서가 그 자체로 지도학습 데이터셋이다 — 수작업 라벨링 없이 모델 학습 데이터를 확보할 수 있는 드문 조건.
4. 유사 시스템의 국내 대학 선행 사례가 아직 없어(§3.4), 성공 시 성과 확산(타 대학 보급·공동 활용)의 선도 위치를 점할 수 있다.
5. 정책·재원과 정합한다 — 정부가 행정문서 초안 AI를 공통 기반으로 표준화하는 흐름(§2.3) 속에서, 본 사업 성과는 AID 전문대학 사업 등 대학 AI 재정지원 사업 대응의 실증 자료가 된다.

## 5. 기대효과

### 5.1 정량 효과

| 지표 | 현재 | 목표 | 근거·산식 |
|---|---|---|---|
| 계획서 초안 작성 기간 | 약 2주(10영업일) | **2~3일** | 브리프 §2 성공 기준. 건당 **7~8영업일 절감** |
| 배점 항목 반영률 | 사람 점검(누락 상존) | **기계 전수 대조·무누락** | 배점 대조 검증기(직접 구현) |
| 수치 출처 추적성 | 수작업(불완전) | **100% (문서명+페이지)** | 인출 기반 생성 — 근거 없으면 빈칸 처리 |
| 실적 데이터 접근 | 문서 재탐색 | **실적 카드 DB 즉시 질의** | 결과보고서 → 정형 테이블 자동 추출 |
| 연간 절감 인일(가정) | — | **약 70~80 인일/년** | 연 10건 대응 가정 × 건당 7~8일 절감. *실제 건수로 보정 필요* |

**목표치의 외부 근거** — 문서 작성 AI의 검증된 효과: 통제 실험에서 작성 시간 **-40%**·품질 +18%(Noy & Zhang, *Science* 2023), 실기업 현장 실험에서 문서 완료 **-12%**(Microsoft, 6,000명+ RCT, 2025). 범용 도구의 수치가 이 수준이고, **도메인 특화 제안서 AI**는 독립 검증 연구에서 **초안 시간 70% 단축**(AutogenAI, 2025), 국내 금융권 특화 에이전트도 검토 시간 70% 단축(신한은행, 2026)을 보고했다. 짜이미의 목표(2주→2~3일, 75~80%)는 특화 시스템 범주의 검증된 상단에 해당하며, 근거 인출·배점 대조 등 도메인 로직이 그 차이를 만든다.

### 5.2 자산 효과 — 남는 것

- **실적 카드 DB**: 계획서 작성 외에도 성과보고·자체평가·기관인증 대응에 재사용 가능한 정형 실적 자산.
- **모델 가중치 4종**(`ZZAIMY-Embed/-Rerank/-Writer/-Extract`): 모델 카드·평가 보고서·버전 이력을 갖춘 산출물 — 기관의 AI 역량 실증 자료이자 후속 사업의 기반.
- **평가 하네스와 평가셋**: 이후 어떤 모델·도구를 도입하든 재사용되는 측정 인프라.

### 5.3 정성 효과

- 조직 지식의 시스템화 — 담당자 교체에도 실적·표현 자산이 기관에 남는다.
- 담당자의 역할 전환 — 자료 발굴·초벌 작성에서 **전략·차별화·검수**로 시간 재배치.
- 전문대학 AI 자체 구축의 선도 사례 — 대외 성과 발표 및 확산 여지 (표현 지침은 브리프 §7.6 준수: "자체 개발 LLM" 아닌 "오픈웨이트 기반 도메인 특화 모델 개발").

### 5.4 목표가 아닌 것 (기대 관리)

- 사람 검수 없는 제출 완성본 자동 생성은 목표가 아니다 — 목표는 **70% 초안**이며 최종 품질 책임은 담당자에게 있다.
- 도입 즉시 전 문서 처리가 아니라 **파일럿(계획서 20~30건) → 전체 확산**의 단계적 접근이다.

### 7.1 인력 계획

- 총 전담 환산 약 **1.5~2.5 FTE × 10개월**. AI 페어 프로그래밍(코드 생성·리서치 자동화)을 전제로 한 최소 편성이며, 도메인 로직 외 전 구간을 오픈소스 조립으로 해결하는 설계(브리프 §5.1)가 이를 뒷받침한다.
- 실적 카드 **사람 검수**가 인력 계획의 실질 병목 — **학생 인력 투입으로 검수 규모를 수백 → 수천 건으로 확장**하여 배포 전 학습 데이터 품질을 극대화한다(research/51). 학생 과업은 정답이 있는 원문 대조 판정에 한정하고, 문체·논리 우열 판정은 기계 검증기 1차 → 학생 다수결 → 담당자 표본 검수의 3단 구조로만 수행한다. 골든 문항·라벨러 간 일치도 측정으로 라벨 품질을 상시 관리한다.
- **학생 문서 접근(확정, 2026-08-23)**: 학생에게는 **Presidio 비식별화 처리를 통과한 문서만 노출**한다. 문서 열람 등급 체계 자체(미해결 질문 #7)는 별도 확정 필요.

## 10. 후속 확장 계획 (본 사업 이후)

> 아래 두 트랙은 **본 사업(P0~P7) 범위에 포함되지 않으며**, 각각 별도 기획·승인으로 착수한다. 본 사업의 산출물이 어디로 이어지는지를 보이기 위한 방향 제시다.

### 10.1 에이전트화 — 파이프라인에서 에이전트로

본 사업의 생성 루프는 고정 순서 파이프라인이다. 후속 트랙에서는 담당자가 개방형 질의(예: "이 공고, 우리가 대응할 만한가?")를 던지면 모델이 필요한 도구를 스스로 골라 호출하는 **에이전트 구조**로 전환한다.

- **베이스 모델 전략**: 에이전트 오케스트레이터는 툴콜 능력을 보유한 베이스 모델(Qwen3.5-35B-A3B)이 담당하고, ZZAIMY-* LoRA는 vLLM 동적 로딩으로 작성 작업일 때만 얹는다. 좁게 특화된 Writer를 에이전트 베이스로 쓰지 않는다 — **특화 모델은 도구, 범용 베이스는 조율자**.
- **도구 집합은 이미 만들어져 있다**: P3~P4 산출물인 실적 카드 DB 질의, 하이브리드 검색, 배점 대조 검증기, 예산 계산기가 그대로 에이전트의 도구(tool)가 된다. 도구 인터페이스는 MCP(Model Context Protocol) 등 표준 규격으로 정의해 재사용성을 확보한다.
- **추가로 필요한 것**: ① 도구 호출 궤적(trajectory) 학습·평가 데이터 구축 ② 태스크 성공률 기준의 에이전트 평가셋 ③ 가드레일 — "수치는 인출만 한다"(브리프 5.3)를 에이전트의 자율 행동에서도 구조 수준에서 강제.
- **가능해지는 것**: 공고 대응 가능성 사전 진단(검색→실적 대조→갭 분석 자율 수행), 신규 공고 모니터링·마감 알림, 복수 부서 실적을 교차 조합한 대응 시나리오 비교.

### 10.2 학사 DB 연계 — 학생 학습·학사행정 지원으로 확장

같은 스택(파싱·검색·검증·서빙)과 모델 자산을 학사 도메인으로 전이한다. §3에서 확인했듯 국내 대학 AI 도입의 주류가 학사·행정 지원이므로, 국고사업 도메인에서 검증한 시스템을 교내 수요가 가장 큰 영역으로 확장하는 순서다.

- **연계 대상**: 학사 DB(학적·수강·성적·비교과·상담 이력)와 학칙·규정·요람. 정형 DB 연계는 RAG가 아니라 **도구 호출(Text-to-SQL/API)** 방식으로 — "수치는 생성하지 않고 인출한다" 원칙을 학점·성적 수치에 동일하게 적용한다.
- **유즈케이스(학생)**: 졸업요건 자동 진단(이수 내역 대조, 부족 학점·요건 명시), 수강 및 비교과 프로그램 추천(실적 카드 DB의 국고사업 프로그램과 직접 연계 — 두 트랙이 만나는 지점), 학칙·규정 질의응답(근거 조항 링크, 서울대 학칙 챗봇 사례와 동형).
- **유즈케이스(행정)**: 학사 공문·안내문 초안, 상담 기록 요약, 학사경고 위험군 조기 파악의 근거 자료 생성.
- **재사용 자산**: ZZAIMY-Embed/-Rerank(교내 문서 도메인이라 상당 부분 전이 가능), PII 파이프라인(학생 개인정보 취급으로 더욱 필수), 평가 하네스, 검증기 패턴, vLLM 서빙 인프라.
- **새로 요구되는 것(선행 조건)**: 학생 개인정보는 실적 문서보다 민감도가 높다 — **본인 데이터만 접근하는 인증·세션 권한 설계**(NFR-02의 확장), 교육기관 개인정보보호 가이드라인 준수, 학사 DB 소관 부서와의 데이터 거버넌스 합의가 착수 전 필수다.
- **재원 정합성**: 교육부 AID 전문대학 사업의 "AI 기반 학생지원체계 구축"(§2.3)과 직접 맞닿는다 — 본 사업 성과가 이 확장의 신청 근거가 된다.
- **시기(안)**: 본 사업 P4 성과 확인 후 별도 기획 착수(2027년 상반기), P7 운영 이관과 병행해 학사 트랙 파일럿 범위 검토.

## 11. 결론

이 사업은 새 지출을 최소화하면서(기보유 하드웨어 + 오픈소스 + 소수 전담 인력) 기관의 사장된 문서 자산을 재정 성과로 직결되는 시스템으로 전환하는 투자다. 위험은 단계별 승인 게이트와 파일럿 우선 접근으로 통제되며, 산출물(시스템 + 모델 4종 + 실적 DB)은 사업 종료 후에도 기관에 남는 자산이자, 에이전트화와 학사 지원 확장(§10)으로 이어지는 기반이다.
