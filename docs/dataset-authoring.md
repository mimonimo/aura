# 실문서 문답의 반복 가능한 검증

문답 생성량이 품질을 보장하지 않는다. 새 반입 자료에서도 같은 검증 절차를 적용하되,
문서 분류·목차 복원·표 해석·정답의 의미 정확성은 원문을 읽어 확인한다.
현재 공통 모듈은 `dataset/authoring.py`, 게시 어댑터는 `scripts/publish_authored_qa.py`다.
DB·SSH·Label Studio 없는 환경에서도 원문 조회 함수를 주입해 같은 검사를 사용할 수 있다.

## 문서 세트 등록

사업명을 코드에 고정하지 않는다. 개인정보 없는 manifest에 사업 ID와 표시명,
사용할 문서 ID 목록을 명시한다. 사업 ID는 동일 사업·문서 계열 내에서 유지하며,
이름이 같은 다른 사업이나 다른 학습/평가 그룹에 재사용하지 않는다.
기존 이름 해시 방식의 사업 ID는 마이그레이션 없이 임의로 새 ID로 바꾸지 않는다.
manifest는 권한 부여 수단이 아니다. 원문 조회 어댑터가 기존 문서 접근 권한을 지켜야 한다.

```json
{
  "program_id": "example-program-2026",
  "program": "예시 사업",
  "document_ids": [1, 3],
  "node_paths": [["사업계획서", "사업 개요"], ["사업계획서", "추진 계획"]]
}
```

`node_paths`는 실제 문서에서 확인한 경로만 넣는다. 아직 복원하지 못했다면 생략한다.
생략 시 목차 대조 상태는 미확인, 미포함 노드 목록은 null로 보고한다. 후보의 경로를
그대로 복사해 목차 전체라고 등록해서는 안 된다. 원문에서 빠진 항목이나 미판독 표도
별도 보류 기록으로 관리해야 한다. 현재 모듈은 목차를 자동 복원하지 않는다.

## 게시 전 검사

1. 문답 ID·필수 필드·근거 참조의 형식과 중복을 검사한다.
2. 사업 ID, 허용 문서 범위와 등록 목차 경로를 대조한다.
3. 원문 조각을 조회한다. 누락/빈 근거는 게시를 중단한다.
4. 부모 문답·대화 순환을 검사하고 실제 이전 질문·답변으로 이력을 만든다.
5. 학습 사본 전체의 개인정보와 답변 수치를 점검한다. 수치는 현재 및 앞선 대화의
   근거만 사용하며 다른 문답의 근거를 빌려 통과시키지 않는다.
6. 부모가 보류되면 후속 질문도 보류한다. 자동 검사 통과는 의미 검수 승인이 아니다.
7. 문답 없는 문서와 등록 목차 중 미포함 경로를 보고한다. 단순 참조 횟수는 전체 내용
   커버리지나 정답률이 아니다.
8. 단독 질문에 사업명 또는 manifest의 검증된 `program_aliases`가 없으면 보류한다.
   '수치는 얼마야?', '계획서는 어떻게 작성해야 해?'처럼 지표/범위가 없는 표현도
   보류한다. 이는 제한된 표현 검사이며 통과가 의미 명확성을 보장하지 않는다.
   부모가 보류되면 후속도 보류한다. 기존 질문·검수본은 자동으로 고쳐 쓰지 않는다.

구조 단계 생성기 `scripts/153_build_tree_cot.py`는 이제 `--program-id program:...`,
`--program`, `--form`, `--done`, `--notice`, `--basic`, `--manual`을 모두 명시해야 한다.
원문에서 확인된 연차는 `--program-year`로 전달하며 미확인 시 생략한다. 공유 사업
카드의 ID를 사용하되 이것만으로 문서 분류가 검증되었다고 보지 않는다.
출력은 실행별 새 폴더에 기록하며 `--replace`로 기존 검수를 삭제하는 옵션은 제거했다.
기본 실행은 후보 파일만 생성하고 `--push`를 지정해야 검수 도구에 게시한다.
같은 절 제목이 반복되어 완성본 대응이 모호하면 뼈대 문답을 만들지 않는다.
이 생성기는 구조 문답 후보용이며 실제 도구 실행·근거 선택 학습본과 구분한다.

```sh
.venv/bin/python scripts/publish_authored_qa.py data/training/candidates.json --manifest data/training/manifest.json --author Codex --dry-run
```

위 명령은 운영 원문을 읽지만 게시·파일 생성은 하지 않는다. 보류 건이 있으면 종료 코드2.
검사 결과를 검토한 뒤 `--dry-run`을 빼서 후보를 게시한다. 사업 정보 없이 게시하는 옛
호출법은 더 이상 허용하지 않는다. 기존 태스크를 덮어써 사업 정보를 소급 변경하지 않는다.

## 의미 검수와 수정

검수자는 질문에 필요한 범위, 사실/예시/계획/완료 실적의 구분, 조건·예외·주체,
목차 이동, 원문 버전 간 충돌을 확인한다. 제출 시각처럼 문서끼리 충돌한 값은 원본과
후속 정정 근거를 확인하기 전 확정하지 않는다. 추출 편집 메모와 표 병합 오류도 보류 사유다.

AI 검수는 작성자·검수 주체·자기검수 여부·범위·근거/내용 해시·판정을 별도로 기록한다.
사람 주석을 대신 만들어 넣지 않는다. 같은 모델의 자기검수는 독립 검증과 다르다.
질문·답·근거·경로·이력이 달라지면 이전 내용 해시의 검수 결과를 재사용하지 않는다.

수정 시 새 ID와 `revision_of`를 사용하고 후속 질문도 새 부모에 연결한다. 기존 태스크와
주석을 보존하며 대체된 원본에는 `superseded_by`를 남긴다. 변환기는 구버전 및 구버전을
부모로 삼은 문답을 학습 반출에서 제외한다. 새 버전의 자동 학습 승인은 하지 않는다.

## DGX 실문서 확장 순서 (2026-10-01 작업 기준)

사업별 독립 분석이 우선이다. AID를 기본 대상이나 정답 기준으로 두지 않는다.
각 사업의 목적·대상·기간/연차·자체 공고/평가 기준·계획·실적·평가 의견을 먼저
분석한다. 사업 간 연결은 관계 근거와 적용 범위·차이를 확인한 뒤 필요한 질문에서만
수행한다. 모든 사업을 AID와 비교하거나 AID 계획서 작성을 최종 목적으로 삼지 않는다.
사업이 미확정이면 임의 사업으로 폴백하지 않는다. 독립 사업 질의, 동일 사업 연차
비교, 관계 근거가 있는 사업 간 질의, 연결할 근거가 없는 사례를 각각 평가한다.
평가에는 AID가 등장하지 않는 사업 조합도 포함한다.

여러 사업의 승인 데이터를 함께 SFT하는 것이 전제다. 사업별 파일 분리만으로 맥락이
보존된다고 보지 않는다. 모델이 읽는 입력에는 사업·연차·대상 문서·작업 목적과 필요한
원문 근거를, 출력에는 적용 범위·근거에 따른 결과·출처·불확실성을 담는다.
후속 질문은 앞 대화와 함께 구성하며 단독으로 떼어낼 때는 필요한 맥락을 복원한다.
검수용 메타데이터에만 사업이 있거나 질문과 답의 사업·연차가 다르면 보류한다.

수신 완료와 학습 승인을 구분한다. rclone 전송 중 원본을 대상으로 생성/학습하지 않는다.
전송 종료 상태와 원본 목록·크기·가능한 체크섬 대조를 확인한 파일을 별도 manifest로
고정한다. 실패·부분 수신·암호화·추출 실패는 보류하며 원본은 변경하지 않는다.

Claude의 사업 카드/처리본/그래프를 입력으로 사용한다(ADR-0047, 제안 ADR-0048).
폴더 이름만으로 사업을 확정하지 않는다. 사업 ID·명칭·연차·문서 종류·판본·절 ID·
근거 위치와 원문 해시가 일치해야 후보 생성 대상이 된다. 사업 ID 규칙은 Claude와
확정할 때까지 기존 키를 유지한다. 같은 사업의 연차와 다른 사업을 혼동하지 않는다.

단독 질문에는 사업·연차·문서 종류·목차 위치를 명시한다. 맥락이 실제 앞 대화에
있을 때만 후속 질문의 생략을 허용한다. 모르는 연차·기관·관계는 추측하지 않는다.
후보 유형은 직접 근거 질의, 동일 사업 연차 비교, 계획 목표/완료 실적 구분,
평가 의견의 개선 요구, 명시적 사업 간 실적 참고, 근거 부족/충돌로 보류로 나눈다.
다른 사업의 실적은 참고할 수 있지만 그 사업의 평가 기준을 현재 사업에 적용하지 않는다.

CoT는 설명 길이나 단계 수를 품질 지표로 삼지 않는다. 질문 범위, 실제 도구 호출과
반환 근거 ID, 선택/제외 자료의 짧은 사유, 구성한 컨텍스트, 출처가 붙은 답을 검수한다.
실행하지 않은 그래프 탐색을 실행 기록처럼 만들지 않는다. 서빙 도구 스키마와
학습 스키마가 일치하기 전에는 기존 단계 문답을 도구 학습본으로 재포장하지 않는다.

질문 생성 전에 원문 중복·판본·연계 계획서/보고서를 하나의 분리 그룹으로 묶어
학습/평가를 배정한다. 같은 문서의 다른 절, 표현을 바꾼 질문, 파생 후보가 양쪽에
걸치지 않도록 한다. 사업 간 질문은 참조하는 모든 그룹이 같은 분할이어야 한다.
평가에는 관련 없는 사업 기준을 검색 후보에 섞어도 제외하는지 검사하는 사례를 포함한다.
원문 사실·단위·연차·조건·근거 정합성, 개인정보, 독립 검수, 분할 누수 검사를 거친
후에만 승인한다. 후보 증가·AI 자기검수는 승인이나 학습 완료가 아니다.

우선 AID와 LINC3.0 파일럿에서 근거 오선택·잘못된 사업 귀속·보류 판단·절별 누락을
측정하고 보강한다. 전량 다운로드 후 일괄 학습하지 않는다. 이 절은 작업 계약이며
전송 검증/그래프 연동/자동 분할 구현 완료를 뜻하지 않는다.

## 근거 선택 후보 검사 (오프라인)

`scripts/audit_retrieval_cases.py 후보.jsonl`은 사업·연차별 근거 선택과 제외를
검사한다. 사용자 원문 `question`과 범위를 명확히 한 `resolved_question`을 함께
보존한다. 후보 절은 `doc:<id>:sec:<경로>` ID와 사업·문서 종류·본문을 가지며,
`source_hash`는 정규화하지 않은 발췌 본문의 UTF-8 SHA-256이다. 문서 전체 해시와
혼동하지 않는다. 해시 일치는 진위를 증명하지 않으므로 실제 절/본문 대조도 필요하다.

선택 근거는 적용 기준, 대상 사실, 참고 사례로 구분한다. 타 사업 자료는 명시적으로
허용한 참고 사례로만 선택할 수 있다. 연차 범위가 지정되면 적용 기준/대상 사실도
해당 연차와 맞아야 한다. 모든 후보에 선택 또는 제외 사유를 남긴다. 근거가 없으면
`clarify` 또는 `retrieve_more`와 다음 행동을 기록하며 정답을 만들지 않는다.

`--export-gold 새파일.jsonl`은 독립 검수·원문 대조·승인 내용 해시가 기록된
답변 가능 사례만 내보낸다. 한 건이라도 보류면 출력하지 않으며 기존 파일을 덮어쓰지
않는다. 질문/근거/선택이 바뀌면 재검수가 필요하다. 검수 메타데이터는 선언 값이며
검수자 인증을 대신하지 않는다. 현재는 검사용 경로이고 운영 검색·SFT 자동 연결이나
실문서 정답 세트의 독립 검수 완료를 의미하지 않는다.

## 실제 대화와 학습의 컨텍스트 계약 (구현·Claude 연동 대기)

사용자 원문 질문은 보존한다. 짧은 질문을 모델이 이해하도록 명확화한 질의는
별도 필드로 둔다. 질문 접두어만 보강한 데이터를 학습해 모호한 실사용 입력도
자동 해결했다고 평가하지 않는다. 학습 사례에 원문 질문, 앞 대화 상태,
해결된 사업/연차/문서 범위, 필요한 검색, 선택·제외 근거를 함께 포함한다.

대화 상태에는 현재 사업 ID·비교 사업 ID·연차·대상 문서/절·사용자 정정·작업 목적·
미해결 질문·실행 결과를 둔다. 사업 전환 시 이전 사업의 기준을 자동 승계하지 않는다.
관련 사업 실적 참고와 해당 사업에 적용되는 평가 기준은 별도 관계로 관리한다.
범위를 확정할 수 없고 잘못 실행할 위험이 있으면 한 가지 확인 질문을 한다.

각 반복은 의도/범위 결정 → 권한 있는 그래프·문서 검색 → 근거 선택 → 예산 안에
컨텍스트 구성 → 답변/도구 실행 → 결과 검증 → 상태 갱신이다. 입력 예산은 실제
모델 한도에서 시스템 지시·도구 스키마·출력·여유분을 뺀 토큰 수로 계산한다.
초과하기 전에 중복/무관 후보 제거, 먼 대화 요약, 선택 절 요약을 수행한다.
사업 ID·연차·수치/단위/조건·근거 ID/판본·사용자 정정·미해결 충돌·권한은
요약 중 보존한다. 요약은 검색의 길잡이이며 원문 근거를 대체하지 않는다.
최종 수치나 문서 수정 전에는 필요한 원문을 다시 조회한다. 반복 횟수·도구 호출
예산과 무진전 중단 조건을 두고, 압축 뒤 같은 변경을 중복 실행하지 않는다.

회귀 사례: '그 수치는?'의 지표/연차 특정, 사업 전환, 과거 동일 사업 판본 대조,
장문 대화 압축 후 단위/출처/정정 보존, 관련 없는 평가 기준 제외, 접근 불가
근거 제외, 검색 결과 없음, 압축 후 실행 중복 방지. 학습 전 베이스라인과 같은
사례로 비교하며 단순 질문/답 일치뿐 아니라 근거 선택과 실행 결과를 평가한다.

## 미완료 항목

새 사업 실물로 일반화 성능을 측정해야 한다. 자동 검사만으로 같은 답변 품질을 보장할 수 없다.
현재 원본 렌더 대조, 반입 단계의 목차 자동 복원, 문서 전체 커버리지, 독립 검수,
사업 계열 단위 학습/평가 분리와 학습 전 베이스라인은 별도 완료 조건이다.
