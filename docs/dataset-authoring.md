# 실문서 문답의 반복 가능한 검증

문답 생성량이 품질을 보장하지 않는다. 새 반입 자료에서도 같은 검증 절차를 적용하되,
문서 분류·목차 복원·표 해석·정답의 의미 정확성은 원문을 읽어 확인한다.
현재 공통 모듈은 `dataset/authoring.py`, 게시 어댑터는 `scripts/publish_authored_qa.py`다.
DB·SSH·Label Studio 없는 환경에서도 원문 조회 함수를 주입해 같은 검사를 사용할 수 있다.

## 문서 세트 등록

사업명을 코드에 고정하지 않는다. 개인정보 없는 manifest에 사업 ID와 표시명,
사용할 문서 ID 목록을 명시한다. 사업 ID는 동일 사업·문서 계열 내에서 유지하며,
이름이 같은 다른 사업이나 다른 학습/평가 그룹에 재사용하지 않는다.
기존 이름 해시 방식의 사업 ID는 마이그레이션 없이 임의로 새 ID로 바꾸지 않는다.
manifest는 권한 부여 수단이 아니다. 원문 조회 어댑터가 기존 문서 접근 권한을 지켜야 한다.

```json
{
  "program_id": "example-program-2026",
  "program": "예시 사업",
  "document_ids": [1, 3],
  "node_paths": [["사업계획서", "사업 개요"], ["사업계획서", "추진 계획"]]
}
```

`node_paths`는 실제 문서에서 확인한 경로만 넣는다. 아직 복원하지 못했다면 생략한다.
생략 시 목차 대조 상태는 미확인, 미포함 노드 목록은 null로 보고한다. 후보의 경로를
그대로 복사해 목차 전체라고 등록해서는 안 된다. 원문에서 빠진 항목이나 미판독 표도
별도 보류 기록으로 관리해야 한다. 현재 모듈은 목차를 자동 복원하지 않는다.

## 게시 전 검사

1. 문답 ID·필수 필드·근거 참조의 형식과 중복을 검사한다.
2. 사업 ID, 허용 문서 범위와 등록 목차 경로를 대조한다.
3. 원문 조각을 조회한다. 누락/빈 근거는 게시를 중단한다.
4. 부모 문답·대화 순환을 검사하고 실제 이전 질문·답변으로 이력을 만든다.
5. 학습 사본 전체의 개인정보와 답변 수치를 점검한다. 수치는 현재 및 앞선 대화의
   근거만 사용하며 다른 문답의 근거를 빌려 통과시키지 않는다.
6. 부모가 보류되면 후속 질문도 보류한다. 자동 검사 통과는 의미 검수 승인이 아니다.
7. 문답 없는 문서와 등록 목차 중 미포함 경로를 보고한다. 단순 참조 횟수는 전체 내용
   커버리지나 정답률이 아니다.

```sh
.venv/bin/python scripts/publish_authored_qa.py data/training/candidates.json --manifest data/training/manifest.json --author Codex --dry-run
```

위 명령은 운영 원문을 읽지만 게시·파일 생성은 하지 않는다. 보류 건이 있으면 종료 코드2.
검사 결과를 검토한 뒤 `--dry-run`을 빼서 후보를 게시한다. 사업 정보 없이 게시하는 옛
호출법은 더 이상 허용하지 않는다. 기존 태스크를 덮어써 사업 정보를 소급 변경하지 않는다.

## 의미 검수와 수정

검수자는 질문에 필요한 범위, 사실/예시/계획/완료 실적의 구분, 조건·예외·주체,
목차 이동, 원문 버전 간 충돌을 확인한다. 제출 시각처럼 문서끼리 충돌한 값은 원본과
후속 정정 근거를 확인하기 전 확정하지 않는다. 추출 편집 메모와 표 병합 오류도 보류 사유다.

AI 검수는 작성자·검수 주체·자기검수 여부·범위·근거/내용 해시·판정을 별도로 기록한다.
사람 주석을 대신 만들어 넣지 않는다. 같은 모델의 자기검수는 독립 검증과 다르다.
질문·답·근거·경로·이력이 달라지면 이전 내용 해시의 검수 결과를 재사용하지 않는다.

수정 시 새 ID와 `revision_of`를 사용하고 후속 질문도 새 부모에 연결한다. 기존 태스크와
주석을 보존하며 대체된 원본에는 `superseded_by`를 남긴다. 변환기는 구버전 및 구버전을
부모로 삼은 문답을 학습 반출에서 제외한다. 새 버전의 자동 학습 승인은 하지 않는다.

## 아직 남은 검증

새 사업 실물로 일반화 성능을 측정해야 한다. 자동 검사만으로 같은 답변 품질을 보장할 수 없다.
현재 원본 렌더 대조, 반입 단계의 목차 자동 복원, 문서 전체 커버리지, 독립 검수,
사업 계열 단위 학습/평가 분리와 학습 전 베이스라인은 별도 완료 조건이다.
