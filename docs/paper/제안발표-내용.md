## 슬라이드 4 — STEP 2 · 프로젝트 문제기술 / 추진배경

### 현재 상황
영남이공대학교에는 국고사업 관련 문서가 **수만 장 규모의 PDF**로 축적돼 있으나,
파일 서버에 쌓여만 있고 활용 수단이 없다. 새 공고가 나올 때마다 담당자가 과거
문서를 **손으로 뒤져** 사업계획서를 백지에서 다시 작성한다 (공고당 약 **2주** 소요).

### 왜 단순 검색 문제가 아닌가 — 네 가지 난점
- **입력** — 문서 형태가 제각각(디지털 PDF·스캔본·사진·한글). 읽어 들이는 단계부터 정확도가 무너진다.
- **검색** — 방대해서 필요한 실적이 어느 문서 몇 쪽에 있는지 사람이 다 기억할 수 없다.
- **신뢰** — 근거 없는 수치(환각)가 들어가면 **허위 기재로 사업 취소·환수** 사유가 된다.
- **언어** — "학사운영지원", "성과관리 지표" 같은 도메인 용어를 범용 AI는 이해하지 못한다.

### 핵심 통찰
보유 문서는 그 자체로 **학습 데이터셋**이다. 과거 계획서 = "요구사항 → 완성 섹션"의
정답 쌍, 결과보고서 = "PDF → 실적 데이터"의 정답 쌍. **사람 라벨링 없이** 모델 학습
데이터를 확보할 수 있다.

## 슬라이드 5 — STEP 3 · 프로젝트 기대효과

- **효율성** — 계획서 초안 작성 시간을 **2주 → 2~3일**로 단축 (목표). 담당자를 대체하지 않고 가속하는 "70% 초안".
- **신뢰성** — 모든 정량 수치가 실제 보유 문서에서 인출되며 **출처(문서명·페이지) 추적** 가능. 환각 차단.
- **실용성** — 데모가 아니라 실제 교내 행정에 활용하는 온프레미스 시스템. 개인정보는 인덱싱 전 마스킹.
- **학술 성과** — 오픈웨이트 기반 도메인 특화 모델을 개발하고 **베이스 대비 개선폭을 정량 입증**(모델 카드·평가 보고서·논문).

## 슬라이드 7 — STEP 4 · 프로젝트 범위 (기술 설명)

- **OCR / 문서 추출** — PDF·스캔·사진·한글을 텍스트와 표로 변환. 인식 영역을 신뢰도 색으로 시각화하고, 디지털 PDF의 정답 좌표와 대조해 인식률을 정량 개선.
- **하이브리드 검색 + 리랭킹** — 의미 기반(임베딩)과 키워드 기반을 결합하고, 리랭커로 상위 결과를 재정렬. 공고 요구에 맞는 실적 근거를 정확히 인출.
- **섹션별 생성 + 검증** — 통짜로 만들지 않고 배점 항목별로 근거를 넣어 작성. 세 검증기가 수치·배점·예산을 점검.
- **도메인 특화 모델 4종** — 범용 오픈웨이트 모델을 국고사업 문서 도메인에 적응. 지식(수치)은 학습하지 않고 능력(문체·구조)만 학습, 지식은 검색으로 공급.

## 슬라이드 8 — STEP 4 · 프로젝트 흐름도

```
공고문(PDF) 입력 + 방향 지정
        │
        ▼
① 추출·OCR ──► 텍스트·표 추출, 개인정보 마스킹(인덱싱 전)
        │
        ▼
② 검색 ──► 하이브리드 검색 + 리랭킹으로 실적 근거 인출
        │
        ▼
③ 섹션 생성 ──► 배점 항목별 초안 작성 (수치는 인출된 것만)
        │
        ▼
④ 검증 ──► 수치 대조 · 배점 커버리지 · 예산 검산
        │
        ▼
계획서 초안(70%) + 출처 추적  →  담당자 검수
```
