# 중간 발표 PPT 자료 모음

2026-10-18 기준. 앞쪽 「플랫폼 기능 전체 지도」로 무엇을 만들었는지 한 장씩 잡고, 뒤쪽은 중간 발표자료 절 순서대로 장마다 넣을 수치·표·화면이다.
수치는 「어디서」 화면에서 그대로 읽은 값이고, 화면 캡처는 발표 자료 폴더(화면)에 번호 붙은 파일로 있다. 설명 문장은 구현 설명서(같은 화면)를 따른다.

## 발표 핵심 다섯 — PPT 의 뼈대

한 문장: 학교 문서 3.5만 건을 교내에서 데이터로 만들고, 그래프로 범위를 좁혀 근거를 정확히 찾아(정답 18% → 70%), 지어내지 않는 답과 문서 초안을 만드는 행정 에이전트.

| 축 | 메시지 | 대표 수치 | 대표 화면 |
|---|---|---|---|
| ① 데이터화 | 학교 문서 전체를 교내 장비에서 검색되는 데이터로 | 학교 원본 205,011 → 등록 문서 35,456, 조각 185만(10-25) | `16` `14` `02` |
| ② 정확한 근거 찾기 | 질문을 이해해 범위부터 좁혀 찾는 GraphRAG | 정답 문서 상위 5 안 18% → 70%, 답 점수 0.36 → 0.92 | `08` `06` `05` |
| ③ 지어내지 않는 답 | 모든 답에 출처, 근거에 없는 숫자는 표시 | 근거 밖 숫자가 든 답 2/10 → 0 | `04` `20` |
| ④ 문서를 함께 쓰는 에이전트 | 양식 → 절마다 근거로 쓰기 → 모르는 값 묻기 → 한글 양식에 | 공통 양식 5 + 사업별 47 | `11` `12` `13` `21` |
| ⑤ 속도와 학습 준비 | 실사용 속도, 학교 문서로 배울 데이터 | 답 134초 → 16.6초, 학습셋 4,434(보완 중) | `19` |

중간 발표자료는 정해진 8개 절 순서를 지키되 각 절 안을 이 다섯 축으로 채웠다(1절에 다섯 목표, 3절 축별 진행, 4절 축마다 한 장, 5·6절 축 표시). 아래 기능 지도·흐름은 이 다섯을 받치는 자료다.

## 흐름 두 장 — 답 하나, 문서 하나가 나오기까지

임베딩·리랭커 같은 부품은 아래 흐름의 한 칸이다. 발표에서는 흐름을 먼저 보이고 부품은 그 칸을 짚으며 설명한다(구현 설명서 4.4·4.5절).

### 답 흐름

| 단계 | 하는 일 | 왜 필요한가 |
|---|---|---|
| 0. 미리 준비 | 원본을 읽고(OCR·한글·표) 개인정보를 가린 뒤 조각으로 나눠 낱말 색인·임베딩 색인 | 찾을 대상 만들기 |
| 1. 질문 읽기(GraphRAG) | 27B 가 질문에서 어느 사업·연차·서류인지 읽음 | 비슷한 문서가 수만 건 — 범위부터 |
| 2. 범위 좁히기 | 지식그래프로 그 사업·연차 문서만, 계정 열람 범위(공통·부서·학생) 밖은 뺌 | 엉뚱한 해·다른 부서 문서 배제 |
| 3. 후보 찾기(하이브리드) | 낱말 색인 + 임베딩으로 후보 수십 개 | 낱말이 맞는 것과 뜻이 맞는 것을 함께 |
| 4. 다시 줄 세우기(리랭커) | 후보를 질문과 하나씩 맞대어 순서를 다시(규정 검색) | 상위 몇 개의 정확도 |
| 5. 판본 정리 | 같은 문서의 여러 판은 하나만 | 같은 내용이 근거 칸을 다 차지하지 않게 |
| 6. 답 쓰기 | 27B 가 근거 조각만 보고 답, 출처 붙임 | 지어내지 않게 |
| 7. 숫자 검사 | 근거에 없는 숫자에 「(근거 확인 필요)」 | 허위 수치 방지 |
| 8. 기록 | 모델·시간·근거·단계 기록, 담당자 평가 | 다음 개선·학습 재료 |

효과 수치: 1~2단계 — 특정 문서를 묻는 질문에서 정답 문서 상위 5건 안 18% → 70% · 7단계 — 근거 밖 숫자가 든 답 2/10 → 0.

- 대화 목록·사용자 계정처럼 개인 이름이 보이는 화면은 쓰지 않는다
- 숫자는 화면에서 마우스를 올리면 무엇을 셌는지 나온다 — 질문이 나오면 그 설명을 그대로 읽으면 된다
