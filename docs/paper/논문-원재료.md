# 논문 원재료 정리

국문 논문 작성 시 이 문서만 보고 본문을 구성할 수 있도록 핵심만 적는다.
모든 수치는 실측이며, 리허설·미확인은 그렇게 표기한다. 상세 근거는 각 ADR·리포트 참조.

제목 후보: 온프레미스 sLLM 기반 대학 행정문서 처리 플랫폼의 설계와 도메인 특화 개선

## 1. 연구 목표

- 대학 행정문서(국고사업·채용·입학)를 교외 반출 없이 처리하는 온프레미스 AI 플랫폼 구축
- 핵심 주장 두 축
  - 축 A: 문서 반입→추출→검색→검토·작성에 이르는 전 경로의 실사용 수준 구현
  - 축 B: 오픈웨이트 모델의 도메인 특화 개선(베이스라인 대비 개선폭을 수치로 입증)
- 제약: 개인정보 문서라 외부 API 사용 불가. 장비는 DGX Spark 1대
  (aarch64, Blackwell sm_121, 통합메모리 128GB)

## 2. 시스템 구성 (무엇을 만들었나)

- 서빙: vLLM nightly(다이제스트 고정) + Qwen3.5-35B-A3B(MoE, bf16)
  - 실측 첫 토큰 87ms, 30.8 tok/s. 동일 조건 dense 4B(23.0 tok/s)보다 빠름
    → 대역폭 제약 장비에서 MoE가 유리함을 실측으로 확인 (ADR-0004)
  - v0.11.0은 sm_121a ptxas 미지원, FP8은 cutlass 오류 — nightly bf16으로 확정
- 플랫폼: FastAPI + SQLite + 서버사이드 템플릿. 업무 영역(국고사업·채용·입학·일반)
  → 프로젝트(사업·공고·학년도 단위) → 문서 접수·검토·판정·초안의 계층 구조
- 데이터 계약: doc_chunks(제목/문단/표JSON/그림, 읽기 순서)·doc_assets(그림 파일)
  — 렌더링, CSV·MD 내보내기, 후속 검색·작성이 전부 이 계약을 읽는다 (ADR-0007)
- 테스트 128건 자동화, 결정 기록 ADR 7건

## 3. 방법론 — 기술별 (무엇을 어떻게 발전시켰나)

### 3.1 문서 추출 (OCR)
- 문제: 스캔·사진·손글씨·표 혼재 문서에서 기존 OCR(PaddleOCR 계열)의 오인식·구조 손실
- 방법 (입력별 경로 분기, ADR-0007):
  - 사진·4쪽 이하 PDF → 서빙 중인 VLM(Qwen3.5 비전)으로 전사.
    표는 HTML(병합 셀·머리글)로, 강조는 굵게로 지시. 문서 영역은 OpenCV
    사각형 검출→원근 보정으로 자동 크롭. 직인은 색 분리로 별도 추출
  - 5쪽 이상 PDF → MinerU(-m ocr) + LLM 보수적 오타 교정
    (배치 구분자 검증·길이 가드로 환각 차단)
- 결과 (실측):
  - 손글씨 표: PaddleOCR 판독 불능("사nto") → VLM이 표 구조·값 정확 복원
  - 12쪽 문제집: "정달/정당/정단"류 오인식 → 교정 후 정상 76곳 / 잔존 2곳
  - 장식 아이콘(체크박스) 크롭 20건 → 크기·중복 필터로 1건(유의미)만 잔존

### 3.2 검색 (RAG)
- 문제: 규정 질의에서 부분문자열 검색의 낮은 재현율
- 방법: Kiwi 명사 추출(+도메인 사용자 사전 27어) + IDF + 희귀명사 우선의 어휘
  검색과 KURE-v1 임베딩 검색을 가중 RRF(w_lex 0.4)로 융합. 단계별 실측으로 채택
- 결과 (합성 질의, 조각 692개 시점): 어휘 단독 R@1 0.588 → 임베딩 0.761 →
  하이브리드(임베딩 우세) 0.780 / MRR 0.840
- 코퍼스 정제 효과: 웹 수집 노이즈 제거 전 0.748 → 후 0.780 (+3.2%p)
  — 데이터 품질이 검색 품질로 직결됨을 수치로 확인

### 3.3 도메인 특화 학습 (축 B 리허설)
- 방법: 규정 조각에서 LLM으로 합성 질의 3종 생성(1,749쌍) → 문서 단위 홀드아웃
  분리 → 베이스라인 측정 → KURE-v1 MNR 대조학습 → 동일 홀드아웃 재측정
- 결과: R@1 0.436→0.487(+5.1%p), 단 홀드아웃 39질의·유형 편중이라 참고치.
  사이클(생성→측정→학습→평가→리포트) 자동 완주가 이번 검증의 성과
- 운영 발견: 통합메모리 장비에서 서빙(vLLM)과 CPU 학습 동시 수행 시 메모리
  스파이크로 학습이 반복 강제종료 — 서빙 일시 정지 + max_seq 512 + 아레나 제한으로
  해결(스텝당 33s→10s). 논문의 온프레미스 운영 절에 쓸 것

### 3.4 개인정보 보호 설계
- 원칙: 인풋 문서는 파싱 직후 6종(주민·전화·이메일·계좌·사업자·성명, 체크섬 검증)
  마스킹 후에만 저장·LLM 전달. 기준 문서(규정·공고)는 판단 근거이므로 원문 유지
  (ADR-0006). 마스킹은 인덱싱 이전 단계에 배치(사후 재구축 비용 회피)

### 3.5 검토·작성 파이프라인
- 검토: 업무 영역별 프롬프트(채용은 서열화 금지·사실 정리, 입학은 기준 대조) +
  프로젝트 지침·연결 공고를 우선 근거로 주입. 판정(승인·재검토·반려) 피드백 루프
- 작성(국고사업): 공고 스키마 추출 → 섹션별 생성 → 수치 대조·배점 커버리지 검증.
  재료는 구조 조각(표 포함), 담당자 의견 반영 재작성 루프
- 수치 무결성: 생성 수치는 인출 근거에 존재해야 함(검증기) — 근거 없으면 "(근거 없음)"

## 4. 기여점 (논문 주장으로 쓸 것)

1. 외부 반출 불가 제약에서 단일 장비로 추출→검색→검토·작성 전 경로를 구현하고
   실측치로 각 단계 설계 선택을 정당화 (MoE 서빙, 하이브리드 검색, VLM 추출)
2. 서빙 중인 범용 VLM을 OCR 보완재로 쓰는 입력별 경로 분기 — 손글씨·직인 등
   전통 OCR 한계 영역을 추가 모델 없이 해결
3. 데이터 정제→검색 품질(+3.2%p), 학습 사이클 자동화의 재현 가능한 절차 제시
4. 통합메모리 장비의 서빙·학습 동시 수행 한계와 해법 실측 보고

## 5. 한계·향후 (정직하게 쓸 것)

- Embed 개선폭은 리허설 수치(홀드아웃 편중) — 실데이터 파일럿에서 층화 분할로 재측정
- Writer·Extract·Rerank 특화 학습은 미착수 (실데이터 대기)
- 5쪽 초과 스캔 PDF는 MinerU 품질 의존, 셀 배경색 등 시각 서식 미보존
- 검색은 임베딩 사전계산 방식 — 벡터DB(Qdrant) 이관은 P3 예정
