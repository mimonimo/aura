# 중간 발표자료

2026-10-18(10월 3주차) 기준. 슬라이드 한 장이 아래 절 하나다. 수치는 운영에서 잰 값과 저장소의 측정 기록(실험 로그, 모델 교체 노트, 진행 현황)에서만 가져왔고, 재지 않은 것은 「미측정」으로 적었다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 주제 | 교내 행정 업무 자동화를 위한 sLLM 모델 개발 및 행정 자동화 에이전트 (서비스 이름 AURA) |
| 추진 배경 | 국고사업 계획서를 쓸 때 담당자가 공고를 읽고 흩어진 과거 문서를 일일이 찾아 참고한다. 문서에 개인정보·내부 정보가 있어 외부 AI 서비스에 올릴 수 없다 |
| 목표 | 교내 문서를 검색되는 데이터로 바꾸고, 질문하면 근거와 출처를 짚어 답하며, 공고 양식에 맞춘 초안을 근거와 함께 낸다. 수치는 근거와 대조하고 최종 판단은 담당자가 한다 |
| 조건 | 모든 처리를 교내 장비에서 한다(온프레미스) |
| 장비 | 운영 서버(학과 가상서버, CPU) · 서빙 서버 2대(젯슨 AGX 토르) · 학습 서버(DGX) |
| 팀 | 4명. 팀장(플랫폼·모델 서빙·에이전트), 문서 데이터화·RAG·파인튜닝 1명, 교내 문서·규정 수집 2명 |

## 3. 현재 진행 상황

지금까지 끝낸 것

- 학교 원본 전체를 받아 처리했다. 원본 167,146건(중복 제외 130,046) → 라이브러리 문서 35,469건
- 검색(RAG)과 지식그래프(GraphRAG)를 운영 중이다. 질문하면 27B가 근거를 찾아 출처를 달아 답한다
- 문서 작업 에이전트와 플랫폼 업무 도우미를 운영 중이다
- 검색 모델 두 개(임베딩·리랭커)는 교내 문서로 학습한 판을 쓰고 있다
- 생성 모델 SFT 학습셋을 승인했다(학습 시작 전)

## 4. 중간 결과물

지금 답은 학습하지 않은 베이스 27B가 만든다. 35,000여 문서를 조각낸 검색(RAG)과 지식그래프(GraphRAG)에서 찾은 근거를 보고 답하며, 파인튜닝한 모델이 답하는 것이 아니다.

### 구현 화면

| 화면 | 하는 일 |
|---|---|
| 에이전트 채팅(새 채팅) | 질문을 27B가 읽고 그래프와 검색으로 근거를 찾아 출처 번호를 달아 답한다. 출처를 누르면 오른쪽 작업 패널에 그 대목이 열린다. 문서 작성 요청이면 양식을 골라 구글 독스 작업본에 절마다 초안을 쓴다 |
| 라이브러리 · 문서 | 등록 문서 한 목록. 기준 문서(규정·공고)는 쓰임새 칩으로 구분, 같은 제목은 판본으로 묶음 |
| 라이브러리 · 원본 보관소 | 학교 원본 파일을 사업 분류·연도·문서 종류·처리 상태로 보고, 처리하지 않을 원본은 정리함으로(되돌림 가능) |
| 플랫폼 업무 도우미 | 화면 오른쪽 아래 떠 있는 창. 사용법 안내, 화면 단추와 같은 일을 [실행] 제안으로, 간단한 문서 질문은 바로 답 |
| 그래프 탐색 | 사업 > 연차 > 문서 > 절 지식그래프. 사업 화면에서 연차별 문서, 성과지표, 계획 ↔ 실적 대응 |
| 개발 현황 | 진행 상태와 지표. 화면 숫자는 기계 산출물에서만 |
| 데이터·학습 | 학습 데이터 검수 → 승인 → 학습 단계, 승인된 학습셋 목록 |
| 수집 자료 | 대화·답 실행 기록·답 평가·에이전트 걸음을 기간별로 골라 가린 사본으로 내려받기 |

### 시연 순서

- 1단계: 에이전트 채팅에서 「사업 이름 + 연도 + 계획서의 절」을 묻는다 → 답과 출처 번호 → 출처를 눌러 작업 패널에서 원문 대목 확인
- 2단계: 그래프 탐색에서 같은 사업을 연다 → 연차별 문서와 계획 ↔ 실적 대응
- 3단계: 라이브러리 원본 보관소에서 사업 분류로 원본을 찾고 정리함을 보인다
- 4단계: 채팅에서 초안을 요청한다 → 양식 고름 → 독스 작업본에 절 초안, 근거에 없는 숫자는 「(근거 확인 필요)」 표시
- 5단계: 업무 도우미에 사용법을 묻고 [실행] 제안을 보인 뒤, 개발 현황에서 지표로 마무리

## 5. 변경 사항 및 이슈

| 구분 | 기획 때 또는 문제 | 바뀐 것 · 해결 |
|---|---|---|
| 일정 순서 | 데이터화 → RAG → 파인튜닝 → 에이전트 순서 | 학교 원본 전체가 먼저 들어와 RAG·지식그래프·에이전트를 앞당겨 운영. 파인튜닝은 학습 전 기준을 먼저 잰 뒤 시작 |
| 파인튜닝의 역할 | 학습한 모델이 절별 초안을 쓰는 구조 | 사업 사실·수치는 온톨로지·지식그래프·RAG로 넣고, 학습은 근거를 모아 구성하는 리즈닝·문서 구조에만(ADR-0047) |
| 서빙 속도 | 27B 원본(bf16)이 요청당 2.4~4.5 토큰/초 | NVFP4 양자화 판으로 10.4~10.8(내용 같음, ADR-0023), 이어 MTP로 24. MTP를 켤 때 메모리 비율을 크게 잡아 검토·판독이 약 25분 멈춤 → 비율을 낮추고 되돌리기 스크립트를 둠 |

## 6. 남은 작업

- 파인튜닝: writer-v1 결함 고친 판 재확인 → SFT 학습(DGX, QLoRA) → 같은 시험지로 학습 전후 비교 → 나아지면 양자화해 서빙 장비로 이관 → DPO(담당자 수정 이력으로 선호쌍)
- 검색·답: 사업 안에서 판·문서 고르기, 융합 순위에 정답이 없는 2.5%, 상황으로 묻는 질의 확장, 관계 질문 정확도(27B 읽기 59%)
- 에이전트·초안: 실물 공고 한 건을 처음부터 끝까지, 받지 못한 값 찾기 다듬기, 결과보고서 초안 연결, 에이전트 걸음 기록을 학습 재료로
- 플랫폼: 사업별 목표 대비 실적 화면, 한글 완성본을 한글 프로그램에서 직접 확인·예산표 행 순서, 부서장 범위와 같은 부서 안 등급
- 데이터: 판독 손상 57건 재판독, 미분류 49건·판정 못 한 2개 묶음 확인, 원본 폴더 재정리
- 보안·학교 확인: 개인정보 부서 검토와 열람 등급 체계 확정, 보관·삭제 범위, 외부 전송 결정 6건, 플랫폼 주소 교내 등록
- 시험·발표: 실사용 기록으로 시험지 늘리기(답 30문 → 더 많이), 전 구간 회귀 확인, 논문·발표 준비

## 8. Q&A

- Q. 파인튜닝을 아직 안 했는데 답은 무엇이 만드나요? — 학습하지 않은 베이스 27B가 만듭니다. 35,000여 문서의 검색(RAG)과 지식그래프에서 찾은 근거를 보고 답하고 출처를 답니다. 학습본은 같은 시험지로 비교해 나아질 때만 바꿉니다.
- Q. 왜 계획과 순서가 바뀌었나요? — 학교 원본이 한꺼번에 들어와 근거를 찾는 기반이 먼저 필요했습니다. 또 학습 전 기준을 먼저 재야 파인튜닝의 개선 폭을 보일 수 있습니다.
- Q. AI가 숫자를 지어내면요? — 답과 초안의 숫자를 근거와 대조해, 없는 숫자는 「(근거 확인 필요)」로 표시합니다. 기준 측정에서 근거 밖 숫자가 있는 답은 30문 중 0이었습니다. 표본이 작아 실사용 기록으로 늘릴 예정입니다.
- Q. 개인정보는 어떻게 지키나요? — 모든 처리를 교내 장비에서 합니다. 계정별 열람 범위를 한 규칙으로 묶어 검색 단계에서 거르고, 외부로 나가는 경로 31개를 점검했습니다. 학교 개인정보 검토와 등급 체계 확정은 남은 일입니다.
- Q. 성능 수치는 믿을 만한가요? — 시험지는 실제 문서와 그래프에서 자동으로 뽑은 136문(답 30)입니다. 규정 검색 일부는 합성 질의라 실제보다 좋게 나올 수 있어 방식 비교에만 씁니다. 사람이 쓴 질문 평가는 미측정입니다.
- Q. 답이 얼마나 빠른가요? — 기준 측정에서 중앙값 16.6초입니다. 처음엔 134초였고, 답 꼴 정리와 추측 디코딩(MTP)으로 줄였습니다.
- Q. 남은 기간에 학습이 끝나나요? — 학습셋은 승인됐고 학습·비교·이관 절차가 준비돼 있어 11월 1주 SFT, 11월 3주 DPO가 목표입니다. 학습본이 나아지지 않아도 지금 구성으로 서비스는 그대로 돕니다.
- Q. 더 큰 모델로 바꿀 수 있나요? — 모델 이름·문맥 길이 등을 설정에서 읽게 해 두었고, 같은 점검 한 번으로 지금 모델과 한 표로 견줍니다.
