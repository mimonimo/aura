# 중간 발표자료 구성안

정리 2026-09-22: 구축 현황·검색 수치·실험 기록·남은 일정을 9/20~21 결과(학습본 채택, 재반입 측정, 서빙 서버 2대)로 갱신했다. 이전 정리 이력은 git 기록에 있다.

발표 양식이 확정되기 전의 슬라이드 구성 초안이다. 각 절이 슬라이드 한 장에
해당하며, 지표 수치는 발표 시점의 최신 측정값으로 갱신한다. 수치의 정본은
`논문-원재료.md` 6절 수치 총람과 거기 적힌 리포트다.

## 1. 프로젝트 소개

- 교내 행정업무 자동화를 위한 YNC sLLM 플랫폼 「짜이미(ZZAIMY)」
- 문제의식: 행정 문서는 외부 AI에 올릴 수 없다 — 개인정보·내부정보
- 해법: 교내 장비(운영 서버 + 서빙 서버 2대 + 학습 서버) 위에서 도는 소형 언어모델 시스템.
  완성본이 아니라 70% 초안과 근거를 내고 담당자가 검수한다

## 2. 시스템이 하는 일 (데모 흐름)

- 문서 읽기: 스캔본·사진을 원본 모습 그대로 검색되는 전자문서로 복원
- 규정 응답: 질문하면 등록된 규정에서 근거 대목을 찾아 답변
- 초안 작성: 공고의 작성 항목에 맞춘 계획서 초안을 한글(HWPX)·워드·PDF로
- 검증: 초안의 수치·예산·배점 반영을 검증기가 재확인
- 문서 연관: 기준 문서·접수 문서 사이의 연관을 지식 그래프로 탐색

## 3. 구축 현황 (2026-09-22)

- 완료: 문서 복원 파이프라인(스캔본은 27B 이미지 판독), 하이브리드 검색 +
  리랭커(둘 다 학습본 채택), 검증기 3종, 초안 4형식 출력(docx·pdf·md·hwpx),
  담당자·개발자 계정 분리, 지식 그래프 1단계, 외부 참조 관문, 한글 편집
  에이전트(실장비 검증), 개발자 대시보드·PII 점검 화면, 공개 문서 194건 반입,
  Writer 27B 서빙(젯슨 토르 2대, NVFP4), 운영 서버 상시 가동
- 진행: 개체 수준 그래프 2단계, 초안 그림 삽입, 상황 질의 검색 개선
- 대기: 교내 실물 문서 파일럿(표본·개인정보 검토) → 생성 모델 베이스라인 측정
  → 학습

## 4. 핵심 결과 1 — 문서 복원

- 디지털 PDF는 글자 좌표를 직접 읽어 원문 무손실, 스캔은 화질 보정 + OCR
  투명 글자층(ADR-0007)
- MinerU OCR 어절 F1 0.74~0.84(디지털 PDF 렌더를 스캔처럼 처리, 문서 5건,
  운영 서버 CPU — ocr-cer-bench)
- 시연: 디지털 PDF 실물 문서와 스캔 문제집(12쪽)의 복원 전후 비교 화면

## 5. 핵심 결과 2 — 규정 검색 정확도 (합성 질의)

- 초기 기준선(2026-09-04, 조각 1,236·질의 2,595): 한 번에 정답(Recall@1) 어휘
  0.338 / 임베딩 0.611 / 하이브리드 0.595. 리랭커(표본 300): 0.490 → 0.623
- 현행(2026-09-21, 재반입 조각 4,254·질의 1,026·표본 300): 어휘 0.430 / 임베딩
  0.691 / 하이브리드 0.671 / 운영(리랭커까지) 0.763, 후보 10개 안 0.927
- 학습본 효과: 리랭커 학습본이 학습에 안 쓴 문서에서 Recall@1 0.649 → 0.711,
  리랭킹 속도 질의당 3.75초 → 0.07초(서빙 GPU)
- 합성 질의 자가 검색이라 절대치는 낙관적이며 방식 간 비교용. 개선 폭이
  뚜렷한 것은 리랭커이고, 용어를 모르고 묻는 질의의 22.7%는 아직 못 찾는다

## 6. 핵심 결과 3 — 검증기

- 원칙: 수치는 인출하고 생성하지 않는다
- 한국어 단위 동치 판정("6천만 원" = "60,000,000원"), 예산 곱셈 재계산 —
  LLM이 아닌 결정론 로직
- 배점 누락 검출 — 키워드 판정(결정론)에 임베딩 의미 판정을 더한 2단
  (ADR-0015). 합성 표본에서 키워드만 0/55점 → 45/55점, 판정 폭은 실제
  초안으로 재보정 예정

## 7. 정직한 실험 기록

- 검색 모델 추가 학습: 첫 리허설(홀드아웃 96질의)은 베이스 미달(Recall@1
  0.271 → 0.219)로 미적용. 운영 검색이 실제로 올린 후보로 다시 학습한
  판(9/20)만 채택했고, 단독 지표만 오른 판(임베딩 v1)은 걸렀다
- 서빙 정밀도: 27B 원본(bf16)은 요청당 2~5 토큰/초라 실사용이 어려웠고, NVFP4
  양자화 판이 같은 입력에서 3~4배 빠르며 내용이 같음을 확인해 채택. FP8은 젯슨
  빌드에서 실패, 계획에 없던 소형 판독 모델은 없는 문장을 지어내 제거
- 외부 OCR 엔진 실물 대결: MinerU hybrid-engine·dots.ocr는 오독·환각 확인 후
  보류, PaddleOCR-VL은 CPU 서버에서 측정 불가(GPU 필요)
- 규칙 기반 연관 판정(개체 하나 겹침·키워드 포함)의 오분류를 실측하고
  학습된 임베딩 판정으로 전환(ADR-0015)
- 부정적 결과도 기록하는 것이 방법론의 일부

## 8. 남은 일정

- 교내 실물 문서 파일럿 → 골드셋 구축, 층화 홀드아웃 재측정
- Qwen3.8-27B 베이스라인 측정 → DGX에서 SFT → DPO → 양자화 판으로 서빙 이관
- 작성·추출 모델 학습(임베딩·리랭커는 실물 문서로 재학습)
- 논문 작성과 최종 발표
