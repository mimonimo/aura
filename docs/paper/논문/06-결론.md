# 6. 결론

AURA는 행정 문서를 학교 밖으로 보내지 않고도 근거를 갖춘 초안을 생성할 수 있음을 자동 시험 수준에서 확인하였다. 남은 과제는 실제 담당자의 문서와 질문으로
품질을 다시 측정하고, 검증한 학습 절차를 더 큰 모델에 적용하는 것이다.

## 6.1 연구 요약 및 기여점

본 연구의 기여는 1.2절에서 제시한 네 기술, 곧 문서 데이터화, GraphRAG, 문서 작성 에이전트, 영역 단위 공동 편집을 교내 장비만으로 하나의 서비스로 통합하고
각각의 효과를 측정한 데 있다. 생성·임베딩·리랭커 모델은 모두 교내에서 운영하며, 장비는 운영 서버, 서빙 장비 두 대, 학습 장비로 역할을 나누었다.
네 기술은 문장의 의미를 이해해야 하는 판단은 모델에 맡기고 실행과 검사는 코드로 처리하는 공통 구조를 따른다.

문서 데이터화에서는 교내 문서 약 3만 5천 건을 형식에 맞는 경로(텍스트 레이어 추출, MinerU[21]·27B 판독, 한글 문서 변환 도구 kordoc[28])로 읽었다. 이어서 표 구조를
보존하고 개인정보를 처리한 뒤 청크로 나누고, 서류 종류와 사업, 버전을 정리해 색인과 지식 그래프를 구축하였다. 판독 경로는 실제 문서로 엔진을
비교해 정했으며, 스캔 판독의 어절 F1은 27B가 0.839로 MinerU의 0.690보다 높아 가장 우수했다.

GraphRAG에서는 27B가 질문을 온톨로지 용어로 해석하고 코드가 그래프에서 검색 범위를 정한 뒤 어휘 검색과 의미 검색을 RRF[38]로 결합하였다.
같은 평가 데이터셋에서 그래프 단계만 바꾸어 측정한 결과, 27B는 질문에서 사업·연도·서류 종류를 91% 맞게 해석했고, 질문한 내용을 상위 5건 안에
찾아오는 비율은 일반 RAG 47%에서 93%로, 그 내용을 근거로 답한 비율은 50%에서 100%로 올랐다. 옛 사업 이름으로 후속·전신 사업을 묻는 질문은
27B의 질문 해석을 더한 구성만 모두 찾았다(19문 중 19문). 계획서와 실적보고서를 함께 찾아야 하는 질문은 보완 과제로 남겼다(5.7절).

문서 작성 에이전트는 양식을 선택하고 절마다 작성한 뒤 원본 한글 서식 그대로 완성본을 생성한다. 약점이었던 재작성 요청 반영은 특정 사례에 맞춘 규칙을 덧붙이지 않고 작성 절차를 바꾸어 개선하였다.
재작성 전용 도구를 두고, 하위 절을 [개요] → [본문] → 검토 순서로 작성하게 하며, 문단 끝에 근거 출처를 적게 하였다. 그 결과 「더 구체적으로」
요청의 반영이 1/3에서 3/3으로 늘었고, 지어낸 숫자는 개선 전후 모두 0건이었다.

영역 단위 공동 편집은 기안기가 공동 편집 API를 제공하지 않는 조건에서, 모든 문단을 편집 영역으로 감싸 영역마다 편집권을 부여하는 방식으로 구현하였다. 한 화면에서
입력한 글자가 다른 화면에 나타나기까지의 지연은 중앙값 221ms였고 사라진 글자는 없었으며, AURA 에이전트도 사람과 같은 경로로 한 문서에 작성한다.

이와 함께 측정이 실제와 다른 수치를 내는 경로 세 가지를 찾아 절차로 차단하였다. 이런 경로를 막지 않으면 바꾼 구성의 효과를 잘못 판단하게 된다. 운영 설정을 읽지 않은 측정에서 리랭커와 임베딩이 CPU용 기반 모델로 대체된 경우, 문서 색인을 만든
모델과 질문을 벡터로 바꾸는 모델이 어긋난 경우, 미세조정(SFT)으로 학습한 추가 가중치가 서빙 모델에 적용되지 않은 경우다. 모델 교체 기준과 정답 로그확률 확인은 다음 모델을 도입할 때 사용할
비교 절차로 정리하였다.

## 6.2 결과 평가 및 한계점

5장의 결과로 볼 때, 근거를 갖춘 답변과 초안을 생성한다는 목표는 평가 데이터셋 수준에서 달성되었다. 그러나 평가 데이터셋 대부분이 합성 질의이거나 그래프에서 자동으로 추출한
질문이어서, 실제 담당자 질문에서의 성능은 아직 확인되지 않았다. 영역별 결과와 한계는 다음과 같다.

검색과 답변 생성에서는 규정 검색 운영 구성이 합성 질의 표본 300건에서 정답 조문을 1위에 올린 비율(R@1)이 0.740, 상위 5개 안에 넣은 비율(R@5)이
0.857이었다. 모델 교체 기준 v2 시험(답변 30문)에서는 오류, 빈 답변, 표시되지 않은 근거에 없는 수치가 모두 0건이었고, 근거에 정답 문서가 포함된
비율은 90%, 답변 시간의 중앙값은 16.6초였다. 다만 GraphRAG의 이점은 평가 질문을 그래프에서 만들었으므로 실제보다 크게 나타났을 수 있어,
6.3.1절의 골드셋(사람이 만든 평가 데이터셋)으로 다시 확인한다.

문서 처리에서는 표를 평문으로 바꾸는 처리, 쪽 번호, 버전, 서류 종류 항목에서 수집 충실도가 개선되었음을 측정으로 확인하였다. 그러나 서류 종류와 사업 판정은
기존 규칙과의 일치율만 있고 정답률은 사람이 정한 정답으로 따로 재야 한다. 암호가 걸렸거나 손상되어 처리에 실패한 111건은 읽지 못하며, 표 셀
배경색 같은 시각 서식은 보존하지 못한다.

문서 작성에서는 짧은 서식(예산 변경, 출장 보고, 기안문)을 끝까지 채웠고 지어낸 숫자는 모든 측정에서 0건이었다. 긴 사업계획서는 절 단위 위임으로 끝까지 작성한
버전이 나왔지만, 절을 위임할지의 판단이 실행마다 달라지고 시간이 3~4배 걸린다. 시나리오 평가는 버전마다 3회이고 같은 27B가 채점했으므로
버전 비교에만 사용한다. 행을 늘린 서식 표가 쪽 아래로 넘치던 문제는 해결하였다. 완성본 서식을 위해 기관별 글꼴·여백 설정을 담은 기관 서식 프로필과 서식 대조 도구를 추가했으나,
기준 문서의 모양에 가깝게 맞추는 작업은 아직 진행 중이다.

파인튜닝은 더 큰 모델에 적용하기 위한 실험으로 수행하였으며, Writer 27B에서 학습 절차와 데이터를 검증하였다. 교내 실문서 학습쌍 4,434쌍으로 LoRA[17] SFT를
수행한 결과, 시험 문항 220개에서 정답 글과 겹치는 정도(chrF)가 27.9에서 36.6으로 오르고 질문에 없는 숫자가 든 답의 비율이 4.1%에서 0%로 줄었다. 사실을 암기시키지 않고 근거를 모아 답을
구성하는 방식만 학습해도, 학습한 형식의 요청에서는 정확성과 형식이 함께 개선되었다. 한편 학습쌍이 한 가지 형식뿐이어서 에이전트 단계의 JSON 요청에도
학습한 형식으로 답했다. 그 결과 문서 작성 시나리오에서 학습 전 모델은 두 번 모두(2/2) 작업 문서를 만들었으나 학습 후에는 한 번도 만들지 못했다(0/2). 더 큰 모델에서는 플랫폼의 요청 형식을 학습 데이터에 포함해
이를 보완한다. 현재 서비스에서는 기반 모델인 27B가 RAG와 GraphRAG 근거로 답한다.

공동 편집에서는 헤드리스 크롬 세 창 측정에서 글자 지연 중앙값이 221ms였고 사라진 글자는 0자였다. 제목과 표 셀의 수정 내용과 서식,
AURA가 작성한 절은 다시 불러오기 없이 열린 화면에 반영된다. 실제 기안기에서 세 창이 Enter를 섞어 빠르게 동시 입력한 시험과, AURA가 다른 절을 작성하는
동안의 동시 입력 시험에서도 글자 누락, 문단 겹침, 사본 밀림은 없었다. 다만 한 편집 영역은 먼저 잡은 사람만 편집할 수 있고, 표·그림·용지처럼
편집 영역에 담기지 않는 수정은 한 사람씩 문서 전체를 저장한 뒤 다른 화면이 새 버전을 받는다.
또한 편집 영역의 위치 측정은 공개 API 없이 기안기 내부 구조에 의존하므로, 제품 버전이 바뀌면 편집 영역 표시가 어긋날 수 있다.

운영과 제도 면에서는 학교의 결정과 실제 환경에서의 검증이 남아 있다. 열람 등급 체계, 개인정보의 부서 검토, 보관·삭제 범위, 외부 전송에 관한 남은 결정 6건에 학교의 확인이 필요하다. 부서 드라이브는
각 부서 총괄 책임자가 실제로 연결하는 일이 남아 있다. 개인정보 탐지는 정규식과 항목 이름 같은 문맥 단서에 의존하므로 단서 없이 적힌 이름이나 주소를 놓칠 수 있다.
따라서 더 큰 모델용 학습 데이터를 반출할 때는 사람 검수를 추가한다. 설치·운영 패키지를 이용하면 다른 기관도 플랫폼을 설치하고 자체 LLM 서버, 사용자,
원본 폴더를 관리 화면에서 연결할 수 있다. 다만 설치부터 백업·복구·업데이트까지의 검증은 빈 Ubuntu 컨테이너에서만 수행하였다.

## 6.3 향후 연구 방향

다음 단계는 실제 담당자의 문서와 질문으로 다시 측정하는 데서 시작한다. 이를 바탕으로 학습 절차를 더 큰 모델에 적용하고, 대용량 문서의 공동 편집과 모델 교체 절차를 보완한다.

### 6.3.1 실사용 평가와 파일럿 운영

파일럿에서는 최근 3~5년의 유사 유형 사업계획서 20~30건과 그에 대응하는 결과보고서로 범위를 한정하고, 실제 공고 한 건을 처음부터
끝까지 처리한다. 출처가 표시된 초안과 공고의 평가 배점 항목별 반영 여부를 정리한 보고서를 생성하고, 담당자가 수정한 분량과 이유를 기록한다. 같은 기간에 담당자가 직접 작성한 질의로
200~500문항 규모의 검색 골드셋을 구축해 합성 평가 데이터셋보다 현실에 가까운 성능을 측정한다. 골드셋의 정답은 검수자 두 명이 판정하고 두 판정의 일치율을 기록한다. 생성 결과는 어느 모델의 출력인지 밝히지 않은
사람 평가(문체·논리 5점 척도)로 평가하고, 언어 모델 판정[73]은 보조 지표로만 사용한다. 서류 종류와 사업 판정도 표본을 사람이 판정해 정확도를 측정한다.

### 6.3.2 대형 모델 미세조정과 교체

27B로 검증한 학습 절차와 데이터(교내 실문서 학습쌍, 개인정보 반출 검사, 사업 단위 학습·검증·시험 분리)를 더 큰 모델에 적용해 운영 모델로 사용하는 것이
목표다. 이번에 사용한 4,434쌍은 사람 검수 없이 자동으로 생성한 데이터였으므로, 더 큰 모델용 절차에서는 사람 검수를 추가한다. 27B 실험에서 드러난 에이전트 단계의 JSON 형식 문제를 막기 위해,
학습 데이터에는 플랫폼이 실제로 모델에 보내는 요청 형식의 예시를 대부분 자동으로 생성해 추가한다. 절차는 다음과 같다.

1. 운영과 분리된 시험 DB에서 공개 문서와 가상 사업으로 문서 작업 시나리오를 실행하며, 에이전트 단계 JSON, 작업 메모 갱신, 채팅 답, 절 작성,
   재작성 요청의 메시지(시스템 지시·도구 목록·대화)를 AURA가 모델 서버에 요청을 보내는 지점에서 그대로 기록한다.
2. 형식 검사 통과 여부, 시나리오 채점 점수, 자료에 없는 숫자가 들어 있는지를 자동으로 점검해 기준을 통과한 답만 남긴다.
3. 절 본문은 이번 학습쌍(4,434쌍)의 좋은 답을 실제 절 작성 요청 형식에 넣어, 정답에 가까운 내용, 적절한 길이, 지어낸 숫자 0건이라는 장점을 유지한다.
4. 사람 검토는 요청 종류마다 수십 건의 표본으로 수행한다.

학습 전후 비교에서는 먼저 정답 로그확률로 학습 결과가 반영되었는지 확인한 뒤, 시험 문항의 chrF·ROUGE-L·항목 점수, 맥락 이해 30문항, 문서 작성 시나리오를
같은 조건으로 비교한다.

실제 도입 시 더 큰 모델이나 파인튜닝한 모델로 교체할 수 있도록, 모델 이름, 컨텍스트 길이, 추론 모드를 끄는 설정값을 코드에 고정하지 않고 연결 설정에 두었다. 컨텍스트
길이는 서버가 알려 주는 값을 사용하며, 작업 메모와 최근 대화가 차지하는 분량도 컨텍스트 길이에 비례하도록 정하였다. 교체할 때는 운영 설정을 그대로 둔 채
후보 모델과 운영 모델을 같은 데이터로 나란히 측정한다. 컨텍스트 길이가 긴 모델에서 절 단위 위임의 필요성이 줄어드는지도 같은 시나리오로 측정한다.

### 6.3.3 대용량 문서 공동 편집과 기능 확장

행정 서식에는 100~400쪽에 이르는 문서도 있다. 이번 연구에서는 451쪽 문서까지 편집 영역 목록 읽기, 편집 영역 위치 측정, 파일 쓰기의 지연을 측정했고,
5.5절에서 보인 것처럼 바뀐 부분만 주고받는 방식으로 지연을 줄였으며, 실제 기안기의 세 창 동시 입력도 확인하였다. 남은 과제는 여러 실제 계정에서의 지연 측정, 표나 도식이 포함된 AURA 절을
다시 불러오기 없이 열린 화면에 반영하는 기능, 여러 앱 프로세스가 같은 DB를 사용할 때 1초 주기로 전달되는 알림의 지연 단축이다.

그 밖에 결과보고서 작성까지 실제 업무에 쓰려면 기능 몇 가지를 보강해야 한다. 한글 완성본을 한글 프로그램에서 직접 열어 확인하고, 예산표와 명단표의 행 순서를 대응시키는 기능을 추가한다. 규정 용어를 모르는 사용자가 상황을
설명하며 묻는 질의에 대비해 구현해 둔 질의 확장 기능에는 어떤 운영 모델을 사용할지 정해야 한다. 관계 평가 문항 36문에서 계획서와 실적보고서를 모두
찾아야 정답으로 인정하는 엄격한 기준의 적중률은 33.3%에 그치므로 이를 높이고, 사업별 목표 대비 실적 화면을 결과보고서 초안 작성과 연결한다.

제도 면에서는 같은 부서 동료의 문서 검토 의견과 그래프의 사업 별칭·연관 관계를 열람 범위에 따라 제한할지 결정하고, 6.2절의 남은 결정 6건도 학교 기준에 맞춰 확정한다.

AURA는 사람이 검수하는 초안을 생성하는 경로와 안전장치를 갖추었고, 그 품질은 자동 평가 수준에서 확인되었다. 실제 담당자의 문서와 질문으로 측정한 품질,
사람 평가, 더 큰 모델의 학습은 파일럿 운영과 다음 단계에서 확인하며, 이를 거치면 교내 문서 업무를 실제로 덜어 주는 도구로 자리 잡을 수 있을 것이다.
