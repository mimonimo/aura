# 5. 평가 및 결과

이 장은 AURA 각 단계의 평가 잣대와 측정값을 정리한다. 수치는 저장소의 측정 기록(실험 로그, ADR, 개발 현황 문서, 측정 결과 파일)에 있는
값만 쓰고 표마다 출처를 적는다. 재지 않은 것은 「미측정」, 기록을 확인하지 못한 것은 「미확인」으로 둔다.
측정 일자는 모두 2026년이며 월-일로 적는다. 무엇을 쓰지 않기로 했는지도 설계 판단의 근거이므로 채택하지 않은 검색 후보도 싣는다.

## 5.1 평가 방법

### 5.1.1 평가 원칙

평가는 프로젝트의 평가 계획과 품질 기준을 따르며, 원칙은 다섯이다.

첫째, 기준선 없이 개선을 주장하지 않는다. 바꾸기 전에 같은 시험지로 현재 구성을 재어 저장하고, 바꾼 뒤 같은 실행으로 다시 잰다(생성 모델
교체 기준, 시험지 v2).

둘째, 운영 연결 설정과 함께 잰다. 9-21 에 서빙 장비 설정을 읽지 않은 측정이 임베딩과 리랭커를 운영 서버 CPU 의 바탕 모델로 조용히 대체해
운영 구성 값이 실제보다 0.1 낮게 나왔다(실험 로그 2절). 그 뒤 모든 측정은 운영 설정을 읽고 띄우며, 답한 모델과 대체 실행 수를 기록한다.

셋째, 같은 시험지·같은 채점끼리만 비교한다. 시험지를 고치면 판 번호를 올리고 기준선을 다시 잰다.

넷째, 코드가 세는 지표(근거 밖 숫자, 정답 문서 적중, 서식 깨짐)를 주 근거로 하고, 언어 모델 채점은 판끼리 비교하는 보조 지표로만
쓴다.

다섯째, 잡음 폭을 먼저 잰다. 같은 구성을 반복해 흔들림 크기를 보고 그보다 큰 차이만 차이로 읽는다(문서 작성 시나리오 판마다 3회, SFT
비교의 같은 모델 대조군).

### 5.1.2 지표 정의

이 장에서 쓰는 지표의 정의는 [표 5-1] 과 같다.

| 대상 | 지표 | 정의 |
|---|---|---|
| 검색 | R@k (Recall@k) | 정답 조각이 상위 k 안에 든 질의의 비율 |
| 검색 | MRR@10 | 정답 조각 순위의 역수 평균(10위 밖은 0) |
| 검색 | 후보 진입률 | 리랭커에 넘기는 후보 20개 안에 정답이 든 비율(리랭커 뒤 성능의 상한) |
| 검색 | 정답 문서@k | 사업 문서 검색에서 정답 문서가 상위 k(절 질문 5, 관계 질문 6) 안에 든 비율 |
| 검색 | 같은 판 · 같은 사업 | 정답 문서와 같은 판본 묶음의 문서, 같은 사업의 문서가 상위 k 안에 든 비율 |
| 검색 | recall@10(근사 검색) | 정확 계산 상위 10 가운데 근사 색인(HNSW[37])이 돌려준 비율 |
| 답 | 근거에 정답 문서 | 모델에 실제로 건넨 근거 묶음에 정답 문서가 든 답의 비율 |
| 답 | 근거 밖 숫자 | 답의 숫자 가운데 모델에 건넨 근거에 없는 것(코드가 셈, 「(근거 확인 필요)」 표시 숫자 제외) |
| 답 | 정답 사실 재현율 | 정답 절의 숫자 사실 가운데 답에 나온 비율(요약 답에서 낮게 나와 모델 간 상대 지표로만 씀) |
| 문서 처리 | 어절 F1 | 판독 결과와 원문의 어절 단위 정밀도·재현율의 조화 평균 |
| 문서 처리 | 규칙 일치 · 빈칸 채움 | 27B 갈래 판정이 규칙과 같은 비율, 규칙이 비운 문서에 갈래를 붙인 비율 |
| 문서 작성 | 쓴 절 · 칸 채움 | 서식의 쓸 자리 가운데 에이전트가 채운 절 수, 칸 채움 비율 |
| 문서 작성 | 지어낸 숫자 | 작업본 본문의 숫자 가운데 근거·담당자 글에 없는 것(단위만 바꾼 같은 금액은 같은 값, ADR-0068) |
| 문서 작성 | 작성방법 반영 · 고쳐 쓰기 반영 | 작성방법이 요구한 표·도식·출처의 유무, 「더 구체적으로」 요청 뒤 글이 1.15배 넘게 늘었는지(코드가 셈) |
| 문서 작성 | 채점 점수(5점) | 같은 27B 가 기준표로 매긴 구체성·논리·문체·근거(판 비교용) |
| 모델 비교 | chrF · ROUGE-L | 시험 문항 정답과 생성 답의 글자 n-gram F 점수[63], 최장 공통 부분열 F 점수[64] |
| 모델 비교 | 정답 토큰당 평균 로그확률 | 정답 글을 모델에 넣었을 때의 토큰당 평균 로그확률. 생성 없이 재므로 샘플링 잡음이 없고, 학습이 서빙에 들어갔는지 본다 |
| 모델 비교 | 둘 중 나은 답 고르기 점수 | 채점 모델[65]이 두 답의 순서를 바꿔 두 번 고른 결과의 (이김 + 비김 × 0.5) ÷ 문항 수. 0.5 가 같음 |
| 공동 편집 | 글자 지연 | 한 화면에서 확정한 글자가 다른 화면에 나타나기까지의 시간(중앙값·90%·최대) |
| 서빙 | 초당 토큰 · 첫 글자 시간 | 요청 하나의 생성 속도, 요청부터 첫 토큰까지의 시간 |

### 5.1.3 시험지와 측정 도구

지표마다 쓴 시험지는 [표 5-2] 와 같다. 측정은 모두 저장소의 측정 스크립트로 다시 돌릴 수 있다.

[표 5-2] 시험지와 측정 도구

시험은 임시 DB 에서 하고 운영 데이터는 읽기만 한다. 시험지 원문과 결과 원자료는 개인정보와 교내 문서를 담을 수 있어 저장소 밖에 두고,
저장소에는 집계와 판단만 남겼다.

## 5.2 검색 품질

### 5.2.1 규정 검색

규정 검색은 교내 규정·지침을 조문 단위로 찾는다. 첫 기준선은 9-04 에 조각 1,236개, 합성 질의 2,595건으로 쟀다(실험 로그 1절).

| 방식 | R@1 | MRR@10 | R@10 |
|---|---|---|---|
| 어휘(Kiwi[33] 명사 + IDF[34]) | 0.338 | 0.413 | 0.567 |
| 임베딩(KURE-v1[29]) | 0.611 | 0.700 | 0.877 |
| 하이브리드(RRF[35], 같은 가중) | 0.520 | 0.647 | 0.879 |
| 하이브리드(임베딩 우세) | 0.595 | 0.692 | 0.877 |

[표 5-3] 규정 검색 첫 기준선(09-04, 질의 2,595건)

어휘 가중을 0.2~1.2 로 바꿔 보니 0.2~0.5 에서 MRR@10 이 0.692~0.693 으로 평평해 서비스 기본값 0.4 를 유지했다. 같은 날 바탕 리랭커
(bge-reranker-v2-m3)로 하이브리드 상위 10 을 다시 정렬하자 표본 300건에서 R@1 이 0.490 에서 0.623 으로 올랐다.

학습본과 후보 비교는 [표 5-4] 와 같다. 리랭커 학습본 Rerank v1(바탕 bge-reranker-v2-m3[32])은 운영 하이브리드가 실제로 올린 후보 20개로
목록 단위 학습을 했다. 임베딩은 첫 리허설(9-03)이 바탕보다 낮아 배포하지 않았고, v1 은 단독 지표만 오르고 운영 하이브리드에서 이득이 없어
학습 방식을 고쳤고, 후보 진입률이 오른 v2 를 운영에 넣었다(ADR-0021). 공개 KURE-v2(다중 벡터)[29]는 학습 없이도 학습본에 근접했으나 운영 경로에서 이득이
없어 쓰지 않았다(ADR-0025).

| 모델 | 비교 | 결과 | 판정 |
|---|---|---|---|
| Rerank v1 | 홀드아웃 12문서(질의 114건), 바탕 대 학습본 | R@1 0.649 → 0.711, MRR 0.751 → 0.790 | 채택(ADR-0020) |
| Embed 첫 리허설(v0) | 홀드아웃 96질의, 바탕 대 학습본 | R@1 0.271 → 0.219, R@5 0.667 → 0.615 | 배포 안 함 |

[표 5-4] 검색 모델 학습본과 후보 비교

운영 구성(하이브리드 → 리랭커, 후보 20)의 회차별 값은 [표 5-5] 와 같다. 9-21 은 문서함 재반입 뒤 처음 유효한 값, 10-18 은 규정 조각이
9,595개로 늘고 채점 규칙이 바뀐 뒤의 값이다.

| 측정 | 질의 | 어휘 R@1 | 임베딩 R@1 | 하이브리드 R@1 | 운영 구성 R@1 | 운영 구성 R@5 · R@10 |

[표 5-5] 규정 검색 운영 구성 회차별 값(실험 로그 5·20절)

10-14 에서 10-18 로 오른 몫(운영 구성 R@5 0.787 → 0.857)의 상당 부분은 검색 개선이 아니라 채점 규칙 변경과 조각 증가에서 왔다. 채점
규칙 변경은 다음 두 실험에서 나왔다.

하이브리드 가중 재측정(10-14~15). 운영 임베딩은 같은 생성기의 합성 질의로 학습했으므로 임베딩 단독 값이 부풀었을 수 있다. 학습 문서와
겹치는 질의를 빼고 남은 깨끗한 질의 22,084건으로 가중을 다시 쟀다.

| 어휘 가중 | 후보 20 진입률 | 하이브리드 R@1 | MRR@10 | 리랭커 뒤 R@1(표본 600) |
|---|---|---|---|---|
| 0 | 0.906 | 0.625 | 0.714 | 0.708 |
| 0.2 | 0.906 | 0.618 | 0.711 | 0.710 |
| 0.4(운영) | 0.905 | 0.611 | 0.706 | 0.707 |
| 1.0 | 0.903 | 0.570 | 0.678 | — |

[표 5-6] 깨끗한 질의로 다시 잰 하이브리드 가중(실험 로그 10절)

가중 0~0.6 에서 후보 진입률 차는 0.05%p 이하이고, 리랭커 뒤 R@1 차는 600건 가운데 3~4건으로 95% 구간이 0 을 포함한다. 가중은 융합 순서만
바꾸고 그 순서는 리랭커가 다시 세우므로 0.4 를 유지했다. 질의 생성기가 학습과 같아 문체 누수는 가르지 못했다.

후보 단계 손실 감사(10-15). 운영 후보 정리를 거친 진입률(0.906)이 임베딩 원순위 상위 20(0.955)보다 낮아 후보 정리가 정답을 잃는 것처럼
보였다. 정답이 빠진 2,081건을 나누자 1,247건은 같은 규정이 판본·파일만 달리해 여러 번 등록된 경우로, 같은 본문의 조각이 후보 안에 남아
있었다. 채점이 원래 조각 하나만 정답으로 센 탓이다. 같은 본문(공백을 지운 글자 8-gram 의 90% 이상)도 정답으로 인정하도록 채점만 고친 결과(운영 코드는
그대로)가 [표 5-7] 이다.

[표 5-7] 채점 보정 전후(실험 로그 11절)

새 채점에서도 남은 융합 놓침 2.5%(22,084문 가운데 541)를 나누면 58% 는 시행일·부칙·정족수처럼 어느 규정에나 있는 조문, 13% 는
「이 규정」 처럼 규정 이름을 대지 않은 지시어 질의였다. 실제 놓침 후보는 154건(전체 질의의 0.70%)이다(실험 로그 21절). 대부분 합성 시험지가
만든 답할 수 없는 질의여서 검색 단계를 바꿀 근거로 보지 않았다. 다만 용어를 모르고 상황으로 묻는 질의의 22.7%(9-20 측정)는 두 축 모두
상위 20 에 들지 못해 리랭커나 후보 수로 줄지 않는다(실험 로그 4절).

리랭커를 서빙 장비 GPU 로 옮기자 질의당 시간이 3.75초에서 0.07초로 줄어 후보를 10개에서 20개로 늘렸다(ADR-0020). 27B 생성 모델로 후보를
다시 매기는 방식은 568M 리랭커보다 부정확하고 53배 느렸다.

### 5.2.2 사업 문서 검색과 GraphRAG

사업 문서 검색은 온톨로지 그래프로 사업·연차·서류 갈래를 좁힌 뒤 하이브리드 검색을 한다. 같은 시험지에서 그래프 단계만 바꿔
쟀다(10-14, 실험 로그 9절). A 는 그래프 단계를 끈 전문 검색 RAG, B 는 운영 기본(이름 맞추기로 범위를 좁힘), C 는 B 에 27B
질문 읽기를 더해 관계를 따라가는 구성이다.

| 지표 | A 전문 검색 | B 그래프 | C 그래프 + 27B 읽기 |
|---|---|---|---|
| 절 질문 정답 문서 상위 5(73문) | 18% (13) | 64% (47) | 70% (51) |
| 절 질문 MRR | 0.120 | 0.546 | 0.602 |
| 관계 질문 전체(75문) | 13% | 9% | 45% |
| 관계: 앞·뒤 단계(19문) | 47% | 5% | 100% |
| 관계: 평가(20문) | 5% | 25% | 50% |
| 관계: 계획↔실적 둘 다(36문) | 0% | 3% | 14% |
| 검색 한 번 중앙값 | 1.21초 | 1.58초 | 6.45초 |
| 답 근거에 정답 문서(36문) | 31% | 53% | 75% |
| 근거 밖 숫자 | 1/152 | 1/111 | 0/169 |
| 답 전체 시간 중앙값 | 29.8초 | 37.7초 | 42.3초 |
| 블라인드 판정 정답성 평균(0~2) | 0.36 | 0.75 | 0.92 |
| 블라인드 판정 완결성 평균(0~2) | 0.44 | 0.64 | 0.94 |

[표 5-8] 전문 검색 RAG 와 GraphRAG 비교(10-14)

사업·연도·문서를 지목하는 절 질문은 이름 맞추기 그래프(B)만으로 정답 문서 적중이 18% 에서 64% 로 올랐다(95% 구간 11~28% 대 53~74%).
관계 질문은 C 에서만 전문 검색을 넘었다. B 는 질문에 적힌 사업으로 범위를 좁혀 앞·뒤 단계 사업을 밀어냈고, C 는 앞 단계·편입 관계를
따라가 19문을 모두 맞혔다. 답 판정은 모드를 가린 LLM 판정자[65] 셋이
했다(10문 30답의 사람 판정 대조: 완전 일치 60%, 1점 이내 100%). 근거 밖 숫자는 세 모드 모두 1% 미만으로 차이가 없었다. 이 결과로
27B 질문 읽기를 운영에 켰다.

GraphRAG 가 더 느린 까닭은 [표 5-9] 로 확인했다. 전문 검색도 어휘 색인(GIN)과 벡터 색인(HNSW)을 타므로
전체 조각(10-18 기준 1,848,580개)에서도 검색 한 번이 1.21초였고, 그래프 범위 정하기와 짝 문서 담기가 0.37초(A→B), C 의 27B 질문 읽기 호출이
4.87초(B→C)를 더했다. 답 시간 차이는 대부분 답 쓰기에서 났다. 전문 검색은 엉뚱한 근거로 짧게 답하거나 「없다」 로 끝내는 일이 많았고, C 는
맞는 근거로 더 긴 답을 썼다.

| 시간(중앙값) | A 전문 검색 | B 그래프 | C 그래프 + 27B 읽기 |
|---|---|---|---|
| 검색 한 번 | 1.21초 | 1.58초 | 6.45초 |
| 답 가운데 근거 문서 찾기(규정·사업 문서) | 4.62초 | 5.07초 | 9.29초 |
| 답 가운데 27B 가 답을 쓰는 시간 | 24.81초 | 33.90초 | 34.84초 |
| 답 전체 | 29.75초 | 37.74초 | 42.30초 |

### 5.2.4 벡터 색인 이전

사업 문서 벡터를 운영 서버 메모리의 배열에서 PostgreSQL pgvector[36] 의 HNSW[37] 색인으로 옮겼다(ADR-0057).
10-06 대결에서 고정 질문 80문의 정답 문서 적중은 0.688 에서 0.675 로 1문 차였고, 검색 시간은 3.49초에서 1.85초로 줄었다. 운영 서버
메모리에서는 5GB 넘는 배열이 빠졌다. 근사 검색의 정확 계산 대비 recall@10 은 0.915(벡터 131.9만 개, 질의 200, ef_search 300)다.

### 5.3.1 판독 엔진 선택

스캔 PDF 판독 엔진은 사업 문서 24건(사업마다 하나, 본문 3쪽)을 세 엔진으로 읽어 같은 잣대로 골랐다(ADR-0050).

| docling[21](기본 OCR) | 0.334 | 5.6초 |

[표 5-13] 스캔 판독 엔진 비교

docling 은 깨진 한국어를 많이 내어 「글이 충분하다」 는 검사를 통과해 버리므로 뺐다. 대량 처리는 처리량 때문에 MinerU, 짧은 스캔
문서와 사진은 27B 판독을 먼저 쓴다. 앞서 비교한 MinerU hybrid-engine 은 「Ⅱ유형」 → 「표유형」 오독과 절반의 본문
추출량(2,423자 대 4,804자), dots.ocr[73] 는 고유명사 오독과 영어 환각이 나와 쓰지 않았다(실험 로그 1절).

글자층의 65.7% 가 깨진 36쪽 스캔 매뉴얼 비교에서는 계획 밖의 소형 판독 모델이 5쪽을 21초에 읽었지만 없는 문장을 지어내고 줄을 반복했고,
27B 원본(bf16)은 128초 걸려 원문대로 읽어 판독 모델을 27B 로 통일했다(실험 로그 6절).

디지털 PDF 는 판독하지 않고 원본 글자층을 글자 좌표째 읽는다. MinerU 가 글자층이 있는 문서를 스캔으로 다뤄 「기초과학」 을 「기추과하」 로
읽은 사고 뒤, 글자층을 먼저 감지해 경로를 나누게 했다(실험 로그 2절).

모드를 기본으로 끈 뒤 한 건이 약 10초로 줄었고, 다시 읽은 708건 가운데 695건에 값이 나왔다.

## 5.4 생성·문서 작성 품질

### 5.4.1 답의 근거와 숫자

답에서 가장 큰 위험은 근거에 없는 숫자다. 수치 검증기가 답의 숫자를 모델에 건넨 근거와 대조해 없는 숫자에 「(근거 확인 필요)」 를
붙이게 하고, 답 꼴을 「핵심 먼저, 요점 5개 이내, 600자 안팎」 으로 바꿨다(실험 로그 15절). 표시하지 않은 근거 밖
숫자가 있는 답은 기준 v1 의 답 10문에서 2/10 이던 것이 0/10 이 됐고, 시험지 v2 의 답 30문에서도 0 이었다. 배점 반영 판정은 합성 표본에서
낱말 맞추기로 0/55 이던 것을 학습된 표현의 돋보임 규칙으로 45/55 까지 올렸다(ADR-0015). 합성 표본 값이므로 실제 초안으로 다시 맞춰야 한다.

답 쓰기에서 27B 의 생각 모드를 켤지는 블라인드 채점으로 정했다(실험 로그 12절, 절 질문 12 · 관계 질문 12, 검색 경로 고정).

|---|---|---|
| 생성 시간 평균 · 중앙값 · 느린 쪽 10% | 45 · 44 · 72초 | 323 · 232 · 689초 |
| 출력 토큰 평균 | 528 | 3,868 |
| 근거 밖 숫자 | 2/165 (1.2%) | 16/195 (8.2%) |
| 답에 생각 글이 섞여 나옴 | 0/24 | 16/24 |
| 채점 평균(0~2) · 만점 답 | 0.875 · 6/24 | 0.333 · 1/24 |

[표 5-16] 답 쓰기 생각 모드 켬과 끔(10-15)

같은 질문끼리 비교하면 나아짐 0 · 나빠짐 12 · 같음 12 로 부호 검정 p<0.001 이다. 켜면 평균 7배 느리고 근거 밖 숫자가 늘었으며, 서빙에
생각 글을 답과 가르는 설정(reasoning parser)이 없어 생각 글이 답 칸에 섞였다. 그래서 끈 채 두었다(그 설정이 없는 서빙에서의 비교다).

대화 기억은 실제 27B 로 3턴 대화를 한 번 돌려 확인했다(ADR-0065). 첫 질문 「AI 교육 쪽으로 뭔가 사업」 은 작업 메모의 목표 「2027년
1학년 대상 AI 교육 사업계획서 작성 및 목차 구성」 이 됐고, 대상·예산 5천만원·기간이 원문대로 남았다. 답에 단계 추론
글이 섞인 경우는 0, 가장 큰 호출은 당시 문맥 한도 16,384 토큰 가운데 5,400~7,900 토큰이었다.

호출은 당시 한도 16,384 토큰에 거의 닿았으나(16,292~16,373) 잘림은 없었다(지금 서빙 문맥은 262,144 토큰). 판마다 3회이고 채점이 같은 27B 의 자기 평가이므로, 기본값은 회차를 더
모으고 담당자가 결과 문서를 본 뒤 정한다.

### 5.4.5 Writer SFT 결과(ADR-0069)

더 큰 모델에 적용하기 전에 학습 절차와 데이터를 검증하려고, Writer(Qwen3.8-27B)에 교내 실문서 학습쌍 4,434쌍으로 LoRA[15] SFT(r32, BF16
바탕, 2에폭)를 하고 병합해 운영과 같은 NVFP4 로 줄인 뒤, 떼어 둔 시험 문항 220개와 맥락 이해 30문항으로 학습 전 모델과 비교했다(질문·생성 설정·채점 모델 동일). 측정 방법은 4.11.4 절의 [표 4-21] 에 적었다.

| 지표 | 학습 전(Qwen3.8-27B) | SFT 뒤 |
|---|---|---|
| 정답 토큰당 평균 로그확률(40문항) | -1.845 | -1.153 |
| 정답 겹침 chrF · ROUGE-L(220문항) | 27.9 · 16.8 | 36.6 · 27.3 |
| 종류별 chrF: 규정 첫 질문 · 사업 자료 첫 질문 | 20.6 · 18.3 | 31.7 · 34.6 |
| 정답 대비 길이 | 1.81배 | 0.96배 |
| 질문에 없는 숫자가 든 답 · 잘린 답 | 4.1% · 2.7% | 0% · 0% |
| 표를 쓴 답 | 84.1% | 95.9% |
| 항목 점수(1~5) 지시 · 맥락 · 형식 · 근거 · 문체 · 완결 | 4.95 · 4.96 · 4.87 · 4.98 · 4.52 · 4.94 | 5.00 · 5.00 · 4.91 · 5.00 · 4.77 · 4.995 |
| 맥락 이해 30문항 | 30/30 | 30/30 |

[표 5-20] Writer SFT 전후 비교(시험 220문항, 10-24)

코드가 세는 지표는 모두 SFT 쪽이 나았다. 정답 로그확률이 오른 것(-1.845 → -1.153)은 학습이 서빙 모델에 들어갔다는 뜻이고, 정답 겹침이
오르고(chrF 27.9 → 36.6) 답 길이가 정답에 맞게 줄었으며(1.81배 → 0.96배) 질문에 없는 숫자가 든 답과 잘린 답은 0% 가 됐다. 항목 점수는 두
모델 모두 5점 가까이라 변별력이 낮고, 맥락 이해는 둘 다 30/30 이었다.

채점 모델에게 둘 중 나은 답을 고르게 하면 학습 전 모델 답을 더 자주 골랐다(SFT 기준 0.309, 95% 구간 0.264~0.355, 같은 모델 대조군 0.516).
채점 모델이 학습 전 모델과 같은 바탕이고 긴 답에 기울어, 시험 문항만으로는 우열을 정하지 않았다. 문서 작성 시나리오에서는 SFT 병합본으로
문서 작업 에이전트가 작업본을 만들지 못했고(학습 전 2/2 → 0/2, 에이전트 단계 출력을 읽지 못한 턴 18%), 평범한 업무 질문에도 학습셋의 답 틀이
나왔다(플랫폼 답변 지시 15/15). 학습쌍이 「한 줄 지시 + 질문 → 근거 설명·답변」 한 가지 꼴뿐이라 에이전트 단계의 JSON 요청에도 그 틀로 답한 것이다.

이 실험으로 확인한 것은 셋이다. 첫째, 교내 실문서 학습쌍과 학습·병합·NVFP4 재양자화·이관 절차가 끝까지 돌고, 학습한 꼴의 요청에서는
정답 근접·알맞은 길이·지어낸 숫자 0 이 함께 나아진다. 둘째, 학습이 서빙에 들어갔는지는 생성 비교 전에 정답 로그확률로 몇 분 안에 가린다.
앞서 LoRA 어댑터를 서빙에 얹은 시도는 키 이름이 맞지 않아 붙지 않았는데, 정답 로그확률이 학습 전 모델과 소수 다섯째 자리까지 같아 드러났다.
셋째, 시험 문항 점수만으로는 부족하고 문서 작성 시나리오와 평범한 질문의 답 꼴 점검을 함께 봐야 한다.

더 큰 모델에서 보완할 것은 학습 데이터의 꼴이다. 플랫폼이 실제로 보내는 요청(에이전트 단계 JSON, 작업 메모 갱신, 채팅 답, 절 쓰기·고쳐 쓰기)을
학습 데이터에 넣고, 사람 검수를 거친 뒤 같은 네 묶음으로 학습 전후를 잰다(ADR-0069, 6.3.2 절).

글자 지연은 보내기 간격 300ms 안에서 중앙값 0.2초 남짓이고, 끊김·재연결·동시 입력에서도 잃은 글자가 없었다. 서버 쪽 동작(칸 잡기, 판 번호,
충돌 사본, 상한, 파일 써 넣기 등)은 자동 시험 47개로 지킨다.

확인했고(표의 「운영 세 창」 줄) 글자 지연 분포는 재지 않았다.

큰 문서는 가장 큰 공통 양식을 이어 붙인 합성 문서(53쪽 필드 157 · 163쪽 314 · 451쪽 942, 그림 66, 지어낸 글)로 쟀다. 처음 구조는 긴 절에서
무너졌다. 줄바꿈이 칸 안 줄 나눔으로 들어가 고치면 절이 한 문단으로 붙어 기안기가 한 글자마다 그 문단을 다시 배치했고, 칸 글 전체를
주고받았으며, 5만 자 상한에서 글이 잘렸다. 줄바꿈을 문단으로 바꾸고, 상한 대신 초과를 거절하고, 바뀐 부분만 주고받고, 받은 칸을 30ms

## 5.6 서빙 속도

생성 모델 27B 는 젯슨 AGX 토르[11] 두 대에서 vLLM[9] 으로 서빙한다. 정밀도와 디코딩 방식에 따른 속도는 [표 5-22] 와 같다.

| 단계 | 요청 하나 초당 토큰 | 판독 5쪽 | 검토 1건 | 출처 |
|---|---|---|---|---|
| bf16 원본 | 2.4~4.5 | 128초 | 225초 | ADR-0023 |
| NVFP4[12] 양자화 | 10.4~10.8 | 29초 | 82초 | ADR-0023 |
| NVFP4 + MTP[14] 추측 디코딩[13](검토 장비) | 10.6 → 23.8(2.25배, 평균 수용 길이 2.2) | — | — | 실험 로그 16절 |
| NVFP4 + MTP 추측 디코딩(답 장비) | 약 12 → 24.6 | — | — | 실험 로그 16절 |

[표 5-22] 27B 서빙 정밀도와 추측 디코딩

NVFP4 판은 판독 내용이 bf16 과 같았다. 추측 디코딩은 본 모델이 짐작한 토큰을 검증해 받아들이므로 출력 분포가 바뀌지 않으며, 켠 뒤에도
갈래 판정 표본 50의 규칙 일치·빈칸 채움(0.92 · 0.96)과 답 근거의 정답 문서(0.8)가 같았고 갈래 판정 한 건은 4.4초에서 2.8초가 됐다. 추측
디코딩 속도는 시험 문장 3개로 잰 값이다.

답 전체 시간 중앙값이 기준 v1 134초에서 v2 16.6초로 준 것은 답 꼴 정리(평균 약 1,200 토큰이던 답을 600자 안팎으로)와 추측 디코딩이 함께 낸
결과라 둘을 가르지 않았다. SFT 병합본은 답이 짧아져 문항당 시간이 29.6초에서 16.8초로 줄었다(20문항, ADR-0069).

추측 디코딩을 켤 때 GPU 메모리 비율 0.35(43GB)가 시작 시점의 빈 메모리(36GB)보다 커 엔진이 뜨지 못했고 검토·판독이 약 25분 멈췄다. 비율을
0.28(가중치 약 16GB + 캐시 약 27만 토큰)로 낮춰 띄우고, 켜는 스크립트와 되돌리는 스크립트를 함께 두었다.

학교 원본은 원본 장부로 따라가며 걸러 반입했다(5.3.3절). 지난 문서의 한글 양식은 특정 파일·사업을 지목하는 규칙 없이 장부와 본문에서 잰
값만으로 공통 양식과 지난 사업 문서로 나눴다. 정리는 계획 파일의 지문이 그대로일 때만 돌고, 바뀔 줄을 먼저 백업해 1주 지켜본 뒤 지운다.

### 5.7.4 측정이 거짓 수치를 낸 사례

9-21 에는 측정 세 번이 무효가 됐다. 서빙 장비 설정을 읽지 않은 측정이 리랭커와 질의 임베딩을 CPU 바탕 모델로 조용히 대체해 운영 구성 값이
0.1 낮게 나왔다(5.1.1). 9-22 재색인 때는 기본 모델이 KURE-v1 로 돌아가 색인과 질의 모델이 어긋났고 서빙 점검이 잡았다. 5.4.5 의
어댑터가 서빙에 붙지 않은 사례도 같다. 세 경우 모두 값만으로는 그럴듯했고, 실제로 답한 모델을 함께 기록하는 절차로 잡혔다.

## 5.9 평가의 한계

이 장의 값은 다음 한계 안에서 읽어야 한다.

- 시험지의 성질. 규정 검색의 R@k 는 27B 로 만든 합성 질의로 자기 조각을 찾는 측정이라 절대치가 낙관적이다. GraphRAG 와 기준 v2 의 시험지는
  그래프에서 자동으로 뽑은 절·관계 질문이라 실제 담당자 질문과 다르다. 사람이 쓴 골드셋(평가 계획의 200~500문항)으로 잰 값은 아직 없다.
- 표본 크기. 기준 v2 의 답은 30문, 문서 작성 시나리오는 판마다 3회다. 답이 10문일 때 「근거에 정답 문서」 는 잴 때마다 0.5~0.8 사이로
  흔들렸고, 양식 만들기 묶음은 같은 판의 회차 차이가 판 차이만큼 컸다.
- 자기 채점. 문서 작성 채점 점수와 SFT 비교의 나은 답 고르기는 같은 27B 계열 모델이 매겨 판끼리 비교하는 데만 썼다. 사람 판정은 GraphRAG
  판정의 10문 대조뿐이다.
- 정확도 미측정. 서류 갈래 판정과 사업 재판정은 규칙과의 일치율과 옮긴 건수만 있고, 사람 정답 대비 정확도는 미측정이다. 학습 전 측정
  30건의 문항 구성과 통과 기준은 학습 장비 기록에 있어 저장소에서는 미확인이다.
- 개인정보. 잔여 0 은 정규식 검사 결과이며 완전 제거를 뜻하지 않는다.
- 공동 편집. 지연 값(큰 문서 포함)은 헤드리스 크롬 세 창의 측정이다. 실브라우저 세 칸 동시 편집은 동작만 확인했고(5.8.1 절) 지연은 재지
  않았다.
- 서빙. 속도 값은 대부분 한 번에 한 요청을 보낸 측정이라, 여러 사람이 동시에 쓰는 부하에서의 지연은 미측정이다.
