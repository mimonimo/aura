# 초록

국고사업 공고, 사업계획서, 실적보고서, 규정 같은 대학 행정 문서에는 개인정보와 기관 내부 정보가 들어 있어
상용 클라우드 AI 서비스에 보낼 수 없으며, 담당자는 지난 문서를 직접 찾아 읽고 옮겨 적는다. 본 프로젝트는 교내 장비만으로 동작하는 문서 처리
플랫폼 AURA를 구현하였다. 장비는 GPU가 없는 운영 서버 한 대, 모델 서빙용 NVIDIA Jetson AGX Thor 두 대, 원본 보관·일괄 처리·학습용 NVIDIA DGX 한 대로 구성된다.

AURA는 디지털 PDF, 스캔 문서, 사진, 한글(HWP·HWPX), 오피스 파일을 표 구조를 보존하며 읽고, Presidio와 한국형 패턴 인식기 8종으로 개인정보를 탐지한다.
검색은 Kiwi 형태소 분석 기반 어휘 검색과 의미 검색을 순위 융합(RRF)으로 결합하고, 교내 문서로 학습한
KURE-v1 임베딩과 bge-reranker-v2-m3 리랭커를 사용한다. 교내 문서 약 3만 5천 건은 사업·연차·문서·절을 잇는 지식 그래프로 구성하고, 그 온톨로지를 OWL·SHACL로 검사하였다.
오픈 모델 Qwen3.8-27B를 vLLM과 NVFP4로 서빙하며, 이 모델이 질문을 온톨로지 용어로 해석해 그래프로 검색 범위를 좁히자 절 질문에서 정답 문서가
상위 5개 안에 드는 비율이 전문 검색의 18%에서 70%로 올랐다. 답은 모델에 제공한 근거만 인용하며, 근거에 없는 숫자는 코드가 따로 표시한다.
문서 작업 에이전트는 도구를 선택해 절을 작성하고 수정하며, 원본 HWPX 서식을 유지한 채 내용을 채운다. 또한 웹 한글 기안기에서 사람과 칸 단위로 함께 편집하며,
이때 한 화면에서 입력한 글자가 다른 화면에 나타나기까지의 지연은 중앙값 221ms이다.

생성 모델의 지도 학습(SFT)은 더 큰 모델에 적용하기 위한 실험으로, 학습 절차와 데이터를 작성 모델 27B에서 검증하였다. 교내 실문서 학습쌍 4,434쌍으로 학습하자 시험 문항의 정답 겹침(chrF)이
27.9에서 36.6으로 오르고, 질문에 없는 숫자가 든 답의 비율이 4.1%에서 0%로 줄었다. 반면 학습쌍이 한 가지 형식뿐이어서 에이전트 단계의 JSON 요청에도 학습한 형식으로 답하는
문제가 드러났으므로, 더 큰 모델에서는 플랫폼의 요청 형식까지 학습 데이터에 포함한다. AURA의 산출물은 담당자가 검토해 완성하는 초안이다.

주제어: 온프레미스 LLM, 검색 증강 생성, 지식 그래프, 온톨로지, 문서 작업 에이전트, 행정 문서, HWPX, 공동 편집
