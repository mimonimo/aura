# Abstract

대학 행정 부서가 다루는 국고사업 공고, 사업계획서, 실적보고서, 교내 규정은 양이 많고 흩어져 있으며 사업명과 서식이 해마다 바뀐다.
대학에 재정을 지원하는 중앙정부 부처·기관만 34곳에 이르고, 2025년에는 5개 재정지원사업이 RISE로 통합되었다. 그래서 담당자는 흩어진 지난 문서를
직접 찾아 읽고 옮겨 적으며 새 문서를 작성해 왔다. 일반 지식 근로자도 근무 시간의 약 19%를 업무에 필요한 정보를 찾는 데 쓰는 것으로 조사되었다.
그러나 행정 문서에는 개인정보와 기관 내부 정보가 포함되어 있어, 입력한 문서가 외부 서버로 전송되는 상용 AI 서비스를 이용하기 어렵다. 개인정보
보호법은 개인정보를 국외 서버로 옮길 때 별도 요건을 두고 있고, 국가정보원의 생성형 AI 보안 가이드라인도 공공기관이 내부망에 자체 구축한 AI 모델을
쓰도록 권고한다. 이에 본 연구는 교내 로컬 LLM으로
운영되는 행정 문서 처리 플랫폼 AURA를 개발하였다. 문서는 학교 밖으로 나가지 않으며, 플랫폼은 운영 서버 1대, 모델 서빙 장비 2대(NVIDIA Jetson AGX Thor),
학습 장비 1대(NVIDIA DGX)에서 동작하고, 로컬 LLM(Qwen3.8-27B)을 비롯한 모든 모델을 vLLM으로 학교 안에서 서빙한다.

AURA는 PDF, 스캔 문서, 한글(HWP·HWPX), 오피스 파일 등 형식이 제각각인 교내 문서 약 3만 5천 건을 표 구조를 살려 읽고, 개인정보를 마스킹한 뒤
사업·연차·문서·절을 연결한 지식 그래프로 정리한다. 질문을 받으면 로컬 LLM이 질문에서 사업명과 연도, 문서 종류를 해석하고, 온톨로지 기반 GraphRAG로
검색 범위를 먼저 좁힌 뒤 하이브리드 검색으로 근거를 찾아 출처와 함께 제시한다. 근거에 없는 숫자는 코드가 따로 표시해 담당자가 확인하게 한다.
문서 작성 에이전트는 이 근거로 양식의 각 절을 작성하며, 맞는 양식이 없으면 양식부터 설계하고, 완성본은 원본 한글 서식을 그대로 유지한다.
담당자와 에이전트는 웹 한글 기안기에서 한 문서를 함께 편집할 수 있으며, 한 사람이 입력한 글은 0.2초 안에 다른 사람의 화면에 나타난다.

평가 결과, GraphRAG에 LLM 질문 해석을 더한 AURA의 방식은 일반 RAG보다 정답 문서를 더 잘 찾았다. 교내 문서로 만든 질문 144개에서 질문한 내용을
상위 5건 안에 찾아오는 비율은 47%에서 93%로, 그 내용을 근거로 답한 비율은 50%에서 100%로 높아졌다. 특히 옛 사업 이름으로 후속 사업을 묻는
질문에서 차이가 커, 찾아오는 비율이 42%에서 100%로 높아졌다. 또한 생성 모델을 교내 실제 문서로 만든 학습 데이터 4,434쌍으로 추가 학습(SFT)한 결과,
답변이 정답 글에 더 가까워지고(chrF 27.9 → 36.6) 질문에 없는 숫자를 쓰는 답이 사라져(4.1% → 0%) 답변 품질이 좋아졌다.

이는 교내 장비만으로도 행정 문서의 검색과 작성을 지원할 수 있음을 보여 준다. 플랫폼은 모델 이름과 문맥 길이를 설정만으로 바꾸도록 설계하였으므로,
향후 교직원의 시범 운영으로 효과를 검증한 뒤 더 큰 모델로 교체해 같은 학습 절차를 적용하고, 다른 부서와 기관으로 확대하여 실제 학교 행정에 도입할 수 있다.
AURA가 만드는 결과는 모두 담당자가 검토해 완성하는 초안이다.
