# 부록. AURA 사용 설명서

이 부록은 AURA 를 처음 쓰는 사람이 화면을 따라가며 일을 끝낼 수 있게 쓴 사용 설명서다. 앞부분은 역할별로 처음 해 볼 일을 짧게 보이고, 가운데는 실제
업무 장면(사업계획서 초안 만들기, 지난 사업 문서 다시 쓰기, 여럿이 한 보고서 쓰기, 규정 묻기)을 처음부터 끝까지 따라가며, 뒷부분은 화면별 기능표,
관리자 화면, 자주 묻는 질문, 문제 해결, 용어 풀이를 둔다.

적는 방식은 다음과 같다.

- 화면 이름과 단추 이름은 화면에 적힌 그대로 「」 로 묶는다. 예: 「새 채팅」, 「파일 가져오기」.
- 화면을 찾아가는 길은 「사이드바 → 문서함 → 공통 → 공통 양식」 처럼 화살표로 잇는다. 괄호 안의 주소(/hwp 등)는 브라우저 주소창에 보이는 경로다.
- 화면 그림은 시험 계정·지어낸 자료로 찍었다(실제 학교 문서·개인 정보 없음).
- 「참고:」 로 시작하는 줄은 알아 두면 편한 점이다.
- [n] 은 본문 99 참고 문헌의 번호다. 부록은 화면 사용법만 다루며 기술 설명은 2~4 장을 본다.
- 화면의 예시 이름(부서·사람·사업)은 모두 시험 환경의 가상 값이다.

## 부록 1. AURA 한눈에 보기

### 1.1 AURA 는 무엇을 하는가

AURA 는 영남이공대학교 교내 행정 문서를 교내 장비 안에서만 읽고, 찾고, 쓰는 플랫폼이다. 문서는 학교 밖 AI 서비스로 나가지 않는다. 할 수 있는 일은
크게 넷이다.

| 하고 싶은 일 | 쓰는 화면 | 한 줄 설명 |
|---|---|---|
| 규정·지난 사업 자료를 묻기 | 「새 채팅」 | 근거 문서를 찾아 출처와 함께 답한다 |
| 문서 찾기와 정리 | 「라이브러리」, 「검색」 | 들어온 문서를 사업·연도·종류로 거르고 원문을 본다 |
| 한글 문서를 함께 쓰기 | 「문서함」, 웹 한글 기안기 | 부서 폴더의 한글 문서를 브라우저에서 열고 여럿이 동시에 고친다 |
| 사업 문서 초안 쓰기 | 프로젝트, 「새 채팅」의 문서 작업 | AURA 가 양식을 고르고 절마다 초안을 쓰며, 사람이 검토해 한글로 내보낸다 |

AURA 가 쓰는 글은 사람이 검토하는 초안이다. 숫자와 최종 판단은 언제나 근거 문서에서 확인한다. 답 아래에도 「수치와 최종 판단은 근거 문서에서
확인하세요.」 라는 문구가 늘 붙어 있다.

### 1.3 계정과 등급

계정 역할은 교직원·학생·관리자 셋이다. 교직원은 다시 작업 권한 등급 넷으로 나뉜다. 등급은 프로젝트를 만들고 진행 현황을 보는 범위를 정하며, 어떤
문서를 찾아볼 수 있는지는 등급이 아니라 소속 부서로 정해진다.

| 등급 | 하는 일 | 할 수 있는 것 |
|---|---|---|
| 일반 | 공유받은 일에 참여 | 질문·검색, 공유받은 프로젝트에서 작업. 새 프로젝트는 만들지 않는다(「프로젝트 만들기」 권한을 받으면 만든다) |
| 행정 담당자 | 사업의 행정 지원 | 사업 책임자와 같은 단계. 프로젝트를 만들고 맡은 사업의 진행을 본다 |
| 사업 책임자 | 세부 사업 책임 | 프로젝트를 만들고 진행하며, 자기가 책임자인 프로젝트·사업의 진행 현황을 본다. 같은 부서 일반 직원에게 「프로젝트 만들기」 권한을 줄 수 있다 |
| 총괄 책임자 | 부서장 | 자기 부서와 그 아래 팀·센터 프로젝트의 진행 현황을 모두 보고 사업 책임자를 정한다. 부서 드라이브를 연결한다 |
| 관리자 | 시스템 전체 관리(최대 2명) | 모든 화면과 개발 화면 |

[표 부록-2] 교직원 등급

참고: 등급을 정해 두지 않은 교직원 계정은 사업 책임자로 본다.

## 부록 2. 역할별 빠른 시작

### 2.1 교직원 — 처음 10분

1. 브라우저로 AURA 주소에 들어가 「아이디」 와 「비밀번호」 를 넣고 「로그인」 을 누른다.

   [그림 부록-2] 로그인 화면 (그림 docs/images/figures-1025/fA-02-login.jpg)

2. 사이드바 맨 아래 사용자 메뉴를 열어 「설정」 으로 들어간다(/settings).
3. 처음 받은 비밀번호라면 「비밀번호 변경」 을 눌러 바꾼다(아래 3.1).
4. 같은 화면의 「구글 계정」 카드에서 「구글 계정 연결」 을 눌러 학교 구글 계정(ync.ac.kr)을 잇는다(아래 3.2). 구글 문서 작업본과 드라이브 가져오기에 쓴다.
5. 「문서 편집기」 카드에서 한글 완성본을 열 곳을 「구글 문서」 와 「웹 한글 기안기」 가운데 고른다.
6. 사이드바의 「새 채팅」 을 눌러 첫 질문을 해 본다. 예: 「출장비 정산 기한이 언제야?」
7. 답 아래의 출처를 눌러 오른쪽에 원문 대목이 열리는지 확인한다.
8. 사이드바의 「문서함」 을 눌러 우리 부서 폴더를 열어 본다.

참고: 사이드바 아래에 「AI 미연결 · 답변 대기」 가 보이면 답 모델이 잠시 연결되지 않은 것이다. 질문은 보낼 수 있고, 연결되면 답이 온다.

### 2.2 학생 — 학사 질문하기

학생 계정은 학사 규정을 묻는 대화만 쓴다. 사이드바에는 「새 채팅」 과 「최근 대화」 만 있다.

1. 로그인한 뒤 「새 채팅」 을 누른다. 머리에 「학사 질문」 이 보인다.
2. 빈 화면에 「학사 관련해 무엇이든 물어보세요」 와 예시 질문 네 개가 있다. 예시를 누르거나 입력 칸(「학사 관련 질문을 입력하세요」)에 직접 쓴다.
3. 「보내기」 를 누르면 학생에게 공개된 학사 규정만 찾아 답한다.
4. 답 아래 출처를 누르면 규정의 해당 대목을 본다.
5. 비밀번호는 「설정」 의 「비밀번호」 카드에서 「비밀번호 변경」 으로 바꾼다.

[그림 부록-3] 학생 계정의 채팅 화면 (그림 docs/images/figures-1025/fA-03-student-chat.jpg)

참고: 학생은 파일 첨부, 답변 방식 고르기, 문서 패널이 없다. 라이브러리·문서함 같은 주소로 들어가면 「학생 계정은 학사 질문 대화만 씁니다」 가 뜬다.

### 2.3 일반 직원 — 공유받은 프로젝트에서 일하기

1. 동료가 프로젝트를 나와 나누면 사이드바 「공유받은 프로젝트」 에 그 프로젝트가 생긴다. 줄 끝에 나눈 사람 이름이 보인다.
2. 눌러 열면 머리 아래 띠에 「○○ 님이 함께 작업하도록 공유한 프로젝트입니다」(또는 참조로 받았으면 「참조로 공유된 ○○ 님의 프로젝트입니다 — 읽기 전용」)가 보인다.
3. 「함께 작업」 으로 받았으면 대화를 열고 작업 문서를 고칠 수 있다. 「참조」 로 받았으면 읽기만 한다.

### 2.4 사업 책임자·행정 담당자 — 프로젝트 만들기

1. 사이드바 「내 프로젝트」 옆 「프로젝트 추가」(+)를 누른다.
2. 「업무」 를 고르고(국고사업·채용·입학·일반 행정), 「자료(선택)」 에 공고나 지난 계획서를 고르면 이름이 저절로 정해진다. 자료가 없으면 「프로젝트 이름」 을 쓴다.
3. 필요하면 「사업단(선택)」, 「마감일(선택)」 을 넣고 「만들기」 를 누른다.
4. 프로젝트 화면이 열리면 부록 3.1 의 순서로 초안을 만든다.

### 2.5 총괄 책임자 — 부서 정비

1. 사이드바 「조직 관리」 → 왼쪽 트리에서 부서를 고르고 「구성원」 탭에서 사람을 체크한 뒤 「등급 바꾸기」(「일반」·「행정 담당자」·「사업 책임자」)를 누른다. 추가 권한은 줄 끝 … › 「추가 권한」.
2. 「부서 설정」 탭의 부서 드라이브에서 「구글 드라이브 연결」 을 눌러 부서가 함께 쓸 학교 계정(부서 공용 메일 권장)으로 로그인한다.
3. 사업 하나를 열어 「진행 현황」 탭으로 부서 프로젝트의 진행을 본다.

### 2.6 관리자 — 첫 점검

1. 사이드바 아래 「개발 현황」 을 눌러 개발 화면으로 들어간다(/dev).
2. 「사용자·계정」 에서 계정·부서를 확인하고, 「학교 계정 연결 현황」 에서 구글 앱이 등록됐는지 본다.
3. 「도구·모델 연결」 의 「LLM 연결」 에서 서버별 「연결 확인」 을 누른다.
4. 「RAG 공간」 에서 공통·부서·학생 RAG 의 문서 수를 확인한다.
5. 업무 화면으로 돌아가(「업무 화면으로」) 「테스트 보기」 로 다른 계정이 보는 범위를 확인한다(부록 5.2).

## 부록 3. 업무 장면별 따라 하기

### 3.1 사업계획서 초안을 처음부터 끝까지 만들기

장면: 사업 책임자가 새 국고사업 공고에 맞춰 사업계획서 초안을 만든다. 공고 파일이 있고, 작년 계획서가 라이브러리에 있다.

1단계. 프로젝트 만들기

1. 사이드바 「내 프로젝트」 옆 「프로젝트 추가」(+)를 누른다.
2. 「업무」 에서 「국고사업」 을 고른다.
3. 「자료(선택)」 에서 이번 공고를 고른다. 이름이 자동으로 정해진다.
4. 「마감일(선택)」 을 넣고 「만들기」 를 누른다.

   [그림 부록-4] 「프로젝트 추가」 창 (그림 docs/images/figures-1025/f4-16-project-add-dialog.jpg)

2단계. 재료 모으기

1. 프로젝트 화면(/project/번호)의 「프로젝트 문서」 에서 「문서 추가」 를 누른다.
2. 공고 원문은 「내 컴퓨터에서 올리기」, 부서 폴더나 드라이브의 파일은 「문서함·구글 드라이브에서 가져오기」, 규정·지침은 「문서함 문서를 기준으로 연결」 로 넣는다.
3. 넣은 문서는 「첨부 문서」·「참고 문서」·「기준 문서」 로 나뉘어 보인다. 줄마다 「기준으로 쓰기」·「기준에서 빼기」 로 바꿀 수 있다.
4. 「관련 지난 사업」 의 「지난 사업 연결」 을 눌러 작년 사업을 잇는다.
5. 「작성 원칙」 에 지켜야 할 점을 한 줄씩 적고 「추가」 를 누른다. 예: 「근거 조항 함께 적기」, 「예산은 백만원 단위」.

   [그림 부록-5] 프로젝트 화면 — 프로젝트 문서, 작성 원칙, 관련 지난 사업 (그림 docs/images/figures-1025/f4-17-project-chat-docs.jpg)

참고: 프로젝트에 올린 문서는 그 프로젝트의 대화에서 다른 문서보다 먼저 근거로 쓰인다.

3단계. 대화로 초안 요청하기

1. 프로젝트 화면 위 입력 칸(「… 에서 새 대화 시작」)에 요청을 쓰고 「대화 시작」 을 누른다. 예: 「이 공고로 사업계획서 초안 써 줘. 대상은 1학년, 예산은 5천만원, 기간은 내년 3월부터 12월까지.」
2. 채팅 화면이 열린다. 입력 칸 왼쪽 「답변 방식」 이 「문서 작업」 인지 확인한다(기본값).
3. AURA 가 먼저 쓸 양식을 정한다. 프로젝트에 작성 서식이 있으면 그것을, 없으면 공통 양식 가운데 맞는 것을 고르고, 맞는 양식이 아예 없으면 양식부터 만든다.
4. 오른쪽 문서 패널에 작업 문서가 생기고, 머리에 「AURA · 「절 이름」 작성 중」 이 보이며 절이 하나씩 채워진다.
5. 답 아래 「작업 내역」 을 펼치면 AURA 가 어떤 근거를 찾고 어떤 절을 썼는지 단계별로 보인다.

   [그림 부록-6] 대화와 작업 문서를 나란히 둔 화면 — AURA 가 절을 쓰는 중 (그림 docs/images/01-chat-hwp-agent.jpg)

4단계. 모르는 값 채우기

1. AURA 가 자료에서 찾지 못한 값(예: 사업단장 이름, 협약 기관 수)은 답 안의 「필요한 값 입력으로 이동」 단추로 모인다.
2. 「필요한 값 입력」 칸에 값을 넣는다. Enter 는 다음 칸, Shift+Enter 는 줄바꿈이다.
3. 모르는 값은 체크한 뒤 「선택한 줄 자료에서 찾기」 를 누르면 프로젝트 문서에서 찾아 제안한다. 제안된 값은 「확인」 하거나 「고치기」 한다.
4. 「저장」 을 누른다. 빈 칸은 다음에 다시 묻는다.

   [그림 부록-7] 「필요한 값 입력」 칸 (그림 docs/images/figures-1025/f4-19-needed-values.jpg)

5단계. 고쳐 쓰기와 모양 바꾸기

1. 대화로 고칠 점을 말한다. 예: 「2번 절 더 구체적으로」, 「추진 일정은 표로」, 「용지 가로로, 쪽 번호는 아래 가운데」.
2. AURA 는 이미 쓴 절을 다시 읽고 지시대로 절 전체를 고쳐 쓴다. 디자인 지시는 문서에 바로 반영된다.
3. 직접 고치고 싶으면 문서 패널에서 기안기의 「편집 도구」 를 눌러 펼친 뒤 고친다.

참고: 근거에 없는 숫자는 AURA 가 「○○」 로 가려 둔다. 지어낸 숫자를 막기 위한 것이므로 값을 알면 직접 넣는다.

6단계. 검토 받기

1. 「이 초안 검토해 줘」 처럼 요청하면 AURA 가 작성방법·배점 항목에 비추어 빠진 점을 알려 준다.
2. 동료에게 보이려면 프로젝트 머리의 공유 단추(「공유 안 함」)를 눌러 나눈다(부록 4.6).

7단계. 한글 파일로 내보내기

1. 대화에 「한글 파일로 내보내 줘」 라고 쓴다. AURA 가 작업본 내용을 원본 한글 서식 그대로 채운 완성본을 만든다.
2. 웹 한글 기안기에서 연 문서라면 머리줄 「⋯」 → 「내려받기」 에서 「한글(hwpx)」·「한글(hwp)」·「PDF」·「Word(docx)」 가운데 고른다.
3. 최종본을 드라이브에 두려면 「⋯」 → 「구글 드라이브에 올리기」 를 누른다.

   [그림 부록-8] 기안기 「⋯」 메뉴 — 다른 이름으로 저장, 문서 틀 고치기, 내려받기, 구글 드라이브에 올리기 (그림 docs/images/figures-1025/f4-24-editor-more-menu.jpg)

참고: 원본이 .hwp 인 양식은 hwpx 로 바꾸어 다룬다. 문서함에 올릴 때 .hwp 와 .hwpx 모두 받는다.

### 3.2 지난 사업 문서를 찾아 다시 쓰기

장면: 행정 담당자가 작년 결과보고서 양식을 찾아 올해 판으로 쓰려 한다.

방법 가. 문서함에서 양식 찾기

1. 사이드바 「문서함」(/hwp)을 연다.
2. 왼쪽 「부서 폴더」 에서 「공통」 을 열고 「지난 사업 문서」 → 사업 이름 → 목적 폴더로 들어간다. 어디서나 쓰는 빈 양식은 「공통」 → 「공통 양식」 에 있다.
3. 잠긴 양식 줄의 「사본 만들기」 를 누른다.
4. 「사본을 어디에 만들까요」 창에서 우리 부서 폴더, 「내 폴더」, 또는 프로젝트를 고르고 「사본 만들기」 를 누른다. 사본이 기안기로 열린다.

   [그림 부록-9] 문서함 — 왼쪽 위치(즐겨찾기·최근 폴더·내 폴더·부서 폴더·구글 드라이브)와 오른쪽 목록 (그림 docs/images/03-hwp-box.jpg)

   [그림 부록-10] 「사본을 어디에 만들까요」 창 (그림 docs/images/figures-1025/f4-23-copy-where-dialog.jpg)

참고: 위쪽의 「양식으로 시작」 을 누르면 양식 이름으로 찾아 바로 사본을 만들 수 있다.

방법 나. 라이브러리에서 지난 문서 찾기

1. 사이드바 「라이브러리」 를 연다.
2. 왼쪽 「사업별로 보기」 에서 사업 이름을 거르고 고른다.
3. 위 거르기에서 「모든 종류」 를 「결과보고서」 같은 종류로, 「모든 기간」 을 기간으로 좁힌다. 찾기 칸에 낱말을 넣고 「본문까지」 를 켜면 본문 낱말로도 찾는다.
4. 문서를 눌러 문서 화면(/doc/번호)을 연다. 「원본 열기」 로 원본을, 「내려받기」 로 파일을 받는다. 한글 양식이면 「기안기로 작업」 으로 바로 연다.

   [그림 부록-11] 라이브러리 — 쓰임새 칩, 업무·종류 거르기, 사업별로 보기 (그림 docs/images/04-library.jpg)

방법 다. 지난 사업에서 찾기

1. 프로젝트 머리의 「지난 사업」 링크, 원본 보관소의 「지난 사업에서 찾기」, 검색 결과의 「지난 사업에서 찾기 →」 가운데 하나로 「지난 사업」 화면(/projects/archived)을 연다.
2. 「사업명」·「수행 연도」·「사업단」 으로 거르고 「검색」 을 누른다.
3. 줄의 「문서 보기」 로 그 사업 문서를 보고, 「참조 연결」 로 지금 프로젝트에 잇는다.

방법 라. 대화로 묻기

1. 「새 채팅」 에서 「작년 LINC 3.0 결과보고서에서 취업 성과 부분 찾아 줘」 처럼 사업·연도·문서 종류를 넣어 묻는다.
2. 답의 출처를 눌러 원문 대목을 확인한다.
3. 「이 문서로 작업」 을 눌러 작업 문서로 가져온다.

참고: 질문에 문서 이름을 「」 로 묶어 적으면 그 문서로 좁혀 찾는다. 예: 「「2025 사업계획서」 의 추진 체계 절 보여 줘」.

### 3.3 여럿이 한 보고서를 동시에 쓰기

장면: 한 부서의 세 사람이 같은 실적보고서의 서로 다른 곳을 동시에 고친다. AURA 도 한 절을 맡는다. 제목·소제목·표 칸까지 문서 전체가 칸으로 나뉘어 있어 어디를 고쳐도 같다.

1단계. 같은 문서 열기

1. 세 사람 모두 「문서함」 에서 같은 문서를 연다. 문서가 웹 한글 기안기로 열린다(/hwp/번호/edit).
2. 머리줄 오른쪽에 같이 있는 사람이 동그라미로 보인다. 맨 끝이 「나」 이고, 다른 사람이 넷을 넘으면 「+N」 이 붙는다.

   [그림 부록-12] 기안기 머리줄 — 문서함, 문서 이름과 폴더 경로, 저장 상태, 같이 있는 사람 동그라미, 편집 도구, 「⋯」 (그림 docs/images/figures-1025/fA-12-editor-header.jpg)

2단계. 누가 어디서 쓰는지 보기

1. 동그라미에 마우스를 올리거나 「+N」 을 누르면 같이 있는 사람 목록이 열린다. 줄마다 「쓰는 중 · 칸 이름」 또는 「보는 중 · 칸 이름」 이 보인다.
2. 줄이나 동그라미를 누르면 화면이 그 사람을 따라간다. 내가 치거나 직접 굴리면 멈춘다.
3. 문서 안에서 남이 쓰는 칸은 옅은 바탕(여러 줄 칸은 왼쪽 옅은 막대), 칸 끝의 색 커서, 종이 여백의 이름표로 보인다.

   [그림 부록-13] 남이 쓰는 칸 표시 — 옅은 바탕, 색 커서, 이름표, 같이 있는 사람 목록 (그림 docs/images/figures-1025/g01-coedit-pane-people.jpg)

3단계. 칸 잡기와 놓기

1. 아무 데나 누르고 글을 쓰기 시작하면 그 자리의 칸은 내 것이 된다. 따로 잡는 단추는 없고, 첫 글자를 치는 순간 잡힌다.
2. 다른 칸으로 옮기면 쓰던 글을 다 보낸 뒤 앞 칸은 저절로 놓인다. 창을 닫아도 곧바로 놓인다.
3. 칸을 눌러 보기만 하면 잡지 않고 목록에 「보는 중」 으로만 나온다.
4. 한동안 쓰지 않으면 「「칸」 칸을 N초 동안 고치지 않으면 다른 사람도 쓸 수 있게 풀려요」 가 뜬다. 계속 쓸 것이면 「계속 쓰기」 를 누른다.
5. 다른 사람이 내 칸을 기다리면 「○○ 님이 「칸」 칸을 쓰려고 기다려요」 가 뜬다. 다 썼으면 「넘겨주기」 를 누른다.

4단계. 막혔을 때

1. 남이 쓰는 칸에 치면 글은 들어가지 않고 그 칸의 이름표가 잠깐 흔들린다. 내 글이 남의 글과 섞이지 않게 막아 둔 것이다. 그 칸이 걸친 범위를 골랐을 때는 서식 단추도 막힌다.
2. 쓰던 사람이 놓으면 이름표가 사라지고 바로 쓸 수 있다.
3. 연결이 끊기면 저장 상태가 「오프라인 — 연결되면 저장」 으로 바뀐다. 그동안 쓴 글은 브라우저에 두었다가 다시 이어지면 보낸다.
4. 드물게 같은 칸에 두 사람의 글이 겹치면 내 글은 버리지 않고 사본으로 둔다. 「… 내 글은 사본으로 따로 두었어요」 의 「내 글 보기」, 또는 「⋯」 → 「충돌로 따로 둔 내 글」 에서 꺼내 「복사」 한다.

5단계. 서식과 구조 고치기

1. 글자 색·크기·글꼴·굵게 같은 서식은 기안기 툴바로 바꾸면 그대로 다른 사람 화면에도 간다. 여러 칸을 골라 한꺼번에 바꿔도 된다.
2. 칸을 넘어 드래그해 고르고 서식째 복사·붙여넣기를 할 수 있다.
3. 표에 줄을 더하거나 그림·용지를 바꾸는 일, 칸을 넘는 붙여넣기는 화면이 알아채 저절로 「문서 틀 고치기」 로 저장한다. 그때만 다른 사람 화면이 새 판으로 바뀌고, 그들의 칸 글은 그대로 남는다.
4. 직접 시작하려면 머리줄 「⋯」 → 「문서 틀 고치기」 를 누르고, 다 하면 머리줄의 「끝내기」 를 누른다. 한 번에 한 사람만 한다.

6단계. AURA 와 함께 쓰기

1. 문서를 대화의 작업 문서로 가져온 뒤(부록 4.2 의 「파일 가져오기」) 「3번 칸은 AURA 가 채워 줘」 처럼 요청한다.
2. AURA 도 한 사람처럼 칸을 잡고, 글이 한 줄씩 써 내려가는 것이 모든 화면에 보인다. 동그라미는 「A」, 이름표는 「AURA (시킨 사람 요청)」 이다.
3. 사람이 잡고 있는 칸은 AURA 가 쓰지 않는다.

7단계. 저장 확인

1. 머리줄 저장 상태가 「저장됨」 이면 서버에 들어간 것이다. 고치는 중에는 「고치는 중」·「저장 중」 이 잠깐 보인다.
2. 저장된 칸 글은 몇 초 뒤 한글 파일에도 써 넣어진다. 앞 판은 부서 폴더의 판 기록에 남는다.

참고: 문서는 처음 열 때 칸으로 감싸진다. 아주 큰 문서처럼 감싸지 않은 문서는 한 사람씩 고친다. 나중에 연 사람에게는 「○○ 님이 편집 중 — 보기 전용, 끝나면 바로 이어서 고칠 수 있습니다」 가 보인다.

[그림 부록-14] 칸이 없는 문서를 나중에 연 사람의 화면 — 보기 전용 (그림 docs/images/02-hwp-edit-lock.jpg)

참고: 공통 양식은 아무도 바로 고치지 않는다. 「사본 만들기」 로 사본을 만든 뒤 쓴다. 저장 상태에 「공통 양식 — 보기 전용」 이 보인다.

### 3.4 규정 질문하기

장면: 교직원이 연구년 신청 자격을 묻는다.

1. 「새 채팅」 을 누른다.
2. 「답변 방식」 이 「문서 작업」 인지 확인한다. 이 방식이 교내 등록 문서를 근거로 답한다.
3. 「연구년 신청 자격이 어떻게 돼?」 라고 쓰고 「보내기」 를 누른다.
4. 답은 첫머리 1~3문장의 답, 근거 요점, 출처 순이다. 출처를 누르면 오른쪽에 규정 원문의 그 조항이 열린다.
5. 답 앞의 「생각 과정 펼치기」 를 누르면 AURA 가 [1단계 질문 파악] → [2단계 근거 확인] → [3단계 답 구성] 으로 따진 과정이 보인다.
6. 답이 맞으면 「도움됨」, 아쉬우면 「아쉬움」 을 눌러 까닭(「근거 문서가 틀림」·「숫자·사실이 틀림」·「질문과 다른 답」·「너무 길거나 짧음」·「느림」·「기타」)을 고르고 「보내기」 를 누른다.

[그림 부록-15] 규정 질문의 답 — 출처와 오른쪽 원문 대목 (그림 docs/images/figures-1025/fA-15-regulation-answer-source.jpg)

[그림 부록-16] 「생각 과정」 을 펼친 답과 입력 칸 아래 문맥 사용량 (그림 docs/images/figures-1025/f4-15-answer-sources-thinking.jpg)

### 3.5 기안문·출장 보고처럼 짧은 문서 빨리 쓰기

1. 「새 채팅」 에서 「다음 주 서울 출장 보고서 써 줘. 출장지는 ○○, 목적은 협약 회의」 처럼 요청한다.
2. AURA 가 공통 양식 가운데 출장 보고 양식을 골라 작업 문서를 만들고 채운다.
3. 오른쪽 문서 패널에서 결과를 보고 고칠 점을 대화로 말하거나 직접 고친다.
4. 「한글 파일로 내보내 줘」 로 완성본을 받는다.

비밀번호 바꾸기

1. 「비밀번호 변경」 을 누른다.
2. 「현재 비밀번호」 와 「새 비밀번호」 를 넣는다. 「보기」 를 누르면 친 글자가 보인다.

1. 「구글 계정」 카드의 「구글 계정 연결」 을 누른다.
2. 구글 로그인 창에서 학교 계정으로 로그인하고 권한을 허용한다. 「ync.ac.kr 계정만 연결할 수 있습니다.」 — 개인 계정은 연결되지 않는다.
3. 돌아오면 카드에 연결된 계정과 「작성하는 문서는 이 계정의 드라이브에 만들어집니다」 안내가 보인다.

### 4.2 채팅

채팅 화면(「새 채팅」, /chat 또는 /chat/번호)은 대화 칸과 오른쪽 문서 패널로 되어 있다.

답변 방식 셋

입력 칸 옆 「답변 방식」 에서 고른다. 학생에게는 이 고르기가 없고 늘 교내 문서로 답한다.

| 방식 | 언제 쓰나 | 무엇이 밖으로 나가나 |
|---|---|---|
| 「문서 작업」(기본) | 규정·사업 문서를 근거로 답을 받거나 작업 문서를 쓰고 고칠 때 | 없음. 교내 등록 문서만 찾는다 |
| 「기본 대화」 | 문서와 상관없는 일반 질문(문장 다듬기, 개념 설명) | 없음. 문서 없이 모델이 답하고 출처가 없다고 밝힌다 |
| 「웹 검색」 | 공개된 바깥 정보(정부 보도자료, 일반 지식)가 필요할 때 | 질문 글만 웹 검색에 보낸다. 문서·첨부는 나가지 않고, 질문에 개인정보가 있으면 보내지 않는다 |

[표 부록-4] 답변 방식

내 질문 옆에는 그 질문을 보낸 방식이 꼬리표(「문서 작업」·「기본 대화」·「웹 검색」)로 붙는다.

| 입력줄 | 첨부(「파일 또는 사진 첨부」) | 파일을 함께 읽게 한다. 파일을 끌어 놓아도 된다(「파일을 놓으면 첨부됩니다」) |
| 입력줄 | 「보내기」 | 질문을 보낸다. 답을 기다리는 동안 다음 질문을 써 둘 수 있다 |
| 입력줄 오른쪽 | 「문맥 N% 사용」 | 이 대화가 모델 문맥 한도를 얼마나 쓰는지. 누르면 「문맥 관리」 창 |
| 답 위 | 「생각 과정 펼치기」 / 「접기」 | 답 앞의 단계 추론을 본다 |

### 4.3 라이브러리와 원본 보관소

라이브러리(사이드바 「라이브러리」)는 등록한 문서를 찾고 폴더로 묶는 곳이다. 위쪽 탭은 「문서」·「원본 보관소」·「지식그래프」 다.

| 자리 | 단추·거르기 | 하는 일 |
|---|---|---|
| 업무 탭 | 「전체 업무」·「국고사업」·「채용」·「입학」·「일반 행정」 | 업무로 거른다 |
| 쓰임새 칩 | 「전체」·「기준」·「작성·결과」 | 기준 문서(규정·지침·공고)와 작성·결과 문서를 나눠 본다 |
| 올리기 | 「문서 올리기」(「기준」 칩에서는 「기준 등록」) | 파일을 올린다 |
| 거르기 | 「모든 종류」, 찾기 칸, 「본문까지」, 「찾기」 | 종류·제목·접수번호·본문 낱말로 찾는다 |
| 더 거르기 | 「모든 형식」, 「모든 기간」, 「모든 상태」, 정렬, 「조건 지우기」 | 형식·기간·처리 상태로 좁힌다 |
| 왼쪽 | 「폴더」, 「+ 폴더 만들기」, 「사업별로 보기」 | 폴더와 사업으로 묶어 본다 |
| 줄 고르기 | 「할 일 선택…」 → 「적용」 | 고른 문서를 폴더에 담거나 뺀다 |

[표 부록-6] 라이브러리

문서 올리기

1. 「문서 올리기」 를 누른다.
2. 「파일(여러 개 가능)」 에 파일을 고른다.
3. 「폴더」(없으면 「폴더 없이」), 「사업」(없으면 「사업 없음」), 「사업 연도(선택)」, 「업무 갈래」(모르면 「자동으로 정하기」)를 고른다.
4. 「올리기」 를 누른다. 문서는 처리 중을 거쳐 처리 완료가 된다.

참고: 올린 문서의 서류 갈래(공고·계획서·결과보고서 등)와 사업은 AURA 가 본문을 읽고 정한다. 이름도 파일 이름 대신 본문 제목으로 정해진다.

문서 화면(/doc/번호)

| 단추 | 하는 일 |
|---|---|
| 「원본 열기」 | 원본을 본다. 한글·오피스 파일은 열람용 PDF 로 바꿔 보인다 |
| 「내려받기」 | 「원본 파일」·「글자 찾기 되는 PDF」·「워드 파일」·「텍스트」 등으로 받는다 |
| 「기안기로 작업」 | 한글 양식을 웹 한글 기안기로 연다 |

| 「관리」 | 「폴더」, 「공개 범위」, 「사업 정보 다시 찾기」, 「접수번호 수정」, 「문서 삭제」 |
| 「담당자 판정」 | 「승인」·「재검토 요청」·「반려」 |

[표 부록-7] 문서 화면

원본 보관소(/archive)는 학교 원본 파일의 장부다. 왼쪽 「사업별로 보기」·「사업 연도」·「문서 종류」·「처리 상태」 로 거르고, 줄의 「원본 열기」 로 원본을

### 4.4 문서함

문서함(사이드바 「문서함」, /hwp)은 부서 폴더 꼴로 한글 문서를 두고 웹 한글 기안기로 여는 곳이다.

| 자리 | 들어 있는 것 |
|---|---|
| 왼쪽 「위치」 | 「즐겨찾기」, 「최근 폴더」, 「내 폴더」(나만 보는 폴더), 「부서 폴더」, 「구글 드라이브」(「내 드라이브」와 공유 드라이브) |
| 위쪽 단추 | 「새 문서」, 「양식으로 시작」, 「올리기」, 「새 폴더」 |
| 목록 열 | 「이름」·「수정일」·「수정한 사람」. 누가 편집 중이면 「○○ 편집 중」 |
| 파일 줄 | 「사본 만들기」(잠긴 양식), 「내려받기」, 「지우기」 |
| 폴더 줄 | 「이름 바꾸기」, 즐겨찾기 별 |

[표 부록-8] 문서함

자주 하는 일

- 새 폴더: 「새 폴더」 를 누르면 목록에 새 줄이 생기고 바로 이름을 짓는다.
- 즐겨찾기: 폴더 줄의 별을 누른다(「즐겨찾기에 넣기」). 왼쪽 「즐겨찾기」 에 나타난다.
- 내 컴퓨터 파일 넣기: 「올리기」 로 .hwp·.hwpx 파일을 올린다.
- 드라이브 파일 넣기: 왼쪽 「구글 드라이브」 에서 한글 파일 줄의 「가져오기」 를 누르면 지금 폴더에 받아 기안기로 연다.
- 지우기: 줄을 여럿 고르면 「N개 선택」 이 뜬다. 「지우기」 를 누르면 부서 휴지통으로 옮겨지고, 관리자가 되살릴 수 있다.

참고: 공통 양식과 지난 사업 문서는 따로 있는 메뉴가 아니라 「부서 폴더」 → 「공통」 안의 「공통 양식」, 「지난 사업 문서」 폴더다. 양식은 잠겨 있어 「사본 만들기」 로 써야 한다.

참고: 구글 계정을 잇지 않았으면 「구글 드라이브」 자리에 「학교 구글 계정을 연결하면 드라이브도 여기서 봅니다.」 가 보인다.

### 4.5 웹 한글 기안기

웹 한글 기안기는 브라우저에서 한글 문서를 여는 한컴 편집기다[51]. 문서함에서 문서를 누르거나 채팅 문서 패널의 「한글」 쪽에서 연다.

[그림 부록-20] 「편집 도구」 를 펼친 기안기 — 메뉴, 리본, 서식줄 (그림 docs/images/figures-1025/f4-24-editor-more-menu.jpg)

| 자리 | 단추·표시 | 하는 일 |
|---|---|---|
| 머리줄 왼쪽 | 「문서함」(대화 안에서는 「목록」) | 문서함으로 돌아간다 |
| 머리줄 | 문서 이름, 「부서 › 폴더」 | 이름을 눌러 바꾼다 |
| 머리줄 | 저장 상태 | 「불러오는 중」, 「저장됨」, 「저장 중」, 「고치는 중」, 「오프라인 — 연결되면 저장」 등 |
| 머리줄 | 같이 있는 사람 동그라미, 「나」, 「+N」 | 누가 어느 칸에 있는지 |
| 머리줄 | 「편집 도구」 | 메뉴·리본·서식줄을 펼치거나 접는다 |
| 머리줄 | 「⋯」 | 「다른 이름으로 저장」, 「문서 틀 고치기」, 「충돌로 따로 둔 내 글」, 「내려받기」, 「구글 드라이브에 올리기」, 「문서함에서 보기」 |
| 대화 안 | 「전체 보기」, 「문서 패널 닫기」 | 크게 보거나 패널을 닫는다 |

[표 부록-9] 기안기 머리줄

찾기·바꾸기·쪽 설정 같은 편집 기능은 기안기 자체의 창(Ctrl+F, Ctrl+H, 리본)을 그대로 쓴다. 고치면 바로 자동 저장되므로 따로 저장 단추를 누를
필요가 없다.

공동 편집 안내 문구 모음

| 문구 | 뜻 | 할 일 |
|---|---|---|
| 이름표가 흔들림 | 그 칸은 다른 사람이 쓰고 있다 | 다른 곳을 쓰거나 기다린다(이름표가 사라지면 쓸 수 있다) |
| 「N초 안에 이어 쓰지 않으면 이 칸이 다른 사람에게 풀려요」 | 오래 쓰지 않아 곧 풀린다 | 「계속 쓰기」 |
| 「○○ 님이 지금 내 칸을 쓰려고 기다려요」 | 내 칸을 남이 기다린다 | 다 썼으면 「넘겨주기」 |
| 「… 내 글은 사본으로 따로 두었어요」 | 글이 겹쳐 내 글을 사본으로 두었다 | 「내 글 보기」 에서 복사해 다시 넣는다 |
| 「○○ 님이 문서 틀 고치는 중」 | 다른 사람이 표·그림·용지를 고친다 | 칸 안만 쓴다. 저장되면 새 판으로 바뀐다 |
| 「○○ 님이 편집 중 — 보기 전용 …」 | 칸으로 감싸지 않은 문서를 다른 사람이 고친다 | 끝나면 이어서 고친다 |
| 「다시 연결하는 중」, 「오프라인 — 연결되면 저장」 | 연결이 잠깐 또는 20초 넘게 끊겼다 | 그대로 쓰면 이어질 때 보낸다 |
| 「○○ 님이 이 문서를 새로 저장했습니다 …」 | 다른 사람이 문서 전체를 새로 저장했다 | 「다시 불러오기」 |

안내는 문서 아래쪽 가운데에 떠 있는 작은 알림으로 나와 문서를 가리거나 밀지 않는다.

### 4.6 프로젝트

프로젝트는 사업 하나의 문서·작성 원칙·기준 문서·지난 사업·대화를 묶어 두는 곳이다(/project/번호).

| 자리 | 들어 있는 것 |
|---|---|
| 머리 | 업무·첨부·참고·기준 문서 수, 마감, 「책임 ○○」, 공유 단추(「공유 안 함」 / 「공유 중 · N」), 「관리」, 「더 보기」 |
| 탭 | 「대화·문서」, 「진행 현황」(볼 권한이 있을 때만) |
| 「대화·문서」 탭 | 새 대화 칸과 「대화 시작」, 「프로젝트 문서」(「문서 추가」), 「작성 원칙」, 「관련 지난 사업」, 「이어서 대화하기」, 「작업 문서」 |
| 「진행 현황」 탭 | 「참여자」, 「요청 기록」, 「사용량」, 「작업 요약」(「요약 만들기」) |

[표 부록-11] 프로젝트 화면

나누기

1. 머리의 「공유 안 함」 을 누른다. 「프로젝트 공유」 창이 열린다.
2. 「나만 보기」(담당자와 관리자만) 대신 「함께 쓰기」(고른 부서·사람과 나눔)를 고른다.
3. 「이름·아이디·부서로 찾기」 에서 사람이나 부서를 찾거나 「우리 부서(○○) 모두와」 를 누른다.
4. 줄마다 권한을 고른다. 「참조」 는 읽기 전용(공개 대화와 작업 문서를 읽음), 「함께 작업」 은 읽기·쓰기(대화를 열고 작업 문서를 고침)다.
5. 「저장」 을 누른다.

[그림 부록-21] 「프로젝트 공유」 창 (그림 docs/images/figures-1025/f4-20-project-share-dialog.jpg)

참고: 「비공개」 로 둔 대화는 나눠도 다른 사람에게 보이지 않는다.

사업 책임자 정하기: 머리의 「책임 ○○」 칩을 누르면 「함께 작업」 으로 나눈 사람 가운데 사업 책임자를 고를 수 있다.

보관: 사업이 끝나면 「관리」 → 「보관」 을 누른다. 목록에서 빠지고 「지난 사업」 으로 옮겨진다. 다시 꺼내려면 「보관 해제」 를 누른다.

### 4.7 그래프 탐색

그래프 탐색(라이브러리의 「지식그래프」 탭, 또는 문서 화면의 「관계 보기」, /graph/explore)은 사업·연차·문서·절 사이의 관계를 그림으로 본다.

1. 왼쪽 찾기 칸(「사업 찾기 · 문서·단위과제·지표도」)에 사업 이름을 넣는다.
2. 목록에서 사업을 누르면 가운데에 그 사업 중심의 그래프가 그려진다.
3. 점(노드)을 누르면 오른쪽 패널에 정보가 보인다. 「이웃 펼치기」 로 이어진 점을 더 펼치고, 「이것만 보기」 로 좁히며, 「문서 열기 ↗」 로 문서를 연다.
4. 「다시 배치」 로 그림을 다시 놓고, 「화면 맞춤」 으로 한눈에 맞춘다.
5. 「사업별 표」 를 누르면 같은 내용을 연차·문서 표로 본다.

[그림 부록-22] 그래프 탐색 — 사업 중심 그래프와 노드 패널 (그림 docs/images/figures-1025/fA-22-graph-node-panel.jpg)

참고: 관리자에게는 「온톨로지」 탭과 「내려받기」 가 더 있다. 내려받기 창에서 「온톨로지 설계도」(OWL[40])·「검사 규칙」(SHACL[42])·「검사 결과」 등을 받는다.

### 4.8 검색

1. 사이드바 「검색」 을 누르거나 Ctrl+K 를 누른다. 빠른 찾기 창이 뜬다.
2. 「대화·프로젝트·문서 찾기」 칸에 낱말을 넣는다. 탭(「전체」·「대화」·「프로젝트」·「문서」·「한글 문서」)으로 거른다.
3. 이름에서 찾지 못하면 Enter 를 눌러 본문까지 찾는다. 검색 화면(/search)에서는 「문서」·「본문 대목」·「프로젝트」·「대화」 로 나뉘어 보인다.

### 4.9 업무 도우미

업무 도우미는 채팅 밖 모든 화면 오른쪽 아래의 둥근 단추로 연다. 화면 사용법을 묻거나 화면에서 할 일을 맡긴다.

1. 오른쪽 아래 단추를 눌러 「업무 도우미」 창을 연다.
2. 「메시지를 입력하세요」 칸에 묻는다. 예: 「이 규정 학생에게 공개하려면 어떻게 해?」, 「새 프로젝트 만들고 계획서 쓰기 시작해 줘」.
3. 도우미가 할 일을 제안하면 「이렇게 하겠습니다 — …」 와 함께 「실행」 단추가 뜬다. 누르면 서버가 권한을 다시 확인한 뒤 화면 단추와 같은 일을 한다. 직접 하고 싶으면 「화면에서 직접」 을 누른다. 화면 위 커서가 그 단추를 가리켜 보인다.
4. 화면의 글을 선택하면 「쉽게 설명」·「간추리기」·「관련 규정 찾기」·「직접 묻기」 메뉴가 뜬다.
5. 지난 대화는 창 머리의 「지난 대화」 에서 이어 간다.

[그림 부록-23] 업무 도우미 창과 「실행」 제안 (그림 docs/images/figures-1025/fA-23-helper-run-suggestion.jpg)

참고: 사업 문서의 내용을 묻는 질문은 도우미가 에이전트 대화(「새 채팅」)로 넘긴다.

### 4.10 조직 관리

사이드바 「조직 관리」(/team) 한 화면에서 한다. 왼쪽은 부서 트리(들여쓰기·「부서 찾기」·＋/－ 펼치기·끌어다 놓아 옮기기), 맨 위 「전체 사용자」는 관리자에게만 보인다. 오른쪽은 고른 것의 상세다.

### 4.11 사업 관리

사업 관리(/programs/admin)는 교내 사업 장부를 연도별 표로 보는 곳이다.

1. 위 탭 「전체」·「현행 사업」·「지난 사업」 과 연도 단추(「전체 연도」·각 해)로 거른다.
2. 「사업·별칭·부서·책임자 찾기」 로 찾는다. 「거르기」 로 부서·분류·지원기관을, 「보기」 로 보일 열과 「금액 단위」 를 정한다.
3. 줄 끝 「⋯」 에서 「편집」, 「지정 신청」, 「수정 신청」, 「프로젝트 연결」, 「다른 사업과 합치기」, 「목록에서 빼기」 를 고른다.
4. 「내보내기」 로 「엑셀(원본 양식)」·「엑셀(전체 연도)」·「CSV」 를 받는다.

참고: 사업 책임자·행정 담당자는 맡은 사업을 읽기만 한다. 고칠 점은 「수정 신청」 으로 보내고, 관리자나 총괄 책임자가 처리한다.

### 5.1 사용자·계정, 등급, 부서

계정 만들기

1. 「사용자·계정」(/dev/users) → 「사용자」 카드의 「사용자 추가」 를 누른다.
2. 아이디·이름·역할(교직원·학생·관리자)·부서·등급을 넣는다. 다른 부서를 겸하면 「＋ 겸직 부서 더하기」.
3. 저장한 뒤 줄의 「편집」 → 「임시 비밀번호 만들기」 로 처음 비밀번호를 만들어 본인에게 따로 전한다.

[그림 부록-27] 사용자·계정 — 사용자 표와 부서 표 (그림 docs/images/08-users.jpg)

부서 만들기: 「부서」 카드의 「부서 추가」. 부서를 만들면 그 부서 RAG 가 함께 생긴다. 「상위 부서 정하기」 로 처·단 아래에 팀·센터를 둔다.

구글 앱 등록(처음 한 번): 「학교 계정 연결 현황」 카드의 「앱 등록」 → 「Google 앱 등록」 창. 등록한 뒤에는 사람마다 설정 화면에서 자기 학교 계정을 잇는다.

참고: 관리자는 최대 두 명이다. 부서 드라이브 연결은 그 부서 총괄 책임자가 하고, 관리자는 「부서」 카드에서 연결 계정·폴더·권한을 확인만 한다(「권한 맞추기」).

### 5.2 테스트 보기

다른 계정이 보는 화면·검색·답 범위를 그대로 확인하는 기능이다.

1. 업무 화면 사이드바 아래 「테스트 보기」 를 누른다.
2. 「역할」(학생·교직원), 「등급(교직원)」, 「부서」 를 고르고 「적용」 을 누른다.
3. 맨 위에 「테스트 보기 중 — … 계정의 화면·검색 범위입니다.」 띠가 뜬다. 이 상태로 질문·검색을 해 보면 그 계정이 받는 답과 같다.
4. 띠의 「원래대로」 로 돌아온다.

| 하고 싶은 일 | 하는 곳 |

| 학사 규정을 학생에게 공개 | 「규정·지침」 카드 → 「검색에 쓰는 규정」 탭 → 줄의 「관리」 → 「학생 공개로」(여럿이면 체크 뒤 「학생 공개」) |

### 5.4 도구·모델 연결

모델 호출은 용도(답, 반입 검토, 이미지 판독, 업무 도우미)마다 어느 서버의 어느 모델을 쓸지 이 화면에서 정한다.

1. 「LLM 연결」 카드에서 서버마다 「설정」 을 눌러 「연결 확인」 한다.
2. 문서 작업 기본 서버는 「기본 서버로 지정」 으로 바꾼다.
3. 「단계별 모델」 에서 용도별 모델을 「변경」 하고 「변경사항 저장」 을 누른다.
4. 「외부 연결」 카드의 「연결 상태 확인」 으로 웹 검색 연결을 본다.

### 5.5 개인정보·반출 점검

1. 「처리 정책」 의 「내부 마스킹 설정」 에서 반입·첨부·답의 가림을 항목별로 켜고 끈다. 기본은 꺼짐이고, 학습 반출은 이 설정과 상관없이 늘 가린다.
2. 「점검 도구」 의 「자가 점검 실행」 으로 개인정보 가림이 알려진 꼴을 모두 잡는지 확인한다.
3. 「잔여 검사 실행」 으로 저장된 본문에 남은 개인정보 꼴을 찾는다.

### 5.6 데이터·학습과 수집 자료

- 「데이터·학습」(/dev/train): 학습 문답을 Label Studio[18] 에서 검수하고(「원문과 답변 검수하기」, 「완료한 검수 결과 반영」), 학습 장비의 학습셋 목록과 학습 점검(「TensorBoard 그래프 ↗」, TensorBoard[62])을 본다. 학습셋 원문은 학습 장비 밖으로 나오지 않고, 이 화면에는 이름·상태·건수만 보인다.
- 「수집 자료」(/dev/collect): 항목과 기간을 고르고 「선택 항목 내려받기 묶음 만들기」 → 「만든 묶음」 의 「내려받기」. 묶음은 늘 가린 사본이고 사람은 가명으로 바뀐다. 항목 줄의 「구조·표본 보기」 는 필드 이름·형식·뜻과 가린 앞 3건을 보인다. 묶음 안에는 항목마다 같은 필드 차례의 JSONL 파일 하나와, 건수·기간·필드·가림·가명·나눔 규칙을 적은 manifest.json 이 들어 있다.

### 5.7 공동 편집 시연

한 화면에서 세 사람의 공동 편집을 보이는 관리자 기능이다(업무 화면 사이드바 아래 「공동 편집 시연」, /dev/coedit-demo).

1. 「공동 편집 시연」 을 누른다. 처음이면 시연 계정 셋(로그인할 수 없는 계정)과 빈 시연 문서(1·2·3 절과 4 절 「AURA 정리」)가 저절로 만들어진다.
2. 화면이 세 칸으로 나뉘고, 칸마다 다른 시연 계정의 커서가 자기 절(1·2·3)에 가 있다.
3. 각 칸에서 자기 절이나 제목에 글을 쓰고 서식을 바꾼다. 다른 칸 화면에 0.2초 안팎으로 글이 나타나고, 옅은 바탕·색 커서·이름표가 보인다.
4. 한 칸에서 다른 사람이 쓰는 절에 쳐 보면 그 이름표가 흔들리고 글은 들어가지 않는다.
5. 「AURA 정리 쓰기」 를 누르면 27B 가 1~3 절을 읽고 4 절에 정리를 쓴다. 세 칸에서 글이 써 내려가고, 단추는 「AURA 읽는 중」 → 「AURA 쓰는 중」 으로 바뀐다(1~3분).
6. 시연이 끝나면 「새 빈 문서」 를 한 번 더 눌러 쓴 글을 모두 지운 새 문서를 연다.

## 부록 6. 자주 묻는 질문

문. 내가 올린 문서가 학교 밖 AI 로 나가는가.
답. 나가지 않는다. 답·검색·판독 모델은 모두 교내 장비에서 돈다. 밖으로 나가는 것은 「웹 검색」 방식을 골랐을 때의 질문 글(개인정보가 있으면 보내지 않음)과, 내 학교 구글 계정으로 만든 구글 문서 작업본뿐이다.

문. 답에 나온 숫자를 그대로 써도 되는가.
답. 출처를 눌러 원문에서 확인한 뒤 쓴다. 근거에 없는 숫자에는 「(근거 확인 필요)」 가 붙고, 문서 작업에서는 「○○」 로 가려진다.

문. 다른 부서 문서는 왜 찾아지지 않는가.
답. 문서마다 부서와 공개 범위가 있고, 검색은 처음부터 내가 볼 수 있는 문서 안에서만 한다. 다른 부서 자료가 업무에 필요하면 관리자에게 추가 부서를 요청한다.

문. 프로젝트 추가(+) 단추가 보이지 않는다.
답. 일반 등급은 프로젝트를 만들지 않는다. 같은 부서 사업 책임자나 총괄 책임자에게 「프로젝트 만들기」 권한을 받거나, 공유받은 프로젝트에서 작업한다.

문. 같은 문서를 둘이 열었는데 한 사람이 보기 전용이다.
답. 칸(누름틀)이 없는 문서는 한 사람씩 고친다. 먼저 연 사람이 닫으면 바로 이어서 고칠 수 있다. 여럿이 동시에 쓰려면 칸이 있는 양식을 쓴다.

문. 공통 양식을 열었더니 고쳐지지 않는다.
답. 공통 양식은 모두가 쓰는 원본이라 잠겨 있다. 「사본 만들기」 로 내 폴더나 부서 폴더에 사본을 만들어 쓴다.

문. AURA 가 쓴 초안을 바로 제출해도 되는가.
답. 아니다. AURA 의 결과는 사람이 검토하는 초안이다. 숫자·고유명사·결정할 값은 담당자가 확인하고, 「한글 파일로 내보내 줘」 로 받은 완성본도 한글 프로그램에서 한 번 열어 본다.

문. 학생 계정으로 무엇을 물을 수 있는가.
답. 학생에게 공개로 지정된 학사 규정에 관한 질문이다. 사업 문서나 부서 자료는 찾지 않는다.

문. 한글(.hwp) 파일도 되는가.
답. 된다. 문서함에 .hwp 와 .hwpx 모두 올릴 수 있고, 라이브러리도 hwp 를 읽는다.

문. 대화가 길어지면 앞 내용을 잊는가.
답. AURA 는 대화마다 작업 메모(지금 목표·확정된 것·진행 상황·남은 일)를 답 뒤에 고쳐 두고 다음 요청에 함께 쓴다. 입력 칸 옆 「문맥 N% 사용」 이 높으면 새 대화로 나누는 것이 좋다.

| 작업 문서, 작업본 | 대화와 함께 AURA 와 사람이 고치는 문서 |
| 작성 원칙 | 프로젝트에서 AURA 가 글을 쓸 때 지킬 점 |

| 충돌 사본 | 같은 칸에 글이 겹쳤을 때 버리지 않고 따로 둔 내 글 |
| 같이 있는 사람 | 같은 문서를 지금 열고 있는 사람. 머리줄 동그라미로 보인다 |
| RAG | 질문에 맞는 문서를 먼저 찾아 그 내용을 근거로 답하는 방식[1] |
| RAG 공간 | 검색 범위 묶음. 공통 RAG(전 교직원), 부서 RAG(그 부서), 학생 RAG(학생 공개 규정) |
| 지식그래프 | 사업·연차·문서·절을 관계로 이은 그림. 찾을 범위를 좁히는 데 쓴다 |
| 온톨로지 | 지식그래프에 어떤 종류의 점과 관계가 있는지 정한 설계도 |
| 생각 과정 | 답 앞에 AURA 가 질문 파악 → 근거 확인 → 답 구성 순으로 따진 글 |
| 작업 메모 | 긴 대화에서 목표·확정 값·남은 일을 잊지 않게 AURA 가 적어 두는 요약 |
| 문맥 | 모델이 한 번에 읽을 수 있는 글의 양. 「문맥 N% 사용」 으로 보인다 |
| 등급 | 교직원의 작업 권한 단계. 일반·행정 담당자·사업 책임자·총괄 책임자 |
| 참조 / 함께 작업 | 프로젝트를 나눌 때의 권한. 읽기 전용 / 읽기·쓰기 |
