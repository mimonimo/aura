# 부록. AURA 사용 설명서

이 부록은 AURA 를 처음 쓰는 교직원과 관리자를 위한 사용 설명서다. 앞부분은 역할별로 처음 할 일, 가운데는 실제 업무 장면(사업계획서 초안, 지난 사업
문서 다시 쓰기, 공동 편집, 규정 질문), 뒷부분은 화면별 기능, 관리자 화면, 자주 묻는 질문, 문제 해결, 용어 풀이다.

화면과 단추 이름은 화면에 적힌 그대로 「」 로 묶고, 괄호 안 주소(/hwp 등)는 브라우저 주소창의 경로다. 그림은 시험 계정과
가상 자료로 찍었다. [n] 은 본문 참고 문헌 번호이며, 기술 설명은 2~4 장을 본다.

## 부록 1. AURA 한눈에 보기

### 1.1 AURA 는 무엇을 하는가

AURA 는 영남이공대학교 교내 행정 문서를 교내 장비 안에서만 읽고, 찾고, 쓰는 플랫폼이다. 문서는 학교 밖 AI 서비스로 나가지 않는다.

| 하고 싶은 일 | 쓰는 화면 | 한 줄 설명 |
|---|---|---|
| 규정·지난 사업 자료를 묻기 | 「새 채팅」 | 근거 문서를 찾아 출처와 함께 답한다 |
| 문서 찾기와 정리 | 「라이브러리」, 「검색」 | 들어온 문서를 사업·연도·종류로 거르고 원문을 본다 |
| 한글 문서를 함께 쓰기 | 「문서함」, 웹 한글 기안기 | 부서 폴더의 한글 문서를 브라우저에서 열고 여럿이 동시에 고친다 |
| 사업 문서 초안 쓰기 | 프로젝트, 「새 채팅」 | AURA 가 양식을 고르고 절마다 초안을 쓰며, 사람이 검토해 한글로 내보낸다 |

AURA 가 쓰는 글은 사람이 검토할 초안이다. 숫자와 최종 판단은 근거 문서에서 확인한다.

### 1.2 화면 구성

모든 화면은 왼쪽 사이드바, 가운데 본문, 오른쪽 아래 업무 도우미 단추로 되어 있다. 사이드바에는 「검색」(Ctrl+K), 메뉴(「새 채팅」·「라이브러리」·
「문서함」·「사업 관리」·「조직 관리」), 「내 프로젝트」, 「공유받은 프로젝트」, 「최근 대화」 가 차례로 있다. 맨 아래에는 AI 연결 상태, 「알림」,
내 이름을 누르면 뜨는 사용자 메뉴(「설정」·「로그아웃」, 권한에 따라 「문답 검수」·「테스트 보기」·「개발 현황」)가 있다.

### 1.3 계정과 등급

계정 역할은 교직원·학생·관리자 셋이고, 교직원은 작업 권한 등급 넷으로 나뉜다. 등급은 프로젝트를 만들고 진행 현황을 보는 범위를 정한다. 어떤
문서를 찾아볼 수 있는지는 등급이 아니라 소속 부서로 정해진다.

| 등급 | 하는 일 | 할 수 있는 것 |
|---|---|---|
| 일반 | 공유받은 일에 참여 | 질문·검색, 공유받은 프로젝트에서 작업. 「프로젝트 만들기」 권한을 받으면 프로젝트를 만든다 |
| 행정 담당자 | 사업의 행정 지원 | 사업 책임자와 같은 단계. 프로젝트를 만들고 맡은 사업의 진행을 본다 |
| 사업 책임자 | 세부 사업 책임 | 프로젝트를 만들고, 책임진 프로젝트·사업의 진행 현황을 본다. 같은 부서 일반 직원에게 「프로젝트 만들기」 권한을 준다 |
| 총괄 책임자 | 부서장 | 자기 부서와 아래 팀·센터 프로젝트의 진행 현황을 보고 사업 책임자를 정한다. 부서 드라이브를 연결한다 |
| 관리자 | 시스템 전체 관리(최대 2명) | 모든 화면과 개발 화면 |

[표 부록-2] 교직원 등급

등급을 정하지 않은 교직원 계정은 사업 책임자로 본다.

## 부록 2. 역할별 빠른 시작

### 2.1 교직원: 처음 10분

로그인한 뒤 사용자 메뉴의 「설정」(/settings)에서 처음 받은 비밀번호를 바꾸고, 「구글 계정」 카드에서 학교 구글 계정(ync.ac.kr)을 잇는다. 구글
계정은 구글 문서 작업본과 드라이브 가져오기에 쓴다. 그다음 「새 채팅」 에서 업무 질문 하나를 해 보고 답 아래 출처가 원문 대목으로 열리는지, 「문서함」
에서 우리 부서 폴더가 보이는지 확인한다.

[그림 부록-2] 로그인 화면 (그림 docs/images/figures-1025/fA-02-login.jpg)

### 2.2 학생: 학사 질문하기

학생 계정은 학생에게 공개된 학사 규정을 묻는 대화만 쓴다. 사이드바에는 「새 채팅」 과 「최근 대화」 만 있고, 입력창에 첨부·답변 방식 토글·문서 패널이
없다. 답 아래 출처를 누르면 규정의 해당 대목을 본다.

[그림 부록-3] 학생 계정의 채팅 화면 (그림 docs/images/figures-1027/fA-03-student-chat.jpg)

### 2.3 일반 직원: 공유받은 프로젝트에서 일하기

동료가 프로젝트를 나누면 사이드바 「공유받은 프로젝트」 에 나타난다. 프로젝트 이름 옆 칩이 받은 권한이다. 「함께 작업」 은 대화를 열고 작업 문서를
고칠 수 있고, 「읽기만」 은 보기만 한다. 답의 근거 문서 가운데 내 부서 범위 밖의 것은 「볼 수 없는 자료」 로 보인다.

### 2.4 사업 책임자·행정 담당자: 프로젝트 만들기

「내 프로젝트」 옆 「프로젝트 추가」(+)에서 업무(국고사업·채용·입학·일반 행정)를 고르고 공고나 지난 계획서를 자료로 고르면 이름이 저절로 정해진다.
마감일과 사업단은 선택이다. 만든 뒤에는 부록 3.1 의 순서로 초안을 만든다.

### 2.5 총괄 책임자: 부서 정비

「조직 관리」 에서 부서를 고르고 「구성원」 탭에서 사람의 등급을 정한다. 「부서 설정」 탭의 부서 드라이브에서 부서 공용 학교 계정으로 「구글 드라이브 연결」
을 한다. 부서 프로젝트의 진행은 각 프로젝트의 「진행 현황」 탭에서 본다.

### 2.6 관리자: 첫 점검

사용자 메뉴의 「개발 현황」(/dev)으로 들어가 「도구·모델 연결」 의 「초기 설정」 카드에서 남은 연동 항목과 모델 서버 연결을 확인한다. 이어서
「RAG 공간」 의 문서 수, 「조직 관리」 의 계정·부서와 학교 계정 연결 현황을 보고, 「테스트 보기」 로 다른 계정이 보는 범위를 확인한다(부록 5).

## 부록 3. 업무 장면별 따라 하기

### 3.1 사업계획서 초안을 처음부터 끝까지 만들기

장면: 사업 책임자가 새 국고사업 공고에 맞춰 사업계획서 초안을 만든다. 공고 파일이 있고, 작년 계획서가 라이브러리에 있다.

1. 프로젝트를 만든다. 「프로젝트 추가」 창에서 업무 「국고사업」 과 이번 공고를 고른다.

   [그림 부록-4] 「프로젝트 추가」 창 (그림 docs/images/figures-1027/f4-16-project-add-dialog.jpg)

2. 재료를 모은다. 프로젝트 화면의 「문서 추가」 로 공고 원문, 부서 폴더·드라이브의 파일, 근거가 될 규정·지침을 넣는다. 넣은 문서는 첨부·참고·기준
   문서로 나뉜다. 「지난 사업 연결」 로 작년 사업을 잇고, 「작성 원칙」 에 지킬 점(「예산은 백만원 단위」 등)을 한 줄씩 적는다. 프로젝트에 넣은 문서는
   그 프로젝트의 대화에서 다른 문서보다 먼저 근거로 쓰인다.

   [그림 부록-5] 프로젝트 화면: 프로젝트 문서, 작성 원칙, 관련 지난 사업 (그림 docs/images/figures-1027/f4-17-project-chat-docs.jpg)

3. 대화로 초안을 시킨다. 예: 「이 공고로 사업계획서 초안 써 줘. 대상은 1학년, 예산은 5천만원, 기간은 내년 3월부터 12월까지.」 AURA 는 프로젝트의
   작성 서식이나 공통 양식 가운데 맞는 양식을 고르고(없으면 양식부터 만든다), 오른쪽 문서 패널의 작업 문서에 절을 하나씩 채운다. 답 아래 「작업 내역」
   에서 어떤 근거로 어느 절을 썼는지 본다.

   [그림 부록-6] 대화와 작업 문서를 나란히 둔 화면: AURA 가 절을 쓰는 중 (그림 docs/images/01-chat-hwp-agent.jpg)

4. 모르는 값을 채운다. 자료에서 찾지 못한 값(사업단장 이름, 협약 기관 수 등)은 「필요한 값 입력」 칸에 모인다. 값을 넣거나, 줄을 골라 「선택한 줄
   자료에서 찾기」 로 프로젝트 문서에서 제안을 받는다. 비워 둔 칸은 다음에 다시 묻는다.

   [그림 부록-7] 「필요한 값 입력」 칸 (그림 docs/images/figures-1027/f4-19-needed-values.jpg)

5. 고쳐 쓴다. 「2번 절 더 구체적으로」, 「추진 일정은 표로」, 「용지 가로로」 처럼 말하면 AURA 가 그 절을 다시 읽고 고친다. 직접 고칠 때는 문서
   패널에서 기안기의 「편집 도구」 를 펼친다. 근거에 없는 숫자는 「○○」 로 가려 두므로 값을 알면 직접 넣는다.

6. 검토를 받는다. 「이 초안 검토해 줘」 라고 하면 작성방법·배점 항목에 비추어 빠진 점을 알려 준다. 동료에게는 프로젝트 머리의 공유 단추로 나눈다(부록 4.6).

7. 한글 파일로 내보낸다. 「한글 파일로 내보내 줘」 라고 하면 원본 한글 서식에 내용을 채운 완성본을 만든다. 기안기의 「⋯」 → 「내려받기」 에서
   hwpx·hwp·PDF·docx 로 받고, 「구글 드라이브에 올리기」 로 드라이브에 둔다.

   [그림 부록-8] 기안기 「⋯」 메뉴: 다른 이름으로 저장, 문서 틀 고치기, 내려받기, 구글 드라이브에 올리기 (그림 docs/images/figures-1025/f4-24-editor-more-menu.jpg)

수십 쪽짜리 공모 서식은 한 번에 시키지 말고 나눠 시킨다. 먼저 틀(「과제 견본을 과제 6개로 늘려 줘」), 다음 표지·신청서 값(「대학명: 영남이공대학교,
총괄책임자 성명: 홍길동」 처럼 「이름: 값」), 그다음 절마다(「2.1 을 써 줘」) 시킨다. 앞 답을 쓰는 동안 다음 요청을 보내 두면 차례로 처리된다.

> 참고: 작년 계획서를 양식으로 고르면 AURA 는 그 문서를 근거에서 뺀다. 작년 수치가 올해 문서에 그대로 옮겨지지 않게 하기 위해서다.

### 3.2 지난 사업 문서를 찾아 다시 쓰기

장면: 행정 담당자가 작년 결과보고서 양식을 찾아 올해 판으로 쓰려 한다. 찾는 길은 넷이다.

- 문서함: 「부서 폴더」 → 「공통」 아래 「지난 사업 문서」(사업 → 목적 폴더)와 「공통 양식」 에 양식이 있다. 양식은 잠겨 있어 「사본 만들기」 로 우리
  부서 폴더·내 폴더·프로젝트에 사본을 만들어 쓴다. 위쪽 「양식으로 시작」 은 양식 이름으로 찾아 바로 사본을 만든다.

  [그림 부록-9] 문서함: 왼쪽 위치(내 폴더·부서 폴더·구글 드라이브)와 오른쪽 목록 (그림 docs/images/figures-1027/f4-22-hwp-box.jpg)

  [그림 부록-10] 「사본을 어디에 만들까요」 창 (그림 docs/images/figures-1027/f4-23-copy-where-dialog.jpg)

- 라이브러리: 「사업별로 보기」 에서 사업을 고르고 종류·기간으로 좁힌다. 「본문까지」 를 켜면 본문 낱말로도 찾는다. 한글 양식이면 문서 화면의
  「기안기로 작업」 으로 바로 연다.

  [그림 부록-11] 라이브러리: 폴더, 사업별로 보기, 쓰임새 칩(전체·기준·작성·결과)과 거르기 (그림 docs/images/figures-1027/fA-11-library.jpg)

- 지난 사업 화면(/projects/archived): 보관된 사업을 사업명·연도·사업단으로 찾고, 「참조 연결」 로 지금 프로젝트에 잇는다.

  좁혀 찾는다.

### 3.3 여럿이 한 보고서를 동시에 쓰기

장면: 한 부서의 세 사람과 AURA 가 같은 실적보고서의 서로 다른 곳을 동시에 고친다.

기안기는 문서를 처음 열 때 제목·소제목·표 칸까지 문단을 모두 칸으로 나눈다. 고치는 단위가 칸이다. 글을 쓰기 시작하면 그 칸은 내 것이 되고, 다른
칸으로 옮기거나 창을 닫으면 놓인다. 남이 쓰는 칸에는 글이 들어가지 않고 그 칸의 이름표가 잠깐 흔들린다. 쓰던 사람이 놓으면 바로 쓸 수 있다.

머리줄 오른쪽 동그라미가 지금 같이 있는 사람이다. 동그라미를 누르면 그 사람이 어느 칸을 쓰는지 보이고 화면이 그 사람을 따라간다. 문서 안에서 남이
쓰는 칸은 옅은 바탕, 색 커서, 여백의 이름표로 보인다.

[그림 부록-12] 기안기 머리줄: 문서함, 문서 이름과 폴더 경로, 저장 상태, 같이 있는 사람 동그라미, 편집 도구, 「⋯」 (그림 docs/images/figures-1025/fA-12-editor-header.jpg)

[그림 부록-13] 남이 쓰는 칸 표시: 옅은 바탕, 색 커서, 이름표, 같이 있는 사람 목록 (그림 docs/images/figures-1025/g01-coedit-pane-people.jpg)

실무에서 알아 둘 점은 다음과 같다.

- 서식(글꼴·색·크기)은 칸 안에서 바로 바뀌어 다른 사람 화면에도 간다. 표에 줄을 더하거나 그림·용지를 바꾸는 일은 「문서 틀 고치기」 로 저장되며
  한 번에 한 사람만 한다. 그때 다른 사람 화면은 새 판으로 바뀌고 그들이 쓴 칸 글은 남는다.
- 같은 칸에 두 사람의 글이 겹치면 내 글은 버리지 않고 사본으로 둔다. 「⋯」 → 「충돌로 따로 둔 내 글」 에서 꺼낸다.
- 연결이 끊겨도 그대로 쓰면 이어질 때 보낸다.
- AURA 에게 「3번 칸은 AURA 가 채워 줘」 처럼 맡기면 AURA 도 한 사람처럼 칸을 잡고 쓴다. 사람이 잡은 칸은 쓰지 않는다.
- 앞 판은 판 기록에 남는다.

아주 큰 문서처럼 칸으로 감싸지 않은 문서는 한 사람씩 고친다. 나중에 연 사람은 보기 전용으로 보다가 먼저 연 사람이 닫으면 이어서 고친다.

[그림 부록-14] 칸으로 감싸지 않은 문서(아주 큰 문서 등)를 나중에 연 사람의 화면: 보기 전용 (그림 docs/images/02-hwp-edit-lock.jpg)

### 3.4 규정 질문하기

장면: 교직원이 연구년 신청 자격을 묻는다.

「새 채팅」 에서 답변 방식이 「RAG」 인지 보고 「연구년 신청 자격이 어떻게 돼?」 라고 묻는다. 답은 첫머리 요약, 근거 요점, 출처 순이고, 출처를 누르면
오른쪽에 규정 원문의 그 조항이 열린다. 「생각 과정 펼치기」 로 AURA 가 질문 파악, 근거 확인, 답 구성 순으로 따진 과정을 본다. 답이 틀렸으면
「아쉬움」 으로 까닭을 남긴다.

[그림 부록-15] 규정 질문의 답: 출처와 오른쪽 원문 대목 (그림 docs/images/figures-1027/fA-15-regulation-answer-source.jpg)

[그림 부록-16] 「생각 과정」 을 펼친 답과 입력 칸 아래 문맥 사용량 (그림 docs/images/figures-1027/f4-15-answer-sources-thinking.jpg)

숫자 뒤에 「(근거 확인 필요)」 가 붙으면 그 숫자가 근거 문서에 없다는 뜻이므로 원문에서 꼭 확인한다. 다른 부서 자료를 묻는 질문에는 열람 권한이
없다는 안내만 붙고, 그 문서가 있는지 없는지는 알리지 않는다.

### 3.5 기안문·출장 보고처럼 짧은 문서 빨리 쓰기

「새 채팅」 에서 「다음 주 서울 출장 보고서 써 줘. 출장지는 ○○, 목적은 협약 회의」 처럼 요청하면 AURA 가 공통 양식에서 맞는 양식을 골라 작업 문서를
만들고 채운다. 문서 패널에서 확인하고 고친 뒤 「한글 파일로 내보내 줘」 로 받는다.

### 4.2 채팅

채팅 화면(/chat)은 대화 칸과 오른쪽 문서 패널로 되어 있다. 입력창 아래 도구줄에서 첨부, 답변 방식, 「RAG 범위」, 답변 깊이를 고른다.

| 방식 | 언제 쓰나 | 무엇이 밖으로 나가나 |
|---|---|---|
| 「RAG」 | 규정·사업 문서를 근거로 답을 받거나 문서를 쓰고 고칠 때. 「RAG 범위」 로 공통·부서 RAG 를 좁힌다 | 없음. 내 계정 범위의 교내 문서만 찾는다 |
| 「일반」 | 문장 다듬기, 개념 설명 같은 일반 질문 | 없음. 문서 없이 모델이 답하고 출처가 없다고 밝힌다 |
| 「인터넷에서 찾아보기」 | 일반 답 끝에 모델이 확인을 권할 때 누른다 | 질문 글만 웹 검색에 보낸다. 문서·첨부는 나가지 않고, 개인정보가 든 질문은 보내지 않는다 |

[표 부록-4] 답변 방식

프로젝트 대화와 파일을 붙인 질문은 「RAG」 로 시작한다. 답을 쓰는 동안 보낸 요청은 「다음 요청 n건 대기」 에 쌓였다가 차례로 처리되므로, 긴 서식을
절마다 시킬 때 미리 넣어 두면 된다.

| 단추·표시 | 하는 일 |
|---|---|
| 답변 깊이(「꼼꼼하게」·「빠르게」) | 기본은 「꼼꼼하게」(생각을 거쳐 자료를 넓게 보고 점검). 간단한 질문은 「빠르게」 |
| 「문맥 N% 사용」 | 이 대화가 모델 문맥 한도를 얼마나 쓰는지. 높으면 새 대화로 나눈다 |
| 「작업 내역」 | 문서 작업에서 AURA 가 거친 단계 |
| 「필요한 값 입력으로 이동」 | AURA 가 찾지 못한 값을 넣는 칸으로 간다 |
| 「비공개」 / 「부서 공개」 | 프로젝트 대화를 부서 동료에게 보일지 정한다 |

[표 부록-5] 채팅 화면의 단추

문서 패널에는 위쪽 편집기 고르기(「한글」 기안기 또는 「구글」 문서), 이 대화와 함께 고치는 「작업 문서」, 그리고 첨부·참고·기준 문서 묶음이 있다.

양식으로 새로 만든다.

| 「진행 현황」 탭 | 볼 권한이 있을 때만. 요청·참여자·작업 문서·사용량 요약, 사람별 거르기, 날짜별 사용량, 대화별 요청 기록, 사람별 작업 요약 |

공유 단추를 누르면 「프로젝트 공유」 창이 열린다. 「나만 보기」 면 담당자와 관리자만 보고, 「공유」 면 고른 부서·사람에게 「읽기만」 또는 「함께
작업」 으로 나눈다. 나눔은 고른 부서·사람에게만 가고 아래 팀이나 다른 부서로 저절로 퍼지지 않는다. 「비공개」 로 둔 대화는 나눠도 보이지 않는다.

[그림 부록-21] 「프로젝트 공유」 창 (그림 docs/images/figures-1027/f4-20-project-share-dialog.jpg)

사업 책임자는 머리의 「책임 ○○」 에서 「함께 작업」 으로 나눈 사람 가운데 고른다. 사업이 끝나면 「관리」 → 「보관」 으로 「지난 사업」 에 옮긴다.

### 4.7 그래프 탐색

그래프 탐색(/graph/explore)은 사업·연차·문서·절 사이의 관계를 그림으로 본다. 라이브러리의 「지식그래프」 나 문서 화면의 「관계 보기」 로 연다. 사업을
고르면 그 사업 중심의 그래프가 그려지고, 점을 눌러 이어진 점을 펼치거나 문서를 연다. 「사업별 표」 는 같은 내용을 표로 보인다. 관리자는 온톨로지
설계도(OWL[40])와 검사 규칙(SHACL[42])을 내려받는다.

### 4.8 검색

사이드바 「검색」 이나 Ctrl+K 로 대화·프로젝트·문서·한글 문서를 이름으로 빠르게 찾는다. 이름에서 찾지 못하면 Enter 로 본문까지 찾는 검색
화면(/search)으로 간다.

### 4.9 업무 도우미

업무 도우미는 채팅 밖 화면의 오른쪽 아래 둥근 단추로 여는 옆 패널이다. 화면 사용법을 묻거나 할 일을 맡긴다. 「문서함에서
○○ 폴더 열어 줘」 처럼 시키면 AURA 커서가 화면을 옮기고 창을 열고 칸에 값을 넣는다. 저장 같은 마지막 단추는 직접 말했을 때만 누르고, 그렇지
않으면 「실행」 단추로 확인을 받는다. 화면의 글을 선택하면 「쉽게 설명」 같은 메뉴로 그 대목을 묻는다.

[그림 부록-23] 업무 도우미 창과 「실행」 제안 (그림 docs/images/figures-1027/fA-23-helper-run-suggestion.jpg)

사업 문서의 내용을 묻는 질문은 도우미가 「새 채팅」 으로 넘긴다.

### 4.10 조직 관리

조직 관리(/team)는 왼쪽 부서 트리와 오른쪽 상세로 된 한 화면이다.

| 고른 것 | 누가 | 하는 일 |
|---|---|---|
| 부서 › 「구성원」 | 그 부서 사업 책임자·총괄 책임자·관리자 | 사람을 골라 「옮기기」·「등급 바꾸기」·「빼기」, 「사람 추가」(겸직), 추가 권한 |
| 부서 › 「부서 설정」 | 보기는 교직원 누구나, 고치기는 권한만큼 | 총괄 책임자, 부서 RAG, 부서 이름·위치·하위 부서, 부서 드라이브 |
| 「전체 사용자」 | 관리자 | 계정 찾기·추가·편집, 역할·부서 바꾸기, 사용 중지 |
| 「학교 계정 연결 현황」 | 관리자 | 구글 앱 등록, 허용 도메인, 사람별 연결 |

[그림 부록-24] 조직 관리: 왼쪽 부서 트리와 고른 부서의 구성원 (그림 docs/images/figures-1027/f3-06-org-chart.jpg)

소속 사람이 있는 부서는 지우지 않는다. 총괄 책임자는 관리자가 정하고, 사업 책임자는 일반 직원에게 「프로젝트 만들기」 권한만 줄 수 있다.

### 4.11 사업 관리

사업 관리(/programs/admin)는 교내 사업 장부를 연도별 표로 보는 곳이다. 현행·지난 사업과 연도로 거르고, 사업·부서·책임자로 찾는다. 줄 끝 「⋯」 에서
편집, 프로젝트 연결, 다른 사업과 합치기를 하고, 「내보내기」 로 엑셀·CSV 를 받는다. 사업 책임자·행정 담당자는 맡은 사업을 읽기만 하고, 고칠 점은
「수정 신청」 으로 보내면 관리자나 총괄 책임자가 처리한다.

### 5.1 계정, 등급, 부서

### 5.2 테스트 보기

다른 계정이 보는 화면·검색·답 범위를 그대로 확인하는 기능이다. 사용자 메뉴의 「테스트 보기」 에서 역할·등급·부서를 고르면 맨 위에 띠가 뜨고, 이
상태에서 한 질문·검색은 그 계정이 받는 결과와 같다. 띠의 「원래대로」 로 돌아온다. 「특정 사람만 문서를 못 찾는다」 는 문의를 확인할 때 쓴다.

### 5.3 RAG 공간

RAG 공간은 AURA 가 어느 문서 묶음에서 찾을지 정하는 곳이다. 규정 등록과 공개는 라이브러리 「기준」 칩에서 한다.

| 하고 싶은 일 | 하는 곳 |
|---|---|
| 학사 규정을 학생에게 공개 | 라이브러리 「기준」 칩 → 규정 줄 「…」 → 「학생 공개로」 |
| 반입 자료 속 규정을 기준 문서로 | 라이브러리 「기준」 칩 → 「새 판·미등록」 → 「검색에 추가」 |
| 규정을 검색에서 빼기 | 라이브러리 「기준」 칩 → 줄 「…」 → 「검색에서 빼기」 |
| 다른 부서가 우리 부서 RAG 를 찾게 하기 | RAG 공간 › 부서 줄 › 「다른 부서에 열기」 |
| 이 계정이 이 규정을 찾는지 확인 | 「검색 범위 시험」 |

### 5.4 도구·모델 연결

용도(답, 반입 검토, 이미지 판독, 업무 도우미)마다 어느 서버의 어느 모델을 쓸지 정하는 화면이다. 맨 위 「초기 설정」 카드는 새로 설치한 서버에서 남은
연동 항목을 보이고, 「서버 설정」 카드는 검색 서버·웹 검색 키·원본 폴더 같은 값을 서버 파일 대신 화면에서 정한다. 「LLM 연결」 에서 서버별로 연결을
확인하고 기본 서버를 정하며, 「단계별 모델」 에서 용도별 모델을 바꾼다.

[그림 부록-29] 도구·모델 연결: LLM 연결과 단계별 모델 (그림 docs/images/figures-1027/fA-29-llm-connections.jpg)

모델 이름과 문맥 길이는 코드가 아니라 이 설정에 있어, 더 큰 모델로 바꿀 때 코드를 고치지 않는다.

### 5.5 개인정보·반출 점검

반입·첨부·답의 개인정보 가림을 항목별로 켜고 끄는 화면이다. 기본은 꺼짐이고, 학습 반출은 이 설정과 상관없이 늘 가린다. 가림 기능이 알려진 꼴을
잡는지 보는 자가 점검은 합성 표본으로 매일 돌고, 저장된 본문에 남은 개인정보 꼴을 찾는 검사는 주 한 번 돈다.

### 5.6 문답 검수 권한

모델 학습에 쓸 문답을 사람이 검수할 때만 쓴다. 「조직 관리」 에서 검수할 교직원에게 추가 권한 「SFT 문답 검수」 를 주면 그 사람의 사용자 메뉴에
「문답 검수」(/review)가 생겨 Label Studio[18] 검수 화면을 연다.

### 5.7 모델을 바꾸기 전에

모델을 바꾸기 전에 「품질·성능」 의 「모델 비교」 카드에서 후보와 운영 모델을 나란히 잰 결과를 본다. 카드에는 결론 한 줄과 문서 작성·속도 수치가
있고, 「자세히」 에서 항목별 점수와 표본 답을 비교한다. 교체는 「도구·모델 연결」 에서 한다(부록 5.4).

| 증상 | 확인할 곳 | 할 일 |
|---|---|---|
| 모든 사용자에게 「AI 미연결 · 답변 대기」 | 「도구·모델 연결」 › 「LLM 연결」 | 안 되는 서버를 찾아 답 연결을 다른 서버로 바꾼다. 서버 자체는 서버 담당자가 다시 띄운다 |

## 부록 6. 자주 묻는 질문

문. 내가 올린 문서가 학교 밖 AI 로 나가는가.
답. 나가지 않는다. 답·검색·판독 모델은 모두 교내 장비에서 돈다. 밖으로 나가는 것은 「인터넷에서 찾아보기」 를 눌렀을 때의 질문 글(개인정보가 있으면
보내지 않음)과, 내 학교 구글 계정으로 만든 구글 문서 작업본뿐이다.

문. 다른 부서 문서는 왜 찾아지지 않는가.
답. 검색은 처음부터 내 부서 범위의 문서 안에서만 한다. 다른 부서 자료가 업무에 필요하면 관리자에게 겸직 부서를 요청하거나, 그 부서가 부서 RAG 를
열어 주어야 한다.

문. 프로젝트 추가(+) 단추가 보이지 않는다.
답. 일반 등급은 프로젝트를 만들지 않는다. 같은 부서 사업 책임자에게 「프로젝트 만들기」 권한을 받거나, 공유받은 프로젝트에서 작업한다.

문. AURA 가 쓴 초안을 바로 제출해도 되는가.
답. 아니다. 숫자는 출처의 원문에서 확인하고(근거에 없는 숫자에는 「(근거 확인 필요)」 가 붙거나 「○○」 로 가려진다), 내보낸 한글 완성본도 한글
프로그램에서 한 번 열어 본다.

문. 한글(.hwp) 파일도 되는가.
답. 된다. 문서함과 라이브러리 모두 .hwp 와 .hwpx 를 받는다. 양식 채우기는 hwpx 로 바꾸어 다룬다.

문. 대화가 길어지면 앞 내용을 잊는가.
답. AURA 는 대화마다 목표·확정된 것·남은 일을 작업 메모로 고쳐 두고 다음 요청에 함께 쓴다. 「문맥 N% 사용」 이 높으면 새 대화로 나누는 것이 좋다.

## 부록 7. 문제 해결

실무에서 막히기 쉬운 증상만 모았다. 표에 없는 증상은 관리자에게 화면 그림과 함께 알린다.

| 증상 | 까닭과 할 일 |
|---|---|
| 사이드바에 「AI 미연결 · 답변 대기」 | 답 모델 서버에 잠시 닿지 않는다. 질문은 보내 두면 연결된 뒤 답한다. 오래가면 관리자에게 알린다 |
| 문서 작업 답이 오래 걸린다 | 근거를 찾고 절마다 쓰느라 걸린다. 「작업 내역」 에서 진행을 보고, 다음 요청은 미리 보내 둔다 |
| 「관리자가 구글 앱을 등록한 뒤 연결할 수 있습니다.」 | 구글 앱 등록 전이다. 관리자에게 요청한다 |
| 구글 연결이 끊겼다는 안내 | 연결이 만료됐다. 설정의 「구글 계정」 에서 다시 연결한다 |
| 문서함에 「한글 편집기 연결 안 됨」 | 기안기 서버에 닿지 않는다. 그동안 「새 문서」·「양식으로 시작」 은 꺼진다. 잠시 뒤 다시 연다 |
| 공통 양식이 고쳐지지 않는다 | 모두가 쓰는 원본이라 잠겨 있다. 「사본 만들기」 로 사본을 만들어 쓴다 |
| 쳐도 글이 들어가지 않고 이름표가 흔들린다 | 다른 사람이 그 칸을 쓰는 중이다. 다른 곳을 쓰거나 기다린다 |
| 내 글이 사라진 것 같다 | 같은 칸에 글이 겹쳐 사본으로 두었다. 「⋯」 → 「충돌로 따로 둔 내 글」 에서 꺼낸다 |
| 올린 문서가 「처리 중」 에서 오래 멈춘다 | 긴 스캔 문서는 판독에 시간이 걸린다. 「실패」 가 되면 암호나 손상 여부를 확인한다 |

## 부록 8. 용어 풀이

본문에서 풀지 않은 낱말만 모았다.

| 용어 | 쉬운 풀이 |
|---|---|
| 기준 문서 | 규정·지침·공고처럼 판단의 기준이 되는 문서. 조항 단위로 찾는다 |
| 공통 양식 | 어느 부서나 쓰는 빈 양식. 잠겨 있어 사본을 만들어 쓴다 |
| 칸(누름틀) | 한글 문서에서 이름으로 찾는 자리. 공동 편집은 칸 단위로 한다 |
| 문서 틀 고치기 | 칸에 담기지 않는 표·그림·용지 고침. 한 번에 한 사람만 한다 |
| 충돌 사본 | 같은 칸에 글이 겹쳤을 때 버리지 않고 따로 둔 내 글 |
| RAG | 질문에 맞는 문서를 먼저 찾아 그 내용을 근거로 답하는 방식[1] |
| RAG 공간 | 검색 범위 묶음. 공통 RAG(전 교직원), 부서 RAG(그 부서), 학생 RAG(학생 공개 규정) |
| 지식그래프 | 사업·연차·문서·절을 관계로 이은 그림. 찾을 범위를 좁히는 데 쓴다 |
| 온톨로지 | 지식그래프에 어떤 종류의 점과 관계가 있는지 정한 설계도 |
| 생각 과정 | 답 앞에 AURA 가 질문 파악, 근거 확인, 답 구성 순으로 따진 글 |
| 문맥 | 모델이 한 번에 읽는 글의 양. 「문맥 N% 사용」 으로 보인다 |
