# 부록. AURA 사용 설명서

이 부록은 AURA를 처음 사용하는 교직원과 관리자를 위한 사용 설명서다. 역할별 시작 안내, 업무별 사용 예, 화면별 기능, 운영 관리,
시스템 관리, 자주 묻는 질문, 문제 해결 순으로 구성했다. 동작 원리는 본문 3~4장에서 다루고, 여기서는 화면 조작만 설명한다.

화면과 단추 이름은 화면에 적힌 그대로 「」로 묶고, 괄호 안 주소(/hwp 등)는 브라우저 주소창의 경로다. 그림은 시험 계정과
가상 자료로 촬영했다. [n]은 본문의 참고 문헌 번호다.

## 부록 1. AURA 개요

### 1.1 AURA의 주요 기능

AURA는 영남이공대학교 교내 행정 문서의 판독, 검색, 작성을 교내 장비 안에서만 처리하는 플랫폼이다. 문서는 학교 밖 AI 서비스로 나가지 않는다.
부록 1~4는 AURA를 쓰는 교직원·학생, 부록 5는 계정과 검색 범위를 관리하는 운영 관리자, 부록 6은 모델·서버를 맡는 개발·유지보수 담당자를 위한 내용이다.

| 업무 | 사용 화면 | 내용 |
|---|---|---|
| 규정·지난 사업 자료 질문 | 「새 채팅」 | 근거 문서 검색과 출처를 단 답변 |
| 문서 찾기와 정리 | 「라이브러리」, 「검색」 | 등록 문서의 사업·연도·종류별 거르기와 원문 확인 |
| 한글 문서 공동 작성 | 「문서함」, 웹 한글 기안기 | 부서 폴더의 한글 문서를 브라우저에서 열어 여러 사람이 동시 편집 |
| 사업 문서 초안 작성 | 프로젝트, 「새 채팅」 | AURA의 양식 선택과 절별 초안 작성, 사람 검토 뒤 한글 파일로 내보내기 |

AURA가 작성하는 글은 사람이 검토할 초안이다. 숫자와 최종 판단은 근거 문서에서 확인한다.

### 1.2 화면 구성

모든 화면은 왼쪽 사이드바, 가운데 본문, 오른쪽 아래 업무 도우미 단추로 되어 있다([그림 A-1]). 사이드바에는 「검색」(Ctrl+K), 메뉴(「새 채팅」·「라이브러리」·
「문서함」·「사업 관리」·「조직 관리」), 「내 프로젝트」, 「공유받은 프로젝트」, 「최근 대화」가 차례로 있다. 맨 아래에는 AI 연결 상태, 「알림」,
내 이름을 누르면 뜨는 사용자 메뉴(「설정」·「로그아웃」, 권한에 따라 「문답 검수」·「테스트 보기」·「개발 현황」)가 있다.

[그림 A-1] AURA 첫 화면 (그림 docs/images/figures-1027/fA-01-first-screen.jpg)

메뉴는 계정에 따라 [표 A-1]과 같이 다르게 보인다. ○는 메뉴가 보이는 경우, ×는 보이지 않는 경우다.

| 메뉴 | 학생 | 일반 | 행정 담당자 | 사업 책임자 | 총괄 책임자 | 관리자 |
|---|---|---|---|---|---|---|
| 「새 채팅」, 「최근 대화」 | ○ | ○ | ○ | ○ | ○ | ○ |
| 「검색」, 「라이브러리」, 「문서함」 | × | ○ | ○ | ○ | ○ | ○ |
| 「사업 관리」 | × | × | ○(담당 사업) | ○(담당 사업) | ○(자기 부서) | ○(전체) |
| 「조직 관리」 | × | ○(보기) | ○(보기) | ○(담당 부서 구성원) | ○(담당 처·단 이하) | ○(전체·계정) |
| 「프로젝트 추가」(+) | × | △ | ○ | ○ | ○ | ○ |
| 「알림」, 업무 도우미 | × | ○ | ○ | ○ | ○ | ○ |
| 사용자 메뉴 「문답 검수」 | × | △ | △ | △ | △ | ○ |
| 사용자 메뉴 「테스트 보기」, 「개발 현황」 | × | × | × | × | × | ○ |

주: △는 추가 권한이 있는 경우에만 보인다. 괄호 안은 볼 수 있는 범위다.

[표 A-1] 계정별 메뉴

### 1.3 계정과 등급

계정 역할은 교직원·학생·관리자 세 가지이고, 교직원은 다시 네 등급으로 나뉜다([표 A-2]). 등급은 프로젝트를 만들고 진행 현황을 볼 수 있는 범위를 정한다. 찾아볼 수
있는 문서의 범위는 등급과 관계없이 소속 부서에 따라 정해진다.

| 등급 | 역할 | 권한 |
|---|---|---|
| 일반 | 공유받은 업무에 참여 | 질문·검색, 공유받은 프로젝트에서의 작업, 프로젝트 생성(「프로젝트 만들기」 권한을 받은 경우) |
| 행정 담당자 | 사업의 행정 지원 | 사업 책임자와 같은 권한(프로젝트 생성, 담당 사업 진행 현황 열람) |
| 사업 책임자 | 세부 사업 책임 | 프로젝트 생성, 책임 프로젝트·사업 진행 현황 열람, 같은 부서 일반 직원에게 「프로젝트 만들기」 권한 부여 |
| 총괄 책임자 | 부서장 | 자기 부서와 하위 팀·센터 프로젝트 진행 현황 열람, 사업 책임자 지정, 부서 드라이브 연결 |
| 관리자 | 시스템 전체 관리(최대 2명) | 모든 업무 화면과 개발 화면 사용 |

[표 A-2] 교직원 등급

등급을 정하지 않은 교직원 계정은 사업 책임자로 간주한다.

## 부록 2. 역할별 시작 안내

### 2.1 교직원 시작 안내

로그인 화면([그림 A-2])에서 로그인한 뒤 사용자 메뉴의 「설정」(/settings)에서 처음 받은 비밀번호를 바꾸고, 「구글 계정」 카드에서 학교 구글 계정(ync.ac.kr)을 연결한다. 구글
계정은 구글 문서 작성과 드라이브 가져오기에 사용한다. 그다음 「새 채팅」에서 업무 질문을 하나 해 보고, 답 아래 출처가 원문 대목으로 열리는지와
「문서함」에 우리 부서 폴더가 보이는지 확인한다.

[그림 A-2] 로그인 화면 (그림 docs/images/figures-1025/fA-02-login.jpg)

### 2.2 학생의 학사 질문

학생 계정은 학생에게 공개된 학사 규정을 묻는 대화만 사용한다([그림 A-3]). 사이드바에는 「새 채팅」과 「최근 대화」만 있고, 첨부·답변 방식 선택·문서 패널은
없다. 답 아래 출처를 누르면 규정의 해당 대목이 열린다.

[그림 A-3] 학생 계정 채팅 화면 (그림 docs/images/figures-1027/fA-03-student-chat.jpg)

### 2.3 일반 직원의 공유 프로젝트 참여

동료가 프로젝트를 공유하면 사이드바 「공유받은 프로젝트」에 나타난다. 프로젝트 이름 옆 칩은 받은 권한을 나타낸다. 「함께 작업」은 대화를 열고 작업 문서를
편집할 수 있고, 「읽기만」은 보기만 할 수 있다. 답의 근거 문서 가운데 내 부서 범위 밖의 문서는 「볼 수 없는 자료」로 표시된다.

### 2.4 사업 책임자·행정 담당자의 프로젝트 생성

「내 프로젝트」 옆 「프로젝트 추가」(+)에서 업무(국고사업·채용·입학·일반 행정)를 선택하고 공고나 지난 계획서를 자료로 선택하면 프로젝트 이름이 자동으로 정해진다.
마감일과 사업단은 선택 항목이다. 만든 뒤에는 부록 3.1의 순서로 초안을 만든다.

### 2.5 총괄 책임자의 부서 설정

「조직 관리」에서 부서를 선택하고 「구성원」 탭에서 구성원의 등급을 정한다. 「부서 설정」 탭의 부서 드라이브 항목에서 부서 공용 학교 계정으로
「구글 드라이브 연결」을 누른다. 부서 프로젝트의 진행은 각 프로젝트의 「진행 현황」 탭에서 본다.

### 2.6 관리자 초기 점검

사용자 메뉴의 「개발 현황」(/dev)으로 들어가 「도구·모델 연결」의 「초기 설정」 카드에서 남은 연동 항목과 모델 서버 연결을 확인한다(부록 6.1). 이어서
「RAG 공간」의 문서 수, 「조직 관리」의 계정·부서와 학교 계정 연결 현황을 보고, 「테스트 보기」로 다른 계정이 보는 범위를 확인한다(부록 5.3).

## 부록 3. 업무별 사용 예

### 3.1 사업계획서 초안 작성

사업 책임자가 새 국고사업 공고에 맞춰 사업계획서 초안을 만드는 경우다. 공고 파일이 있고, 작년 계획서가 라이브러리에 있다고 가정한다.

1. 프로젝트를 만든다. 「프로젝트 추가」 창에서 업무 「국고사업」과 이번 공고를 선택한다([그림 A-4]).

   [그림 A-4] 프로젝트 추가 창 (그림 docs/images/figures-1027/f4-16-project-add-dialog.jpg)

2. 재료를 모은다. 프로젝트 화면의 「문서 추가」로 공고 원문, 부서 폴더·드라이브의 파일, 근거가 될 규정·지침을 넣는다. 넣은 문서는 첨부·참고·기준
   문서로 나뉜다. 「지난 사업 연결」로 작년 사업을 연결하고, 「작성 원칙」에 지킬 점(「예산은 백만원 단위」 등)을 한 줄씩 적는다. 프로젝트에 넣은 문서는
   그 프로젝트의 대화에서 다른 문서보다 먼저 근거로 사용된다([그림 A-5]).

   [그림 A-5] 프로젝트 화면 (그림 docs/images/figures-1027/f4-17-project-chat-docs.jpg)

3. 대화로 초안 작성을 요청한다. 예: 「이 공고로 사업계획서 초안 써 줘. 대상은 1학년, 예산은 5천만원, 기간은 내년 3월부터 12월까지.」 AURA는 프로젝트의
   작성 서식이나 공통 양식 가운데 맞는 양식을 선택하고(없으면 양식부터 만든다), 오른쪽 문서 패널의 작업 문서에 절을 하나씩 채운다. 어떤 근거로 어느 절을
   작성했는지는 답 아래 「작업 내역」에서 확인한다([그림 A-6]).

   [그림 A-6] 대화·작업 문서 화면 (그림 docs/images/01-chat-hwp-agent.jpg)

4. 모르는 값을 채운다. 자료에서 찾지 못한 값(사업단장 이름, 협약 기관 수 등)은 「필요한 값 입력」 영역에 모인다. 값을 직접 넣거나, 줄을 선택해 「선택한 줄
   자료에서 찾기」로 프로젝트 문서에서 제안을 받는다. 자료에서 찾은 값은 「자료에서 찾음 · 확인 전」으로 미리 채워지며 담당자가 확인해야 확정된다.
   비워 둔 항목은 다음에 다시 묻는다([그림 A-7]).

   [그림 A-7] 값 입력 영역 (그림 docs/images/figures-1027/f4-19-needed-values.jpg)

5. 수정을 요청한다. 「2번 절 더 구체적으로」, 「추진 일정은 표로」, 「용지 가로로」처럼 말하면 AURA가 그 절을 다시 읽고 수정한다. 수정 결과는 답 아래
   「반영한 것」에서 문서에 들어간 모양 그대로 확인하고, 표나 글꼴이 마음에 들지 않으면 「다른 모양으로 바꾸기」에서 후보를 선택해 다시 꾸민다. 직접 수정할 때는
   문서 패널에서 기안기의 「편집 도구」를 펼친다. 근거에 없는 숫자는 「○○」로 비워 두므로 값을 알면 직접 넣는다.

6. 검토를 받는다. 「이 초안 검토해 줘」라고 하면 작성방법과 배점 항목에 비추어 빠진 점을 알려 준다. 동료와는 프로젝트 머리의 공유 단추로 함께 작업한다(부록 4.6).

7. 한글 파일로 내보낸다. 「한글 파일로 내보내 줘」라고 하면 원본 한글 서식에 내용을 채운 완성본을 만든다. 기안기의 「⋯」 → 「내려받기」에서
   hwpx·hwp·PDF·docx로 받거나, 「구글 드라이브에 올리기」로 드라이브에 저장한다([그림 A-8]).

   [그림 A-8] 기안기 추가 메뉴 (그림 docs/images/figures-1025/f4-24-editor-more-menu.jpg)

수십 쪽 분량의 공모 서식은 한 번에 요청하지 말고 나누어 요청한다. 먼저 문서 틀(「과제 견본을 과제 6개로 늘려 줘」), 다음 표지·신청서 값(「대학명: 영남이공대학교,
총괄책임자 성명: 홍길동」처럼 「항목: 값」 형식), 그다음 절별 내용(「2.1을 써 줘」) 순으로 요청한다. 앞 답변을 작성하는 동안 다음 요청을 보내 두면 차례로 처리된다.
작년 계획서를 양식으로 선택하면 AURA는 그 문서를 근거에서 뺀다. 작년 수치가 올해 문서에 그대로 옮겨지지 않게 하기 위해서다.

### 3.2 지난 사업 문서 검색과 재사용

행정 담당자가 작년 결과보고서 양식을 찾아 올해 버전으로 작성하는 경우다. 지난 문서를 찾는 방법은 네 가지다.

- 문서함: 「부서 폴더」 → 「공통」 아래 「지난 사업 문서」(사업 → 목적 폴더)와 「공통 양식」에 양식이 있다. 양식은 잠겨 있어 「사본 만들기」로 우리
  부서 폴더·내 폴더·프로젝트에 사본을 만들어 사용한다. 위쪽 「양식으로 시작」은 양식 이름으로 찾아 바로 사본을 만든다([그림 A-9], [그림 A-10]).

  [그림 A-9] 문서함 화면 (그림 docs/images/figures-1027/f4-22-hwp-box.jpg)

  [그림 A-10] 사본 위치 선택 창 (그림 docs/images/figures-1027/f4-23-copy-where-dialog.jpg)

- 라이브러리: 「사업별로 보기」에서 사업을 선택하고 종류·기간으로 좁힌다. 「본문까지」를 켜면 본문 낱말로도 찾는다. 한글 양식이면 문서 화면의
  「기안기로 작업」으로 바로 연다([그림 A-11]).

  [그림 A-11] 라이브러리 화면 (그림 docs/images/figures-1027/fA-11-library.jpg)

- 지난 사업 화면(/projects/archived): 보관된 사업을 사업명·연도·사업단으로 찾고, 「참조 연결」로 현재 프로젝트에 연결한다.
- 대화: 「작년 LINC 3.0 결과보고서에서 취업 성과 부분 찾아 줘」처럼 사업·연도·문서 종류를 넣어 묻는다. 문서 이름을 「」로 묶으면 그 문서로
  좁혀 찾는다.

### 3.3 보고서 공동 편집

한 부서의 세 사람과 AURA가 같은 실적보고서의 서로 다른 곳을 동시에 고치는 경우다.

기안기는 문서를 처음 열 때 제목·소제목·표 셀을 포함한 모든 문단을 편집 영역(누름틀, 이름이 붙은 입력 영역)으로 나누며, 편집은 영역 단위로 한다. 한 영역에 글을 쓰기 시작하면 그 영역의 편집권을 갖고, 다른
영역으로 옮기거나 창을 닫으면 편집권이 풀린다. 다른 사람이 쓰는 영역에는 글이 들어가지 않고 그 영역의 이름표가 잠깐 흔들린다. 쓰던 사람이 영역을 떠나면 바로 쓸 수 있다.

기안기 상단 표시줄 오른쪽의 동그라미는 지금 같은 문서를 열고 있는 사람이다. 동그라미를 누르면 그 사람이 쓰는 영역으로 화면이 따라간다. 문서 안에서 다른 사람이
쓰는 영역은 옅은 바탕색, 색 커서, 여백의 이름표로 표시된다([그림 A-12], [그림 A-13]).

[그림 A-12] 기안기 상단 표시줄 (그림 docs/images/figures-1025/fA-12-editor-header.jpg)

[그림 A-13] 편집 중 영역 표시 (그림 docs/images/figures-1025/g01-coedit-pane-people.jpg)

함께 쓸 때 알아 둘 점은 다음과 같다.

- 편집 영역 안에서 바꾼 서식(글꼴·색·크기)은 바로 다른 사람 화면에도 반영된다. 표에 줄을 더하거나 그림·용지를 바꾸는 일은 「문서 틀 고치기」로 저장하며
  한 번에 한 사람만 할 수 있다. 저장되면 다른 사람 화면은 새 버전으로 바뀌고, 각자 영역에 쓴 글은 그대로 남는다.
- 같은 영역에 두 사람의 글이 겹치면 내 글은 버리지 않고 사본으로 보관한다. 「⋯」 → 「충돌로 따로 둔 내 글」에서 꺼낸다.
- 연결이 끊긴 동안 쓴 글은 연결이 돌아오면 자동으로 전송된다.
- 「3번 칸은 AURA가 채워 줘」처럼 요청하면 AURA도 한 사람처럼 편집 영역을 잡고 작성한다. 사람이 잡은 영역에는 작성하지 않는다.
- 이전 버전은 버전 기록에 남는다.

아주 큰 문서처럼 편집 영역으로 나누지 않은 문서는 한 번에 한 사람만 편집한다. 나중에 연 사람은 보기 전용으로 보다가, 먼저 연 사람이 문서를 닫으면 이어서 편집한다([그림 A-14]).

[그림 A-14] 보기 전용 문서 화면 (그림 docs/images/02-hwp-edit-lock.jpg)

### 3.4 규정 질문

교직원이 연구년 신청 자격을 묻는 경우다.

「새 채팅」에서 답변 방식이 「RAG」인지 확인하고 「연구년 신청 자격이 어떻게 돼?」라고 묻는다. 답은 요약, 근거 요점, 출처 순으로 나오며, 출처를 누르면
오른쪽에 규정 원문의 해당 조항이 열린다. 「생각 과정 펼치기」를 누르면 AURA가 질문 파악, 근거 확인, 답 구성 순으로 판단한 과정을 볼 수 있다. 답이 틀렸으면
「아쉬움」을 눌러 이유를 남긴다([그림 A-15], [그림 A-16]).

어느 규정이 현행 버전인지는 라이브러리 기준 문서 탭의 「규정 목록」에서 본다. 규정마다 현행 버전과 최종 개정일이 나오고, 「구판 보기」를 누르면 이전 버전이
펼쳐진다. 답의 근거가 구판이면 출처 이름에 「구판」이 붙는다.

[그림 A-15] 규정 답변과 출처 (그림 docs/images/figures-1027/fA-15-regulation-answer-source.jpg)

[그림 A-16] 답변의 추론 과정 보기 (그림 docs/images/figures-1027/f4-15-answer-sources-thinking.jpg)

숫자 뒤에 「(근거 확인 필요)」가 붙으면 그 숫자가 근거 문서에 없다는 뜻이므로 원문에서 꼭 확인한다. 다른 부서 자료를 묻는 질문에는 열람 권한이
없다는 안내만 붙고, 그 문서가 있는지 없는지는 알리지 않는다.

### 3.5 짧은 문서 작성

「새 채팅」에서 「다음 주 서울 출장 보고서 써 줘. 출장지는 ○○, 목적은 협약 회의」처럼 요청하면 AURA가 공통 양식에서 맞는 양식을 선택해 작업 문서를
만들고 채운다. 문서 패널에서 확인하고 수정한 뒤 「한글 파일로 내보내 줘」로 받는다.

### 4.5 웹 한글 기안기

웹 한글 기안기는 브라우저에서 한글 문서를 여는 한컴 편집기다[53]. 문서함에서 문서를 누르거나 채팅 문서 패널에서 「한글」 편집기를 선택해 연다. 찾기·바꾸기·쪽
설정 같은 편집 기능은 기안기 자체의 메뉴와 리본을 그대로 사용하며, 고친 내용은 자동으로 저장된다. 여럿이 함께 쓰는 방법은 부록 3.3에 있다. 메뉴와 리본이 보이는 기안기 화면은 [그림 A-8], 상단 표시줄의 단추와 표시는 [표 A-9]와 같다.

| 단추·표시 | 기능 |
|---|---|
| 문서 이름, 「부서 › 폴더」 | 문서 이름과 위치 표시(이름을 눌러 변경) |
| 저장 상태 | 현재 저장 상태 표시(「저장됨」, 「저장 중」, 「오프라인: 연결되면 저장」 등) |

| 「편집 도구」 | 메뉴·리본·서식줄 펼치기·접기 |
| 「⋯」 | 「다른 이름으로 저장」, 「문서 틀 고치기」, 「충돌로 따로 둔 내 글」, 「내려받기」, 「구글 드라이브에 올리기」, 「문서함에서 보기」 |

주: 따라가기는 동그라미를 다시 누르거나 직접 입력하거나 화면을 움직이면 멈춘다.

### 4.6 프로젝트

프로젝트(/project/번호)는 사업 하나의 문서·작성 원칙·기준 문서·지난 사업·대화를 묶어 관리하는 화면이다. 구역별 내용은 [표 A-11]과 같다.

| 구역 | 내용 |
|---|---|
| 머리 | 문서 수, 마감, 「책임 ○○」, 공유 단추(「공유 안 함」 / 「공유 중 · N」), 「관리」 |
| 「대화·문서」 탭 | 새 대화, 프로젝트 문서, 작성 원칙, 관련 지난 사업, 지난 대화, 작업 문서 |
| 「진행 현황」 탭 | 열람 권한이 있는 사람에게만 표시. 요청·참여자·작업 문서·사용량 요약, 사람별 거르기, 날짜별 사용량, 대화별 요청 기록, 사람별 작업 요약 |

[표 A-11] 프로젝트 화면

공유 단추를 누르면 「프로젝트 공유」 창이 열린다. 「나만 보기」를 선택하면 담당자와 관리자만 보고, 「공유」를 선택하면 선택한 부서나 사람에게 「읽기만」 또는 「함께
작업」 권한으로 공유한다. 기본 권한은 「읽기만」이다. 공유는 선택한 부서·사람에게만 적용되며 하위 팀이나 다른 부서로 자동으로 넓어지지 않는다. 「비공개」로 둔 대화는 공유해도 보이지 않는다.
다른 부서 사용자는 대화의 질문과 답을 읽을 수 있지만, 근거 원문과 첨부는 그 사용자에게 열람 권한이 있는 문서만 열린다([그림 A-20]).

[그림 A-20] 프로젝트 공유 창 (그림 docs/images/figures-1027/f4-20-project-share-dialog.jpg)

사업 책임자는 머리의 「책임 ○○」에서 「함께 작업」 권한으로 공유한 사람 가운데 선택한다. 사업이 끝나면 「관리」 → 「보관」으로 「지난 사업」에 옮긴다.

### 4.7 그래프 탐색

그래프 탐색(/graph/explore)은 사업·연차·문서·절 사이의 관계를 그림으로 본다. 라이브러리의 「지식그래프」나 문서 화면의 「관계 보기」로 연다. 사업을
선택하면 그 사업 중심의 그래프가 그려지고, 점을 눌러 이웃 점을 펼치거나 문서를 연다. 사업 그래프 화면은 사업별로 연차별 문서, 성과지표, 계획서 절과
실적보고서 절의 대응 관계를 표로 보여 준다. 관리자는 「온톨로지」 보기에서 전체 구조와 최근 구조 검사 결과를 확인하고, 온톨로지 설계도(OWL[44]),
검사 규칙(SHACL[45]), 검사 결과, 노드·관계·사업 목록 파일을 내려받는다. 열람 권한이 없는 문서의 점은 그래프에 나타나지 않는다([그림 A-21]).

[그림 A-21] 그래프 탐색 화면 (그림 docs/images/figures-1027/fA-22-graph-node-panel.jpg)

### 4.8 검색

사이드바 「검색」이나 Ctrl+K로 대화·프로젝트·문서·한글 문서를 이름으로 빠르게 찾는다. 이름에서 찾지 못하면 Enter로 본문까지 찾는 검색
화면(/search)으로 간다. 검색 화면의 결과는 「문서」, 「본문 대목」, 「프로젝트」, 「대화」로 나뉘며, 본문 대목을 누르면 문서 화면의 해당 위치가 열린다.

### 4.9 업무 도우미

업무 도우미는 채팅 밖 화면의 오른쪽 아래 둥근 단추로 여는 옆 패널이다(학생 계정에는 없다). 화면 사용법을 묻거나 할 일을 시킨다.
「문서함에서 ○○ 폴더 열어 줘」, 「라이브러리에서 LINC 3.0 사업 찾아 줘」처럼 시키면 도우미가 화면 위 AURA 커서로 화면을 옮기고 창을 열어
입력란을 채우고, 「선택」·「확인」·「다음」 같은 단추를 바로 누른다. 프로젝트 만들기와 에이전트 대화로 넘기기도 시키는 즉시 처리한다.
삭제·보내기·제출처럼 결과를 되돌리기 어려운 단추와 공개 범위·공유를 바꾸는 일은 담당자가 「지워 줘」처럼 직접 시켰을 때만 처리하고, 그렇지 않으면
도우미 창에 제안을 띄워 담당자가 「실행」을 눌러야 처리한다. 「학생에게 장학 규정을 보이게 하려면?」처럼 방법을 물으면 설명과 함께 이런 제안이 붙는다.
화면의 글을 선택하면 「쉽게 설명」, 「관련 규정 찾기」 같은 메뉴로 그 대목을 묻는다([그림 A-22]).

[그림 A-22] 업무 도우미 창 (그림 docs/images/figures-1027/fA-23-helper-run-suggestion.jpg)

제안에서 「화면에서 직접」을 선택하면 화면 위 AURA 커서가 대상 줄과 단추를 차례로 가리키며, 칸 채우기와 「선택」·「확인」 같은 단추는 그대로 처리한다.
확인이 필요한 마지막 단추에서는 커서가 가리키기만 하므로, 가리킨 단추를 직접 누르거나 제안의 「실행」으로 처리한다([그림 A-23]).

[그림 A-23] 업무 도우미 자동 실행 화면 (그림 docs/images/figures-1027/f4-31-helper-proposal.jpg + f4-31b-helper-screen-cursor.jpg)

사업 문서의 내용을 묻는 질문이나 문서 작성 요청은 도우미가 에이전트 대화(「새 채팅」)로 바로 넘긴다.

### 5.2 RAG 공간

RAG 공간은 AURA가 어느 문서 집합에서 찾을지 정하는 곳이다. 규정 등록과 공개는 라이브러리 「기준」 칩에서 한다. 작업별 경로는 [표 A-14], RAG 공간 화면은 [그림 A-29]와 같다.

| 작업 | 경로 |
|---|---|
| 학사 규정을 학생에게 공개 | 라이브러리 「기준」 칩 › 규정 줄 「…」 › 「학생 공개로」 |

### 5.3 다른 계정 화면 확인

다른 계정이 보는 화면·검색·답 범위를 그대로 확인하는 기능이다. 사용자 메뉴의 「테스트 보기」에서 역할·등급·부서를 선택하면 맨 위에 띠가 뜨고, 이
상태에서 한 질문·검색은 그 계정이 받는 결과와 같다. 띠의 「원래대로」로 돌아온다. 「특정 사람만 문서를 못 찾는다」는 문의를 확인할 때 사용한다.

### 5.4 개인정보 점검

수집 문서·첨부·답의 개인정보 마스킹을 항목별로 켜고 끄는 화면이다. 기본값은 꺼짐이고, 학습 데이터 반출에서는 이 설정과 관계없이 항상 마스킹한다. 마스킹 기능이 알려진 개인정보 형식을
제대로 찾는지 보는 자가 점검은 합성 표본으로 매일 실행되고, 저장된 본문에 남은 개인정보 형식을 찾는 검사는 주 1회 실행된다. 결과가 그보다
오래되면 확인이 필요하다는 경고가 뜬다. 수집 때 남긴 마스킹 기록은 문서명과 유형으로 찾을 수 있다. 마스킹을 켰다가 꺼도 이미 마스킹된 본문은 되살아나지 않으므로,
원문이 필요하면 원본을 다시 수집한다.

## 부록 6. 시스템 관리(개발·유지보수)

시스템 관리는 모델 서버 연결, 모델 학습과 교체, 장애 대응처럼 AURA가 계속 동작하도록 유지하는 일이다. 관리자 계정으로 「개발 현황」에 들어가
[표 A-13]의 시스템 관리 화면을 사용한다.

### 6.1 도구·모델 연결

용도(답, 수집 검토, 이미지 판독, 업무 도우미)마다 어느 서버의 어느 모델을 사용할지 정하는 화면이다. 맨 위 「초기 설정」 카드는 새로 설치한 서버에서 남은
연동 항목을 보여 주고, 「서버 설정」 카드는 검색 서버·웹 검색 키·원본 폴더 같은 값을 서버 파일 대신 화면에서 정한다. 「LLM 연결」에서 서버별로 연결을
확인하고 기본 서버를 정하며, 「단계별 모델」에서 용도별 모델을 바꾼다([그림 A-30]).

[그림 A-30] 도구·모델 연결 화면 (그림 docs/images/figures-1027/fA-29-llm-connections.jpg)

「단계별 모델」 카드는 문서 작업, 수집 검토, 이미지 판독, 업무 도우미의 네 용도마다 서버와 모델을 한 줄씩 보여 준다. 줄에서 다른 서버나 모델을
선택하고 저장하면 그 용도에 바로 적용된다([그림 A-31]). 모델 이름과 컨텍스트 길이는 코드에 고정되어 있지 않고 이 설정에 저장되므로, 더 큰 모델로 바꿀 때 코드를 고칠 필요가 없다.

[그림 A-31] 단계별 모델 설정 (그림 docs/images/figures-1027/f4-33-stage-models.jpg)

### 6.2 학습 데이터 검수와 학습 상태

문답 검수 권한은 모델 학습에 사용할 문답을 사람이 검수할 때만 사용한다. 「조직 관리」에서 검수할 교직원에게 추가 권한 「SFT 문답 검수」를 주면 그 사람의 사용자 메뉴에
「문답 검수」(/review)가 생기고, 여기서 자기에게 배정된 검수 목록과 검수 매뉴얼을 보며 Label Studio[20] 검수 화면을 연다.
관리자는 「데이터·학습」(/dev/train)의 「문답 검수」 표에서 검수가 끝난 작업의 「완료한 검수 결과 반영」을 누른다. 「승인 데이터·산출물」에서는 학습셋별 파일과
「학습셋 표본」을, 「학습 상태 보기」(/dev/train/run)에서는 학습 점검 결과와 손실 곡선(TensorBoard[63])을 본다. 손실 곡선으로 학습이 정상적으로 수렴하는지를
학습 장비에 접속하지 않고 확인한다([그림 A-32]). 학습셋 원문은 학습 장비에만 있고, 이 화면에는 이름·상태·건수 같은 목록 정보만 표시된다.

## 부록 7. 자주 묻는 질문

문. 내가 올린 문서가 학교 밖 AI로 나가는가.
답. 나가지 않는다. 답·검색·판독 모델은 모두 교내 장비에서 동작한다. 밖으로 나가는 것은 「인터넷에서 찾아보기」를 눌렀을 때의 질문 글(개인정보가 있으면
보내지 않음)과, 내 학교 구글 계정으로 만든 구글 문서 작업 문서뿐이다.

문. 다른 부서 문서는 왜 찾아지지 않는가.
답. 검색은 처음부터 내 부서 범위의 문서 안에서만 한다. 다른 부서 자료가 업무에 필요하면 관리자에게 겸직 부서를 요청하거나, 그 부서가 부서 RAG를
열어 주어야 한다.

문. 프로젝트 추가(+) 단추가 보이지 않는다.
답. 일반 등급은 기본적으로 프로젝트를 만들 수 없다. 같은 부서 사업 책임자에게 「프로젝트 만들기」 권한을 받거나, 공유받은 프로젝트에서 작업한다.

문. AURA가 쓴 초안을 바로 제출해도 되는가.
답. 아니다. 숫자는 출처의 원문에서 확인하고(근거에 없는 숫자에는 「(근거 확인 필요)」가 붙거나 「○○」로 비워진다), 내보낸 한글 완성본도 한글
프로그램에서 한 번 열어 본다.

문. 한글(.hwp) 파일도 되는가.
답. 된다. 문서함과 라이브러리 모두 .hwp와 .hwpx를 받는다. 양식 채우기는 hwpx로 바꾸어 다룬다.

문. 대화가 길어지면 앞 내용을 잊는가.
답. AURA는 대화마다 목표·확정된 것·남은 일을 작업 메모로 갱신해 두고 다음 요청에 함께 사용한다. 「문맥 N% 사용」이 높으면 새 대화로 나누는 것이 좋다.

## 부록 8. 문제 해결

실무에서 막히기 쉬운 증상과 사용자가 직접 할 수 있는 해결 방법을 모았다([표 A-16]). 표에 없는 증상은 관리자에게 화면 그림과 함께 알린다.

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| 사이드바에 「AI 미연결 · 답변 대기」 | 답 모델 서버와의 연결이 잠시 끊김 | 보내 둔 질문은 연결이 돌아오면 차례로 답한다. 몇 분이 지나도 그대로이면 관리자에게 알린다. 그동안 필요한 문서는 「라이브러리」에서 직접 찾아 원문을 확인한다 |
| 문서 작업 답이 늦음 | 근거 검색과 절별 작성에 드는 시간 | 「작업 내역」에서 진행 단계를 확인하고, 다음 요청은 미리 보내 둔다(「다음 요청 n건 대기」로 차례 처리). 간단한 질문은 답변 깊이를 「빠르게」로 바꾸고, 긴 서식은 절별로 나누어 요청한다(부록 3.1). 「문맥 N% 사용」이 높으면 새 대화로 나눈다 |
| 「관리자가 구글 앱을 등록한 뒤 연결할 수 있습니다.」 | 관리자가 구글 앱을 아직 등록하지 않음 | 관리자에게 「Google 앱 등록」을 요청한다. 그동안은 문서 패널의 편집기를 「한글」로 선택해 기안기로 작성한다 |
| 구글 연결이 끊겼다는 안내 | 연결 만료 | 「설정」의 「구글 계정」 카드에서 학교 구글 계정(ync.ac.kr)을 다시 연결한다. 개인 계정은 연결되지 않는다. 다시 연결해도 끊기면 관리자에게 문의한다 |
| 문서함에 「한글 편집기 연결 안 됨」 | 기안기 서버와의 연결이 끊김(그동안 「새 문서」·「양식으로 시작」 비활성) | 잠시 뒤 문서함을 다시 연다. 계속되면 관리자에게 문의한다. 급하면 줄의 「내려받기」로 파일을 받아 한글 프로그램에서 고친 뒤 「올리기」로 다시 올린다 |
| 공통 양식 수정 불가 | 모두가 쓰는 원본이라 잠겨 있음 | 줄의 「사본 만들기」로 우리 부서 폴더·내 폴더·프로젝트에 사본을 만들거나 위쪽 「양식으로 시작」으로 바로 사본을 만들어 쓴다. 양식 자체의 오류는 관리자에게 알린다 |
| 입력한 글이 들어가지 않고 이름표가 흔들림 | 다른 사람이 그 영역을 편집 중 | 다른 영역을 먼저 쓴다. 상단 표시줄의 동그라미로 누가 쓰는지 확인하고, 그 사람이 영역을 떠나면 바로 쓸 수 있다. 오래 기다려야 하면 그 사람에게 「넘겨주기」를 부탁한다(부록 4.5) |
| 내 글이 사라진 것 같음 | 같은 영역에 두 사람의 글이 겹쳐 내 글을 사본으로 보관함 | 「⋯」 › 「충돌로 따로 둔 내 글」에서 꺼내 복사해 다시 넣는다. 저장 상태가 「오프라인: 연결되면 저장」이면 연결이 돌아올 때 자동으로 저장된다. 그래도 없으면 버전 기록에서 이전 버전을 확인한다 |
| 올린 문서가 「처리 중」에서 오래 멈춤 | 쪽 수가 많은 스캔 문서는 판독에 시간이 걸림 | 잠시 기다린 뒤 다시 확인한다. 오래 그대로이면 쪽을 나누어 다시 올리거나, 관리자에게 문서 이름과 접수번호를 알린다 |
| 올린 문서가 「실패」 | 암호가 걸렸거나 손상된 파일 | 암호를 풀어 저장한 파일을 다시 올린다. 그래도 실패하면 관리자에게 문서 이름을 알린다(관리자는 「원본 관리」에서 다시 처리) |

[표 A-16] 문제 해결
