# 부록. AURA 사용 설명서

이 부록은 AURA를 처음 사용하는 교직원과 관리자를 위한 사용 설명서다. 역할별로 처음 할 일, 업무 장면별 사용법, 화면별 기능,
관리자 안내, 자주 묻는 질문, 문제 해결 순으로 구성했다. 동작 원리는 본문 3~4장에서 다루고, 여기서는 화면 조작만 설명한다.

화면과 단추 이름은 화면에 적힌 그대로 「」로 묶고, 괄호 안 주소(/hwp 등)는 브라우저 주소창의 경로다. 그림은 시험 계정과
가상 자료로 촬영했다. [n]은 본문의 참고 문헌 번호다.

## 부록 1. AURA 한눈에 보기

### 1.1 AURA는 무엇을 하는가

AURA는 영남이공대학교 교내 행정 문서를 교내 장비 안에서만 읽고, 찾고, 쓰는 플랫폼이다. 문서는 학교 밖 AI 서비스로 나가지 않는다.

| 하고 싶은 일 | 사용 화면 | 설명 |
|---|---|---|
| 규정·지난 사업 자료를 묻기 | 「새 채팅」 | 근거 문서를 찾아 출처와 함께 답한다 |
| 문서 찾기와 정리 | 「라이브러리」, 「검색」 | 등록된 문서를 사업·연도·종류로 걸러 원문을 확인한다 |
| 한글 문서를 함께 쓰기 | 「문서함」, 웹 한글 기안기 | 부서 폴더의 한글 문서를 브라우저에서 열고 여러 사람이 동시에 편집한다 |
| 사업 문서 초안 쓰기 | 프로젝트, 「새 채팅」 | AURA가 양식을 선택하고 절마다 초안을 작성하며, 사람이 검토해 한글로 내보낸다 |

AURA가 작성하는 글은 사람이 검토할 초안이다. 숫자와 최종 판단은 근거 문서에서 확인한다.

### 1.2 화면 구성

모든 화면은 왼쪽 사이드바, 가운데 본문, 오른쪽 아래 업무 도우미 단추로 되어 있다([그림 부록-1]). 사이드바에는 「검색」(Ctrl+K), 메뉴(「새 채팅」·「라이브러리」·
「문서함」·「사업 관리」·「조직 관리」), 「내 프로젝트」, 「공유받은 프로젝트」, 「최근 대화」가 차례로 있다. 맨 아래에는 AI 연결 상태, 「알림」,
내 이름을 누르면 뜨는 사용자 메뉴(「설정」·「로그아웃」, 권한에 따라 「문답 검수」·「테스트 보기」·「개발 현황」)가 있다.

### 1.3 계정과 등급

계정 역할은 교직원·학생·관리자 세 가지이고, 교직원은 다시 네 등급으로 나뉜다([표 부록-2]). 등급은 프로젝트를 만들고 진행 현황을 볼 수 있는 범위를 정한다. 어떤
문서를 찾아볼 수 있는지는 등급이 아니라 소속 부서로 정해진다.

| 등급 | 역할 | 권한 |
|---|---|---|
| 일반 | 공유받은 업무에 참여 | 질문·검색과 공유받은 프로젝트에서의 작업. 「프로젝트 만들기」 권한을 받으면 프로젝트도 만든다 |
| 행정 담당자 | 사업의 행정 지원 | 사업 책임자와 같은 권한. 프로젝트를 만들고 맡은 사업의 진행을 본다 |
| 사업 책임자 | 세부 사업 책임 | 프로젝트를 만들고 책임진 프로젝트·사업의 진행 현황을 본다. 같은 부서 일반 직원에게 「프로젝트 만들기」 권한을 준다 |
| 총괄 책임자 | 부서장 | 자기 부서와 하위 팀·센터 프로젝트의 진행 현황을 보고 사업 책임자를 정한다. 부서 드라이브를 연결한다 |
| 관리자 | 시스템 전체 관리(최대 2명) | 모든 업무 화면과 개발 화면 사용 |

[표 부록-2] 교직원 등급

등급을 정하지 않은 교직원 계정은 사업 책임자로 간주한다.

## 부록 2. 역할별 빠른 시작

### 2.1 교직원: 처음 10분

로그인 화면([그림 부록-2])에서 로그인한 뒤 사용자 메뉴의 「설정」(/settings)에서 처음 받은 비밀번호를 바꾸고, 「구글 계정」 카드에서 학교 구글 계정(ync.ac.kr)을 연결한다. 구글
계정은 구글 문서 작업본과 드라이브 가져오기에 사용한다. 그다음 「새 채팅」에서 업무 질문을 하나 해 보고, 답 아래 출처가 원문 대목으로 열리는지와
「문서함」에 우리 부서 폴더가 보이는지 확인한다.

[그림 부록-2] 로그인 화면 (그림 docs/images/figures-1025/fA-02-login.jpg)

### 2.2 학생: 학사 질문하기

학생 계정은 학생에게 공개된 학사 규정을 묻는 대화만 사용한다([그림 부록-3]). 사이드바에는 「새 채팅」과 「최근 대화」만 있고, 첨부·답변 방식 선택·문서 패널은
없다. 답 아래 출처를 누르면 규정의 해당 대목이 열린다.

[그림 부록-3] 학생 계정의 채팅 화면 (그림 docs/images/figures-1027/fA-03-student-chat.jpg)

### 2.3 일반 직원: 공유받은 프로젝트에서 일하기

동료가 프로젝트를 공유하면 사이드바 「공유받은 프로젝트」에 나타난다. 프로젝트 이름 옆 칩은 받은 권한을 나타낸다. 「함께 작업」은 대화를 열고 작업 문서를
편집할 수 있고, 「읽기만」은 보기만 할 수 있다. 답의 근거 문서 가운데 내 부서 범위 밖의 문서는 「볼 수 없는 자료」로 표시된다.

### 2.4 사업 책임자·행정 담당자: 프로젝트 만들기

「내 프로젝트」 옆 「프로젝트 추가」(+)에서 업무(국고사업·채용·입학·일반 행정)를 선택하고 공고나 지난 계획서를 자료로 선택하면 프로젝트 이름이 자동으로 정해진다.
마감일과 사업단은 선택 항목이다. 만든 뒤에는 부록 3.1의 순서로 초안을 만든다.

### 2.5 총괄 책임자: 부서 정비

「조직 관리」에서 부서를 선택하고 「구성원」 탭에서 구성원의 등급을 정한다. 「부서 설정」 탭의 부서 드라이브 항목에서 부서 공용 학교 계정으로
「구글 드라이브 연결」을 누른다. 부서 프로젝트의 진행은 각 프로젝트의 「진행 현황」 탭에서 본다.

### 2.6 관리자: 첫 점검

사용자 메뉴의 「개발 현황」(/dev)으로 들어가 「도구·모델 연결」의 「초기 설정」 카드에서 남은 연동 항목과 모델 서버 연결을 확인한다. 이어서
「RAG 공간」의 문서 수, 「조직 관리」의 계정·부서와 학교 계정 연결 현황을 보고, 「테스트 보기」로 다른 계정이 보는 범위를 확인한다(부록 5).

## 부록 3. 업무 장면별 따라 하기

### 3.1 사업계획서 초안을 처음부터 끝까지 만들기

장면: 사업 책임자가 새 국고사업 공고에 맞춰 사업계획서 초안을 만든다. 공고 파일이 있고, 작년 계획서가 라이브러리에 있다.

1. 프로젝트를 만든다. 「프로젝트 추가」 창에서 업무 「국고사업」과 이번 공고를 선택한다([그림 부록-4]).

   [그림 부록-4] 「프로젝트 추가」 창 (그림 docs/images/figures-1027/f4-16-project-add-dialog.jpg)

2. 재료를 모은다. 프로젝트 화면의 「문서 추가」로 공고 원문, 부서 폴더·드라이브의 파일, 근거가 될 규정·지침을 넣는다. 넣은 문서는 첨부·참고·기준
   문서로 나뉜다. 「지난 사업 연결」로 작년 사업을 잇고, 「작성 원칙」에 지킬 점(「예산은 백만원 단위」 등)을 한 줄씩 적는다. 프로젝트에 넣은 문서는
   그 프로젝트의 대화에서 다른 문서보다 먼저 근거로 사용된다([그림 부록-5]).

   [그림 부록-5] 프로젝트 화면: 프로젝트 문서, 작성 원칙, 관련 지난 사업 (그림 docs/images/figures-1027/f4-17-project-chat-docs.jpg)

3. 대화로 초안 작성을 요청한다. 예: 「이 공고로 사업계획서 초안 써 줘. 대상은 1학년, 예산은 5천만원, 기간은 내년 3월부터 12월까지.」 AURA는 프로젝트의
   작성 서식이나 공통 양식 가운데 맞는 양식을 선택하고(없으면 양식부터 만든다), 오른쪽 문서 패널의 작업 문서에 절을 하나씩 채운다. 어떤 근거로 어느 절을
   작성했는지는 답 아래 「작업 내역」에서 확인한다([그림 부록-6]).

   [그림 부록-6] 대화와 작업 문서를 나란히 둔 화면: AURA가 절을 쓰는 중 (그림 docs/images/01-chat-hwp-agent.jpg)

4. 모르는 값을 채운다. 자료에서 찾지 못한 값(사업단장 이름, 협약 기관 수 등)은 「필요한 값 입력」 영역에 모인다. 값을 직접 넣거나, 줄을 선택해 「선택한 줄
   자료에서 찾기」로 프로젝트 문서에서 제안을 받는다. 자료에서 찾은 값은 「자료에서 찾음 · 확인 전」으로 미리 채워지며 담당자가 확인해야 확정된다.
   비워 둔 항목은 다음에 다시 묻는다([그림 부록-7]).

   [그림 부록-7] 「필요한 값 입력」 영역 (그림 docs/images/figures-1027/f4-19-needed-values.jpg)

5. 수정을 요청한다. 「2번 절 더 구체적으로」, 「추진 일정은 표로」, 「용지 가로로」처럼 말하면 AURA가 그 절을 다시 읽고 수정한다. 수정 결과는 답 아래
   「반영한 것」에서 문서에 들어간 모양 그대로 확인하고, 표나 글꼴이 마음에 들지 않으면 「다른 모양으로 바꾸기」에서 후보를 선택해 다시 꾸민다. 직접 수정할 때는
   문서 패널에서 기안기의 「편집 도구」를 펼친다. 근거에 없는 숫자는 「○○」로 비워 두므로 값을 알면 직접 넣는다.

6. 검토를 받는다. 「이 초안 검토해 줘」라고 하면 작성방법과 배점 항목에 비추어 빠진 점을 알려 준다. 동료와는 프로젝트 머리의 공유 단추로 함께 작업한다(부록 4.6).

7. 한글 파일로 내보낸다. 「한글 파일로 내보내 줘」라고 하면 원본 한글 서식에 내용을 채운 완성본을 만든다. 기안기의 「⋯」 → 「내려받기」에서
   hwpx·hwp·PDF·docx로 받거나, 「구글 드라이브에 올리기」로 드라이브에 저장한다([그림 부록-8]).

   [그림 부록-8] 기안기 「⋯」 메뉴: 다른 이름으로 저장, 문서 틀 고치기, 내려받기, 구글 드라이브에 올리기 (그림 docs/images/figures-1025/f4-24-editor-more-menu.jpg)

수십 쪽 분량의 공모 서식은 한 번에 요청하지 말고 나누어 요청한다. 먼저 문서 틀(「과제 견본을 과제 6개로 늘려 줘」), 다음 표지·신청서 값(「대학명: 영남이공대학교,
총괄책임자 성명: 홍길동」처럼 「항목: 값」 형식), 그다음 절별 내용(「2.1을 써 줘」) 순으로 요청한다. 앞 답변을 작성하는 동안 다음 요청을 보내 두면 차례로 처리된다.

> 참고: 작년 계획서를 양식으로 선택하면 AURA는 그 문서를 근거에서 뺀다. 작년 수치가 올해 문서에 그대로 옮겨지지 않게 하기 위해서다.

### 3.2 지난 사업 문서를 찾아 다시 쓰기

장면: 행정 담당자가 작년 결과보고서 양식을 찾아 올해 버전으로 작성하려 한다. 지난 문서를 찾는 방법은 네 가지다.

- 문서함: 「부서 폴더」 → 「공통」 아래 「지난 사업 문서」(사업 → 목적 폴더)와 「공통 양식」에 양식이 있다. 양식은 잠겨 있어 「사본 만들기」로 우리
  부서 폴더·내 폴더·프로젝트에 사본을 만들어 사용한다. 위쪽 「양식으로 시작」은 양식 이름으로 찾아 바로 사본을 만든다([그림 부록-9], [그림 부록-10]).

### 3.3 여럿이 한 보고서를 동시에 쓰기

장면: 한 부서의 세 사람과 AURA가 같은 실적보고서의 서로 다른 곳을 동시에 고친다.

기안기는 문서를 처음 열 때 제목·소제목·표 셀을 포함한 모든 문단을 편집 영역(누름틀, 이름이 붙은 입력 영역)으로 나누며, 편집은 영역 단위로 한다. 한 영역에 글을 쓰기 시작하면 그 영역의 편집권을 갖고, 다른
영역으로 옮기거나 창을 닫으면 편집권이 풀린다. 다른 사람이 쓰는 영역에는 글이 들어가지 않고 그 영역의 이름표가 잠깐 흔들린다. 쓰던 사람이 영역을 떠나면 바로 쓸 수 있다.

머리줄 오른쪽 동그라미는 지금 같은 문서를 열고 있는 사람이다. 동그라미를 누르면 그 사람이 쓰는 영역으로 화면이 따라간다. 문서 안에서 다른 사람이
쓰는 영역은 옅은 바탕색, 색 커서, 여백의 이름표로 표시된다([그림 부록-12], [그림 부록-13]).

[그림 부록-12] 기안기 머리줄: 문서함, 문서 이름과 폴더 경로, 저장 상태, 같이 있는 사람 동그라미, 편집 도구, 「⋯」 (그림 docs/images/figures-1025/fA-12-editor-header.jpg)

[그림 부록-13] 다른 사람이 쓰는 영역 표시: 옅은 바탕, 색 커서, 이름표, 같이 있는 사람 목록 (그림 docs/images/figures-1025/g01-coedit-pane-people.jpg)

함께 쓸 때 알아 둘 점은 다음과 같다.

- 편집 영역 안에서 바꾼 서식(글꼴·색·크기)은 바로 다른 사람 화면에도 반영된다. 표에 줄을 더하거나 그림·용지를 바꾸는 일은 「문서 틀 고치기」로 저장하며
  한 번에 한 사람만 할 수 있다. 저장되면 다른 사람 화면은 새 버전으로 바뀌고, 각자 영역에 쓴 글은 그대로 남는다.
- 같은 영역에 두 사람의 글이 겹치면 내 글은 버리지 않고 사본으로 보관한다. 「⋯」 → 「충돌로 따로 둔 내 글」에서 꺼낸다.
- 연결이 끊긴 동안 쓴 글은 연결이 돌아오면 자동으로 전송된다.
- 「3번 칸은 AURA가 채워 줘」처럼 요청하면 AURA도 한 사람처럼 편집 영역을 잡고 작성한다. 사람이 잡은 영역에는 작성하지 않는다.
- 이전 버전은 버전 기록에 남는다.

아주 큰 문서처럼 편집 영역으로 나누지 않은 문서는 한 번에 한 사람만 편집한다. 나중에 연 사람은 보기 전용으로 보다가, 먼저 연 사람이 문서를 닫으면 이어서 편집한다([그림 부록-14]).

[그림 부록-14] 편집 영역으로 감싸지 않은 문서(아주 큰 문서 등)를 나중에 연 사람의 화면: 보기 전용 (그림 docs/images/02-hwp-edit-lock.jpg)

### 3.4 규정 질문하기

장면: 교직원이 연구년 신청 자격을 묻는다.

「새 채팅」에서 답변 방식이 「RAG」인지 확인하고 「연구년 신청 자격이 어떻게 돼?」라고 묻는다. 답은 요약, 근거 요점, 출처 순으로 나오며, 출처를 누르면
오른쪽에 규정 원문의 해당 조항이 열린다. 「생각 과정 펼치기」를 누르면 AURA가 질문 파악, 근거 확인, 답 구성 순으로 판단한 과정을 볼 수 있다. 답이 틀렸으면
「아쉬움」을 눌러 이유를 남긴다([그림 부록-15], [그림 부록-16]).

어느 규정이 현행 버전인지는 라이브러리 기준 문서 탭의 「규정 목록」에서 본다. 규정마다 현행 버전과 최종 개정일이 나오고, 「구판 보기」를 누르면 이전 버전이
펼쳐진다. 답의 근거가 구판이면 출처 이름에 「구판」이 붙는다.

[그림 부록-15] 규정 질문의 답: 출처와 오른쪽 원문 대목 (그림 docs/images/figures-1027/fA-15-regulation-answer-source.jpg)

[그림 부록-16] 「생각 과정」을 펼친 답과 입력창 아래 문맥 사용량 (그림 docs/images/figures-1027/f4-15-answer-sources-thinking.jpg)

숫자 뒤에 「(근거 확인 필요)」가 붙으면 그 숫자가 근거 문서에 없다는 뜻이므로 원문에서 꼭 확인한다. 다른 부서 자료를 묻는 질문에는 열람 권한이
없다는 안내만 붙고, 그 문서가 있는지 없는지는 알리지 않는다.

### 3.5 기안문·출장 보고처럼 짧은 문서 빨리 쓰기

「새 채팅」에서 「다음 주 서울 출장 보고서 써 줘. 출장지는 ○○, 목적은 협약 회의」처럼 요청하면 AURA가 공통 양식에서 맞는 양식을 선택해 작업 문서를
만들고 채운다. 문서 패널에서 확인하고 수정한 뒤 「한글 파일로 내보내 줘」로 받는다.

### 4.2 채팅

채팅 화면(/chat)은 대화 영역과 오른쪽 문서 패널로 되어 있다. 입력창 아래 도구줄에서 첨부, 답변 방식, 「RAG 범위」, 답변 깊이를 선택한다. 답변 방식은 [표 부록-4]와 같다.

| 방식 | 언제 쓰나 | 무엇이 밖으로 나가나 |
|---|---|---|
| 「RAG」 | 규정·사업 문서를 근거로 답을 받거나 문서를 작성하고 수정할 때. 「RAG 범위」로 공통·부서 RAG를 좁힌다 | 없음. 내 계정 범위의 교내 문서만 찾는다 |
| 「일반」 | 문장 다듬기, 개념 설명 같은 일반 질문 | 없음. 문서 없이 모델이 답하고 출처가 없다고 밝힌다 |
| 「인터넷에서 찾아보기」 | 일반 답 끝에 모델이 확인을 권할 때 누른다 | 질문 글만 웹 검색에 보낸다. 문서·첨부는 나가지 않고, 개인정보가 든 질문은 보내지 않는다 |

[표 부록-4] 답변 방식

프로젝트 대화와 파일을 붙인 질문은 「RAG」로 시작한다. 답을 쓰는 동안 보낸 요청은 「다음 요청 n건 대기」에 쌓였다가 차례로 처리되므로, 긴 서식을
절마다 요청할 때 미리 넣어 두면 된다. 답 주변의 단추와 표시는 [표 부록-5]와 같다.

| 단추·표시 | 하는 일 |
|---|---|
| 답변 깊이(「꼼꼼하게」·「빠르게」) | 기본값은 「꼼꼼하게」로, 단계별로 추론하며 자료를 넓게 보고 점검한다. 간단한 질문에는 「빠르게」를 선택한다 |
| 「문맥 N% 사용」 | 이 대화가 모델 문맥 한도를 쓴 비율. 높으면 새 대화로 나눈다 |
| 「작업 내역」 | 문서 작업에서 AURA가 거친 단계(찾은 근거와 쓴 절)를 보여 준다 |
| 「필요한 값 입력으로 이동」 | AURA가 찾지 못한 값을 입력하는 영역으로 이동한다 |
| 「반영한 것」 | AURA가 이번 답에서 문서에 넣은 편집 영역·글·표를 문서 모양 그대로 보여 준다 |
| 「다른 모양으로 바꾸기」 | 표·글꼴 후보 가운데 하나를 누르면 방금 반영한 부분을 그 모양으로 다시 꾸민다 |
| 「비공개」 / 「부서 공개」 | 프로젝트 대화를 부서 동료에게 보일지 정한다 |
| 「연관 자료」, 「적용 기준」 | 작업 패널에서 이번 답의 근거 목록과 이 대화에 적용한 기준 문서를 보여 준다 |
| 「아쉬움」 | 답이 틀린 이유(「근거 문서가 틀림」, 「숫자·사실이 틀림」 등)를 여러 개 선택하고 한 줄 의견을 남긴다 |
| 「이 질문부터 다시 생성」 | 선택한 질문부터 다시 답한다. 그 뒤의 대화는 이력에 보관된다 |

[표 부록-5] 채팅 화면의 단추

문서 패널에는 위쪽 편집기 고르기(「한글」 기안기 또는 「구글」 문서), 이 대화와 함께 편집하는 「작업 문서」, 그리고 첨부·참고·기준 문서 목록이 있다.
다른 문서를 작업 문서로 넣을 때는 「파일 가져오기」에서 부서 폴더나 드라이브의 파일을 선택한다. 작업 문서가 없을 때 「문서 쓰자」라고 하면 AURA가
양식을 선택해 새로 만든다([그림 부록-18], [그림 부록-19]).

편집기를 「구글」로 선택하면 작업 문서를 구글 문서로 작성하며, 이때는 학교 구글 계정 연결이 필요하다. 「드라이브에서 문서 가져오기」로 가져온 문서는
업로드한 문서와 같이 처리되고, 「이 문서로 작업」을 누르면 사본이 만들어져 대화에 연결된다. 그 뒤 대화에서 내리는 지시는 그 문서의 편집으로 처리된다.
「한글 파일로 내보내 줘」라고 하면 작업본의 절 본문을 원본 hwpx 서식에 채워 프로젝트 드라이브의 작성 폴더에 올리고, 「제출본」이라고 덧붙이면
【작성방법】 안내 상자를 뺀다. 구글 문서 작업본을 되돌릴 때는 구글 문서의 버전 기록을 사용한다.

문서함(/hwp)은 한글 문서를 부서 폴더 구조로 보관하고 웹 한글 기안기로 여는 화면이다. 공통 양식과 지난 사업 문서도 「부서 폴더」 → 「공통」 아래에 있다. 구역별 기능은 [표 부록-8]과 같다.

| 구역 | 기능 |

| 위쪽 단추 | 「새 문서」, 「양식으로 시작」, 「올리기」(.hwp·.hwpx), 「새 폴더」 |

| 줄 단추 | 잠긴 양식의 「사본 만들기」, 「내려받기」, 「지우기」(부서 휴지통으로 이동하며 관리자가 복원), 폴더 이름 바꾸기, 즐겨찾기 |

[표 부록-8] 문서함

구글 드라이브의 한글 파일은 줄의 「가져오기」로 현재 폴더에 받아 기안기로 연다. 구글 계정을 연결하지 않았으면 드라이브 목록이 비어 있다.

### 4.5 웹 한글 기안기

웹 한글 기안기는 브라우저에서 한글 문서를 여는 한컴 편집기다[53]. 문서함에서 문서를 누르거나 채팅 문서 패널에서 「한글」 편집기를 선택해 연다. 찾기·바꾸기·쪽
설정 같은 편집 기능은 기안기 자체의 메뉴와 리본을 그대로 사용하며, 고친 내용은 자동으로 저장된다. 여럿이 함께 쓰는 방법은 부록 3.3에 있다. 메뉴와 리본이 보이는 기안기 화면은 [그림 부록-8], 머리줄의 단추와 표시는 [표 부록-9]와 같다.

| 단추·표시 | 하는 일 |
|---|---|
| 문서 이름, 「부서 › 폴더」 | 문서 이름과 위치 표시. 이름을 눌러 바꾼다 |
| 저장 상태 | 「저장됨」, 「저장 중」, 「오프라인: 연결되면 저장」 등 현재 저장 상태 표시 |
| 같이 있는 사람 동그라미 | 같은 문서를 연 사람을 4명까지 표시하고 나머지는 「+N」으로 묶는다. AURA가 쓰는 동안에는 「A」 동그라미가 붙는다. 동그라미를 누르면 그 사람을 따라가고(다시 누르거나 직접 입력하거나 화면을 움직이면 멈춤), 「+N」을 누르면 「쓰는 중」·「보는 중」 목록이 열린다 |
| 「편집 도구」 | 메뉴·리본·서식줄을 펼치거나 접는다 |
| 「⋯」 | 「다른 이름으로 저장」, 「문서 틀 고치기」, 「충돌로 따로 둔 내 글」, 「내려받기」, 「구글 드라이브에 올리기」, 「문서함에서 보기」 |

[표 부록-9] 기안기 머리줄

### 4.6 프로젝트

프로젝트(/project/번호)는 사업 하나의 문서·작성 원칙·기준 문서·지난 사업·대화를 묶어 관리하는 화면이다. 구역별 내용은 [표 부록-11]과 같다.

| 구역 | 내용 |
|---|---|
| 머리 | 문서 수, 마감, 「책임 ○○」, 공유 단추(「공유 안 함」 / 「공유 중 · N」), 「관리」 |
| 「대화·문서」 탭 | 새 대화, 프로젝트 문서, 작성 원칙, 관련 지난 사업, 지난 대화, 작업 문서 |
| 「진행 현황」 탭 | 볼 권한이 있는 사람에게만 표시. 요청·참여자·작업 문서·사용량 요약, 사람별 거르기, 날짜별 사용량, 대화별 요청 기록, 사람별 작업 요약 |

[표 부록-11] 프로젝트 화면

공유 단추를 누르면 「프로젝트 공유」 창이 열린다. 「나만 보기」를 선택하면 담당자와 관리자만 보고, 「공유」를 선택하면 선택한 부서나 사람에게 「읽기만」 또는 「함께
작업」 권한으로 공유한다. 기본 권한은 「읽기만」이다. 공유는 선택한 부서·사람에게만 적용되며 하위 팀이나 다른 부서로 자동으로 넓어지지 않는다. 「비공개」로 둔 대화는 공유해도 보이지 않는다.
다른 부서 사용자는 대화의 질문과 답을 읽을 수 있지만, 근거 원문과 첨부는 그 사용자에게 열람 권한이 있는 문서만 열린다([그림 부록-20]).

[그림 부록-20] 「프로젝트 공유」 창 (그림 docs/images/figures-1027/f4-20-project-share-dialog.jpg)

사업 책임자는 머리의 「책임 ○○」에서 「함께 작업」으로 나눈 사람 가운데 선택한다. 사업이 끝나면 「관리」 → 「보관」으로 「지난 사업」에 옮긴다.

### 4.7 그래프 탐색

그래프 탐색(/graph/explore)은 사업·연차·문서·절 사이의 관계를 그림으로 본다. 라이브러리의 「지식그래프」나 문서 화면의 「관계 보기」로 연다. 사업을
선택하면 그 사업 중심의 그래프가 그려지고, 점을 눌러 이웃 점을 펼치거나 문서를 연다. 사업 그래프 화면은 사업별로 연차별 문서, 성과지표, 계획서 절과
실적보고서 절의 대응 관계를 표로 보여 준다. 관리자는 「온톨로지」 보기에서 전체 구조와 최근 구조 검사 결과를 확인하고, 온톨로지 설계도(OWL[44]),
검사 규칙(SHACL[45]), 검사 결과, 노드·관계·사업 목록 파일을 내려받는다. 열람 권한이 없는 문서의 점은 그래프에 나타나지 않는다([그림 부록-21]).

[그림 부록-21] 그래프 탐색: 사업 중심 그래프와 노드 패널 (그림 docs/images/figures-1027/fA-22-graph-node-panel.jpg)

### 4.8 검색

사이드바 「검색」이나 Ctrl+K로 대화·프로젝트·문서·한글 문서를 이름으로 빠르게 찾는다. 이름에서 찾지 못하면 Enter로 본문까지 찾는 검색
화면(/search)으로 간다. 검색 화면의 결과는 「문서」, 「본문 대목」, 「프로젝트」, 「대화」로 나뉘며, 본문 대목을 누르면 문서 화면의 해당 위치가 열린다.

### 4.9 업무 도우미

업무 도우미는 채팅 밖 화면의 오른쪽 아래 둥근 단추로 여는 옆 패널이다(학생 계정에는 없다). 화면 사용법을 묻거나 할 일을 요청한다.
「학생에게 장학 규정을 보이게 하려면?」처럼 물으면 답에 제안이 붙고, 「실행」을 누르면 바로 처리하며 「화면에서 직접」을 누르면 화면 위 커서가 해당 단추를 가리킨다.
「문서함에서 ○○ 폴더 열어 줘」처럼 시키면 AURA 커서가 화면을 옮기고 창을 열고 입력란에 값을 넣는다. 저장·만들기·올리기 같은 마지막 단추는 「저장해 줘」처럼
직접 말했을 때만 누르고, 그렇지 않으면 가리키기만 한다. 화면의 글을 선택하면 「쉽게 설명」, 「관련 규정 찾기」 같은 메뉴로 그 대목을 묻는다([그림 부록-22]).

[그림 부록-22] 업무 도우미 창과 「실행」 제안 (그림 docs/images/figures-1027/fA-23-helper-run-suggestion.jpg)

「화면에서 직접」을 선택하면 도우미 창의 제안 아래에서 화면 위 AURA 커서가 대상 줄과 단추를 차례로 가리킨다. 이때 마지막 단추는 누르지 않으므로, 가리킨 단추를 직접 누르거나 제안의 「실행」으로 처리한다([그림 부록-23]).

[그림 부록-23] 업무 도우미의 제안과 「실행」·「화면에서 직접」, 화면 위 커서 (그림 docs/images/figures-1027/f4-31-helper-proposal.jpg + f4-31b-helper-screen-cursor.jpg)

사업 문서의 내용을 묻는 질문은 도우미가 「새 채팅」으로 넘긴다.

### 5.1 계정, 등급, 부서

계정과 부서는 「조직 관리」에서 다룬다(부록 4.10). 계정은 「전체 사용자」 → 「계정 추가」로 아이디·이름·역할·부서·등급을 넣어 만들고, 줄의 「편집」
에서 임시 비밀번호를 만들어 본인에게 따로 전한다([그림 부록-27]). 부서를 만들면 그 부서 RAG가 함께 생긴다.

### 5.2 RAG 공간

RAG 공간은 AURA가 어느 문서 집합에서 찾을지 정하는 곳이다. 규정 등록과 공개는 라이브러리 「기준」 칩에서 한다. 일마다 어디서 하는지는 [표 부록-14], RAG 공간 화면은 [그림 부록-29]과 같다.

| 하고 싶은 일 | 하는 곳 |
|---|---|
| 학사 규정을 학생에게 공개 | 라이브러리 「기준」 칩 → 규정 줄 「…」 → 「학생 공개로」 |
| 수집 자료 속 규정을 기준 문서로 | 라이브러리 「기준」 칩 → 「새 판·미등록」 → 「검색에 추가」 |
| 규정을 검색에서 빼기 | 라이브러리 「기준」 칩 → 줄 「…」 → 「검색에서 빼기」 |
| 다른 부서가 우리 부서 RAG를 찾게 하기 | RAG 공간 › 부서 줄 › 「다른 부서에 열기」 |
| 이 계정이 이 규정을 찾는지 확인 | 「검색 범위 시험」 |

### 5.3 테스트 보기

다른 계정이 보는 화면·검색·답 범위를 그대로 확인하는 기능이다. 사용자 메뉴의 「테스트 보기」에서 역할·등급·부서를 선택하면 맨 위에 띠가 뜨고, 이
상태에서 한 질문·검색은 그 계정이 받는 결과와 같다. 띠의 「원래대로」로 돌아온다. 「특정 사람만 문서를 못 찾는다」는 문의를 확인할 때 쓴다.

### 5.4 도구·모델 연결

용도(답, 수집 검토, 이미지 판독, 업무 도우미)마다 어느 서버의 어느 모델을 쓸지 정하는 화면이다. 맨 위 「초기 설정」 카드는 새로 설치한 서버에서 남은
연동 항목을 보여 주고, 「서버 설정」 카드는 검색 서버·웹 검색 키·원본 폴더 같은 값을 서버 파일 대신 화면에서 정한다. 「LLM 연결」에서 서버별로 연결을
확인하고 기본 서버를 정하며, 「단계별 모델」에서 용도별 모델을 바꾼다([그림 부록-30]).

[그림 부록-30] 도구·모델 연결: LLM 연결과 단계별 모델 (그림 docs/images/figures-1027/fA-29-llm-connections.jpg)

「단계별 모델」 카드는 문서 작업, 수집 검토, 이미지 판독, 업무 도우미의 네 용도마다 서버와 모델을 한 줄씩 보여 준다. 줄에서 다른 서버나 모델을
선택하고 저장하면 그 용도에 바로 적용된다([그림 부록-31]). 모델 이름과 문맥 길이는 코드가 아니라 이 설정에 있어, 더 큰 모델로 바꿀 때 코드를 고치지 않는다.

[그림 부록-31] 도구·모델 연결의 「단계별 모델」 (그림 docs/images/figures-1027/f4-33-stage-models.jpg)

### 5.5 개인정보·반출 점검

수집 문서·첨부·답의 개인정보 마스킹을 항목별로 켜고 끄는 화면이다. 기본값은 꺼짐이고, 학습 데이터 반출에서는 이 설정과 관계없이 항상 마스킹한다. 마스킹 기능이 알려진 개인정보 형식을
제대로 찾는지 보는 자가 점검은 합성 표본으로 매일 실행되고, 저장된 본문에 남은 개인정보 형식을 찾는 검사는 주 1회 실행된다. 결과가 그보다
오래되면 확인이 필요하다는 경고가 뜬다. 수집 때 남긴 마스킹 기록은 문서명과 유형으로 찾을 수 있다. 마스킹을 켰다가 꺼도 이미 마스킹된 본문은 되살아나지 않으므로,
원문이 필요하면 원본을 다시 수집한다.

### 5.6 문답 검수 권한

이 권한은 모델 학습에 쓸 문답을 사람이 검수할 때만 사용한다. 「조직 관리」에서 검수할 교직원에게 추가 권한 「SFT 문답 검수」를 주면 그 사람의 사용자 메뉴에
「문답 검수」(/review)가 생기고, 여기서 자기에게 배정된 검수 목록과 검수 매뉴얼을 보며 Label Studio[20] 검수 화면을 연다.
관리자는 「데이터·학습」(/dev/train)의 「문답 검수」 표에서 검수가 끝난 작업의 「완료한 검수 결과 반영」을 누른다. 「승인 데이터·산출물」에서는 학습셋별 파일과
「학습셋 표본」을, 「학습 상태 보기」(/dev/train/run)에서는 학습 점검 결과와 손실 곡선(TensorBoard[63])을 본다. 손실 곡선으로 학습이 정상적으로 수렴하는지를
학습 장비에 접속하지 않고 확인한다([그림 부록-32]). 학습셋 원문은 학습 장비에만 있고, 이 화면에는 이름·상태·건수 같은 목록 정보만 표시된다.

[그림 부록-32] 학습 상태와 TensorBoard 손실 곡선 (그림 docs/images/figures-1027/f4-36-train-status.jpg)

## 부록 6. 자주 묻는 질문

문. 내가 올린 문서가 학교 밖 AI로 나가는가.
답. 나가지 않는다. 답·검색·판독 모델은 모두 교내 장비에서 동작한다. 밖으로 나가는 것은 「인터넷에서 찾아보기」를 눌렀을 때의 질문 글(개인정보가 있으면
보내지 않음)과, 내 학교 구글 계정으로 만든 구글 문서 작업본뿐이다.

문. 다른 부서 문서는 왜 찾아지지 않는가.
답. 검색은 처음부터 내 부서 범위의 문서 안에서만 한다. 다른 부서 자료가 업무에 필요하면 관리자에게 겸직 부서를 요청하거나, 그 부서가 부서 RAG를
열어 주어야 한다.

문. 프로젝트 추가(+) 단추가 보이지 않는다.
답. 일반 등급은 프로젝트를 만들지 않는다. 같은 부서 사업 책임자에게 「프로젝트 만들기」 권한을 받거나, 공유받은 프로젝트에서 작업한다.

문. AURA가 쓴 초안을 바로 제출해도 되는가.
답. 아니다. 숫자는 출처의 원문에서 확인하고(근거에 없는 숫자에는 「(근거 확인 필요)」가 붙거나 「○○」로 비워진다), 내보낸 한글 완성본도 한글
프로그램에서 한 번 열어 본다.

문. 한글(.hwp) 파일도 되는가.
답. 된다. 문서함과 라이브러리 모두 .hwp와 .hwpx를 받는다. 양식 채우기는 hwpx로 바꾸어 다룬다.

문. 대화가 길어지면 앞 내용을 잊는가.
답. AURA는 대화마다 목표·확정된 것·남은 일을 작업 메모로 갱신해 두고 다음 요청에 함께 사용한다. 「문맥 N% 사용」이 높으면 새 대화로 나누는 것이 좋다.

## 부록 7. 문제 해결

실무에서 막히기 쉬운 증상만 모았다([표 부록-16]). 표에 없는 증상은 관리자에게 화면 그림과 함께 알린다.

| 증상 | 원인과 조치 |
|---|---|
| 사이드바에 「AI 미연결 · 답변 대기」 | 답 모델 서버에 잠시 닿지 않는다. 질문은 보내 두면 연결된 뒤 답한다. 오래가면 관리자에게 알린다 |
| 문서 작업 답이 오래 걸린다 | 근거를 찾고 절마다 작성하느라 시간이 걸린다. 「작업 내역」에서 진행을 보고, 다음 요청은 미리 보내 둔다 |
| 「관리자가 구글 앱을 등록한 뒤 연결할 수 있습니다.」 | 구글 앱 등록 전이다. 관리자에게 요청한다 |
| 구글 연결이 끊겼다는 안내 | 연결이 만료됐다. 설정의 「구글 계정」에서 다시 연결한다 |
| 문서함에 「한글 편집기 연결 안 됨」 | 기안기 서버에 닿지 않는다. 그동안 「새 문서」·「양식으로 시작」은 꺼진다. 잠시 뒤 다시 연다 |
| 공통 양식이 수정되지 않는다 | 모두가 쓰는 원본이라 잠겨 있다. 「사본 만들기」로 사본을 만들어 사용한다 |
| 입력해도 글이 들어가지 않고 이름표가 흔들린다 | 다른 사람이 그 영역을 쓰는 중이다. 다른 곳을 쓰거나 기다린다 |
| 내 글이 사라진 것 같다 | 같은 영역에 글이 겹쳐 사본으로 두었다. 「⋯」 → 「충돌로 따로 둔 내 글」에서 꺼낸다 |
| 올린 문서가 「처리 중」에서 오래 멈춘다 | 긴 스캔 문서는 판독에 시간이 걸린다. 「실패」가 되면 암호나 손상 여부를 확인한다 |
