02 왜 어려운가 · 원인

단순한 "문서 검색" 문제가 아니다

원인 01 · 입력

문서 형태가 제각각이다

디지털 PDF뿐 아니라 스캔본, 사진, 한글(HWP) 파일이 섞여 있다. 읽어 들이는(추출) 단계부터 정확도가 무너진다.

원인 02 · 검색

방대해서 근거를 못 찾는다

필요한 실적 수치가 어느 문서 몇 쪽에 있는지 사람이 다 기억할 수 없다. 검색이 틀리면 그 위의 모든 작업이 무의미해진다.

원인 03 · 신뢰

수치를 잘못 쓰면 사업이 취소된다

계획서의 정량 수치는 근거가 있어야 한다. 근거 없는 수치(환각)가 들어가면 허위 기재로 사업 취소·환수 사유가 된다.

원인 04 · 언어

범용 AI는 도메인 용어를 모른다

"학사운영지원", "성과관리 지표" 같은 교내·국고사업 용어의 관계를 범용 모델은 이해하지 못한다.

03 해결 · 프로젝트

공고에서 요구를 읽고, 실적에서 근거를 채운다

새 공고문(PDF)을 넣고 방향 몇 가지를 지정하면, 기관의 실제 실적에 근거한 사업계획서 초안을 만든다. 공고가 계획서의 뼈대를, 우리 실적이 그 내용을 이룬다.

핵심 통찰

보유 문서 = 학습 데이터셋

과거 계획서는 "요구사항 → 완성 섹션"의 정답 쌍이고, 결과보고서는 "PDF → 실적 데이터"의 정답 쌍이다. 사람의 라벨링 없이 모델 학습 데이터를 확보할 수 있다.

  • 목표는 70% 초안 완성본이 아니라, 사람이 검수하는 초안. 담당자를 대체하지 않고 가속한다.
  • 모든 수치는 출처 추적 초안의 정량 수치마다 문서명·페이지를 단다.
  • 작성 시간 2주 → 2~3일 목표
04 해결 구조

네 단계 파이프라인

통짜로 생성하지 않는다. 읽고 → 찾고 → 섹션별로 쓰고 → 검증한다. 각 단계가 독립적으로 측정·개선된다.

01

추출 · OCR

PDF·스캔·사진·한글을 텍스트와 표로. 개인정보는 인덱싱 전에 마스킹.

02

검색

공고 요구사항에 맞는 실적 근거를 하이브리드 검색 + 리랭킹으로 인출.

03

섹션 생성

배점 항목별로 근거를 넣어 초안 작성. 수치는 인출된 것만 사용.

04

검증

수치 대조 · 배점 커버리지 · 예산 검산 — 세 검증기가 초안을 점검.

05 핵심 기술 ① · 문서를 정확히 읽기

OCR — 인식률이 시스템의 바닥이다

실전 입력은 깨끗한 PDF만이 아니다. 스캔본·사진의 글자를 얼마나 정확히 읽느냐가 검색·생성 품질의 하한을 정한다.

0.81 어절 F1
현행 엔진(MinerU) 실측 인식 정확도 실측
가시화

인식 영역 시각화

OCR이 읽은 영역을 신뢰도 색(초록=확신, 주황=재판독 대상)으로 표시해 어디가 약한지 눈으로 확인.

개선 방법론

디지털 ↔ 스캔 영역 대조

디지털 PDF의 정답 좌표와 스캔 인식 영역을 겹쳐, 글자뿐 아니라 영역 인식까지 정량 평가·개선.

도전자 모델(PaddleOCR-VL) 대결은 GPU 서버 확보 후 진행 — CPU 전용 환경에서는 실용성 미달로 확인됨(정직한 부정 결과 기록).

06 핵심 기술 ② · 근거를 정확히 찾기

하이브리드 검색 + 리랭킹

의미 기반(임베딩)과 키워드 기반을 결합(RRF)하고, 리랭커로 상위 결과를 재정렬한다. 검색 정확도를 실제로 측정하며 개선했다.

07 핵심 기술 ③ · 도메인 특화 (파인튜닝)

오픈웨이트 위에 도메인을 입힌 모델 4종

범용 모델을 국고사업 문서 도메인에 적응시킨다. 성과 요건만을 위한 학습이 아니라, 실제 시스템 성능을 올리는 방식으로. 베이스 대비 개선폭을 정량 입증한다.

08 신뢰성 · 절대 원칙

지어내지 않는 시스템

행정 문서는 정확성이 곧 신뢰다. 설계 단계부터 지키는 규칙으로 환각과 유출을 원천 차단한다.

환각 차단

수치는 인출하고 생성하지 않는다

초안의 모든 정량 수치는 인출된 근거에 존재해야 한다. 검증기가 초안의 수치를 원문과 대조한다.

개인정보

인덱싱 이전에 마스킹

실제 교내 문서에 포함된 개인정보는 검색 인덱스에 들어가기 전에 제거한다.

권한

열람 등급을 검색 단계에서 필터

문서 열람 권한을 검색 시점에 적용 — 사후에 붙이기 어려운 것을 처음부터 설계에 넣는다.

예산

계산은 결정론 로직으로

예산 검산에 LLM을 쓰지 않는다. 수치 계산은 규칙 기반으로 정확히.
