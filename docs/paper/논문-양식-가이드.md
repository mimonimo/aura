# 논문 양식 가이드 (2025 캡스톤 논문집 분석)

작년 논문집(사이버보안과, 8편 수록, 672쪽) 실물에서 뽑은 형식 기준.
우리 논문도 이 틀에 맞춰 작성한다.

## 전체 구조

한 편이 학술지 논문이 아니라 60~70쪽 분량의 프로젝트 보고서형 논문이다.
(표본: 1번 논문 본문 시작 p9 → 참고문헌 p77)

구성 순서:
1. 표지 (프로젝트 제목, PROJECT 번호, 팀원, 팀명)
2. 목차 (점선 리더 + 쪽번호, 1./1.1/1.1.1 세 단계)
3. 그림 목차 ([그림 n-m] 장-번호 체계), 표 목차
4. 1. 서론 — 1.1 프로젝트 배경 및 목적 / 1.2 핵심내용 / 1.3 기대효과 / 1.4 프로젝트 구성
5. 2. 관련 연구 — 사용 기술을 2.x, 2.x.x로 하나씩 소개
6. 3. 환경 구축 및 시스템 설계 — 인프라·아키텍처
7. 4.~ 구현 (기능별 장), 평가·시연
8. 결론
9. 참고 문헌 — [n] 출처명. 제목 + URL 나열식

## 지면 형식

- 매 쪽 머리글: 좌측에 논문 제목, 우측에 "영남이공대학교 ○○과", 쪽번호
- 그림·표 캡션: [그림 2-3], [표 3-1] 장-일련 체계, 캡션은 하단
- 문체: "~한다/~이다" 서술형. "본 프로젝트의 핵심은 …이다",
  "…할 것으로 기대된다" 같은 표현 관례

## 우리 논문에의 적용 (초안 목차 대응)

- 1.1 배경·목적 ← 브리프 0~1장(온프레미스 필요성, 개인정보 제약)
- 1.2 핵심내용 ← 축 A(플랫폼 전 경로) + 축 B(도메인 특화 개선)
- 1.3 기대효과 ← 실사용 전제(70% 초안 + 사람 검수), 교내 행정 적용
- 2. 관련 연구 ← 기술별 소개: vLLM/Qwen3.5(MoE), MinerU·OCR, KURE 임베딩,
  하이브리드 검색(RRF), python-hwpx 등 — 각 2.x절
- 3. 설계 ← architecture.md + ADR 7건
- 4. 구현 ← 실험-로그.md의 OCR·복원 실험, 검증기 3종, 플랫폼 기능
- 5. 평가 ← 정량 지표(기준선 표, 학습 결과 — 부정 결과 포함), 실물 검증 사례
- 결론·향후 ← 파일럿 계획, 남은 한계
- 참고 문헌 ← 판정 노트들의 출처 URL 목록이 그대로 재료

주의: 분량 관례가 60쪽대이므로 스크린샷·다이어그램(그림 목차 채울 것)을
구현 단계마다 캡처해 모아둬야 한다 — /dev 대시보드·복원 뷰·검증 결과 화면 등.
