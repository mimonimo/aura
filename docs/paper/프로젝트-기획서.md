# 캡스톤디자인 프로젝트 기획서


## 프로젝트명

교내 행정업무 자동화를 위한 YNC sLLM 플랫폼 구축 (시스템명 「짜이미(ZZAIMY)」)

## 배경 및 필요성

대학 행정 부서는 국고사업 공고 분석, 계획서 작성, 채용·입학 서류 검토처럼
문서 중심의 반복 업무를 수행한다. 이 문서들은 개인정보와 내부 정보를 담고
있어 외부 클라우드 AI 서비스에 올릴 수 없고, 그 결과 문서 업무의 자동화가
사실상 이루어지지 못하고 있다. 교내 장비 위에서 동작하는 소형 언어모델(sLLM)
기반 시스템이라면 문서를 외부로 내보내지 않고도 이 업무를 지원할 수 있다.

## 목표

교내 장비에서 운영되는 행정 문서 처리 플랫폼을 구축한다. 운영 서버(학과
가상서버, CPU)가 웹·검색·OCR·문서 관리를 맡고, 서빙 서버(젯슨 토르 2대)가
생성·판독·검색 모델을, 학습 서버(DGX)가 모델 학습을 맡는 구성이다. 데모가 아니라 실제 학교 행정에 쓰는 것을 전제로 하며,
시스템의 역할은 완성본 생성이 아니라 70% 수준의 초안과 검토 근거를 제공하고
최종 판단은 담당자가 내리는 구조로 설계한다.

## 개발 내용

1. 문서 읽기: 스캔본·사진·PDF·HWP로 접수되는 행정 문서를 표 구조까지
   보존하며 읽어내고, 원본 모습 그대로 검색·복사가 가능한 전자문서로
   복원한다. 개인정보는 저장 전에 자동으로 가린다.
2. 규정 검색과 응답: 교내 규정·지침을 등록해 두면, 담당자의 질문에
   해당 규정 대목을 찾아 근거와 함께 답한다. 키워드 검색과 의미 기반
   검색을 결합하고 리랭커로 상위 결과를 다시 정렬해 정확도를 높인다. 의미
   검색 모델과 리랭커는 교내 문서로 추가 학습한 판을 쓴다.
   문서 사이의 연관은 규칙이 아니라 학습된 임베딩의 의미 유사로 판정해
   지식 그래프로 보여 준다.
3. 계획서 초안 작성: 공고문에서 작성 항목과 평가 기준을 읽어내고, 접수된
   자료 가운데 각 항목과 의미가 가까운 대목을 재료로 항목별 초안을
   작성한다. 결과는 한글(HWPX)·워드·PDF·마크다운 파일로 제공하며, 한글
   문서는 실제 한글 프로그램을 자동 조작하는 에이전트가 만든다.
4. 검증: 초안에 들어간 모든 수치가 근거 자료에 실제로 존재하는지와 예산
   계산이 맞는지는 LLM이 아닌 결정론 검증기로 확인한다. 평가 항목을
   빠짐없이 다뤘는지는 키워드 판정에 임베딩 기반 의미 판정을 더해
   확인한다.
5. 모델 개선: 공개 모델(오픈웨이트)을 그대로 쓰는 데서 출발해 베이스라인을
   먼저 측정하고, 교내 문서로 추가 학습(SFT, 이후 DPO)했을 때의 개선 폭을
   측정한다. 개선이 입증된 모델만 채택한다. 검색 모델 둘(임베딩·리랭커)은
   교내 문서로 학습한 판을 이미 운영에 쓰고 있고, 생성·판독·검토·추출은
   27B 한 모델이 맡는다.
   생성과 판독 모델은 Qwen3.8-27B다. 2주차 미팅에서 지도교수가 지정했다. 이
   모델은 이미지 입력이 되는 멀티모달이라 스캔 문서와 사진 판독을 별도 모델
   없이 맡고, 문맥이 26만 토큰이라 계획서 전체를 한 번에 읽으며, dense 구조라
   LoRA 학습과 vLLM 서빙이 검증된 경로다. NVIDIA가 젯슨용 양자화 판을 공식
   배포해 교내 장비에서 원본보다 서너 배 빠르게 돌고 내용이 같음을 확인했다.
   국내 모델과 견주면 이렇다. EXAONE 4.0 32B는 글만 받아 판독을 못 맡기고,
   라이선스가 연구·교육 목적 한정(NC)이라 실제 행정 운영에 쓰려면 별도 계약이
   필요하다. HyperCLOVA X SEED Think 32B는 이미지·영상 입력을 받는 멀티모달이라
   기능으로는 대안이 되지만, 서비스에 "Powered by HyperCLOVA X"를 표시하고
   학습본 이름 앞에 "HyperCLOVA X"를 붙여야 하는 조건이 있고 젯슨용 공식
   양자화 판이 없다. Qwen은 Apache 2.0이라 이런 조건이 없다.
   한국어 지식을 묻는 벤치마크(KMMLU)에서는 국내 모델이 앞선다. EXAONE 4.0 32B가
   75.2, HyperCLOVA X 32B가 71.3인 데 비해 Qwen 계열의 Qwen3-VL 32B는 47.4이고
   Qwen3.8-27B 자체의 수치는 확인하지 못했다. 우리 시스템은 규정과 실적 같은
   지식을 모델이 외우지 않고 검색으로 넣어 주는 구조라 이 격차가 결과에 직접
   오지 않으며, 모델에는 문서를 읽고 형식에 맞춰 쓰는 능력만 요구한다. 그
   능력에서 Qwen3.8-27B는 업무 문서·코딩 벤치마크(SWE-bench Pro 61.7)로 검증된
   상위권이다. 다만 이것은 우리 문서로 잰 값이 아니므로, 실물 문서로 베이스라인을
   잴 때 HyperCLOVA X SEED Think 32B를 비교군으로 넣어 검토·초안·판독 품질을
   같은 입력으로 잰다.

## 개발 환경

- 장비: 운영 서버는 학과 ESXi 가상서버(CPU, GPU 없음, 상시 가동). 서빙은
  젯슨 AGX 토르 2대(통합 메모리 122GB) — 토르 02는 대화·초안, 토르 03은 문서
  검토·이미지 판독과 검색 모델 서비스. 학습은 DGX 전용. 초기 검증(9월 1주)은
  NVIDIA DGX Spark에서 수행했고 현재는 사용하지 않는다
- 서빙: vLLM. 생성·판독 모델은 Qwen3.8-27B(오픈웨이트, 멀티모달, 2주차 미팅
  확정) 하나로 통일하며, 젯슨에서는 NVFP4 양자화 판을 쓴다(원본 대비 3~4배
  속도, 내용 동일 — ADR-0023). 초기 서빙 검증은 Qwen3.5-35B-A3B로 수행(ADR-0004)
- 문서 처리: MinerU(구조 추출·OCR, docling·tesseract 폴백), 자체 복원
  파이프라인, 스캔본은 Writer 모델의 이미지 판독, Presidio 기반 개인정보 마스킹
- 검색: 임베딩(KURE-v1 베이스 학습본) + 형태소(Kiwi) 키워드 검색의
  하이브리드(RRF) + 리랭커(bge-reranker-v2-m3 베이스 학습본)
- 플랫폼: FastAPI 웹 애플리케이션, 계정·권한 분리, 외부 인터넷이 차단된
  환경에서 자립 동작

  이전 — 완료
- 3~5주(9/15~10/5): 교내 문서·규정집 반입과 파싱, 평가셋 구축 — 진행 중.
  공개 문서 194건 반입·색인 완료, 검색 모델 학습본 채택(9/20), 서빙 서버
  2대 구성(9/21). 교내 실물 문서는 수령 대기
- 6~8주(10/6~10/26): 검색·실적 카드 DB, 생성 모델 베이스라인 측정
- 9~10주(10/27~11/9): 생성 파이프라인·검증기 고도화, 실물 문서 파일럿
- 11~12주(11/10~11/23): 모델 추가 학습과 개선 폭 측정
- 13주(11/24~11/30): 평가 정리, 논문 작성, 발표 준비(12월 초 발표회)

문서 읽기·복원, 규정 검색, 초안 생성, 검증기는 1~2주에 앞당겨 구축을
마쳤고, 이후 주차에서는 실물 문서로 검증·고도화한다.

## 기대 효과

- 문서를 외부로 내보내지 않는 행정 AI의 교내 실사용 선례
- 공고 분석부터 계획서 초안까지 걸리는 시간 단축
- 수치·예산 검증 자동화로 계획서 오기재 위험 감소
- 오픈웨이트 모델의 도메인 특화 개선 폭을 수치로 입증하는 연구 결과
