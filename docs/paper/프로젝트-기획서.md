# 캡스톤디자인 프로젝트 기획서

## 프로젝트명

교내 행정업무 자동화를 위한 YNC sLLM 플랫폼 구축

## 배경 및 필요성

대학 행정 부서는 국고사업 공고 분석, 계획서 작성, 채용·입학 서류 검토처럼
문서 중심의 반복 업무를 수행한다. 이 문서들은 개인정보와 내부 정보를 담고
있어 외부 클라우드 AI 서비스에 올릴 수 없고, 그 결과 문서 업무의 자동화가
사실상 이루어지지 못하고 있다. 교내 장비 위에서 동작하는 소형 언어모델(sLLM)
기반 시스템이라면 문서를 외부로 내보내지 않고도 이 업무를 지원할 수 있다.

## 목표

교내 장비(DGX Spark) 한 대로 운영되는 행정 문서 처리 플랫폼을 구축한다.
데모가 아니라 실제 학교 행정에 쓰는 것을 전제로 하며, 시스템의 역할은
완성본 생성이 아니라 70% 수준의 초안과 검토 근거를 제공하고 최종 판단은
담당자가 내리는 구조로 설계한다.

## 개발 내용

1. 문서 읽기: 스캔본·사진·PDF·HWP로 접수되는 행정 문서를 표 구조까지
   보존하며 읽어내고, 원본 모습 그대로 검색·복사가 가능한 전자문서로
   복원한다. 개인정보는 저장 전에 자동으로 가린다.
2. 규정 검색과 응답: 교내 규정·지침을 등록해 두면, 담당자의 질문에
   해당 규정 대목을 찾아 근거와 함께 답한다. 키워드 검색과 의미 기반
   검색을 결합해 정확도를 높인다.
3. 계획서 초안 작성: 공고문에서 작성 항목과 평가 기준을 읽어내고, 접수된
   자료를 재료로 항목별 초안을 작성한다. 결과는 한글(HWPX)·워드·PDF
   파일로 제공한다.
4. 검증: 초안에 들어간 모든 수치가 근거 자료에 실제로 존재하는지,
   예산 계산이 맞는지, 평가 항목을 빠짐없이 다뤘는지를 AI가 아닌
   결정론 검증기로 확인한다.
5. 모델 개선: 공개 모델을 그대로 쓰는 데서 출발해, 교내 문서로 추가
   학습시켰을 때의 개선 폭을 측정한다. 개선이 입증된 모델만 채택한다.

## 개발 환경

- 장비: NVIDIA DGX Spark (통합메모리 128GB, 온프레미스 단독 운영)
- 서빙: vLLM, Qwen3.5-35B-A3B (오픈웨이트, 비전 입력 지원)
- 문서 처리: MinerU(구조 추출·OCR), 자체 복원 파이프라인
- 검색: KURE-v1 임베딩 + 형태소 기반 키워드 검색의 하이브리드
- 플랫폼: FastAPI 웹 애플리케이션, 계정·권한 분리

## 추진 일정 (13주)

- 1~2주: 장비 검증, 파서 비교 선정, 설계 문서 작성 — 완료
- 3~6주: 문서 읽기·복원, 규정 검색, 초안 생성, 검증기 구축 — 진행 중
- 7~10주: 교내 실물 문서 파일럿, 모델 추가 학습과 개선 폭 측정
- 11~13주: 평가 정리, 논문 작성, 발표 준비

## 기대 효과

- 문서를 외부로 내보내지 않는 행정 AI의 교내 실사용 선례
- 공고 분석부터 계획서 초안까지 걸리는 시간 단축
- 수치·예산 검증 자동화로 계획서 오기재 위험 감소
- 오픈웨이트 모델의 도메인 특화 개선 폭을 수치로 입증하는 연구 결과
