## 1. 학습 데이터 생성 (모델별)

### 사업 맥락 기반 문답 (현재 우선순위)

각 사업의 실문서를 원문과 실제 목차로 읽고 사업 → 연차 → 문서 → 절·항목을 식별한다. 사업은 서로 독립적이어서
한 사업의 기준을 다른 사업에 적용하지 않는다. 여러 사업을 함께 SFT하므로 모델이 읽는 질문, 앞 대화, 근거, 답변에
사업 맥락이 들어가야 한다. 후속 질문을 단독으로 떼어 내거나 사업 정보가 메타데이터에만 있는 후보는 보강하거나 보류한다.

- 후보마다 `program_id`, `node_path`, 질문, 이전 대화, 답변, 원문 근거와 위치를 유지한다.
- 개요, 세부 설명, 조건 비교, 후속 질문, 근거 부족 확인처럼 질문 의도를 다양하게 하되, 표현만 바꿔 개수를 늘리지 않는다.
- 수치는 값을 외우게 하지 않고, 수치의 역할·단위와 근거에서 값을 찾는 방법을 학습시킨다.
- 이름·연락처 같은 실제 개인정보는 학습 사본에서 뺀다. 내부 원문 마스킹 설정으로 이 보호를 끌 수 없다.

검수는 Label Studio 「ZZAIMY 근거 기반 문답 검수」에서 하고, 주석 작성 완료와 SFT 승인을 구분한다. 승인본 변환과
학습·평가 관리는 개발자 화면 `/dev/train`에 모여 있다. 검증 전 후보는 학습에 쓰지 않는다.

품질 기준은 근거 일치, 목차 범위, 사업 맥락, 개인정보 검수 승인, 중복·분리 검사다. 파일별 반출 관문을 통과한 뒤에도
전체 학습 묶음에서 사업별 train/validation/test 분리와 중복을 다시 검사한다.

### ZZAIMY-Embed (베이스 KURE-v1)

```
코퍼스 조각 → 합성 질의 생성(로컬 LLM, 실무형·공고 요구사항형·키워드형)
 → 왕복 검증 필터(생성한 질의로 원래 조각이 상위에 검색되는지 확인)
 → 어려운 오답 채굴("같은 사업 다른 연도" 같은 함정을 명시적으로 학습)
 → (질의, 정답 조각, 오답) 학습 쌍
```

프레임워크는 sentence-transformers(MNR 대조학습)다. CPU로 돌린 v0 시험 학습은 베이스에 못 미쳐 배포하지 않았고,
토르 03 GPU에서 학습한 v2(2에폭 20분)를 후보 진입률 기준으로 채택했다. 색인과 질의 임베딩은 같은 모델로 묶어
서빙한다(ADR-0021). 공개된 KURE-v2는 다중 벡터 모델이라 별도 검색 경로로 측정했고, 학습 전 상태로는 운영 경로에서
이득이 없어 채택하지 않았다(ADR-0025).

다음 학습(v3)에서는 실물 골드 세트로 KURE-v1 베이스와 KURE-v2 베이스를 같은 학습 쌍으로 학습해 같은 질의로 비교한다.
채택 기준은 융합 뒤·리랭킹 뒤 지표가 오차 범위(±0.013)를 넘어 앞서는 것이고, 특히 상황형 질문에서의 개선을 본다.

### ZZAIMY-Rerank (베이스 bge-reranker-v2-m3)

Embed와 같은 데이터 자산을 다시 쓰므로 추가 생성 비용이 없다. 교차 인코더 순위 학습이다.

v1을 채택했다. 운영 하이브리드 검색이 실제로 올린 후보로 목록 단위 학습을 했고, 문서 단위 홀드아웃 12건에서
R@1이 0.649에서 0.711로 올랐다. 서빙은 토르 03 GPU에서 질의당 0.07초이며, 근거 하한은 모델을 바꿀 때마다 다시
잰다(ADR-0020). 생성 모델(27B)로 후보를 다시 매기는 방식은 덜 정확하고 53배 느려 쓰지 않는다.

### ZZAIMY-Writer (베이스 Qwen3.8-27B, dense)

```
과거 계획서 20~30건 → 목차 기준으로 절 단위 분해
 → 역구성(retro-fill): 입력 = [공고 요구사항 + 평가지표] + [인용 실적의 근거 블록] + [방향 요약]
 → 수치 환각 방지 정제(§2)
 → (입력, 출력 = 실제 제출 절 원문) 쌍 + 사업 단위 홀드아웃 분리
```

학습은 DGX에서 bf16 LoRA SFT로 하고 TRL·PEFT 학습 스크립트를 쓴다(LLaMA-Factory 는 10-18 걷어냄). QLoRA 4bit는 bitsandbytes의 aarch64·CUDA 13 지원을
확인한 뒤 고를 수 있는 대안이다. 학습본은 bf16 병합 → NVFP4 양자화를 거쳐 `scripts/116_ship_and_serve.sh writer`로
두 토르에 올린다(ADR-0023).

dense 27B를 고른 이유: LoRA 어댑터와 vLLM LoRA 서빙이 dense 모델에서 검증된 경로다. MoE는 학습 시 전문가 전체가
메모리에 올라가고, 라우팅 때문에 적은 데이터의 SFT가 불안정하다.

현재 베이스 모델이 두 토르에서 NVFP4로 서빙 중이다(요청당 10.4~10.9 tok/s). 이미지 판독, 반입 검토, 대화, 초안,
문서 작업 에이전트의 판단을 모두 이 모델이 맡는다. 실문서 평가셋을 분리하고 베이스라인을 측정한 뒤 학습한다.
첫 학습본 writer-v1(SFT, LoRA bf16)은 DGX 에서 학습을 마쳤고(10-22), 어댑터 writer-sft 를 토르 02 에 올려 운영 모델과 같은 보류분·시나리오로
견주는 중이다(10-23~). 병합·NVFP4 재양자화본 writer-sft-merged 도 같은 비교에 넣는다.

실문서 학습쌍(ADR-0039): 위 역구성을 실제로 수행하는 도구가 `scripts/152_build_real_sft.py`다. 양식(작성 서식)과
완성본(사업계획서) 한 쌍에서 절마다 입력(서빙 프롬프트와 같은 꼴: 작성 방법, 근거, 사실 목록, 양식 표 격자)과
출력(편집 계획 JSON: 문단, 새 표, 양식 표 칸 채움, 도식)을 만든다. 검수는 Label Studio 「ZZAIMY 실문서 절 작성」에서
하고, 승인 전에는 학습하지 않는다.

### ZZAIMY-Extract (베이스 Qwen3.8-27B, Writer와 같은 모델)

추출은 27B가 구조화 출력(xgrammar)으로 맡는다. 소형 4B 증류는 파일럿 규모에서 처리량이 문제로 드러날 때만
검토한다(ADR-0026). 아래 교사 추출 → 검수 → SFT 절차는 27B 어댑터에도 그대로 적용된다.

```
파일럿 결과보고서 → 교사 모델(Writer 베이스 + xgrammar) 추출
 → 사람 검수 수백 건(실적 카드 검수와 같은 작업)
 → 검수 완료본으로 SFT. 서빙 때도 xgrammar를 함께 써서 형식을 이중으로 보장
```

## 2. 수치 환각 방지: 학습 데이터 정제 규칙

1. 출력(절 원문)의 모든 수치와 고유 실적명을 기계적으로 뽑는다.
2. 입력 근거에 없는 수치가 출력에 있으면 근거를 역검색해 입력에 더하고, 찾지 못하면 그 학습 쌍을 버린다.
   수치를 가림 문자로 바꾸면 문체가 흐트러지므로 버리는 것을 원칙으로 한다.
3. 정제 통과율과 폐기 사유 분포를 데이터 카드에 기록한다.
4. 정제기는 검증기(수치 대조)와 같은 코드를 쓴다. 학습과 서빙이 같은 기준으로 수치를 판정한다.

## 4. 평가 원칙

상세는 [평가 계획](eval-plan.md)에 있다.

- 모든 개선폭은 베이스라인 보고서 대비로만 주장한다.
- 평가셋은 문서·사업 단위로 분리한다. 같은 문서나 사업이 학습과 평가 양쪽에 들어가지 않는다.
- Writer의 수치 환각률은 결정론적 대조기로 재며, 0에 수렴하는 것이 합격선이다.
- 각 모델 판마다 학습 설정, 데이터 스냅샷 해시, 평가 결과를 모델 카드에 남긴다.
