## 1. 학습 데이터 생성 파이프라인 (모델별)

### 현재 우선순위: 사업 맥락 기반 문답

실문서 7개를 원문·실제 목차로 읽고 사업 → 문서 → 절·항목을 식별한다.
각 후보는 `program_id`, `node_path`, 질문, 이전 대화, 답변, 원문 근거·위치를 유지한다.
개요·세부 설명·조건 비교·후속 질문·근거 부족 확인 등 질문 의도를 다양화하되,
단순 표현 바꾸기로 개수를 늘리지 않는다. 검증 가능한 근거 설명과 최종 답변을 검수한다.

Label Studio 「ZZAIMY 근거 기반 문답 검수」에 누적하며, 주석 작성 완료와 SFT 승인은
구분한다. 현재 프로젝트 조회는 `/dev/train?tab=data`, 승인 파일은 `tab=exports`다.
검수 결과의 승인본 변환은 아직 미연결이며, 검증 전 후보를 바로 학습하지 않는다.
이름·연락처 등 실제 개인정보는 학습 사본에서 제외한다. 수치의 역할·단위·근거에서
값을 찾는 방법을 학습시키고, 특정 기관의 실적을 고정 정답으로 암기시키지 않는다.
수치 일반화·합성값 변형은 입력 근거와 답변을 함께 바꿔 일관성을 확인해야 하며,
해당 자동화는 아직 완료되지 않았다. 내부 원문 마스킹 설정으로 학습 보호를 끌 수 없다.

품질 기준은 근거 일치·목차 범위·사업 맥락·개인정보 검수 승인과 중복·분리 검사다.
파일별 반출 관문 통과 후에도 전체 학습 묶음에서 사업별 train/validation/test 분리와
중복을 재검증한다. 문서 전체 목차 대비 문답 커버리지와 실문서 베이스라인이 필요하다.

### ZZAIMY-Embed (베이스: KURE-v1)

```
파일럿 코퍼스 청크 → 합성 질의 생성 (로컬 LLM, 질의 유형 3종: 실무형/공고 요구사항형/키워드형)
 → 라운드트립 품질 필터 (생성 질의로 원청크가 상위 검색되는지 자기 검증)
 → 하드 네거티브 채굴: hn_mine + 도메인 규칙("같은 사업 다른 연도" 함정을 명시 학습)
 → (질의, 정답 청크, 네거티브) 수만 쌍
```

프레임워크: sentence-transformers(MNR 대조학습). 현황: v0 리허설(09-03, CPU)은 베이스 미달로
미배포, v2(09-20, 토르 03 GPU, 2에폭 20분)는 후보 진입률로 판정해 채택. 색인과 질의 임베딩을
같은 모델로 묶어 서빙한다(ADR-0021). 공개 KURE-v2 는 다중 벡터 모델이라 별도 검색 경로로 재어 보았고
학습 전 상태로는 운영 경로에서 이득이 없어 채택하지 않았다(ADR-0025). 실물 골드 세트가 생기면 v3 학습 때
KURE-v1 베이스와 KURE-v2 베이스를 같은 학습 쌍으로 학습해 같은 질의로 대결시킨다. 채택 기준은 융합 뒤·리랭커 뒤
값이 오차 범위(±0.013)를 넘어 앞서는 것, 특히 상황형 질문에서다.

### ZZAIMY-Rerank (베이스: bge-reranker-v2-m3)

Embed와 동일 데이터 자산 재활용 (추가 생성 비용 0). cross-encoder 순위 학습.
현황: v1 채택(09-20), 운영 하이브리드가 실제로 올린 후보 20개로 목록 단위 학습, 문서 단위
홀드아웃 12건에서 R@1 0.649 → 0.711. 서빙은 토르 03 GPU(질의당 0.07초), 근거 하한은 모델마다
다시 잰다(ADR-0020). 생성 모델(27B)로 후보를 다시 매기는 방식은 덜 정확하고 53배 느려 쓰지 않는다.

### ZZAIMY-Writer (베이스: Qwen3.8-27B, dense — 2주차 미팅 확정, 2026-09-08)

```
과거 계획서 20~30건 → 목차 기준 섹션 해체 (수백~수천 쌍)
 → retro-fill 역구성: 입력 = [공고 요구사항+평가지표] + [인용 실적의 역검색 근거 블록] + [방향성 요약]
 → 【수치 환각 방지 정제 — 절대 규칙, 아래 §2】
 → (입력, 출력=실제 제출 섹션 원문) 쌍 + 사업 단위 홀드아웃 분리
```

학습: 현재 DGX는 bf16 LoRA SFT → DPO, LLaMA-Factory/학습 스크립트 사용(HANDOFF의 9/22 환경 검증).
QLoRA 4bit는 bitsandbytes aarch64 CUDA 13 지원 확인 후 선택하는 대안이며 현재 기본이 아니다. 학습은 DGX 에서,
학습본은 bf16 병합 → NVFP4 양자화 → `scripts/116_ship_and_serve.sh writer` 로 두 토르에 올린다(ADR-0023).
dense 27B를 고른 이유: LoRA 어댑터·DPO·vLLM LoRA 서빙이 dense에서 검증된 경로이고, MoE는 학습 시
전문가 전체가 메모리에 올라가며 라우팅 때문에 소량 데이터 SFT·DPO가 불안정하다.
현황: 베이스가 두 토르에 NVFP4 로 서빙 중(요청당 10.4~10.9 tok/s). 이미지 판독·반입 검토·대화·초안이
모두 이 모델이다. 현재 실문서 7개 세트로 문답 품질·목차 맥락을 검수 중이다. 생성 후보를 학습 완료로
취급하지 않는다. 실문서 평가셋 분리 및 베이스라인 측정 후 학습한다. 공개 공고 표본 측정과는 구분한다.
실문서 학습쌍(2026-09-29, ADR-0039): 위 retro-fill 을 실제로 돌리는 것이 `scripts/152_build_real_sft.py` 다 — 양식(작성서식)
× 완성본(사업계획서) 한 쌍에서 절마다 입력(서빙 프롬프트 꼴: 작성방법·근거·사실 목록·양식 표 격자) / 출력(편집 계획 JSON:
문단·새 표·양식 표 칸 채움·도식)을 낸다. 첫 실측 28건(절 작성 24·표 채우기 4) + DPO 15쌍, `data/training/real_sft.jsonl`
은 과거 생성 후보다. 검수는 Label Studio 「ZZAIMY 실문서 절 작성」이며 승인 전 학습 금지.

### ZZAIMY-Extract (베이스: Qwen3.8-27B — Writer 와 같은 모델, ADR-0026 제안)

현황(2026-09-22): 추출은 27B 가 형식 강제(xgrammar)로 맡고, 소형 4B 증류는 파일럿 규모 실측에서 처리량이
문제로 보일 때만 되살린다. 아래 교사 추출 → 검수 → SFT 절차는 27B 어댑터에도 그대로 적용된다.

```
파일럿 결과보고서 → 교사 모델(Writer 베이스 + xgrammar) 추출
 → 사람 검수 수백 건 (실적 카드 검수 UC-5와 동일 작업 — 이중 활용)
 → 검수 완료본으로 SFT. 서빙 시에도 xgrammar 병행 (형식 이중 보증)
```

## 2. 수치 환각 방지 — 학습 데이터 정제 규칙 (절대 규칙)

1. 출력(섹션 원문)의 모든 수치·고유 실적명을 기계 추출한다.
2. 입력 근거 블록에 없는 수치가 출력에 있으면: 근거를 역검색해 입력에 추가하거나,
   찾지 못하면 해당 학습 쌍을 폐기한다. 수치 마스킹 치환은 문체 왜곡 위험이
   있어 쓰지 않는다, 폐기가 원칙.
3. 정제 통과율·폐기 사유 분포를 데이터 카드에 기록한다 (모델 카드 재료).
4. 이 정제기는 검증기 1종(수치 대조)과 같은 코드를 공유한다, 학습과 서빙이
   동일 기준으로 수치를 판정하게 한다.

## 4. 평가 프로토콜

상세는 `eval-plan.md`. 원칙만 고정한다:

- 모든 개선폭은 베이스라인 리포트(W8) 대비로만 주장한다.
- 평가셋 분리는 문서·사업 단위 (같은 문서/사업이 학습·평가 양쪽에 못 간다).

- 각 모델 v0.x마다 학습 YAML·데이터 스냅샷 해시·평가 결과를 모델 카드에 기록.
