# OCR 대결 벤치 (도전자 모델)

68번(ocr-cer-bench)과 같은 문서·같은 렌더·같은 채점(어절 F1, 순서 무관)으로
도전자 OCR을 측정한다. 현행 MinerU 기준선은 docs/ocr-cer-bench.md의 동일 문서 행과 비교.

## 2026-09-08 — PaddleOCR-VL 0.9B (CPU 전용 VM에서 대결 시도)

**결과: 도전자 측정 불가 — CPU에서 실행 불가능함을 확인.**

운영 서버(ESXi VM, GPU 없음, 8 vCPU)에서 PaddleOCR-VL-0.9B를 transformers로
직접 구동(float32) 시도. 모델 로드·forward는 통과했으나 **1페이지 생성이
60분 안에 끝나지 않았다**(문서 5 단독 1쪽: rc=124 타임아웃). 문서 5·6·7·8을
2쪽씩 돌린 배치에서도 4건 모두 90분 타임아웃으로 결과 미산출.

- 원인: NaViT 동적 고해상도 비전 인코더가 만드는 긴 시퀀스를 CPU float32로
  디코딩하는 비용이 감당 불가. 0.9B라도 VLM 디코딩은 GPU 전제.
- 부작용: 4건 × 90분 = 약 6시간 동안 VM CPU가 포화되어 SSH·웹이 응답 지연.
  (VM이 죽은 것은 아니며 배치 종료 후 정상 복귀 — load 0, 웹 200.)
- **판정: PaddleOCR-VL 대결은 GPU 서버(vLLM)에서만 유효.** DGX나 온디맨드
  GPU 확보 후 재개한다. CPU 전용 운영 서버에서는 MinerU가 유일한 실용 엔진.
