# 3~4년치 문서 반입 — 분류 계약 제안

상태: Claude 검토 요청. 구현 완료 또는 분류 정확도 검증 완료가 아니다.
사용자 요구: NAS/수동 반입 모두 부서·업무별 분류, RAG와 학습에 일관되게 사용.

## 코드에서 확인한 차이

- 수동 `/upload`는 dept/access_level을 받고 access_policy.classify를 호출한다.
- `ingest/nas_sync.py::add`는 target/sector를 저장하지만 부서·담당자·열람등급
  입력이 없고, sync의 add_document 호출에도 해당 필드가 전달되지 않는다.
- NAS 원천별 수정시각·크기 검사와 내용 해시 중복 검사는 존재한다. 이를 전역
  중복 관리나 개정판 관리가 완료됐다는 뜻으로 해석하면 안 된다.
- 문서유형에 따른 공개 기본값은 업무 분류의 추정과 분리해야 한다. 내부 규정·
  개인정보 포함 계획서가 “기준 문서”라는 이유만으로 공개되면 안 된다.

## 공통 반입 계약

사용자 추가 사례: 장학금 안내가 “기준 문서”로만 표시되는 문제.
“장학금”은 업무 분야, “신청 안내/공고/규정/서식”은 문서 유형,
“기준으로 사용”은 활용 역할, “공개/부서/담당자”는 접근 정책이다.
서로 대체하지 않는 독립 축으로 모델링한다. 기존 regulation 값만으로 장학금이나
부서를 추정하지 않는다. 목록에는 업무 경로+문서 유형을 우선하고 활용 역할은
보조 배지로 둔다. 장학금을 입학/일반행정에 임의로 합치지 않는다.
예시(분류안, 실제 문서 확정 아님): 학생지원 > 장학금 > 국가장학금 /
신청 안내 / 기준으로 사용 / 2026학년도 2학기. 소관 부서는 학교 사전으로 확인한다.

| 분류축 | 저장할 정보 | 결정 방법 |
|---|---|---|
| 출처 | NAS 원천/상대경로 또는 수동 업로드, 원본명, 해시, 반입배치 | 시스템 기록 |
| 소관 | 부서 식별자·담당자·프로젝트 | 원천 기본값 또는 명시 선택 |
| 업무 | 국고사업·채용·입학·일반행정 및 세부 업무 | 등록 사전 + 내용 기반 추천 |
| 문서유형 | 공고·계획서·결과보고서·규정·서식·증빙 | 명시값 우선, 추정은 근거 보관 |
| 시간 | 작성일·대상연도·사업연도·효력기간 | 서로 다른 필드, 모르면 미확인 |
| 개정 | 문서군·개정번호·대체 문서 관계 | 동일파일과 개정판을 구분 |
| 보안 | 열람범위·민감정보 처리상태 | 권한 있는 명시값/보수적 정책 |
| 품질 | 분류 출처·근거·확인상태·규칙/모델 버전 | 자동 기록, 수정 이력 유지 |

폴더명은 분류 단서이지 확정 사실이 아니다. 폴더와 내용이 충돌하면 확인 대기.
모델이 업무/유형을 추천할 수는 있어도 열람 범위를 자동으로 넓히면 안 된다.
부서 명칭 변경은 동일 식별자+별칭으로 관리해 연도별로 흩어지지 않게 한다.

## 단계 및 관문

1. 원천 등록·반입 미리보기: 범위, 예상 개수, 기본 분류/권한을 확인한다.
2. 원본 보관·중복 검사: 같은 내용은 중복 연결로, 내용이 바뀐 문서는 개정 후보로.
3. 파싱·보호 처리: 쪽수/표/본문 품질과 개인정보 처리 결과를 기록한다.
4. 분류 검증: 누락·충돌·저신뢰는 확인 대기. 권한 미확정은 공용 색인에서 제외.
5. 검색용 분할: 문서ID·쪽·절·표·부서·업무·연도·권한·버전을 모든 검색자료가 상속.
6. 검색 색인: 승인된 범위만 적재. 분류/권한/본문 변경 시 관련 색인을 갱신한다.
7. 학습 후보 선별: 별도 승인·PII·수치 근거 검증을 거쳐 학습쌍을 만든다.

검색용 분할 자체는 학습 데이터가 아니다. 3~4년치 전체를 자동 학습 대상으로 삼지 않는다.
같은 문서의 조각/개정판이 학습과 평가에 나뉘어 들어가지 않도록 문서군 단위로 분리한다.

## 운영 UI

### 본 문서·붙임·관련·개정 관계

파일별 원본/해시/권한을 보존하고 문서군 ID와 관계 유형(붙임, 참조, 개정)을
별도 저장한다. 한 붙임이 여러 본 문서에 연결될 수 있어 단일 부모 필드만으로
제한하지 않는다. 파일명 번호만으로 연결을 확정하지 않고 업로드 묶음·NAS 경로·
본문의 붙임목록을 단서로 연결 후보와 근거를 남긴다. 누락 붙임도 표시한다.
원천 파일 단위 권한을 우선하며 묶음 연결이 접근권한을 넓히면 안 된다.
검색 인용은 실제 근거 파일/쪽을 가리키고, 허용된 범위 안에서 본 문서·붙임을
함께 탐색한다. 삭제는 연결 해제와 실제 파일 삭제를 구분한다.
평가 분리는 관련 개정판·본 문서·붙임을 같은 문서군으로 취급해 누출을 막는다.

### VM 저장 공간

관리자 화면은 문서 저장 경로의 파일시스템 전체/사용/가용 바이트와 확인 시각,
용량 부족 경고를 표시한다. 다른 마운트의 루트 디스크 값을 대신 보여주면 안 된다.
원본 외 OCR 이미지·복원 PDF·검색 색인·백업이 공간을 쓰므로 원본 크기만으로
반입 가능량을 계산하지 않는다. OS 예약 영역 때문에 전체-사용과 가용이 다를 수 있다.
폴더별 상세 집계는 요청마다 전체 트리를 스캔하지 말고 별도 주기 집계로 제공한다.
미리보기/배치 시작 전 가용 공간 확인 및 부족시 새 작업 보류, 정리시 삭제 확인 필요.

- 원천별 기본 분류 설정 → 배치별 진행 현황 → 확인 대기함 → 확정 분류별 문서 목록.
- 실패/중복/확인대기/검색가능 건수를 구분하고 중단한 배치는 재개할 수 있게 한다.
- 일괄 수정은 적용 대상 미리보기·확인·변경 이력·검색 반영 상태를 표시한다.
- 분류 검수는 문서마다 전부 수작업하는 방식이 아니라 예외와 표본을 중심으로 한다.

## Claude 요청 및 완료 기준

우선 NAS/수동 공통 메타데이터와 보안 기본값부터 맞춘다. 필드/API 계약 확정 후
Codex가 원천 설정·반입 미리보기·확인대기 UI를 담당한다. 기존 데이터의 일괄
소급 변경은 별도 계획·백업·표본 검수 이후 진행한다.

동일 합성 문서를 NAS/수동으로 넣어 출처를 제외한 분류/권한이 일치하는지,
부서 누락/폴더 충돌/개정판/같은 파일 재시도/중도 중단/민감 기준문서 시나리오를
검증한다. 예상 연간 문서 수·용량·파일 형식 비중은 실제 원천 목록으로 조사하며
“3~4년”만으로 처리시간이나 저장용량을 추정하지 않는다.
