# GraphRAG(온톨로지 + RAG) 대 풀텍스트 RAG 비교 (10월 13~14일)

## 왜 쟀나

AURA 는 사업 문서 질문에 답할 때 지식그래프(사업 → 연차 → 문서 → 절, 계획↔실적 짝, 앞·뒤 단계 사업, 평가 관계)로
후보 문서를 먼저 좁히고 그 안에서 어휘·임베딩 검색을 한다. 그래프를 짓고 유지하는 데는 비용이 든다. 그 비용이
값을 하는지, 같은 질문을 그래프 없이 전체 조각에서 찾을 때와 견주어 수치로 보이려고 이 실험을 했다.

## 무엇을 견줬나

세 모드는 같은 코드에서 사업 문서 검색의 그래프 단계만 다르다. 재순위(ZZAIMY_GRANT_RERANK)는 운영 설정 그대로(꺼짐)
세 모드가 같고, 답을 쓰는 모델(27B, AgentResponder)과 프롬프트도 같다.

- A 풀텍스트 RAG: 그래프 단계를 끈다. 사업·연차·갈래 좁히기, 그래프 절 노드로 같은 제목의 절 앞세우기, 관계 근거
  담기를 하지 않고 사업 문서 전체 조각에서 어휘(Kiwi 명사·희소 가중)와 임베딩(Embed v2) 순위를 RRF 로 섞는다.
  근거 머리의 「사업 > 연차 > 문서」 경로도 그래프에서 오므로 A 에서는 파일 이름만 붙는다.
- B 온톨로지 + RAG(운영 기본): 그래프 단계가 질문의 사업 이름·「N차년도」·갈래 낱말을 이름 맞추기로 읽어 후보를 좁힌다.
- C B + 27B 질문 읽기: 그래프 단계에서 27B 가 질문을 온톨로지 말(사업·연차·갈래·따라갈 관계)로 읽는다
  (graph/question_read, ZZAIMY_GRAPH_READ=1 과 같은 일). 관계를 읽으면 짝 문서·앞뒤 사업까지 넓힌다.

스위치는 `grant_search.graph_mode("fulltext"|"graph"|"graph_read")`(contextvar)와 `search(..., graph=False)` 다.
운영 기본은 바뀌지 않는다(시험 tests/test_grant_search.py·tests/test_graph_mode_chat.py). 관리자 계정은 대화 입력줄의
「검색:」 선택으로 질문 하나만 실험 모드로 물을 수 있고, 그때 질문 위에 「[실험 · …]」 표시가 붙는다. 다른 계정이
값을 보내도 무시한다.

## 해석

절 질문에서 그래프의 몫이 가장 크다. 사업 이름과 연도·갈래를 그래프로 먼저 좁히면 정답 문서가 상위 5에 드는 비율이
18% 에서 64% 로 오른다(구간이 겹치지 않는다). 풀텍스트는 같은 제목의 절이 다른 사업·다른 해 문서에도 흔해서(「과제 배경 및
목표」, 「세부 추진계획」) 같은 사업까지는 90% 찾지만 그 해 그 문서는 놓친다. 답에서도 그대로 이어진다 — 근거에 정답 문서가
드는 비율 31% → 53%, 정답 절의 숫자 사실 재현율 3% → 29%, 판정 정답성 0.36 → 0.75.

관계 질문은 이름 맞추기(B)만으로는 나아지지 않는다. 앞·뒤 단계 질문에서 B 는 질문에 적힌 사업(예: 전문대학 혁신지원사업)으로
범위를 좁혀 버려 정작 물은 전신 사업(특성화 전문대학 육성사업) 문서를 범위 밖으로 밀어낸다(47% → 5%). 풀텍스트가 47% 인 것은
「건너편 사업 문서 아무것이나 하나」라는 너그러운 정답 조건 덕이 크다. 질문을 27B 가 관계로 읽어 그래프의 succeeded_by·
integrated_into 를 따라가면 19문 모두 맞힌다(C 100%). 평가 질문도 evaluates 를 따라가는 C 가 50% 로 가장 높다. 계획↔실적
짝은 세 모드 모두 낮다(0·3·14%). 한 연차에 계획서가 수십 건(협약반별)이라 정답 짝 한 쌍을 정확히 상위 6에 함께 넣기 어렵고,
C 도 계획서 쪽은 15/36 까지 끌어오지만 짝 실적보고서는 9/36 에 머문다. 이 갈래가 다음 개선 대상이다.

비용은 지연이다. 검색 한 번은 A 1.2초, B 1.6초(+0.4초), C 6.5초(+5.2초, 27B 읽기). 답변 전체 중앙값은 29.8 → 37.7 → 42.3초인데,
차이의 대부분은 생성 쪽이다 — 그래프로 좁힌 근거가 더 구체적이라 답이 길어진다(생성 24.8 → 33.9초). 근거 밖 수치는 세 모드
모두 1% 안이라(1/152, 1/111, 0/169) 그래프가 지어낸 수치를 줄였다고 말할 근거는 이 표본에 없다. 수치를 근거에서만 쓰게 하는
것은 프롬프트·근거 대조의 몫이고, 그래프의 몫은 맞는 근거를 가져오는 데 있다.

정리하면, 사업·연도·문서를 지목하는 질문에서는 이름 맞추기 그래프만으로 검색 정답이 3.6배(18% → 64%)가 되고 비용은 검색
0.4초다. 관계를 묻는 질문은 27B 읽기로 관계를 따라가야 풀텍스트를 넘는다(13% → 45%, 판정 0.33 → 1.00). 운영에서 27B 읽기를
켤지는 검색 5초 남짓의 추가 지연과 이 차이를 놓고 정한다(scripts/184 와 이 측정이 근거).

- 27B 서버는 사용자와 같이 쓴다. 답변 시간은 그 부하를 포함한 값이다.

## 판정 기준(판정자에게 준 글 그대로)

```
너는 대학 국고 사업 문서(계획서·실적보고서·평가 결과) 질의응답의 답을 채점하는 판정자다. 답을 만든 방식은 알려 주지 않는다(가·나·다는 무작위).
입력 파일의 항목마다: q(질문), set(section=절 질문, relation=관계 질문), type(plan_report=계획 대비 실적, lineage=앞·뒤 단계 사업, evaluates=평가 의견), reference(정답 자료: 절 질문은 정답 문서의 그 절 글, 관계 질문은 정답 문서들의 해당 절 글 또는 앞부분), answers(가·나·다 답).
점수는 정답 자료(reference)에 비추어 매긴다. 정답 자료에 없는 일반론은 맞힌 것으로 치지 않는다.
- correct(정답성, 0~2): 2 = 질문이 가리킨 사업·연도·문서·절의 내용을 답했고, 정답 자료의 핵심 사실(수치·날짜·이름·항목) 가운데 주요한 것을 맞게 담았다. 1 = 일부만 맞다(핵심 사실 일부, 또는 같은 사업의 다른 해·다른 문서 내용을 섞음, 또는 내용은 맞지만 아주 빈약함). 0 = 정답 자료와 맞는 내용이 거의 없거나, 다른 사업·다른 절을 답했거나, 찾지 못했다고만 했다.
- complete(완결성, 0~2): 절 질문은 정답 절의 주요 항목을 얼마나 빠짐없이 다뤘나(2 대부분 / 1 일부 / 0 없음). 관계 질문은 관계의 양쪽을 다 다뤘나 — plan_report 는 계획과 실적 둘 다 구체 내용(2)·한쪽만(1)·없음(0), lineage 는 물은 쪽(전신·후속·편입) 사업의 내용을 구체적으로(2)·막연히(1)·없음(0), evaluates 는 평가 의견을 구체적으로(2)·막연히(1)·없음(0).
- contradiction(true/false): 답에 정답 자료와 어긋나는 수치·날짜·이름이 있으면 true.
- note: 한 줄 이유(30자 안팎).
```
