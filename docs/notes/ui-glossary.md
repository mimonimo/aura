# UI 용어집 — 화면 문구 통일 기준

작성 2026-09-15. 화면 문구에 남아 있던 직역·음차 표현을 자연스러운 행정 용어로
바꾸면서 정한 기준이다. 템플릿(`src/zzaimy/app/templates/`)과 화면에 그대로
보이는 파이썬 문자열(안내문, `?err=`/`?ok=` 문구, HTTP 오류 상세, 검토·초안
상태문)에 적용했다. 식별자·URL·폼 필드명·설정 키·저장 값(영문 키)은 손대지 않았고,
사람이 읽는 낱말만 바꿨다.

## 말투

격식체(~합니다)로 통일한다. 마이크로카피(표 머리글·배지·버튼)는 짧은 명사형을
유지한다. 파이썬 쪽 HTTP 오류 상세는 "~없다", "~필요하다" 같은 반말체가 섞여
있었는데, 이것도 브라우저 화면에 그대로 보이므로 "~없습니다", "~입력하세요"로
맞췄다. 이모지는 쓰지 않는다(채팅 첨부 표시의 클립 이모지는 `[첨부]`로 바꿈).

## 판정 · 검토 · 검수 구분

코드 기준으로 확인한 역할이다. 셋을 섞어 쓰지 않는다.

- 판정: 담당자의 결정. `DECISION_LABELS`(판정 대기·승인·반려·재검토 중), 문서 화면의
  "담당자 판정" 카드, 알림의 "판정 대기 N". 외부 AI 참조의 승인·거부도 담당자 결정이지만
  화면에서는 "승인 여부를 결정"으로 풀어 쓴다.
- 검토: 의견을 내는 일. 에이전트가 만드는 "검토 의견"(`ai_review`), 담당자가 남기는
  "담당자 의견"(`reviews`), 상태 "검토 완료"(`reviewed`), "재검토 요청".
- 검수: Label Studio에서 사람이 학습 예시를 채택·수정·폐기하는 일에만 쓴다
  (데이터 공방 ②, 모델 학습 화면, `ZZAIMY 검수` 프로젝트).
- 자동 분류: 외부 AI 참조에서 기계가 안전/확인 필요/차단을 가르는 단계(`egress.classify`).

## 그대로 둔 것

- 마스킹, 색인, 조각, 코퍼스, 베이스라인, 파인튜닝, 모니터링, 콘솔: 이미 화면 전체에서
  일관되게 쓰이고 대체어가 더 어색하다.
- 저장 값과 식별자: `status`·`decision`·`verdict`·`source`·`doc_type`의 영문 키,
  라우트, 폼 필드, 설정 키, Label Studio 프로젝트명 `ZZAIMY 검수`.
- 문서 파일(`docs/`)과 코드 주석의 "이그레스·세척"은 이 작업 범위 밖이다. 문서 갱신 시
  이 용어집을 따른다.
