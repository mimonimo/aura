# UI/UX 전수 조사

작성 2026-09-08. 로컬 앱(포트 8800, no-auth) 전 화면을 헤드리스 크롬으로
1600px·1100px 두 폭 캡처해 점검했다. 캡처 원본은
`scratchpad/uiaudit/<화면>_<폭>.png` 30장에 있다(세션 scratchpad, 커밋 대상 아님).

점검 축: 패밀리 룩 일관성, 마이크로카피 규칙(짧은 명사형·이모지 배제),
정보 위계, 빈 상태 안내, 반응형, 접근 동선, 오류·대기 상태 표시.

## 전반 인상

플랫폼 전체가 하나의 디자인 언어로 묶여 있다. 사이드바 248px 고정 + 상단바 +
라운드 카드 구조가 전 화면에 일관되고, 색(네이비·포인트블루·연회색 배경)도
흔들림이 없다. 마이크로카피는 대체로 짧은 명사형이고 이모지 없이 라인 아이콘만
쓴다. 빈 상태 안내(채팅 기록 없음, 등록된 의견 없음, 추출 기록 없음, 그래프
빈 상태)와 개인정보 안내("이 장비 밖으로 나가지 않음")가 화면마다 갖춰져 있어
행정 담당자가 처음 봐도 맥락을 잡기 쉽다. 큰 구조 문제는 없고, 아래는 다듬을
지점들이다.

## 화면별 발견

### 채팅 (/chat)

  실제 DOM은 하단 고정 입력창 하나뿐이다. 과대 세로 캡처(2600px)를 오독한

- [낮음] "무엇을 도와드릴까요?"는 다소 상투적이나 자연스러운 범위. 유지 무방.

### 개발 현황 (/dev)
- **[중간] 추출 품질 백로그 카드에 깨진 글자(모지바케)로 보이는 문자열**이 있다
  ("표 신청서_예시.pdf ï ë³ⁱ …"). 실제 OCR 깨짐을 그대로 보여주는 것인지,
  표시 단계 인코딩 버그인지 확인이 필요하다. 후자면 화면에서 깨져 보인다.
  - 판정(2026-09-08, 통합자): 앱 버그 아님 — 개발 중 curl 시딩이 URL 인코딩
    없이 넣은 로컬 테스트 데이터였다. 브라우저·정상 클라이언트 입력은 UTF-8로
    올바르게 저장됨(자동 테스트로 확인). 오염 행은 정리 완료.
- [낮음] 카드가 매우 많아 페이지가 길다. 정보는 잘 나뉘어 있으나, 상단에 섹션
  앵커(개요·진행·모델·지표·자료)를 두면 긴 스크롤 탐색이 수월해진다.

### 설정 (/settings)
- [낮음] 카드 폭은 넓은데(최대 1240px) 폼이 좌측 약 500px에 몰려 우측 여백이
  크다. 카드 폭을 폼에 맞춰 좁히거나 항목을 2열로 배치하면 균형이 산다.

### 프로젝트 (/project/12)
- [낮음] 우측 지침·메모 카드의 빈 상태 아이콘이 살짝 잘려 보인다. 사소.
- 참고: 이전에 지적됐던 2단 그리드 붕괴는 반응형 처리(1080px 이하 1단)로
  해결돼 정상 동작한다.

### 데이터 열람 (/dev/db)
- [낮음] 1100px에서 파일명 열이 잘린다("실적…" "신청…"). table-scroll로 가로
  스크롤은 되지만 좁은 폭에서 답답하다. 아래 반응형 항목과 함께 다룬다.

### 외부 참조 관문 (/dev/egress), 기준 문서 (/criteria), 문서 추출 (/ocr), 홈 (/)
- 큰 문제 없음. 정보 위계·빈 상태·상태 배지가 잘 갖춰져 있다. egress는 세척본과
  제거 내역·판정·승인 흐름이 명확해 특히 완성도가 높다.

## 반응형

- **[중간] 좁은 폭에서도 사이드바가 248px로 고정**된다. 1100px 안팎(보급형
  노트북)에서 content 영역이 좁아져 표·2단 레이아웃이 눌린다. 개선안: 일정 폭
  (예: 1080px) 이하에서 사이드바를 접기(햄버거) 또는 아이콘 축소로 전환한다.
  이 하나가 dev/db 열 잘림 등 여러 좁은-폭 이슈를 함께 완화한다.
- 1600px에서는 전 화면 레이아웃이 안정적이다.

## 접근 동선

- 주요 기능은 사이드바에서 1클릭 접근이 되고, 업무 영역·프로젝트·개발자 메뉴가
  구분돼 있어 길찾기가 명확하다.
- 지식그래프는 채팅·기준 문서 화면에서 진입(2클릭). 자주 쓰면 사이드바에 직접
  두는 것도 고려할 만하다(현재는 부가 기능 위치로 적절).

## 조사 한계 (로컬 환경 제약)

- 로컬 표본 문서가 미처리(received) 상태라 **문서 상세의 초안 생성·AI 읽기
  뷰어·인식 영역 팝업은 로컬에서 확인 불가**하다(처리 중 안내만 뜬다). 이
  화면들은 실데이터가 처리된 운영 VM에서 별도 점검이 필요하다.
- no-auth 모드라 **/login이 홈으로 리다이렉트**된다. 실제 로그인 화면은 인증
  모드에서 별도 확인해야 한다.
- 모델 미탑재라 상단 검색창·채팅 응답 등 검색 의존 기능의 실동작은 미검증.
  상단 "문서 검색"이 전 페이지에 노출되는데 실제 동작 범위 확인이 필요하다.

## 우선순위 top 10

1. [중간] 채팅 입력창 중복 제거 — 하단 고정 하나로 통일(빈 상태 카드는 안내만).
2. [중간] 반응형: 좁은 폭(≤1080px)에서 사이드바 접기/축소 — 노트북 사용성.
3. [중간] /dev 추출 품질 백로그의 깨진 글자 원인 확인·수정(인코딩 버그 여부).
4. [확인] 문서 상세 초안·AI 읽기 뷰어·인식 영역 팝업을 운영 VM 실데이터로 점검.
5. [확인] 상단 검색창 실제 동작 범위 확인(전 페이지 노출 대비 기능 유무).
6. [낮음] 설정 카드 폭·여백 정리(폼 우측 큰 여백).
7. [낮음] /dev 긴 페이지에 섹션 앵커 네비 추가.
8. [낮음] /dev/db 1100px 파일명 열 잘림(2번과 연동해 완화).
9. [낮음] 프로젝트 지침·메모 빈 상태 아이콘 잘림 정리.
10. [확인] 인증 모드에서 로그인 화면 별도 점검(no-auth 리다이렉트로 이번 조사 제외).
