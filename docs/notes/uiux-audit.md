# UI/UX 전수 조사

작성 2026-09-08. 로컬 앱(포트 8800, no-auth) 전 화면을 헤드리스 크롬으로
1600px·1100px 두 폭 캡처해 점검했다. 캡처 원본은
`scratchpad/uiaudit/<화면>_<폭>.png` 30장에 있다(세션 scratchpad, 커밋 대상 아님).

점검 축: 패밀리 룩 일관성, 마이크로카피 규칙(짧은 명사형·이모지 배제),
정보 위계, 빈 상태 안내, 반응형, 접근 동선, 오류·대기 상태 표시.

## 전반 인상

플랫폼 전체가 하나의 디자인 언어로 묶여 있다. 사이드바 248px 고정 + 상단바 +
라운드 카드 구조가 전 화면에 일관되고, 색(네이비·포인트블루·연회색 배경)도
흔들림이 없다. 마이크로카피는 대체로 짧은 명사형이고 이모지 없이 라인 아이콘만
쓴다. 빈 상태 안내(채팅 기록 없음, 등록된 의견 없음, 추출 기록 없음, 그래프
빈 상태)와 개인정보 안내("이 장비 밖으로 나가지 않음")가 화면마다 갖춰져 있어
행정 담당자가 처음 봐도 맥락을 잡기 쉽다. 큰 구조 문제는 없고, 아래는 다듬을
지점들이다.

## 반응형

- **[중간] 좁은 폭에서도 사이드바가 248px로 고정**된다. 1100px 안팎(보급형
  노트북)에서 content 영역이 좁아져 표·2단 레이아웃이 눌린다. 개선안: 일정 폭
  (예: 1080px) 이하에서 사이드바를 접기(햄버거) 또는 아이콘 축소로 전환한다.
  이 하나가 dev/db 열 잘림 등 여러 좁은-폭 이슈를 함께 완화한다.
- 1600px에서는 전 화면 레이아웃이 안정적이다.

## 접근 동선

- 주요 기능은 사이드바에서 1클릭 접근이 되고, 업무 영역·프로젝트·개발자 메뉴가
  구분돼 있어 길찾기가 명확하다.
- 지식그래프는 채팅·기준 문서 화면에서 진입(2클릭). 자주 쓰면 사이드바에 직접
  두는 것도 고려할 만하다(현재는 부가 기능 위치로 적절).

## 조사 한계 (로컬 환경 제약)

- 로컬 표본 문서가 미처리(received) 상태라 **문서 상세의 초안 생성·AI 읽기
  뷰어·인식 영역 팝업은 로컬에서 확인 불가**하다(처리 중 안내만 뜬다). 이
  화면들은 실데이터가 처리된 운영 VM에서 별도 점검이 필요하다.
- no-auth 모드라 **/login이 홈으로 리다이렉트**된다. 실제 로그인 화면은 인증
  모드에서 별도 확인해야 한다.
- 모델 미탑재라 상단 검색창·채팅 응답 등 검색 의존 기능의 실동작은 미검증.
  상단 "문서 검색"이 전 페이지에 노출되는데 실제 동작 범위 확인이 필요하다.

## 2026-09-09 라이브 검토 (사용자 지적 — 배치 처리 중)

사용자가 화면을 훑으며 지적한 항목. [완료]/[대기]/[기능]/[제약]로 트리아지.

1. **[완료] 계정 칩 화이트** — base.html .user-chip 네이비 알약 → 화이트·연한 테두리.
2. **[완료] 현황 타일 = 필터 아님** — index.html 타일을 링크→읽기용 div, "처리 현황"
   라벨 + 파이프라인(접수→처리중→검토완료→판정대기) 화살표. 상태 필터 문구 제거.
3. **[완료→2로 해소] 접수문서가 어느 카드나 같게 나옴** — 상태 필터 제거로 해소.
4. **[대기] 문서 추출(OCR) 헤더 통일** — ocr.html 다크 배너 → 다른 페이지 표준 헤더.
5. **[대기] 산출물 반출** — 체크박스만이라 뭘 반출하는지 모름 → 항목별 내용·용량·설명.
6. **[대기·큼] 데이터 열람(/dev/db)** — 레이아웃 불편. 엑셀형(전체 열·넓은 셀·고정
   헤더·복사) 그리드 뷰로 개선 요청.
7. **[제약] 에이전트 앱 exe화** — zip+bat 대신 단일 exe. macOS에선 Windows exe 크로스
   빌드 불가(PyInstaller는 Windows에서 빌드). → PyInstaller 스펙·빌드 스크립트를
   준비하고 exe는 Windows 워커/CI에서 빌드하는 방식. 또는 원클릭 설치 러너.
8. **[기능·부분완료 2026-09-09] 명령 콘솔 자연어화** — 콘솔에 "개발 검증용" 성격만 명시했고
   자연어 입력은 미구현(LLM 연결 후). 수동 op+JSON 말고 "클로드처럼" 자연어→자동 실행
   (에이전트가 명령 받아 문서 수정). 실제 NL 경로는 프로젝트 대화창이며 LLM(VLLM/
   Claude) 연결 필요. 콘솔은 원래 개발 검증용 — NL 입력으로 개선하거나 대화창으로 유도.
9. **[기능·라벨 정리 2026-09-14] 참조 관문 '질의 제출'** — "(개발 검증용)" 명시 + 실사용 경로
   안내 추가. 수동 한 개씩 입력 불필요 지적. 이 역시 dev 검증
   도구. 실사용은 자동 파이프라인(신규 문서→자동 참조). 라벨·위치 재정리 또는 숨김.

**관통 주제**: #8·#9는 "왜 수동 한 개씩 입력하냐 — 자동/자연어여야" 계열. 이들은
개발 검증용 콘솔이고 제품의 NL 경로는 대화창이다. 콘솔을 NL화하려면 LLM 연결이
전제. UI로는 "개발 검증용" 성격을 분명히 하고, 자연어 입력을 얹는 방향.
