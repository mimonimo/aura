# 2주차 지도 회의 메모 (2026-09-08)

> 지난 기록 — 지금은 「모델 개발 계획」(DPO 는 10-20 범위에서 뺌)과 ADR-0047

회의에서 제시된 방향을 옮기고, 아래에 당시 구현과의 정합 분석을 붙인다.

## 회의 메모

1. 주제
2. 문서 수집 — 각종 보고서
3. 모델을 만드는 목적
   - 에이전트용: 행정업무 자동화, 문서(사업 계획서 및 보고서)
   - 부서별 워크플로
   - 업무 담당자의 노하우 학습(업무 결과물 + 매뉴얼 + 메모)
4. 모델 — Qwen3.8-27B
5. 모델 파인튜닝 절차
6. 온톨로지를 고려한 데이터 생성 및 학습
   SFT 데이터 → 온톨로지 → 모델 학습 → 사용자 활용 → 그래프 생성
7. SFT + DPO + RAG 하이브리드
8. 규정처럼 자주 바뀌는 데이터는 RAG 로

## 정합 분석 (2026-09-08 구현 기준)

이미 같은 방향으로 구축된 것.

- 자주 바뀌는 데이터는 RAG 로(8): 브리프 절대 규칙 8(지식은 검색으로 공급)과 같다. 데이터 공방도 기준 문서를
  학습 쌍에서 뺀다.
- 온톨로지를 고려한 데이터·학습(6): ADR-0009 경량 온톨로지 v1 과 지식 그래프 1단계(/graph). SFT → 온톨로지 → 학습 →
  활용 → 그래프 순환은 데이터 공방(변환·대장)과 그래프 2단계(개체 추출)로 이어진다.
- 업무 노하우 학습(3): 데이터 공방의 세 소스(검토 의견·초안·대화)가 업무 결과물과 메모에 해당한다. 매뉴얼류는 기준
  저장소에 둔다.
- 하이브리드(7): 프로젝트의 최종 형태와 같다.

바뀌는 것.

- 베이스 모델은 Qwen3.8-27B 로 정한다(4). 미해결 질문 #5(Qwen 수용성)가 해소됐다. dense 27B·멀티모달·262K 컨텍스트이며,
  기존 후보 Qwen3-30B-A3B(MoE)는 예비로 둔다. 서빙·학습 계획(serving.yaml·메모리)을 이 모델 기준으로 다시 쓴다.
- DPO 를 다시 넣는다(7). 13주 일정에서 뺐던 항목이다. 순서는 SFT 뒤이며, 선호쌍 재료는 플랫폼의 담당자 판정(채택/보완)과
  재작성 이력에서 나온다. 그래서 판정 기록이 쌓이는 흐름을 유지한다.
- 문서 수집 범위(2) 「각종 보고서」는 데이터 공방·인제스트로 바로 처리할 수 있다.
