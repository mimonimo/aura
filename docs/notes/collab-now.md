# 작업 분담 규칙

여러 작업자가 같은 저장소를 고칠 때 충돌을 막는 규칙이다. 분담·요청 절차의 원본은
`docs/collaboration/README.md` 다.

## 파일 소유권

- 작업을 시작하기 전에 맡을 파일·폴더를 정하고, 끝날 때까지 다른 작업자는 그 범위를 읽기만 한다.
- 범위는 화면 템플릿, 라우트(`src/zzaimy/app/main.py`), 반입 파이프라인, 검색·조각 품질, 평가 하네스,
  지식 그래프처럼 기능 단위로 나눈다.
- 같은 파일을 두 작업자가 동시에 고쳐야 하면 한쪽이 끝난 뒤 이어받는다.

## 배포

- 정본은 깃허브 저장소 하나다. 배포는 커밋·푸시 뒤 운영 VM 이 받아 재시작한다(`scripts/99_deploy.sh`).
- 배포와 서비스 재시작은 한 사람만 한다. 로컬에서 VM 으로 rsync 로 밀어 넣지 않는다. VM 트리가 더러워지면 pull 이 막힌다.
- 운영 서버에서 재처리가 도는 동안에는 무거운 조회·작업을 걸지 않는다.

## 공통

- 저장소 규칙은 `CLAUDE.md` 를 따른다. `data/` 는 커밋하지 않는다.
- 수치는 근거 있는 것만 쓰고, 확인하지 못한 것은 「미확인」으로 적는다.
- 화면 문구는 격식체 완결 문장으로 짧게 쓴다.
