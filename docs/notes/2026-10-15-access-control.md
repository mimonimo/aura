# 권한별 열람 범위 — 경로 × 계정 (2026-10-15)

요구: 문서함·RAG·지식그래프는 계정의 등급(역할·부서)마다 보이는 항목이 달라야 하고, 학생은 이 화면들에 들어오지 못한다.
채팅·도우미도 권한 밖 부서의 자료를 근거로 쓰지 않는다. 부서 RAG 는 부서 공유폴더와 같다 — 그 부서(와 권한을 받은 계정)만 본다.

## 규칙 한 곳

`app/access_policy.py` 가 원본이다.

- `visible(doc, **viewer)` — 문서 한 건 판정. `doc_sql(viewer)` — 같은 뜻의 SQL 조건(목록·건수·칩·폴더·사업 목록).
- `viewer(role, dept, user, data_dir)` / `request_viewer(request)` — 보는 사람. 계정별 추가 권한 부서(`also`, RAG 공간 설정의 grants)를 함께 싣는다.
  화면·라우트마다 따로 만들던 범위 dict(문서함·문서 화면·그래프·원본 장부·프로젝트 참조)를 모두 이것으로 바꿨다.

| 계정 | 볼 수 있는 문서 |
|---|---|
| 관리자(dev) | 전부 |
| 교직원·부서장(staff·head) | 전체 공개(공통) + 부서 제한 가운데 공통·소속 부서·추가 권한 부서 + 자기가 올린 문서 |
| 학생(student) | 학생 공개로 지정한 규정만 |
| 계정에 붙은 모르는 역할 | 학생과 같게(가장 좁게, `viewer` 가 바꾼다) |

이전과 달라진 점: 자기가 올린 문서는 등급과 상관없이 보인다(SQL 쪽은 이미 그랬고 파이썬 쪽만 빠져 있었다). 계정의 모르는 역할은 교직원이 아니라 학생 범위. 권한 밖 원본 열기(`/archive/original`)는 403 대신 404.

채팅 검색 조건과의 관계:

- 사업 문서 검색(`grant_search._access`)은 RAG 공간의 부서 목록(`grant_depts` = 소속 부서 + 공통 + 추가 권한 부서)으로 한 번 더 좁힌다.
  공간 안에서는 visible 과 같은 뜻이고, 공간 밖(다른 부서의 공개 등급 문서, 다른 부서 폴더에 올린 자기 문서)은 검색 후보에서 빠진다 — 더 좁다.
- 규정 조각(`db.list_regulation_chunks`)은 부서를 목록으로도 받게 했다. 추가 권한 부서가 있으면 검색 범위에 `reg_depts` 가 붙어 그 부서 규정도 근거가 된다.
  규정 검색 인자는 `access_guard.reg_kwargs(scope)` 한 곳에서 만든다.
- 테스트(`tests/test_access_matrix.py::test_visible_and_sql_agree`, `test_chat_evidence_stays_in_scope`)가 다섯 계정에서 셋이 어긋나지 않는지 본다.

## 경로 × 계정

합성 계정: 관리자, 기획처 교직원, 산학협력단 교직원, 산학협력단 교직원 + 기획처 추가 권한, 학생. 합성 문서: 공통 사업 문서, 기획처·산학협력단 부서 제한 사업 문서,
산학협력단 담당자 한정 문서, 학생 공개 규정, 교직원 규정, 기획처 부서 제한 규정.

| 경로 | 관리자 | 기획처 | 산학협력단 | 학생 | 바꾼 것 |
|---|---|---|---|---|---|
| 라이브러리 목록·건수·칩·사업 목록 (`/`) | 전부 | 공통 + 기획처 | 공통 + 산학 + 자기 것 | /chat 로 이동 | 조건을 `doc_sql` 로(학생 포함 같은 함수) |
| 라이브러리 폴더 | 전부 | 공통·기획처 폴더 | 공통·산학 폴더 | — | 폴더 수를 볼 수 있는 문서만 세고, 범위 밖 부서 폴더는 이름도 뺌. 문서 화면의 폴더 고르기도 같게 |
| 문서 화면과 하위 경로 (`/doc/{id}/…`, `/api/doc/{id}/google`, `/chat/peek/{id}`) | 전부 | 범위 안만, 밖은 404 | 같음 | 학생 공개 규정만 | 로그인 검사 한 곳이 이미 막고 있었다 — 판정을 `request_viewer` 로 |
| 문서 화면 안의 다른 문서(연결 기준·추천 기준·같은 사업·이 규정을 참조하는 문서) | 전부 | 범위 안만 | 같음 | — | 새로 거름(전에는 제목이 그대로 보였다) |
| 프로젝트 화면의 기준 문서 목록, 대화 화면의 기준 고르기 | 전부 | 범위 안만 | 같음 | 학생 공개 규정 | 새로 거름(부서 제한 규정이 남의 부서에 보였다) |
| 원본 장부 (`/archive`, `/archive/original`) | 전부 | 범위 안 + 등록 전 원본(공통·기획처 폴더) | 같음 | 403 | 범위 밖 부서 폴더의 등록 전 원본도 이름·건수에서 뺌, 권한 밖 원본 열기는 403 → 404 |
| 검색 (`/search`, 상단 검색창) | 전부 | 범위 안만 | 같음 | 403, 검색창 숨김 | 상단 검색창을 학생에게 숨김 |
| 지식그래프 목록·개요·이웃·문서 패널·노드 검색 (`/graph/explore…`, `/graph/program`) | 전부 | 기획처 문서까지 | 산학 문서까지 | 403 | 추가 권한 반영, 범위 밖 문서에서만 나온 단위과제는 이름도 404, 노드 속성의 전체 문서 수(n_docs)는 관리자만, 사업·연차 사이 관계 근거 문구(문서 번호·제목)는 관리자만 |
| 온톨로지·내려받기 (`/graph/explore/schema`·`.ttl`, `/dev/export`) | 열림 | 404·403 | 404·403 | 403 | 그대로(관리자 전용) |
| RAG 공간 (`/dev/rag`) | 열림 | 403 | 403 | 403 | 그대로(관리자 전용) |
| 채팅 근거 — 사업 문서 | 전부 | 공통 + 기획처 | 공통 + 산학 | 쓰지 않음 | 그대로(공간 범위) |
| 채팅 근거 — 규정 | 전부 | 공통 + 기획처 규정 | 공통 규정 | 학생 공개 규정 | 추가 권한 부서 규정 반영, 에이전트의 규정 찾기(source=rules)가 범위 dict 를 통째로 넘겨 깨지던 것 고침 |
| 플랫폼 업무 도우미 lookup | 전부 | 자기 올린 문서·자기 프로젝트 | 같음 | — | 그대로(관리자 아닌 계정은 자기 것만) |

학생은 허용 목록(대화·학생 공개 규정 읽기·로그아웃) 밖의 주소가 모두 403 이다. 화면 메뉴(라이브러리·프로젝트·상단 검색창)는 숨기지만 막는 것은 서버다.

## 등급 밖 질문

- 검색 범위 자체가 계정 범위 안이다 — 권한 밖 부서 문서는 모델에게 건네지지 않는다.
- 질문에 플랫폼이 아는 부서 이름(부서 RAG·계정의 부서)이 나오고 그 부서가 이 계정의 범위(소속 + 추가 권한) 밖이면, 답 머리에
  「기획처 자료는 열람 권한이 없습니다. 공통 자료와 산학협력단 자료 안에서만 찾아 답합니다.」를 붙이고 감사 기록에 남긴다(`access_guard.scope_note`).
  안내에는 부서 이름만 — 그 부서 문서의 제목·건수·있고 없음은 싣지 않는다. 대화·문서 작업 에이전트·구글 문서 질문(`/gdocs/ask`) 모두 같다.
- 27B 지시 한 줄: 응답기(`responder._SYSTEM`)와 문서 작업 에이전트(`doc_agent.SYSTEM`)에 「다른 부서 자료를 찾거나 참조하라는 요청이면
  "그 부서 자료는 열람 권한이 없습니다"라고 알리고 제목·건수·있고 없음은 말하지 않는다」.
- 이전에는 부서 없는 교직원에게는 안내가 없었고, 추가 권한을 받은 부서도 범위 밖으로 안내했다 — 둘 다 고쳤다.

## 남은 판단

1. 부서장(head) 역할은 지금 교직원과 같은 범위다. 부서장에게 부서 안 담당자 한정 문서까지 보이게 할지, 관리자가 아닌 부서 관리자 역할이 필요한지는 정하지 않았다.
2. 프로젝트 화면(`/project/{id}`)은 번호를 알면 다른 계정의 프로젝트 이름·노트가 열린다(문서 목록은 열람 규칙으로 거른다). 프로젝트를 만든 사람·같은 부서만 열게 할지 정해야 한다.
3. 지식그래프의 사업·연차 노드 이름과 사업 사이 관계(연관 사업)는 누구에게나 보인다. 사업 이름은 장부·공개 자료에서 오지만, 별칭(파일 이름에서 모은 표기)과
   관계의 존재는 부서 제한 문서에서 왔을 수 있다. 근거 문구는 관리자만 보이게 했고, 별칭·관계 자체를 범위로 거를지는 정해야 한다.
4. 사업 문서 검색은 RAG 공간 부서로 더 좁힌다. 다른 부서 폴더에 「전체 공개」로 둔 문서나 자기가 다른 부서 폴더에 올린 문서는 문서함에는 보이지만 채팅 근거에는 들지 않는다.
   부서 RAG 를 공유폴더로 보면 맞는 동작이지만, 문서함과 채팅의 범위를 완전히 같게 할지 정할 수 있다.
5. 원본 장부에서 부서 RAG 에 짝지은 폴더(`dept_of_area`)가 지금은 비어 있어 등록 전 원본은 모두 공통으로 보인다. 폴더를 부서에 짝지으면 그때부터 감춰진다.

## 바꾸는 권한 (10-16)

열람과 별도로, 문서를 바꾸는 POST(`/doc/{id}/…` — 지우기·판정·초안·초안 고치기·사업 정보 읽기·갈래·맥락 분석·그림 쪽 판독·
접수번호·검토 의견)는 그 문서를 올린 사람과 관리자만 한다. 로그인 검사(check_auth)에서 열람 검사 바로 뒤에 한 번에 막아
앞으로 생기는 문서 경로도 따른다. 볼 수 있는 누구나 하는 POST 는 품질 신고(`quality-report`)뿐이다. 「테스트 보기」 중에는
개발자가 올린 문서도 남의 문서로 본다. 기관 정보(`/institution`)는 관리자만 바꾼다.

발견 경위: 떠 있는 창의 옛 낱말 규칙(actions.suggest)이 질문 낱말로 짐작한 문서에 「사업 정보 읽기」 를 저절로 돌렸다
(「…계획서의 성과지표」 질문). 확인해 보니 교직원 계정이 볼 수 있는 공통 문서를 지우거나 초안을 다시 만들 수 있었다.
이제 저절로 하는 일은 지금 보고 있는 문서(화면 주소)이고 바꿀 수 있는 계정일 때만, 짐작한 문서에는 바꾸는 단추도 내지 않는다.
같은 부서 동료의 검토 의견처럼 남의 문서에 쓰는 일은 부서 안 등급을 정할 때 다시 연다.
