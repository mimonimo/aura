# 자동화 파이프라인 — 목표 그림과 현재 위치

사용자 비전(2026-09-08): 신규 문서·규정이 들어오면 사람이 단계마다 버튼을
누르지 않아도 에이전트가 자동으로 이어서 처리한다. 지금 만든 기능들은 그
자동 파이프라인의 "수동 단계판"이며, 나중에 오케스트레이션으로 묶는다.

## 목표 연쇄

```
신규 문서·규정 반입
   → 파싱·OCR·PII 마스킹 (인제스트)
   → RAG 색인 보강 (청킹·임베딩·재색인)
   → 분석 (개체 추출·그래프 갱신·연관 문서)
   → 학습 후보 축적 (데이터 공방 — 검토·초안·대화가 쌓임)
   → [임계치 도달] 재학습 제안 (베이스라인 대비 개선 여지 판단)
   → 사람 승인 후 학습 (Label Studio 검수 → LLaMA Board → TensorBoard)
```

## 현재 위치 (단계별 수동/자동)

| 단계 | 지금 | 자동화 트리거로 승격할 지점 |
|---|---|---|
| 인제스트 | 업로드 시 자동 처리 | 이미 자동 (폴더 감시 추가 여지) |
| RAG 색인 보강 | 재색인 필요 감지 → 버튼 | 규정 조각 변경 감지 시 자동 재색인 큐 |
| 개체 추출·그래프 | 배치 스크립트(70) 수동 | 신규 문서 처리 완료 훅에서 자동 |
| 학습 후보 | 데이터 공방 버튼 | 임계치(신규 N건) 도달 시 자동 생성·검수 요청 |
| 재학습 | 전부 수동 | 개선 여지 판단 후 "제안"까지 자동, 실행은 사람 승인 |

## 설계 원칙 (지금 지킬 것)

- 새 기능은 "사람 버튼 → 자동 트리거"로 승격 가능하게 만든다. 즉 각 단계를
  멱등·단독 실행 가능한 함수로 두고(스크립트·라우트가 그 함수를 부르는 형태),
  나중에 오케스트레이터가 같은 함수를 이벤트로 부르면 된다.
- 자동화해도 사람 승인 게이트는 남긴다: 외부 전송(이그레스), 재학습 실행,
  파괴적 작업. 자동은 "준비·제안"까지, 결정은 사람.
- 무거운 작업(재색인·학습)은 큐로 직렬화 — 동시 실행 금지(메모리 사고 방지,
  기존 flock 규율 계승).
- 실제 오케스트레이션 구현은 DGX 확보 + 핵심 기능 안정 후. 지금은 함수
  경계만 그 방향으로 맞춰 둔다.

## 멱등성 확인 (자동 재실행 안전한가)

- 개체 추출(70): 교체 저장 — 멱등 O
- 재색인(66): 조각 기준 재계산 — 멱등 O
- 데이터 공방: 매 실행 새 데이터셋 파일 — 누적(자동화 시 중복 방지 키 필요, 예정)
- 그래프: 매 요청 생성 — 상태 없음 O
