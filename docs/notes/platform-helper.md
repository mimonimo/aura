# 플랫폼 업무 도우미

오른쪽 아래 떠 있는 창(오른쪽에 붙이면 옆 패널)의 에이전트다. 채팅 화면의 에이전트 대화와는 따로 돈다.

| | 에이전트 대화 | 플랫폼 업무 도우미 |
|---|---|---|
| 자리 | 채팅 화면(`/chat`) | 떠 있는 창 또는 옆 패널(채팅·프로젝트 첫 화면 밖 모든 화면, 학생 제외) |
| 하는 일 | 사업 문서 질문, 문서 작성, 구글 문서 작업 | 플랫폼 사용 안내, 플랫폼 안 업무 처리 |
| 코드 | `app/doc_agent.py`, `main._run_doc_agent` | `app/platform_helper.py` |
| 걸음 기록 | `doc_agent_episodes.jsonl` | `platform_helper_episodes.jsonl` |
| 모델 용도 | answer | helper (지정이 없으면 answer 연결) |

걸음 구조는 같다(`doc_agent.run`에 지시만 바꿔 넘긴다). 27B 가 매 걸음 도구 하나를 고르고, 코드는 도구·관문·기록만 맡는다.
요청이 사용법인지, 할 일인지, 문서 내용인지는 모델이 도구를 고르며 정한다. 낱말 규칙은 두지 않는다.

떠 있는 창에 직접 쓴 질문이 도우미로 간다. 화면 글을 골라 묻는 질문(쉽게 설명·관련 규정 찾기 등)은 문서 내용이라 기존 답변 경로로 간다.
창은 지금 보는 화면 경로를 함께 보내고, 도우미 상태에 「지금 보는 화면: RAG 공간 (/dev/rag) — …」 으로 들어간다.

## 도구

- `platform_help` — 화면 안내 자료(`app/platform_guide.py`)에서 찾는다. 지금 화면을 먼저 보인다.
- `platform_lookup` — 동작 대상 목록. 등록된 기준 문서·규정 후보·부서 RAG 는 관리자만, 내가 올린 문서와 처리 상태·내 프로젝트는 누구나 자기 것만.
- `propose_action` — 화면 단추와 같은 일을 제안한다. 바로 실행하지 않는다.
- `open_page` — 화면 열기 단추. 안내 자료에 있고 그 계정이 열 수 있는 화면만.
- `finish` — 안내와 제안을 알리고 마친다. 모르는 값은 여기서 묻는다.

사업 문서를 찾는 도구는 없다. 문서 내용 질문은 `chat.handoff` 로, 문서를 쓰고 싶다는 요청은 `project.start` 로 에이전트 대화에 넘긴다.

## 동작과 권한

| 동작 | 같은 화면 | 계정 |
|---|---|---|
| `regs.audience` 기준 문서 학생 공개·교직원만 | RAG 공간 › 규정·지침, 체크 뒤 작업 줄 「학생 공개」 | 관리자 |
| `regs.register` 반입 자료의 규정 후보를 기준 문서로 | RAG 공간 › 규정·지침 「새 판·미등록」 탭, 작업 줄 「검색에 추가」 | 관리자 |
| `dept_rag.create` 부서와 부서 RAG 만들기 | 조직 관리(`/team`) › 트리 위 「부서」 | 관리자 |
| `project.start` 프로젝트 만들고 에이전트 대화에 첫 요청 보내기 | 사이드바 프로젝트 추가 | 관리자·교직원 |
| `chat.handoff` 에이전트 대화로 넘기기 | 채팅 | 관리자·교직원 |

제안은 대화마다 `chat_proposals:{대화}` 설정에 남고, 새 요청이 오면 앞 제안은 내린다. [실행] 을 누르면
`POST /chat/{대화}/proposals/{id}/run` 이 대화 주인인지, 계정 역할이 되는지, 대상이 아직 맞는지 다시 보고 화면과 같은 함수로 실행한다.
결과와 바뀐 것은 대화에 남고 `platform_actions.jsonl` 에 기록된다. 두 번 눌러도 한 번만 돈다. 프로젝트 만들기와 넘기기는 실행 뒤
새 대화 주소(`go`)를 돌려주고 창이 그리로 옮겨 간다.

## 화면 요소 짚기

제안과 안내 항목마다 같은 일을 하는 화면 자리(`screen`)와 요소 선택자(`target.selector`, 예: `[data-rr="student"]`)를 함께 둔다.
떠 있는 창의 제안 상자에 `data-target-path`·`data-target-selector` 로 붙어 있고, 화면 위 AURA 커서(`static/aura-helper.js`)가 쓴다.
같은 화면이면 「화면에서 직접」·[실행] 을 누를 때 커서가 그 요소로 옮겨 가 강조하고 누르는 모양을 보인다. 다른 화면이면 주소를 옮긴 뒤
(20초 안, `sessionStorage` 의 `auraPoint`) 그 화면에서 이어 가리킨다. 목록을 늦게 불러와 대상이 밀려도 0.1초마다 다시 재어 따라간다.

담당자가 화면 조작을 시키면(「문서함 열어 줘」, 「새 문서 만들어 줘」, 「라이브러리에서 ○○ 사업 찾아 줘」) 도우미가 `open_page` 에
`now=true`(필요하면 찾을 말 `text`)를 넣는다. 제안에 `act {now, text}` 가 실리고, 이 탭에서 보낸 요청의 답이면 창이 바로 대신 한다 —
화면에 보이는 그 화면 메뉴(사이드바 등)를 커서로 누르고 옮겨 간 뒤, 새 화면에서 가리킬 요소를 누르거나(창 열기·새 문서) 찾기 칸에
한 글자씩 넣고 찾기를 보낸다. 화면 열기·창 열기·찾기처럼 자료를 바꾸지 않는 일만 이렇게 하고, 자료를 바꾸는 일은 늘 [실행] 뒤 서버에서 한다.
단추가 꺼져 있거나 요소를 못 찾으면 커서 꼬리표와 창에 한 줄로 알린다. 한 번 한 제안은 `auraDone` 에 남겨 다시 열어도 되풀이하지 않는다.

## 창

틀은 `templates/_aura_helper.html`, 모양은 `static/aura-helper.css`, 동작은 `static/aura-helper.js`. 떠 있는 창 ↔ 오른쪽 붙이기는
창 자리(left·top·width·height)를 스크립트가 정하고 그 사이를 옮겨 보이며 본문은 밀지 않는다(겹쳐 띄움). 가장자리를 끌어 크기를 바꾸고,
모양·크기·열림은 `localStorage` 의 `auraHelper` 에 남아 화면을 옮겨도 이어진다. 640px 미만은 아래 시트. 머리 단추(지난 대화·새 대화·
오른쪽에 붙이기·닫기)는 올리면 이름이 바로 뜬다. 빈 창은 인사 한 줄과 지금 화면 안내 자료의 할 일 칩(`/api/helper/suggest`).
지난 대화는 마지막 대화 시각(`last_at`)으로 오늘·어제·지난 7일·이번 달·달별로 묶고, 찾기(대화 내용까지), 누르면 이어 가기,
줄 끝 … 메뉴로 이름 바꾸기·지우기(공통 확인 창). Enter 보내기·Shift+Enter 줄바꿈, 답을 기다리는 동안 보내기 단추가 멈춤이 되고
(`POST /chat/{대화}/stop` — 다음 걸음부터 하지 않고 늦게 온 답·제안은 버린다), 대기 말풍선에 지금 걸음 이름을 보인다.

## 작성 카드

문서 작업 에이전트가 문서에 쓰는 도구(write_section·rewrite_section·edit_document·create_document)를 부르면 `doc_agent.run` 의
`on_act(도구, 인자, start|done|fail)` 이 진행 상태에 `writing` (지금 쓰는 절, 이번 요청에서 쓴 절)을 싣는다. 대화 쪽 진행 카드에는
「「절」 쓰는 중 · 이번 요청에서 쓴 절 n개」 카드가, 편집기 위 진행 줄에는 AURA 커서와 「AURA가 「절」 작성 중」 이 뜬다.
화면 표시가 실패해도 에이전트 걸음에는 영향이 없다.

## 안내 자료가 낡지 않게

화면 설명은 `platform_guide.PAGES` 에 화면마다 한 항목으로 둔다. 화면 이름은 개발 메뉴(`dev_nav`), 카드 제목은 템플릿의 `<h2>`,
처리 단계는 처리 흐름(`process_flow`)에서 읽는다. `tests/test_platform_agent.py` 가 개발 메뉴의 화면마다 항목이 있는지,
적어 둔 단추 이름·자리(`#id`)·요소 속성이 그 템플릿에 실제로 있는지 확인한다. 화면을 고치면 항목도 같이 고친다.

## 남은 것

- 모델 용도 「helper」 는 연결 화면에서 고른다(비워 두면 문서 작업 연결).
- 동작 늘리기: 계정별 추가 권한, 문서 검색 범위 옮기기, 모델 연결 확인 등 화면에 이미 있는 일.
