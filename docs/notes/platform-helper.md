# 플랫폼 업무 도우미

오른쪽 옆 패널(오른쪽 아래 둥근 단추로 연다)의 에이전트다. 채팅 화면의 에이전트 대화와는 따로 돈다.

| | 에이전트 대화 | 플랫폼 업무 도우미 |
|---|---|---|
| 자리 | 채팅 화면(`/chat`) | 옆 패널(채팅 화면 밖 모든 화면) |
| 하는 일 | 사업 문서 질문, 문서 작성, 구글 문서 작업 | 플랫폼 사용 안내, 플랫폼 안 업무 처리 |
| 코드 | `app/doc_agent.py`, `main._run_doc_agent` | `app/platform_helper.py` |
| 걸음 기록 | `doc_agent_episodes.jsonl` | `platform_helper_episodes.jsonl` |
| 모델 용도 | answer | helper (지정이 없으면 answer 연결) |

걸음 구조는 같다(`doc_agent.run`에 지시만 바꿔 넘긴다). 27B 가 매 걸음 도구 하나를 고르고, 코드는 도구·관문·기록만 맡는다.
요청이 사용법인지, 할 일인지, 문서 내용인지는 모델이 도구를 고르며 정한다. 낱말 규칙은 두지 않는다.

패널에 직접 쓴 질문이 도우미로 간다. 화면 글을 골라 묻는 질문(쉽게 설명·관련 규정 찾기 등)은 문서 내용이라 기존 답변 경로로 간다.
패널은 지금 보는 화면 경로를 함께 보내고, 도우미 상태에 「지금 보는 화면: RAG 공간 (/dev/rag) — …」 으로 들어간다.

## 도구

- `platform_help` — 화면 안내 자료(`app/platform_guide.py`)에서 찾는다. 지금 화면을 먼저 보인다.
- `platform_lookup` — 동작 대상 목록. 등록된 기준 문서·규정 후보·부서 RAG 는 관리자만, 내가 올린 문서와 처리 상태·내 프로젝트는 누구나 자기 것만.
- `propose_action` — 화면 단추와 같은 일을 제안한다. 바로 실행하지 않는다.
- `open_page` — 그 화면으로 옮겨 가 커서가 할 단계(`steps`). 안내 자료에 있고 그 계정이 열 수 있는 화면·요소만. 이미 그 화면이면 열기 단추는 내지 않는다.
- `finish` — 안내와 제안을 알리고 마친다. 모르는 값은 여기서 묻는다.

사업 문서를 찾는 도구는 없다. 문서 내용 질문은 `chat.handoff` 로, 문서를 쓰고 싶다는 요청은 `project.start` 로 에이전트 대화에 넘긴다.

## 동작과 권한

| 동작 | 같은 화면 | 계정 |
|---|---|---|
| `regs.audience` 기준 문서 학생 공개·교직원만 | RAG 공간 › 규정·지침, 체크 뒤 작업 줄 「학생 공개」 | 관리자 |
| `regs.register` 반입 자료의 규정 후보를 기준 문서로 | RAG 공간 › 규정·지침 「새 판·미등록」 탭, 작업 줄 「검색에 추가」 | 관리자 |
| `dept_rag.create` 부서와 부서 RAG 만들기 | 사용자·계정 › 「부서 추가」 | 관리자 |
| `project.start` 프로젝트 만들고 에이전트 대화에 첫 요청 보내기 | 사이드바 프로젝트 추가 | 관리자·교직원 |
| `chat.handoff` 에이전트 대화로 넘기기 | 채팅 | 관리자·교직원 |

제안은 대화마다 `chat_proposals:{대화}` 설정에 남고, 새 요청이 오면 앞 제안은 내린다. [실행] 을 누르면
`POST /chat/{대화}/proposals/{id}/run` 이 대화 주인인지, 계정 역할이 되는지, 대상이 아직 맞는지 다시 보고 화면과 같은 함수로 실행한다.
결과와 바뀐 것은 대화에 남고 `platform_actions.jsonl` 에 기록된다. 두 번 눌러도 한 번만 돈다. 프로젝트 만들기와 넘기기는 실행 뒤
새 대화 주소(`go`)를 돌려주고 화면이 그리로 옮겨 간다.

## 화면 요소 짚기와 AURA 커서

안내 항목(`platform_guide.Task`)마다 화면 요소 선택자(`mark`, 예: `[data-aura="settings-name"]`)와 커서가 해도 되는 범위를 적는다.

| 갈래 | 표시 | 커서 |
|---|---|---|
| 열기·찾기·칸 채우기 | `auto=True` | 담당자가 시키면(`now`) 바로 한다 |
| 마지막 단추(저장·만들기·올리기·공유 저장) | `final=True`, `verbs`(시키는 말의 활용형) | 담당자가 이번 요청에 직접 친 글에 `verbs` 가운데 하나가 있을 때만 누른다 |
| 자료를 바꾸는 단추(학생 공개 등) | 둘 다 없음 | 가리키기만, 실행은 [실행] 뒤 서버 |

등록한 커서 동작: 문서함(폴더 열기·문서 찾아 열기·새 문서·양식으로 시작·양식 이름 거르기), 프로젝트(문서 추가·문서함·드라이브에서 가져오기·
공유 창 열기·공유 저장·진행 현황), 조직 관리(부서 찾기·부서 고르기), 내 설정(성명 칸·성명 저장·비밀번호 변경 창 — 비밀번호 칸은 사람이 친다),
라이브러리(쓰임새 거르기·문서 이름 찾기·사업 찾기·문서 올리기 창과 그 폴더·사업·연도·갈래 칸·올리기), 새 채팅(프로젝트 추가 창과 업무·이름 칸·만들기).
목록에서 하나를 고르는 요소(폴더·문서·부서·칩)는 `text` 에 이름을 넣어 같은 표시의 여럿 가운데 그 이름이 든 것을 고른다.

`open_page` 는 `steps: [{element, text}]` 를 차례로 받는다(최대 6개, 마지막 단추 뒤는 버린다). 서버(`platform_ops.propose_open`)가
단계마다 `ok` 를 정한다 — `auto` 는 `now` 면 바로, `final` 은 `commanded(사람이 친 글, verbs)` 일 때만. 사람이 친 글은 `/chat/ask` 의 질문 그대로
(`Ctx.said`)이고 문서·검색 결과·고른 글은 들어가지 않는다. 쓰는 법을 묻는 꼴(어떻게·방법·…까요·…나요·물음표)이나 그 말 마디 안의 막는 말
(하지 마·말고·안 돼·…선 안·필요 없·못)이 있거나, 동사가 시키는 꼴로 끝나지 않으면(「만들어 둔 프로젝트」·「저장해도」) 시킨 것으로 보지 않는다 —
모르면 가리키기만 하는 쪽이다(10-27 보안 점검). 화면 주소(`page`)는 우리 화면 경로만 받는다(`platform_ops.safe_path` — 맨 앞 `/` 하나, 빈·점 마디·
역슬래시·퍼센트·콜론 없음). 예전에는 `//바깥 주소` 가 라이브러리(`/`) 아래로 맞춰져 화면 열기 주소가 바깥으로 갈 수 있었다.
여러 `open_page` 는 낸 차례대로 이어진다(화면 이동 → 다른 화면에서 이어 하기). 이미 그 화면이고 할 단계가 없으면 열기 단추를 내지 않고 도우미에 알린다.

화면(`static/aura-helper.js`)은 이 탭에서 보낸 요청의 답일 때 단계를 차례로 한다. 다른 화면이면 보이는 그 화면 메뉴를 커서로 눌러 옮겨 가고,
남은 단계는 `sessionStorage` 의 `auraQueue`(20초 안)에 두어 새 화면에서 잇는다. 차례에는 누구(`data-who`)·어느 화면에서 이을지를 함께 두고,
같은 사람·그 화면(커서가 누른 단추로 옮긴 때는 어느 화면이든)일 때만 잇는다. 이을 때 단계와 허락(`ok`)은 저장해 둔 값이 아니라
`GET /chat/{대화}/messages` 의 지금 제안(아직 남고 보고 전인 것)에서 다시 만든다 — 남의 대화는 404 라 이어지지 않고, 새 요청으로 지난 제안은 버린다.
화면 이동(`location.href`)·열기 단추 주소는 `localUrl`(같은 출처, `//`·`/\` 아님)을 지난 것만 쓴다. 그 화면에서는 앞 단계가 연 창이 그려질 때까지 기다린 뒤
칸에 한 글자씩 넣거나(찾기 칸이 GET 폼의 마지막 단계면 찾기를 보낸다, POST 폼은 보내지 않는다) 고르기 칸에서 이름이 맞는 항목을 고르거나 누른다.
화면에서도 한 번 더 막는다 — 제출 단추·POST 폼 단추·`data-aura-final` 은 서버가 허락한 마지막 단계만 누른다.
허락되지 않은 마지막 단추는 가리키기만 하고 제안 상자에 [실행] 을 둔다(사람이 누르면 그 단추까지 한다). 같은 화면이면 「○○ 열기」 대신 「여기서 하기」.
한 번 한 제안은 `auraDone` 에 남겨 다시 열어도 되풀이하지 않는다.

커서가 움직이는 동안 커서 꼬리표와 패널 머리에 지금 하는 일(「AURA · 성명 칸에 입력 중」)이 뜬다. 끝나거나 멈추면 화면이
`POST /chat/{대화}/proposals/{id}/result` 로 단계 번호와 결과 갈래(입력함·고름·누름·옮겨 감·자리 못 찾음·꺼진 단추·가리키기만)를 보내고,
서버가 제안에 적힌 단계 이름·넣은 말로 「화면에서 한 일: …」 한 줄을 대화에 남긴다(제안마다 한 번). 완료 문구는 이 줄로만 생긴다 —
도우미 지시에 「도구 결과에 없는 일을 했다고 말하지 않는다」 가 있고, `finish` 글의 과거형(입력했습니다·눌렀습니다 등)은 예정형으로 바꿔 싣는다.

## 패널

틀은 `templates/_aura_helper.html`, 모양은 `static/aura-helper.css`, 동작은 `static/aura-helper.js`. 넓은 화면은 오른쪽 옆 패널 하나다 —
열면 `html.ag-side` 가 붙어 본문 칸(`.content-col`)이 패널 폭(`--ag-side-w`)만큼 부드럽게 좁아지고, 창(모달)도 남은 본문 가운데에 뜬다.
왼쪽 가장자리를 끌어 폭을 바꾸고(320px ~ 화면 절반) `localStorage` 의 `auraHelper` 에 기억한다. 640px 미만은 아래 시트(겹쳐 띄움).
페이지를 옮기면 저절로 다시 열지 않는다 — 커서가 화면을 옮겨 이어 하는 때만 연다. 머리 단추는 지난 대화·새 대화·닫기(올리면 이름이 바로 뜬다).
빈 패널은 위쪽에 인사 한 줄과 지금 화면 안내 자료의 할 일 칩(`/api/helper/suggest`).
지난 대화는 마지막 대화 시각(`last_at`)으로 오늘·어제·지난 7일·이번 달·달별로 묶고, 찾기(대화 내용까지), 누르면 이어 가기,
줄 끝 … 메뉴로 이름 바꾸기·지우기(공통 확인 창). Enter 보내기·Shift+Enter 줄바꿈, 답을 기다리는 동안 보내기 단추가 멈춤이 되고
(`POST /chat/{대화}/stop` — 다음 걸음부터 하지 않고 늦게 온 답·제안은 버린다), 대기 말풍선에 지금 걸음 이름을 보인다.
맨 아래를 보고 있을 때만 새 글을 따라 내려가고, 위를 읽는 중이면 「맨 아래로」 단추만 띄운다.

## 작성 카드

문서 작업 에이전트가 문서에 쓰는 도구(write_section·rewrite_section·edit_document·create_document)를 부르면 `doc_agent.run` 의
`on_act(도구, 인자, start|done|fail)` 이 진행 상태에 `writing` (지금 쓰는 절, 이번 요청에서 쓴 절)을 싣는다. 대화 쪽 진행 카드에는
「「절」 쓰는 중 · 이번 요청에서 쓴 절 n개」 카드가, 편집기 위 진행 줄에는 AURA 커서와 「AURA가 「절」 작성 중」 이 뜬다.
화면 표시가 실패해도 에이전트 걸음에는 영향이 없다.

## 안내 자료가 낡지 않게

화면 설명은 `platform_guide.PAGES` 에 화면마다 한 항목으로 둔다. 화면 이름은 개발 메뉴(`dev_nav`), 카드 제목은 템플릿의 `<h2>`,
처리 단계는 처리 흐름(`process_flow`)에서 읽는다. `tests/test_platform_agent.py` 가 개발 메뉴의 화면마다 항목이 있는지,
적어 둔 단추 이름·자리(`#id`)·요소 속성이 그 템플릿에 실제로 있는지 확인한다. 화면을 고치면 항목도 같이 고친다.

## 남은 것

- 남은 위험(10-27 보안 점검): `commanded` 는 낱말 규칙이라 드문 말투(「저장해서 보내 줘」 처럼 이어 주는 꼴)는 시킨 것으로 못 읽어 가리키기만 한다(안전 쪽).
  복사된 탭이 20초 안에 커서가 누른 단추 뒤의 차례를 이어받을 수 있다 — 같은 사람·같은 대화의 서버 제안으로만이다.
  결과 보고(`/proposals/{id}/result`)는 대화 주인만 보내지만 갈래(입력함·누름)는 화면이 알린 그대로라, 주인이 스스로 거짓 보고를 남길 수는 있다(남에게 닿지 않음).

- 모델 용도 「helper」 는 연결 화면에서 고른다(비워 두면 문서 작업 연결).
- 동작 늘리기: 계정별 추가 권한, 문서 검색 범위 옮기기, 모델 연결 확인 등 화면에 이미 있는 일.
