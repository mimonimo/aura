# 실문서 반입 전 검토 — 2026-09-22

Codex의 문서·코드 정적 검토. 운영 실문서 검증 또는 보안 승인 완료를 뜻하지 않는다.
실제 개인정보가 포함된 파일을 반입하거나 운영 설정을 변경하지 않았다.

## 반입 전에 닫아야 할 항목

### 1. 문서별 열람 권한 — 우선 확인

`app/main.py`의 `check_auth`는 로그인과 `/dev` 개발자 권한을 검사한다.
`doc_original`은 문서 존재·파일 존재만 검사하고 원본을 반환한다.
`app/regulations.py::find_relevant`의 검색 조건은 sector/dept이며 사용자 열람등급
인자가 없다. `retrieve/stub.py`의 user_access_levels 계약이 운영 검색에도 적용됐다고
판정할 수 없다. 문서상 “열람등급은 검색 단계 필터”와 구현 범위를 구분해야 한다.

Claude 요청: 사용자 A/B의 접근허용 문서를 분리한 합성 계정 테스트로 목록·검색·
채팅 근거·원본·페이지 이미지·내보내기까지 우회 접근을 검사한다. 학교 등급 체계
확정 및 해당 경로의 권한 강제 검증 전에는 제한 문서의 공용 반입을 승인하지 않는다.
공개 자료 파일럿과 제한 자료 파일럿을 분리한다.

### 2. 기준 문서 등록은 마스킹 제외 경로

`main.py::criteria_upload`는 등록 자료를 regulation으로 저장한다.
`pipeline.py::process`의 regulation 분기는 원문을 마스킹하지 않고 적재한다.
이는 ADR-0006 정책이며 자체 결함으로 단정하지 않는다. 다만 담당자가 실물 계획서·
명단을 기준 문서로 잘못 넣을 때의 처리 기준은 반입 전에 확정해야 한다.

Claude 요청: 등록 전 공개/기준 자료 여부 확인, 잘못 분류한 자료의 격리·재처리·
기존 색인 제거 절차를 합성 문서로 검증한다. 제외 정책을 모든 실문서에 확대하지 않는다.

### 3. 개인정보 안내의 보관 범위

`templates/dev_pii.html`은 “원문 값은 저장하지 않습니다”라고 쓴다.
반면 업로드 라우트는 inbox에 원본 파일을 보관하고 `/doc/{id}/original`로 반환한다.
마스킹 감사 기록에 원문 값을 남기지 않는다는 뜻으로 범위를 제한해야 한다.

권장 문구: “마스킹 기록에는 유형과 건수만 저장합니다. 원본 파일은 별도 보관합니다.”
Claude 요청: 원본·마스킹본문·OCR 이미지·백업 각각의 보관기간, 접근권한, 삭제범위와
담당자를 문서화한다. “잔여 0”은 정규식 탐지 범위 결과이지 개인정보 부재 보증이 아니다.

## 현황·품질 설명 정리

### 4. 서로 다른 시점의 검색 성능이 현재 값처럼 보임

`docs/dev-now.md` 상단은 R@1 0.763 / R@10 0.927, 9/22 최근 작업은 재분할 후
0.723 / 0.907이다. `docs/HANDOFF.md` §2는 문서44/청크3767, 최근 현황은
문서194/검색자료3503이다. 모두 측정 시점과 자료 구성을 붙이고 현재 요약은 최신
산출물 하나를 참조해야 한다. 숫자를 추정해서 통일하지 않는다.

### 5. OCR의 정확성 보장 표현

`docs/quality-system.md`는 벡터선·글자층 직독이면 “오타와 구조 왜곡이 원천적으로
발생하지 않는다”고 서술하지만 같은 문서는 표 추출 신뢰도·텍스트 대조를 예정으로 둔다.
권장: “OCR 인식 오류를 줄이며, 표 구조와 텍스트의 일치 여부는 별도 검증한다.”
원본 보기와 추출 결과를 구분하고, 원본 동일 재현 완료로 보고하지 않는다.

## 반입 리허설 완료 조건

- 공개 또는 합성 PDF(디지털/스캔), HWP/HWPX, 병합표, 회전·사진, 다쪽 문서를 사용한다.
- 정상: 등록 → 처리 → 제목/쪽수/본문/표 대조 → 전체 열람 → 검색 근거 원문 이동.
- 실패: 암호화·손상·모델 미연결·중도 중단 → 실패 또는 부분 성공 표시 → 재시도.
- 재시도: 중복 자료·중복 색인이 없어야 하며 기존 정상 자료가 소실되면 안 된다.
- 권한: 다른 담당자의 제한 자료는 검색 결과·근거·원본 URL 모두에서 차단돼야 한다.
- 개인정보: 표/본문/이미지 유래 텍스트를 확인하고 미탐지 이름 등의 한계를 기록한다.
- 복원: 테스트 저장소에서 백업 복원과 색인 짝(모델/문서 버전) 검증까지 수행한다.

테스트 통과와 담당 부서 승인, 운영 실화면 검증을 각각 별도로 기록한다.
