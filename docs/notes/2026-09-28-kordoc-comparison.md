# kordoc 과의 비교 — 흐름·아이디어 대조와 채택 후보 (2026-09-28)

사용자 지시: chrisryugj/kordoc(MIT, TypeScript/Node, 2.2k★, 지자체 공무원이 실물 공문서 수천 건으로 검증)이 우리와 매우 비슷하고
잘 만들어져 있으니, 실물 문서는 우리 기준으로 다시 맞추되 전체 흐름과 아이디어를 견주어 더 좋은 쪽으로 발전시킬 것.
구글독스가 실시간 다중 작업이 되므로 작업 공간은 독스로 두고, 한글(HWPX) 산출은 최종 단계에만.

## 실측 (맥, 우리 실물 세트 3건, 2026-09-28)

| 문서 | kordoc 시간 | kordoc 글자(태그 제외) | 우리 조각 글자(글+표) | kordoc 표(HTML+파이프) | 우리 표 조각 | 그림 kordoc/우리 |
|---|---|---|---|---|---|---|
| 작성서식(ver5).hwpx | 1초 | 21,054 | 24,534 | 62+3(중첩 18) | 90 | 2 / 0 |
| 지표정의서·평가편람(ver5).hwpx | 1초 | 12,333 | 12,973 | 33+22(중첩 1) | 44 | 0 / 0 |
| 사업계획서 Ver.3.3(30MB).hwp | 1초 | 64,187 | 62,494 | 110+134(중첩 31) | 112 | 28 / 25 |

- 글자 양은 비슷하다. hwpx 서식에서 kordoc 이 적은 것은 기본값이 빈 문단·미기입 누름틀 안내문을 빼기 때문(옵션으로 보존 가능).
- 속도 차이가 크다. 옛 hwp 30MB 를 우리는 pyhwp 구조 XML 덤프(약 3분) 뒤 변환하는데 kordoc 은 자체 파서로 1초.
- 표는 HTML 로 내보내 중첩·병합(rowspan/colspan)을 그대로 남긴다. 우리는 표 조각 JSON(cells 행렬)이라 중첩 표를 평문으로 편다.
- RAG 청크(`--format chunks`)는 제목 계층(breadcrumb)을 청크마다 붙이고 표를 독립 청크로 낸다.
- 레이아웃 렌더(`render`)는 서식 62쪽을 1초에 SVG 로 그렸다(PDF 출력은 Puppeteer 필요, 수식 개체 미지원, 쪽에 걸친 표는 시작 쪽만).
  6쪽(작성방법 상자·직인 표)을 PNG 로 봤더니 점선 상자·글자색·병합 표·자간 벌린 글자까지 원본 배치 그대로였다. 우리 열람 PDF 는
  변환기 docx → LibreOffice 로 24초.

## 우리와 겹치는 것 / 우리에게 없는 것

겹침: hwp·hwpx·pdf·xlsx·docx 읽기, 표 복원, 개인정보 가림, RAG 청크, OCR(kordoc 은 PP-OCRv5 내장, 우리는 Writer 판독).
없음(kordoc 에만): 신구대조표 자동 생성(compare), 공문서 규칙 lint(19항), 서식 보존 채우기(fillForm)·패치(patch), 마크다운 → HWPX 생성
(공문 프리셋·수식·차트), 레이아웃 보존 렌더, MCP 도구 17종, 폐쇄망 모드, 압축 폭탄·XXE 방어.
없음(우리에만): 프로젝트·기준/접수 분리, 독스 실시간 협업 작업본, 절 작성 에이전트(재료 수집·asks·채점·실행 기록), 학습(SFT·DPO) 데이터 공방,
열람 등급·부서 범위, 지식그래프.

## 채택 후보 (아이디어 단위, 실물 문서 잣대는 우리 145·144)

1. 읽기 속도: 옛 hwp 는 kordoc 파서로 읽고(Node 사이드카, `--format json/chunks`) 우리 마스킹·색인은 그대로. 반입 지연 3분 → 초.
   조건 — VM 에 Node 설치(sudo), ADR, 145 같은 대조(글자·표·그림)에서 우리 경로 이상일 것. hwpx 는 우리 변환기가 이미 빠르고
   독스 변환(docx)이 필요해 유지.
2. 청크 구조: 제목 계층 breadcrumb 를 우리 doc_chunks 에 넣는다(heading 경로). 절 작성 재료·검색 근거의 맥락이 좋아진다.
3. 열람 렌더: hwpx → SVG/PDF 직접 렌더가 시각 품질이 우리 LibreOffice 경로 이상이면 교체(1초 vs 24초). 수식·걸친 표 한계 확인.
4. 신구대조표: 규정 개정(학칙·규정 판본) 비교에 그대로 쓰는 기능 — 기준 문서 판본(doc_family)에 붙이면 규정 업무 유즈케이스.
5. 공문서 lint: 마무리 단계(안내 상자 삭제 뒤)에 19항 규칙 검사로 붙인다 — 우리 검증기 3종(수치·배점·예산)과 상호 보완.
6. 최종 한글 산출: 독스 작업본 → 마크다운 → 원본 서식에 `patch`(서식 보존) 또는 `generate`. 윈도우 COM 에이전트(ADR-0014) 없이
   리눅스에서 최종 HWPX 를 만들 수 있으면 대체. 작업은 독스에서(다중 인원 실시간), 한글은 산출만.
7. 개인정보 규칙: kordoc 의 규칙 집합(주민·전화·계좌·주소·이름 opt-in)과 우리 인식기를 대조해 빠진 유형 보강.
8. 보안: ZIP 폭탄·XXE 방어를 우리 hwpx 파서에 확인(defusedxml 사용 중, 압축 폭탄 상한은 없음 → 추가).

채택하지 않을 것: 내장 OCR(PP-OCRv5) — 계획 문서의 4종 밖 모델(규칙 9). 판독은 Writer 그대로.
