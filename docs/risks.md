# 위험 관리

> P1 설계 문서(2026-09-01). 2026-09-22 현황을 각 절 끝에 붙였다. 새로 드러난 위험은 §10.

## 1. 개인정보 처리 — 가장 큰 위험

- 원칙: PII 스크리닝은 인덱싱 이전 (절대 규칙 3). 사후 조치 = 벡터DB 전체 재구축.
- 구현 상태: 마스킹 골격 완료(TASK-05): Presidio + 한국형 recognizer 6종,
  `RawDocument`/`MaskedDocument` 타입 강제, 감사 로그(원문 미포함). 실물 표본으로
  recognizer 보강 필요 (학번 형식 #9, 성명 정책 #10 미확정).
- 질문 #11: 기관 개인정보보호 부서 검토: 외부 결재라 우리가 통제 못 하는
  유일한 항목. 막히면 실제 문서를 만질 수 없어 일정 전체가 밀린다.
  → 완화: 즉시 착수 요청(진행 상태 주 단위 확인). 대기 중에는 합성 데이터로
  파이프라인을 완성해 두고(현재 방식), 승인 즉시 실물 투입.

## 2. 접근권한 설계 — 구조는 완료

- 열람 등급 필터링은 검색 단계 (절대 규칙 4). 필드·필터 경로는 구현 완료
  (TASK-06, `AccessLevel`, 기본값 최보수 restricted).
- 남은 위험: 값 체계(#7)가 W2까지 확정되지 않으면 인덱싱을 시작할 수 없다.
  값 교체는 재인덱싱 불요하나, 등급 분류 기준 없이 적재하면 전부 restricted가
  되어 검색이 빈다.

## 3. 수치 환각 — 법적 위험

근거 없는 수치가 계획서에 들어가면 허위 기재, 사업 취소·환수·제재 사유.

이중 방어: ① 파이프라인 구조(수치 대조 검증기, 빈칸+표시 규약, 예산 LLM 금지),
② 학습 데이터 정제(출력 수치 ⊆ 입력 근거 아니면 폐기, model-plan §2).
정제기와 검증기는 코드를 공유해 기준 불일치를 차단한다. 잔여 위험: 고유명사형
실적(수치 아닌 것)의 대조 누락, 실물 데이터로 추출 규칙을 보강한다.

## 4. 파싱 품질 — 전 영역의 상류

- 어떤 후보도 한국어 행정 문서 공개 벤치마크가 없다: 실물 30~50p 없이 확정 금지.
- 하네스는 준비 완료(TASK-04): 명령 한 줄, 재현 가능 지표. 표본 수령(#4)이 유일한 대기.
- W1 관찰: MinerU는 특정 폰트(CID)에서 `-m ocr` 필요, Docling은 실행 간 표 탐지
  변동(3회 중 1회 누락), 실물 판정 시 파서당 3회 이상 실행으로 안정성도 지표화.
- HWP/HWPX 비율(#1) 미확인: HWP 직접 파싱 경로가 필요하면 W3 일정에 추가된다.

## 5. aarch64 + sm_121 빌드 이슈 (실측으로 대부분 해소)

W1 실측: torch 2.13.0·docling·mineru·llamafactory·sentence-transformers 전부
사전 빌드 휠로 설치, 소스 빌드 0건. LoRA·대조학습 역전파 GPU 실행 확인
(ADR-0001). 현황: Spark 는 쓰지 않는다. 젯슨 토르(aarch64 + Blackwell)에서는 NVIDIA 젯슨용 vLLM
이미지로 서빙하며, 양자화 판은 Qwen3.8 전용 빌드가 필요했다(ADR-0023). 27B QLoRA 는 DGX 에서 실측 예정.

## 6. 라이선스 — 관리 중

- 베이스 모델: 전 후보 MIT/Apache 2.0: `ZZAIMY-*` 명명 가능. 예외: Kanana 채택 시
  명명 제약(#5), 채택 전 사용자 결정 필요.
- 도구: MinerU 2026-04 Apache 2.0 전환 확인(리서치). PyMuPDF 계열(AGPL)은 채택 금지 유지.
- 모델 카드에 라이선스 고지 필수 (브리프 7.5).

## 8. 네트워크 노출 (실측 사고 사례 — 2026-09-01)

Spark는 공인 IP다. vLLM 스모크 최초 기동 시 `-p 8000:8000`이 인증 없는 LLM
엔드포인트를 인터넷에 노출시켰고, 외부 접속이 실제로 성공하는 것을 확인 후 즉시
차단했다(127.0.0.1 바인딩 재기동). 규칙으로 승격한다:

- 모든 서비스 포트는 기본 127.0.0.1 바인딩. 원격 사용은 SSH 터널로.
- 외부 개방이 불가피하면 인증(API key) + 방화벽 허용 IP를 함께 건다.
- 대시보드(ADR-0002) 배포 시 이 규칙이 1차 점검 항목이다, 실문서가 지나가는
  화면이므로 노출 시 개인정보 사고가 된다.

## 9. 데이터 유출 방지 (운영 규율)

- 실문서·파싱 결과는 `/data/` 밖으로 나가지 않는다. git 커밋 차단(.gitignore) +
  `git add` 전 status 확인 규율. 리포트·로그에 원문 텍스트를 싣지 않는다
  (bake-off 리포트·PII 감사 로그가 이미 이 규칙으로 구현됨).
- 외부 API로 문서 전송 금지: 전 구성요소 온프레미스 (브리프 4장). 예외는 공개 수집 문서의 판독에
  한해 상용 API 를 쓰는 용도(ADR-0024, 제안)뿐이며 외부 참조 관문(ADR-0008·0019)을 거친다.
- 학생 노출은 비식별화 통과본만 (#15 답변 반영).

## 10. 운영에서 새로 드러난 위험 (2026-09-20~22)

- 측정이 서빙 장비 설정 없이 뜨면 CPU 베이스로 조용히 물러나 거짓 수치가 나온다 → 보고서에 리랭커
  출처·폴백 수를 적고 서빙 장비가 아니면 '운영 구성'이라 부르지 않는다(K-48).
- 젯슨 통합 메모리: 페이지 캐시가 CUDA 메모리를 막고(root 로 비움), 컨테이너 강제 종료가 GPU 메모리를
  붙잡는다(정상 종료 대기, 126). 서빙 교체는 스크립트로만.
- 색인과 질의 임베딩 모델이 어긋나면 검색이 조용히 망가진다 → 서빙 점검(110)이 짝을 확인(ADR-0021).
- 계획 밖 모델을 편의로 끼우면 없는 문장을 지어낸다(gemma4 실측) → 계획 4종만, 채택은 대결 수치로.
- 운영 VM CPU 포화(09-08, 6시간 응답 지연) → 무거운 작업은 코어 절반·낮은 우선순위·순차.
