# 위험 관리

> 착수 단계(2026-09-01)에 쓴 설계 문서에 현재 상태를 더했다. 운영하면서 드러난 위험은 10절에 모았다.

## 1. 개인정보 처리

- 현재 원칙: 내부 문서의 일괄 마스킹은 관리자 설정(기본 꺼짐)이고, 학습 사본만 개인정보 검수와 품질 관문을 거쳐
  반출한다(ADR-0044). 착수 단계에 정한 「색인 전 개인정보 스크리닝」과 `RawDocument`/`MaskedDocument` 강제는 이 결정으로
  바뀌었다.
- 구현: Presidio와 한국형 인식기(주민등록번호, 전화번호, 계좌번호, 사업자등록번호, 학번·수험번호, 생년월일 등),
  원문을 남기지 않는 감사 로그. 학번 형식과 성명 처리 기준은 실물 표본으로 보강한다.
- 기관 개인정보보호 부서의 검토는 외부 결재라 프로젝트가 통제할 수 없다. 실물 문서 사용의 전제이므로 일찍 요청하고,
  기다리는 동안에는 합성 데이터로 파이프라인을 완성해 둔다.

## 2. 접근 권한

- 열람 등급 필터는 검색 단계에 있다(절대 규칙 4). 필드와 필터 경로가 구현돼 있고, 부서·역할별 검색 범위는
  RAG 공간으로 정한다(ADR-0053).
- 남은 위험: 학교 기준의 등급 값 체계가 아직 확정되지 않았다. 값 교체에는 재색인이 필요 없지만, 분류 기준 없이 적재하면
  기본값이 보수적으로 잡혀 검색 결과가 비게 된다. 그때까지는 전체 공개·부서 제한·담당자 한정 세 값으로 운영한다.

## 3. 수치 환각

근거 없는 수치가 계획서에 들어가면 허위 기재가 되고, 사업 취소·환수·제재 사유가 된다.

두 겹으로 막는다. 첫째, 파이프라인 구조다(수치 대조 검증기, 근거 없는 값 가림, 예산 계산에 LLM 미사용). 둘째, 학습 데이터
정제다(출력 수치가 입력 근거에 없으면 그 쌍을 버린다, [모델 개발 계획](model-plan.md) 2절). 정제기와 검증기는 같은 코드를
써서 기준이 어긋나지 않는다. 남은 위험은 수치가 아닌 고유명사형 실적의 대조 누락이며, 실물 데이터로 추출 규칙을 보강한다.

## 4. 파싱 품질

- 한국어 행정 문서에 대한 공개 벤치마크가 없어, 파서는 실물 표본으로 비교해 정했다(ADR-0007·0050·0051).
- 비교 하네스는 명령 한 줄로 재현된다. 같은 파서를 여러 번 돌려 결과의 안정성도 지표로 본다.
- 특정 글꼴(CID)이 든 PDF는 MinerU의 OCR 모드가 필요하다. 한글 문서는 kordoc과 자체 변환기로 직접 읽는다.

## 5. aarch64 빌드

학습·파싱 패키지는 모두 aarch64용 사전 빌드 휠로 설치되고, LoRA·대조학습의 GPU 역전파를 확인했다(ADR-0001).
젯슨 토르(aarch64, Blackwell)에서는 NVIDIA 젯슨용 vLLM 이미지로 서빙하며, Qwen3.8 양자화 판은 전용 빌드가 필요하다
(ADR-0023). 27B LoRA 학습은 DGX에서 측정한다.

## 6. 라이선스

- 베이스 모델은 모두 MIT 또는 Apache 2.0이라 `ZZAIMY-*` 이름을 붙일 수 있다. 다른 베이스를 검토할 때는 이름 제약을
  따로 확인한다.
- 도구: MinerU는 채택 전에 라이선스를 확인했다. AGPL인 PyMuPDF 계열은 쓰지 않는다.
- 모델 카드에 라이선스를 고지한다.

## 7. 프로젝트 고유 위험

| 위험 | 상태 | 대응 |
|---|---|---|
| 개발 인력이 적음 | 확정 | 범위를 캡스톤 실행계획의 축소안으로 유지 |
| 검수 인력 투입 시점 | 미정 | 실물 문서와 함께 확정. 늦어지면 평가셋 규모를 줄인다 |
| 프로젝트 종료 뒤 유지보수 공백 | 대응 중 | ADR, 모델 카드, 재현 스크립트, 인수인계 문서를 계속 쌓고, 배포·서빙·이관을 스크립트 한 줄로 만든다 |
| 발표 시연 실패 | 대응됨 | 플랫폼이 운영 서버에서 상시 가동되고, 공개 문서로도 시연할 수 있다 |
| 생성 모델의 기관 수용성 | 해소 | Writer 베이스를 Qwen3.8-27B로 확정 |

## 8. 네트워크 노출

모델 서버의 포트를 그대로 열면 인증 없는 LLM 엔드포인트가 외부에 노출된다. 초기 검증 장비에서 이를 확인한 뒤
다음을 규칙으로 정했다.

- 모든 서비스 포트는 기본적으로 127.0.0.1에 묶는다. 원격 사용은 SSH 터널로 한다.
- 외부 개방이 불가피하면 인증과 방화벽 허용 목록을 함께 건다. 웹 플랫폼은 비밀번호와 TLS 인증서가 모두 있어야
  127.0.0.1 밖으로 열린다.
- 서빙 장비의 포트는 학과 내부망에서만 쓴다.

## 9. 데이터 유출 방지

- 실문서와 처리 결과는 데이터 폴더 밖으로 나가지 않는다. `.gitignore`로 커밋을 막고, 보고서와 로그에 원문을 싣지 않는다.
- 외부 AI API로 문서를 보내지 않는다(ADR-0043). 밖으로 나가는 것은 외부 검색 모드에서 담당자가 쓴 질문 글뿐이다(ADR-0038).
- 학생에게는 비식별화를 통과한 자료와 학생 공개로 지정한 규정만 보인다.

## 10. 운영에서 드러난 위험

- 측정이 서빙 장비 설정 없이 실행되면 CPU 베이스 모델로 대신 돌아 운영과 다른 수치가 나온다. 보고서에 리랭커 출처와
  대체 실행 수를 적고, 서빙 장비에서 잰 것만 「운영 구성」이라 부른다.
- 젯슨 통합 메모리에서는 페이지 캐시가 CUDA 메모리를 막고, 컨테이너 강제 종료가 GPU 메모리를 붙잡는다. 서빙 교체는
  정상 종료를 기다리는 스크립트로만 한다.
- 색인과 질의 임베딩 모델이 어긋나면 검색이 조용히 망가진다. 서빙 점검(`scripts/110_serving_check.sh`)이 짝을 확인한다(ADR-0021).
- 계획에 없는 모델은 측정에서 근거 없는 문장을 만들어 냈다. 계획한 4종만 쓰고, 새 후보는 같은 입력의 비교 수치로만 채택한다.
- 운영 서버의 CPU가 무거운 작업에 포화되면 화면 응답이 늦어진다. 무거운 작업은 코어 절반, 낮은 우선순위, 순차 실행으로 돌린다.
