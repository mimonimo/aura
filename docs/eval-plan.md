# 평가 계획

> 착수 단계(2026-09-01)에 쓴 설계 문서다. 근거는 [평가 조사](../research/01-L-evaluation.md).
> 원칙: 베이스라인 없이 개선을 주장하지 않는다(브리프 5.5).

현재 상태: 검색은 합성 질의 1,026건으로 초기 기준선과 운영 구성 측정(R@1 0.763)이 있고, 검색 학습본 채택은 이
하네스로 판정했다. 사람이 작성한 골드셋과 생성·추출 평가셋은 실문서 처리와 함께 만든다. 측정 도구는
`scripts/53_eval_retrieval.py`(검색), `scripts/105_rerank_floor.py`(근거 하한), `scripts/106_rerank_holdout_check.py`
(홀드아웃 검증)이고, 결과의 원본은 데이터 폴더의 `platform/eval/`에 남는다.
그 뒤 사업 문서 검색은 자동으로 뽑은 절·관계 질문으로 잰다(`scripts/173_rag_probe.py`·`184_graph_relation_probe.py`,
그래프 단계의 값은 `188_graphrag_vs_fulltext.py`, 노트 「GraphRAG 대 풀텍스트 RAG 비교」). 생성 모델 교체·SFT 판은 같은 시험으로
운영 모델과 견주어 정하고(ADR-0069, `scripts/195`·`202`·`210`~`212`, 결과는 품질·성능 화면 「모델 비교」), Writer SFT v1 은 이 비교로
채택하지 않았다.

## 1. 평가셋 구축 (W3~W5)

### 1.1 검색(IR) 평가셋

| 구성 | 규모 | 출처 |
|---|---|---|
| 골드셋 (사람 작성) | 200~500 문항 | 담당자·검수자가 실무 질의를 직접 작성하고 정답 조각을 원문에서 지정 |
| 합성셋 (자동 생성) | 수천 문항 | 왕복 검증을 통과한 합성 질의에서 표본을 뽑아 사람이 검수 |

- 분리 규칙: 문서 단위. 같은 문서에서 나온 질의는 학습과 평가 양쪽에 들어가지 않는다.
- 정답 기준: 질의당 정답 조각이 1개 이상이다. 부분 정답(같은 문서의 인접 조각)은 검수 때 등급을 매기고
  (2=정답, 1=부분, 0=오답) nDCG 계산에 그대로 쓴다.
- 검수 절차: 검수자 2인이 따로 판정하고, 엇갈린 항목만 조정한다. 판정 일치율(Cohen's κ)을 평가셋 카드에 기록한다.

### 1.2 생성 평가셋 (Writer)

- 홀드아웃: 과거 계획서 가운데 사업 단위로 2~3건을 학습에서 완전히 뺀다.
- 홀드아웃의 각 절에 역구성(retro-fill) 입력을 만들어 두고, 생성 결과를 실제 제출본과 비교한다.
- 사람 평가 문항: 문체 적합성과 논리 완결성을 5점 척도로, 어느 모델의 결과인지 가린 채 평가한다.

### 1.3 추출 평가셋 (Extract)

- 사람 검수를 마친 실적 카드의 20%를 홀드아웃으로 둔다(검수 때 미리 분리).
- 필드별 정답은 검수 확정값이다.

## 2. 지표 정의

| 대상 | 지표 | 도구 | 합격 기준 |
|---|---|---|---|
| 검색 (Embed) | Recall@1/5/20, MRR@10, nDCG@10 | 자체 하네스 | 베이스 대비 유의미한 개선 (수치 목표는 베이스라인 확정 후 설정) |
| 리랭킹 (Rerank) | 재정렬 후 Recall@5/10, nDCG@10 | 자체 하네스 | 위와 같음 |
| 생성 (Writer) | 수치 환각률 | 결정론적 대조기 (수치 대조 검증기와 같은 코드) | 0 수렴 필수 |
| 생성 (Writer) | 평가지표(배점) 반영률 | 배점 검증기 로직 | 베이스 대비 |
| 생성 (Writer) | 문체·논리 | 사람 블라인드 5점 + 로컬 LLM 판정 보조 | 사람 평가가 주, LLM 판정은 보조 |
| 생성 (Writer) | 빈칸 규약 준수율 | 근거 없는 입력에서 지어내지 않는지 | 감시 지표 |
| 추출 (Extract) | 필드별 정확도/F1, 출처 오프셋 정확도 | 자체 하네스 | 교사 모델 대비 열화 한도 내 |
| 추출 (Extract) | 처리량 배수 | 서빙 장비(토르) 실측 | 교사 대비 배수 보고 |

LLM 판정은 온프레미스 제약에 따라 로컬 모델로만 돌린다. 보조 지표이며, 논문의 주장은 결정론 지표와
사람 평가에 근거한다.

## 3. 베이스라인 측정 절차 (W6~W8)

1. 파일럿 코퍼스 인덱싱 완료 상태에서 시작한다.
2. 베이스 모델을 그대로 측정한다. 임베딩은 KURE-v1(비교군 BGE-M3), 리랭커는 bge-reranker-v2-m3,
   Writer·Extract는 베이스의 제로샷이다.
3. 고정 요소를 기록한다: 인덱스 스냅샷 해시, 청킹 파라미터, 검색 설정(k, RRF 가중),
   프롬프트 버전, 시드, 패키지 버전(`configs/*-env.txt`).
4. 결과는 기계 산출물(`platform/eval/retrieval-latest.json`)과 저장소 사본([검색 미니 베이스라인](retrieval-baseline-mini.md) 등,
   `--report`로만 갱신)으로 확정하고, 이후 모든 개선폭 주장의 기준으로 삼는다.
5. 재현: `scripts/53_eval_retrieval.py` 한 줄로 전체를 다시 돌린다. 반드시 `.env.local`을 읽고 실행한다. 서빙 장비 주소가
   비면 CPU 베이스 모델로 대신 돌아 수치가 운영과 달라진다. 보고서에는 리랭커 출처·응답·대체 실행 수를 적고, 후보 수는
   운영과 같은 20개로 한다.

## 4. 반복 규율

- 모델 판마다 같은 평가셋과 같은 하네스로 측정하고 보고서를 쌓는다.
- 평가셋은 베이스라인 확정 후 동결한다. 고쳐야 하면 버전을 올리고 베이스라인을 다시 잰다. 일부만 고친 평가셋을
  옛 베이스라인과 비교하지 않는다.
- 홀드아웃 오염 점검: 학습 시작 전에 학습 데이터 스냅샷과 평가셋의 문서 ID 교집합이 0인지 자동으로 검사한다.
