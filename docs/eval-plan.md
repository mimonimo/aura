# 평가 계획

> 상태: **작성됨 — 승인 대기** (P1 산출물, 브리프 9장 3번)
> 근거: `research/01-L-evaluation.md`. 축 B 성과 입증과 논문 실험 섹션의 골격.
> 원칙: 베이스라인 없이 개선을 주장할 수 없다 (브리프 5.5). 평가셋이 먼저다.

## 1. 평가셋 구축 (W3~W5, 학생 검수 투입 구간)

### 1.1 검색(IR) 평가셋

| 구성 | 규모 | 출처 |
|---|---|---|
| 골드셋 (사람 작성) | 200~500 문항 | 담당자·학생이 실무 질의를 직접 작성, 정답 청크를 원문에서 지정 |
| 합성셋 (자동 생성) | 수천 문항 | 합성 질의 중 라운드트립 통과분에서 표본 추출 → 학생 검수 |

- **분리 규칙: 문서 단위.** 같은 문서에서 나온 질의가 학습·평가 양쪽에 못 간다.
- 정답 기준: 질의당 정답 청크 1개 이상, 부분 정답(같은 문서 인접 청크)은
  검수 시 등급 부여(2=정답, 1=부분, 0=오답) — nDCG 계산에 그대로 쓴다.
- 검수 절차: 학생 2인 독립 판정 → 불일치 항목만 중급자 조정. 판정 일치율(Cohen's κ)을
  평가셋 카드에 기록한다.

### 1.2 생성 평가셋 (Writer)

- 홀드아웃: 과거 계획서 중 **사업 단위로 2~3건**을 학습에서 완전 제외.
- 각 홀드아웃 섹션에 retro-fill 입력을 구성해 두고, 생성 결과를 실제 제출본과 비교.
- 사람 평가 문항: 문체 적합성·논리 완결성 5점 척도, 블라인드(베이스 vs LoRA 무표기).

### 1.3 추출 평가셋 (Extract)

- 사람 검수 완료 실적 카드 중 20%를 홀드아웃 (검수 시점에 미리 분리).
- 필드별 정답 = 검수 확정값.

## 2. 지표 정의

| 대상 | 지표 | 도구 | 합격 기준 |
|---|---|---|---|
| 검색 (Embed) | Recall@1/5/20, MRR@10, nDCG@10 | pytrec_eval/ranx 자체 하네스 | 베이스 대비 유의미 개선 (수치 목표는 베이스라인 확정 후 설정) |
| 리랭킹 (Rerank) | 상위 50 재정렬 후 Recall@5/10, nDCG@10 | 동일 | 동일 |
| 생성 (Writer) | **수치 환각률** | 결정론적 대조기 (검증기 1종과 코드 공유) | **0 수렴 필수** |
| 생성 (Writer) | 평가지표(배점) 반영률 | 배점 검증기 로직 | 베이스 대비 |
| 생성 (Writer) | 문체·논리 | 사람 블라인드 5점 + DeepEval 로컬 저지 보조 | 사람 평가가 주, 저지는 보조 |
| 생성 (Writer) | 빈칸 규약 준수율 | 근거 없는 입력에서 지어내지 않는지 | 감시 지표 |
| 추출 (Extract) | 필드별 정확도/F1, 출처 오프셋 정확도 | 자체 하네스 | 교사 모델 대비 열화 한도 내 |
| 추출 (Extract) | 처리량 배수 | Spark 1대 실측 | 교사 대비 배수 보고 |

LLM 저지(DeepEval)는 **로컬 모델**로만 돌린다 — 온프레미스 제약.
저지 판단은 보조 지표이며 논문 주장의 근거로는 결정론 지표·사람 평가를 쓴다.

## 3. 베이스라인 측정 절차 (W6~W8, ★게이트)

1. 파일럿 코퍼스 인덱싱 완료 상태에서 시작한다.
2. 베이스 모델 그대로 측정: KURE-v1, BGE-M3, (관찰군 Qwen3-Embedding-0.6B) /
   bge-reranker-v2-m3 / Writer·Extract 베이스의 제로샷.
3. 고정 요소를 기록한다: 인덱스 스냅샷 해시, 청킹 파라미터, 검색 설정(k, RRF 가중),
   프롬프트 버전, 시드, 패키지 버전(`configs/*-env.txt`).
4. 결과는 `docs/baseline-report.md`로 확정 — **이후 모든 개선폭 주장의 유일한 기준.**
5. 재현 절차: 명령 한 줄(`scripts/30_eval_*.py` 예정)로 전체 재실행 가능해야 한다.

## 4. 반복 규율

- 모델 v0.x마다 같은 평가셋·같은 하네스로 측정하고 리포트를 누적한다.
- 평가셋은 베이스라인 확정 후 동결한다. 수정이 불가피하면 버전을 올리고
  베이스라인을 재측정한다 (부분 수정 후 옛 베이스라인과 비교하는 것을 금지).
- 홀드아웃 오염 점검: 학습 데이터 스냅샷과 평가셋의 문서 ID 교집합이 0임을
  학습 시작 전 자동 검사한다.
