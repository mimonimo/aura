# G. 하이브리드 검색 / 한국어 형태소 분석

> 조사일: 2026-08-15
> 전제: 행정 문서는 정확한 용어 매칭("성과관리 지표", "산학협력 선도전문대학")이 중요해 BM25 비중이 높을 것으로 예상(브리프 8.1-G). 사업명·지표명 같은 고유 복합명사가 많아 형태소 분석 품질과 **사용자 사전**이 관건.

**Kiwi 채택 시 필수 작업**: 국고사업 도메인 사용자 사전 구축 — 사업명 약칭(예: "LINC", "RISE", "HiVE"), 기관 고유 명칭, 지표명을 고유명사로 등록. 이 사전 품질이 BM25 검색 품질에 직결. 파싱 단계(A)에서 추출한 고빈도 미등록어를 반자동으로 사전에 편입하는 루프를 Phase 2에 포함할 것.

## 융합 전략 (Phase 1 설계 반영)

- 기본: dense(ZZAIMY-Embed) + BM25(Kiwi 토큰) **RRF 융합** → 상위 50 → ZZAIMY-Rerank → 상위 5~10.
- 행정 용어 정확 매칭 요구가 높으므로 BM25 단독 상위 결과가 dense에 밀리지 않도록 융합 가중치를 자체 평가셋으로 튜닝(Phase 3).
- 메타데이터 필터(연도·사업유형·문서종류·열람등급)는 융합 이전 단계에서 강제 — 검색 후 필터링 금지(권한 설계 원칙, risks 연동).

## 위험
1. Kiwi는 사실상 개인 메인테이너 프로젝트(bab2min) — 버스 팩터. 완화: 분석기 인터페이스를 추상화해 교체 가능하게 설계. 현 시점 대안 부재는 사실이므로 수용할 리스크.
2. LGPL v3(Kiwi) — 동적 링크 사용은 무방하나 기관 라이선스 목록에 기록 필요.
3. 표 안 숫자·단위가 많은 문서 특성상 BM25 토큰화 규칙(숫자·단위 처리)을 커스터마이징해야 할 수 있음 — bake-off 시 관찰.
