# 사용자 확인 필요 사항 (누적)

> Phase 0 진행 중 발견된, 사용자만 답할 수 있는 질문들. Phase 0 보고 시 일괄 제시.

## A. 문서 파싱 관련

1. **HWP/HWPX 문서 비율** — 보유 문서와 신규 공고문 중 HWP/HWPX 원본이 있는가? 한국 공공기관 특성상 공고문이 HWP로 배포되는 경우가 많다. HWP가 섞여 있다면 PDF 파싱과 별도의 처리 경로(HWPX 직접 파싱)가 필요하다.
2. **스캔본 비율과 품질** — 수만 장 중 스캔 PDF(이미지)와 born-digital PDF(텍스트 레이어 존재)의 대략적 비율은? 스캔본의 해상도·기울어짐·도장/필기 오염 수준은?
3. **표의 형태** — 결과보고서의 실적 표가 주로 ①워드/한글에서 생성된 선명한 표인가 ②스캔된 표인가 ③엑셀 첨부인가?
4. **문서 실물 표본 제공 가능 시점** — bake-off용으로 결과보고서 표본(민감정보 마스킹 전이라도 개발장비 내 처리 전제) 30~50페이지를 언제 받을 수 있는가?

## K. 생성 모델 관련

5. **명명 vs 한국어 성능 트레이드오프** — Writer 베이스로 Kanana-2-30B-A3B(한국어 최상위권, MoE)가 기술적으로 유력하지만 라이선스상 파생 모델명에 "Kanana" 접두사가 강제된다(`ZZAIMY-Writer` 불가, `Kanana-ZZAIMY-Writer`식만 가능). Phase 3 비교에서 Qwen 계열과의 성능 격차가 크게 나올 경우, 명명을 포기하고 성능을 취할 것인가? (성과 보고 시 "ZZAIMY" 브랜드 일관성에 영향)
6. **중국계 모델(Qwen) 채택에 대한 기관 수용성** — 온프레미스라 데이터 유출 위험은 없으나, 국고사업 성과 보고 맥락에서 중국 기업 베이스 모델 사용에 대한 기관/평가 측의 거부감이 있는가? 있다면 국내 모델(Mi:dm, A.X) 우선 검토로 방향 조정.

## G/H. 검색 인프라 관련

7. **문서 열람 등급 체계** — 문서별 접근 권한 등급(예: 전체 공개/부서 한정/담당자 한정)이 현재 존재하는가? 없다면 인덱싱 전에 등급 분류 기준을 정해야 한다(사후 부여는 전체 재인덱싱 의미 — 브리프 9장).
8. **운영 인력의 기존 기술 경험** — PostgreSQL, Docker, OpenSearch/Elasticsearch 등 운영 경험이 있는 인력이 있는가? 벡터DB 선택(Qdrant 2-스토어 vs pgvector 1-스토어)의 결정 요인.

## M. 개인정보 관련

9. **학번 체계** — 본교 학번 형식(자릿수·연도 접두 등)은? PII 탐지 규칙에 필요.
10. **마스킹 정책 합의** — 문서 내 교직원 성명은 어떻게 처리하나? (계획서에는 "담당 부서·직책"이 필요하지만 개인 성명·연락처는 대개 불필요 — 성명→직책 치환, 연락처→제거를 기본 정책으로 제안) 학생 정보(성명·학번)는 전부 마스킹으로 제안.
11. **개인정보 처리 근거 확인** — 내부 문서의 AI 시스템 처리에 대해 기관 개인정보보호 담당 부서의 검토·승인 절차가 필요한가? 필요하다면 언제 착수하나?

## 공고·계획서 구조 관련 (Phase 1 설계 직결)

12. **공고 양식의 다양성** — 주로 대응하는 부처(교육부/고용부/중기부 등)와 사업 유형은? 부처별 공고 양식·평가표 구조가 얼마나 다른가? (공고 파싱 스키마의 일반화 수준 결정)
13. **계획서 양식의 일관성** — 과거 제출 계획서 20~30건의 목차 구조가 사업 간에 얼마나 유사한가? (Writer 학습 데이터의 섹션 매핑 난이도 결정)
14. **선정/미선정 라벨** — 과거 계획서에 선정 여부 기록이 남아 있는가? (학습 데이터 가중치·평가셋 설계에 활용 가능)
