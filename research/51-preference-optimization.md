# 51. 배포 전 품질 극대화 — 선호 최적화(DPO)와 학생 검수 체계

> 작성일: 2026-08-23 (사용자 지시로 추가된 트랙) · 같은 날 학술 계보 딥리서치로 증보 (전 문헌 웹 검증, 검증일 2026-08-23)
> 배경: "사용자가 사용하는 시점 이전에 최대한 품질을 높여야 하며, 학생 인력이 많으므로 이를 활용할 수 있어야 한다."
> 관련 문서: 01-F(파인튜닝), 01-L(평가), 50(모델 트랙) — 본 문서는 50장 7.3 Writer의 후반 이터레이션을 구체화한다.

## 결론 요약

- InstructGPT(GPT-3.5)식 "N개 후보 → 사람 선택 → 강화"의 **직관은 채택**하되, 구현은 보상모델+PPO가 아닌 **DPO 계열 직접 선호 최적화**로 한다. 이미 선정한 LLaMA-Factory가 DPO/KTO/ORPO/SimPO를 QLoRA와 조합해 기본 지원 — 기존 학습 스택에 설정 파일 하나로 얹힌다.
- 이 선택은 학계·산업 표준과 일치한다: Llama 3가 같은 이유(안정성·확장성)로 PPO 대신 DPO를 택했고(§2.5), 오프라인 DPO의 상한 한계는 **반복(iterative) 구조**로 보완한다(§10).
- 품질 확보는 2단: **배포 전** = 학생 검수로 SFT 데이터 증량 + Best-of-N 선호 학습 / **배포 후** = 초안-수정본 로깅으로 계속 개선.
- 학생 인력의 1순위 투입처는 선호 라벨링이 아니라 **정답이 있는 대조 검수**다. 기존 계획의 실질 병목("사람 검수 수백 건")을 수천 건으로 푸는 것이 배포 전 품질의 가장 큰 지렛대.

## 1. 선호 학습의 계보 — 고전에서 현대까지

> 2026-08-23 웹 딥리서치. 전 항목 arXiv 원문·학회 프로시딩·공식 블로그에서 연도·게재처 확인.

### 1.1 고전 — RLHF의 성립 (2015~2022)

| 연도 | 문헌 | 기여 |
|---|---|---|
| 2015 | [TRPO](https://arxiv.org/abs/1502.05477) (Schulman et al., ICML 2015) | KL 신뢰영역 안에서 정책을 갱신해 단조 성능 개선을 보장하는 정책 최적화 |
| 2017 | [PPO](https://arxiv.org/abs/1707.06347) (Schulman et al., OpenAI) | clipped objective로 TRPO를 단순화 — 이후 RLHF의 표준 RL 엔진 |
| 2017 | [Christiano et al.](https://arxiv.org/abs/1706.03741) (OpenAI+DeepMind, NeurIPS 2017) | **RLHF의 원형** — 명시적 보상함수 없이 인간의 쌍 비교만으로 보상모델을 학습해 RL 구동 |
| 2019 | [Ziegler et al.](https://arxiv.org/abs/1909.08593) (OpenAI) | GPT-2에 RLHF 최초 적용 (감성 이어쓰기·요약) |
| 2020 | [Stiennon et al.](https://arxiv.org/abs/2009.01325) (OpenAI, NeurIPS 2020) | 요약 과제에서 RLHF가 참조 요약·ROUGE 최적화를 능가함을 입증 — InstructGPT의 직계 전신 |
| 2022 | [InstructGPT](https://arxiv.org/abs/2203.02155) (Ouyang et al., OpenAI, NeurIPS 2022) | **SFT → 보상모델 → PPO** 3단 파이프라인 확립. 라벨러 약 40명, 프롬프트 규모 SFT 13k·RM 33k·PPO 31k. 1.3B 모델이 인간 평가에서 175B GPT-3 능가 |
| 2022 | [Constitutional AI / RLAIF](https://arxiv.org/abs/2212.08073) (Anthropic) | 원칙 목록 기반 AI 자기비판 + **AI 피드백 라벨(RLAIF)**로 인간 라벨러 대체 |

### 1.2 고전 방식의 검증된 문제점

PPO 기반 RLHF의 한계는 일화가 아니라 문헌으로 정량화되어 있다:

- **보상 과최적화(reward hacking)** — 프록시 보상모델을 세게 최적화할수록 실제 품질(gold 보상)이 꺾이는 Goodhart 현상의 스케일링 법칙: [Gao, Schulman &amp; Hilton, ICML 2023](https://arxiv.org/abs/2210.10760).
- **학습 불안정성** — DPO 논문 스스로 "RLHF is a complex and often unstable procedure"로 요약; PPO 안정화 조건을 파헤친 [Secrets of RLHF Part I](https://arxiv.org/abs/2307.04964) (Fudan, 2023)은 "안정적 학습은 여전히 퍼즐"이라 표현.
- **메모리 부담** — [RRHF](https://arxiv.org/abs/2304.05302) (NeurIPS 2023): "PPO는 학습 중 모델 4벌(정책·가치·보상·참조) 상주"; [Efficient RLHF](https://arxiv.org/abs/2309.00754) (Microsoft, 2023): "PPO는 SFT 대비 3배 이상의 메모리".

### 1.3 직접 선호 최적화의 등장 (2023~2024)

- **[DPO](https://arxiv.org/abs/2305.18290)** (Rafailov et al., Stanford — NeurIPS 2023 구두발표·Outstanding Main Track **Runner-up**): KL 제약 RLHF의 닫힌 해를 이용해 보상함수를 정책 자체로 재매개변수화("your language model is secretly a reward model"). 보상모델과 RL 루프가 통째로 사라지고, 선호쌍에 대한 단일 분류 손실만 남는다.
- 변형 계열:

| 기법 | 게재 | 차별점 |
|---|---|---|
| [IPO](https://arxiv.org/abs/2310.12036) (DeepMind) | AISTATS 2024 | DPO의 과최적화 발산을 이론적으로 교정 |
| [KTO](https://arxiv.org/abs/2402.01306) | ICML 2024 | 전망이론 기반 — **쌍 불필요**, 응답별 좋음/나쁨 이진 라벨로 학습 |
| [ORPO](https://aclanthology.org/2024.emnlp-main.626/) (KAIST) | EMNLP 2024 | **참조 모델 불필요** — SFT와 선호 정렬을 단일 단계로 통합 |
| [SimPO](https://arxiv.org/abs/2405.14734) (Princeton) | NeurIPS 2024 | 길이 정규화된 참조-프리 보상 — 장황함 편향 완화 |

- **반복(iterative/online) DPO** — 오프라인 1회 학습의 한계를 "현재 모델로 새로 생성 → 판정 → 재학습" 반복으로 보완: [Xiong et al., ICML 2024](https://proceedings.mlr.press/v235/xiong24a.html)이 이론·실험으로, [Dong et al., TMLR 2024](https://arxiv.org/abs/2405.07863)가 실전 레시피로 오프라인 대비 우위를 보고.

### 1.4 검증 가능 보상의 시대 (2024~현재)

- **[GRPO](https://arxiv.org/abs/2402.03300)** (DeepSeekMath, 2024): PPO에서 **가치(critic) 모델을 제거**하고 같은 프롬프트의 응답 그룹 내 상대 점수로 어드밴티지를 추정 — 온라인 RL의 비용을 크게 낮춤.
- **[DeepSeek-R1](https://arxiv.org/abs/2501.12948)** (2025): GRPO + **규칙 기반 보상**(수학 정답 검증·코드 테스트)만으로 추론 능력 창발 — 신경망 보상모델을 배제해 reward hacking 회피.
- **[RLVR](https://arxiv.org/abs/2411.15124)** (Tülu 3, AI2, 2024): 용어를 정의한 논문. 보상모델을 **결정론적 검증 함수**로 대체 — 자동 채점 가능한 태스크(수학·지시 준수)에 적용.
- **분업 구도의 성립**: [2025 서베이(arXiv 2509.08827)](https://arxiv.org/abs/2509.08827)가 정리한 대로, **선호·문체 정렬 = RLHF/DPO 계열, 검증 가능한 추론 = RLVR/GRPO 계열**로 역할이 갈렸다. [Olmo 3](https://allenai.org/blog/olmo3) (AI2, 2025.11)의 공개 레시피 "SFT → DPO → RLVR"가 이 분업을 한 파이프라인 안에서 실증한다.

### 1.5 오픈웨이트 모델의 채택 현황 (기술 보고서 원문 확인)

| 모델 | 정렬 기법 | 비고 |
|---|---|---|
| [Llama 3/3.1](https://arxiv.org/abs/2407.21783) (Meta 2024) | SFT + 거절 샘플링 + **DPO** | 보고서 원문: "PPO 같은 복잡한 RL 대신 안정적이고 확장 쉬운 단순 절차를 택했다" |
| [Qwen2](https://arxiv.org/abs/2407.10671) → [Qwen2.5](https://arxiv.org/abs/2412.15115) → [Qwen3](https://arxiv.org/abs/2505.09388) | 온라인 DPO → DPO+GRPO → **GRPO 중심**(DPO 언급 없음) | 세대별로 오프라인→온라인 전환이 뚜렷 — 우리 Writer 베이스(Qwen3.5)의 직계 흐름 |
| [Zephyr-7B](https://arxiv.org/abs/2310.16944) (HF 2023) | dDPO (AI 피드백 + DPO) | DPO 실용화의 기폭제 |
| [Tülu 2](https://arxiv.org/abs/2311.10702)·[Tülu 3](https://arxiv.org/abs/2411.15124) (AI2) | DPO / SFT→DPO→RLVR | 70B DPO 최초 안정 시연 |
| [EXAONE 3.5](https://arxiv.org/abs/2412.04862) → [4.0](https://arxiv.org/html/2507.11407v2) (LG) | **DPO+SimPO** → SimPER+추론 RL(AGAPO) | 국내 대표 모델도 직접 선호 최적화 계열 |
| [Kanana](https://arxiv.org/html/2502.18934v3) (Kakao 2025) | offline DPO → **online DPO** 반복 | 우리가 취할 반복 구조의 국내 실증 |

프레임워크: [LLaMA-Factory](https://llamafactory.readthedocs.io/en/latest/advanced/trainers.html)(DPO·KTO·ORPO·SimPO), TRL, Unsloth, Axolotl 모두 기본 지원 — 채택 리스크 낮음.

### 1.6 온라인 vs 오프라인 — 정직한 성능 비교

반대 증거도 기록해 둔다:

- [Xu et al., ICML 2024](https://arxiv.org/abs/2404.10719) ("Is DPO Superior to PPO?"): 제목과 반대로, **잘 튜닝된 PPO가 전 실험에서 DPO 이상** — 단 대배치·어드밴티지 정규화·세심한 튜닝이 전제. DPO는 분포 이동(학습 데이터 밖 입력)에 취약.
- [Tang et al., DeepMind 2024](https://arxiv.org/abs/2405.08448): 온라인 우위의 원인은 데이터 품질이 아니라 **온-폴리시 샘플링 그 자체**.

즉 "이론 상한은 온라인이 높다"는 것은 실증된 사실이다. 문제는 그 상한에 도달하는 비용이며, Llama 3조차 그 비용 대신 DPO를 택했다. 소규모 실무 기준으로는 [~2,000 선호쌍 + 3 에포크로 유의미한 개선](https://www.philschmid.de/rl-with-llms-in-2025-dpo)이 보고되어 있어, 우리 데이터 규모(수천 쌍)와 정합한다.

## 2. 왜 RLHF 원형(보상모델 + PPO)이 아닌가

| | RLHF(PPO) | DPO |
|---|---|---|
| 학습 중 상주 모델 | 4벌 (정책·가치·보상·참조) — RRHF 문헌 확인 | 2벌 (학습 대상 + 고정 참조, 참조는 그라디언트 없음) |
| 보상 모델 | 별도 학습 필요 (InstructGPT: 비교 33k) | 없음 — 손실함수에 흡수 |
| 학습 중 생성 | 매 스텝 온라인 샘플링 (느림) | 없음 — 미리 만든 쌍을 배치로 (오프라인, SFT처럼 돈다) |
| 안정성 | 하이퍼파라미터 민감, 과최적화·발산 위험 (§1.2) | SFT급 안정 |
| 짜이미 환경 | Spark 1대에 35B 4벌 불가, 라벨 수백 건짜리 보상모델은 과적합 | QLoRA로 가능, 비용 SFT와 같은 자릿수 |

| 항목 | InstructGPT 전제 | 짜이미 현실 |
|---|---|---|
| 비교 라벨 규모 | 전업 라벨러 약 40명, 수만 건 | 담당자 1~2명 + 학생 8명(2회 집중) |
| 학습 인프라 | 대규모 클러스터 | Spark 1대 (QLoRA) |

DPO 계열은 보상 모델과 RL 루프를 생략하고 (선택본 chosen, 탈락본 rejected) 쌍을 직접 손실함수에 넣는다: 참조 모델 대비 chosen의 확률을 올리고 rejected를 내리되, 항상 참조와의 비율로 계산해 SFT에서 배운 능력에서 폭주하듯 이탈하지 못하게 자동으로 묶인다(고전 RLHF의 KL 페널티가 손실함수 안에 내장된 구조).

## 3. 기법 선택지

| 기법 | 특징 | 짜이미 적합성 |
|---|---|---|
| **DPO** (1안) | 쌍(chosen/rejected) 필요, 참조 모델 1벌 상주 | 표준. LLaMA-Factory 성숙 지원 |
| KTO | 쌍 불필요 — 단건 좋다/나쁘다 라벨로 학습 | 검증기 통과/탈락 라벨을 그대로 쓸 수 있어 유력한 대안 |
| ORPO | 참조 모델 불필요, SFT와 동시 수행 | 메모리 이점. 데이터 적을 때 불안정 보고 있음 |
| SimPO | 참조-프리 + 길이 정규화 | 장황함 편향 완화 목적의 보조 후보 (EXAONE 3.5가 병용) |

**권장**: 1안 DPO, 쌍 구성이 어려운 검증기 단독 판정분은 KTO 병행 검토. P5에서 소규모 A/B로 확정(브리프 원칙 — 실측 전 확정 금지).

## 4. Best-of-N 선호 쌍 생성 — 3단 판정 파이프라인

```
테스트 입력(섹션 요구사항 + 인출 근거) → Writer가 후보 N=4 생성 (vLLM 배치, temperature 다변화)
 → ① 기계 판정 (비용 0, 전수)
      배점 반영 검증기(FR-10) · 수치 ⊆ 인출 근거(FR-09) · 분량 · 출처 주석 유효성
      → 명확한 열세 후보 탈락, 통과/탈락 자체가 KTO 라벨
 → ② 학생 판정 (동률 후보만)
      3인 중복 라벨 + 다수결. 골든 문항(정답 알려진 비교쌍) 무작위 삽입으로 라벨러 신뢰도 상시 측정
 → ③ 전문가 스팟 검수 (표본 10~20%)
      담당자가 다수결 결과 표본 검증 — 학생 판정의 계통 편향 탐지
 → (chosen, rejected) 쌍 축적 → DPO
```

- ①이 전수 필터라서 사람은 "검증기가 못 가르는 것"(문체·논리 동률)만 본다 — 전문가 시간은 기존 계획 그대로.
- 검증 가능한 기준을 보상으로 쓰는 구조(RLVR과 동형 — §1.4)는 이 도메인의 강점: 계획서 품질의 상당 부분이 기계 판정 가능(배점·수치·분량·출처).

## 5. 학생 인력 과업 설계

### 확정 편성 (2026-08-23 사용자 확정 — 질문 #16)

- **총 8명 = 중급 3명 + 초급 5명, 재원은 연구비.**
- 투입은 2회 집중: ① **초기 데이터 추출**(P2~P3 — 실적 카드·평가셋 검수) ② **평가**(P5 — 모델 평가·Best-of-N 선호 라벨링) 각 **1~2개월**.
- 숙련도별 역할 분담(안): **초급 5명** = 정답이 있는 대조 O/X 판정(아래 표) / **중급 3명** = 선호 판정 3인 다수결 패널, 골든 문항·가이드라인 관리 보조, 골드셋 질의 작성 보조. 중급 3명이 정확히 다수결 1패널 규모라 선호 판정 체계와 맞아떨어진다.

### 잘 맞는 과업 — 정답이 있는 대조 판정 (전문성 불요)

| 과업 | 내용 | 효과 |
|---|---|---|
| 실적 카드 검수 | 추출값 ↔ 결과보고서 원문 대조 O/X | Extract 정답 수백 → **수천 건** (FR-06 워크플로에 투입) |
| 수치·출처 대조 | 초안의 수치·출처 주석이 실제 근거 페이지에 있는지 확인 | 평가셋(수치 환각률) 골드 라벨 |
| 배점 반영 확인 | 배점 항목의 본문 반영 여부 O/X | 검증기(FR-10) 정답셋 |
| 골드셋 질의 보조 | 검색 평가용 질의 작성 보조(담당자 감수) | 골드셋 200~500 → 확장 |

### 위험한 과업 — 단독 수행 금지

- **문체·논리 우열의 단독 판정**: 전문성 판단이라 학생 간 일치도가 낮고, 노이즈 낀 선호 데이터는 없느니만 못하다. 반드시 3단 파이프라인(③ 전문가 스팟) 안에서만.

### 품질 관리 장치

- 골든 문항 정답률로 라벨러별 신뢰도 추적, 기준 미달 라벨 폐기.
- 라벨러 간 일치도(Krippendorff's α 등) 상시 측정 — 일치도가 낮은 과업 유형은 가이드라인 보강 또는 과업 회수.
- 투입 전 자격 테스트(연습 문항) + 과업별 작성 가이드 1쪽.

## 6. 배포 후 — 자연 발생 선호 데이터

담당자는 초안을 고쳐 최종본을 제출한다. **모델 초안 = rejected, 최종 제출본 = chosen**으로 자동 로깅하면 실사용이 곧 라벨링이다(별도 설문 불요). 이를 위해 **P4 UI에 초안-수정본 쌍 로깅을 처음부터 내장**해야 한다(FR-18 — 사후 추가 시 파일럿 기간 데이터 유실). 특히 학생 투입이 상시가 아닌 2회 집중이므로, 학생 부재 기간의 선호 데이터는 이 로깅이 유일한 공급원이다.

## 10. 결론 — 우리의 제약과 강점, 그리고 방향

### 제약 (무엇이 안 되는가)

1. **컴퓨트**: Spark 1대, 35B는 QLoRA만 가능. PPO/GRPO류 온라인 RL은 학습 중 상시 샘플링 + 다모델 상주를 요구(§1.2) — 물리적으로 불가. §1.6의 "잘 튜닝된 PPO 우위"는 대배치·튜닝 자원이 전제라 우리에게는 도달 불가능한 상한이다.
2. **데이터**: 선호쌍 수천 건 규모. 수백 건짜리 별도 보상모델은 과적합→reward hacking 경로(§1.2)라 만들지 않는 게 맞다.
3. **사람**: 학생 8명 × 2회 집중(각 1~2개월) — 상시 라벨링 체계는 없다. 라벨이 끊기는 기간이 구조적으로 존재한다.
4. **온프레미스**: 외부 API를 판정자(LLM 저지)로 쓸 수 없다 — 판정은 로컬 검증기·로컬 저지·사람으로만.

### 강점 (무엇이 우리 편인가)

1. **검증 가능한 보상이 공짜로 있다**: 배점 반영·수치 ⊆ 근거·분량·출처 유효성은 전부 결정론적 기계 판정이다. RLVR(§1.4)이 성립하는 전제조건 — "자동 채점 가능한 태스크" — 을 이 도메인이 원래부터 갖추고 있다.
2. **선호 데이터가 자연 발생한다**: 담당자의 초안 수정이 곧 라벨(FR-18) — 라벨링 인건비 없이 쌓이는 온-도메인 선호 쌍.
3. **도메인이 좁아 평가가 명확하다**: 홀드아웃 평가셋(FR-17)으로 과최적화를 조기 감지할 수 있다 — 범용 챗봇 정렬보다 유리한 조건.

### 방향 (그래서 이렇게 간다)

1. **기본 경로 = SFT → 오프라인 DPO.** Llama 3와 동일한 판단(§1.5: "복잡한 RL 대신 안정적이고 확장 쉬운 절차")이며, 우리 데이터 규모(수천 쌍)는 소규모 DPO의 실증 효과 구간(§1.6)에 정확히 들어온다.
2. **검증기 단독 판정분은 KTO로 흡수.** 쌍이 안 만들어지는 통과/탈락 라벨을 버리지 않는다 — 기계 판정 데이터가 사람 라벨보다 훨씬 많이 나오는 우리 구조에 맞는 선택.
3. **온라인 RL은 도입하지 않되, 그 이점은 반복으로 근사한다.** 온라인 우위의 원천은 온-폴리시 샘플링(§1.6 Tang et al.)이다 — 이를 "매 이터레이션 현재 모델로 새로 생성 → 3단 판정 → 재학습"하는 **iterative DPO**(§1.3)로 저비용 근사한다. Qwen2·Kanana가 실증한 경로이며, 학생 2차 투입(P5)이 정확히 이 반복의 판정 단계다.
4. **GRPO/RLVR형 온라인 RL은 에이전트화 트랙으로 이월.** 도구 호출 성공률은 완전한 검증 가능 보상이므로, 기획서 §10.1(에이전트화)이 별도 승인되는 시점에는 GRPO류가 정당화될 수 있다 — 본 사업 범위에서는 검증기를 학습 알고리즘이 아니라 **판정 필터**로만 쓴다.
5. **게이트는 타협하지 않는다.** 매 이터레이션 FR-17 하네스로 수치 환각률·배점 반영률 퇴행을 검사하고, 판정 기준과 독립인 홀드아웃으로 과최적화를 감시한다(§8). 퇴행 시 롤백.

**한 줄 결론**: 짜이미는 "검증 가능한 보상이 있는 좁은 도메인"이라는 강점을 **오프라인 선호 최적화(DPO/KTO) + 반복 구조**로 소화하고, 온라인 RL은 컴퓨트와 보상 신호가 그것을 정당화하는 에이전트 단계로 미룬다 — 고전 RLHF의 직관은 취하되, 그 비용과 불안정성은 취하지 않는다.
