# 50. 모델 개발 트랙 상세 (축 B)

> 조사일: 2026-08-15
> 4개 모델의 베이스 후보·학습 프레임워크·데이터 생성 방안·예상 학습 비용·평가 지표.
> **모든 GPU-시간 수치는 문헌·유사 사례 기반 추정치이며, Phase 2 스모크 테스트로 보정한다.** 실측 전 확정 금지.

## 공통 원칙

1. **순서 강제**: Phase 3에서 베이스 모델로 베이스라인을 먼저 측정한 뒤에만 파인튜닝 시작(브리프 10장). 학습 순서는 7.1 Embed → 7.2 Rerank → 7.3 Writer → 7.4 Extract.
2. **버전 관리**: 각 모델 `v0.1`부터. 학습 설정(YAML)·데이터 스냅샷 해시·평가 결과를 모델 카드에 기록.
3. **라이선스 고지**: 베이스 모델·학습 데이터 출처를 모델 카드에 명기. 전 베이스 후보가 MIT/Apache 2.0 계열(명명 자유 확인 완료 — 01-D·01-K).
4. **지식 주입 금지(5.2)**: 4개 모델 전부 "능력 학습"(검색·문체·추출)이며 문서 내용 암기가 목표가 아니다. Writer 데이터 정제 규칙(하단)이 이를 구조적으로 보증.

## 7.1 ZZAIMY-Embed-v1

| 항목 | 내용 |
|---|---|
| 베이스 후보 | **1안 KURE-v1**(BGE-M3 한국어 파인튜닝, MIT) / 대안 BGE-M3 원본(MIT). 두 시작점 A/B 학습 권장(파이프라인 동일, 추가 비용은 GPU-시간뿐) |
| 학습 프레임워크 | FlagEmbedding(1안, hn_mine 포함) 또는 sentence-transformers(CachedGISTEmbedLoss — KURE 레시피 재현) |
| 학습 방식 | 대조학습(InfoNCE 계열), 하드 네거티브 포함 triplet |

**학습 데이터 생성 파이프라인**
```
파일럿 코퍼스 청크(①공고·지침 + ②계획서 + ③결과보고서, 파싱 완료본)
 → 청크별 합성 질의 생성 (로컬 LLM = Qwen3.5-35B-A3B, vLLM 배치)
    - 질의 유형 3종을 프롬프트로 분리 생성:
      a. 실무형 검색 질의("2023년 재학생 대상 취업 프로그램 성과")
      b. 공고 요구사항형("산학협력 실적 보유 현황")  ← 실사용 분포 반영
      c. 키워드형(BM25 보완 학습용 짧은 질의)
 → 품질 필터: 생성 질의로 원청크가 검색 상위에 오는지 라운드트립 검증(자기 부트스트랩), 중복 제거
 → 하드 네거티브 채굴:
    a. hn_mine: 현 임베딩 기준 상위 30~100위 중 정답 제외 청크
    b. 도메인 규칙: 같은 사업의 다른 연도 청크, 유사 프로그램명의 다른 사업 청크
       (행정 문서 최대 함정 = "비슷한 제목, 다른 연도/사업"을 명시적으로 학습)
 → (질의, 정답 청크, 네거티브들) 수만 쌍
```
- 평가셋 분리: 합성 질의 일부가 아니라 **문서 단위로 분리**(같은 문서의 질의가 학습·평가 양쪽에 못 가게) + 사람 작성 질의 200~500문항을 골드셋으로 별도 구축(Phase 2).

**예상 비용(추정)**: 합성 질의 생성 — 청크 5만 개 × 질의 3종 ≈ 15만 호출: Spark 여러 대 병렬 배치로 1~3일. 학습 — 0.57B 모델, 5만~10만 쌍: **Spark 1대 8~24 GPU-시간/이터레이션**, 3~5회 반복 가정.

**평가 지표**: Recall@1/5/20, MRR@10, nDCG@10 — 베이스(KURE-v1·BGE-M3·Qwen3-Embedding-0.6B 비교군) 대비. 도구: pytrec_eval/ranx 자체 하네스(01-L).

## 7.2 ZZAIMY-Rerank-v1

| 항목 | 내용 |
|---|---|
| 베이스 후보 | **1안 bge-reranker-v2-m3**(Apache 2.0) / 대안 Qwen3-Reranker-0.6B(Apache 2.0, 지시문형) |
| 학습 프레임워크 | FlagEmbedding 리랭커 finetune 스크립트(1안과 동일 체계) |
| 학습 데이터 | **7.1과 동일 자산 재활용**: (질의, 정답, 하드 네거티브) → cross-encoder 이진/순위 학습. 7.1에서 채굴한 하드 네거티브가 리랭커 학습의 핵심 재료 |

**예상 비용(추정)**: 0.57B cross-encoder — **Spark 1대 8~24 GPU-시간/이터레이션**. 데이터 생성 비용은 7.1과 공유(추가 0).

**평가 지표**: 리랭킹 후 Recall@5/10, nDCG@10(1단 검색 상위 50 재정렬 조건), 최종 파이프라인 정답 인용률 기여분(엔드투엔드 A/B).

## 7.3 ZZAIMY-Writer-v1 — 축 B의 본체

| 항목 | 내용 |
|---|---|
| 베이스 후보 | **1안 Qwen3.5-35B-A3B**(Apache 2.0, MoE) / 대안 Qwen3.6-35B-A3B / 비교군 Kanana-2-30B-A3B(명명 제약, 99번 질문 5), Mi:dm-2.0-Base 11.5B(dense 비교군) |
| 학습 프레임워크 | LLaMA-Factory(1안, YAML 재현성) / Unsloth(반복 실험용) — QLoRA(4bit) LoRA SFT |
| 학습 방식 | 섹션 단위 SFT. 입력 = 섹션 요구사항+평가지표+인출 근거+방향성 지시 / 출력 = 실제 제출 계획서의 해당 섹션 원문 |

**학습 데이터 생성 파이프라인**
```
과거 계획서 20~30건 (파싱 완료본)
 → 섹션 해체: 목차 구조 기준 분할 (수백~수천 섹션)
 → 각 섹션에 대해 "당시 입력"을 역구성(retro-fill):
    a. 대응 공고에서 해당 섹션 요구사항·평가지표 추출
    b. 섹션 본문이 인용한 실적·자산을 실적 카드 DB·원문에서 역검색 → 근거 블록 구성
    c. 방향성 지시문은 섹션 요지를 LLM으로 요약해 생성(사람 검수 표본)
 → 【수치 환각 방지 정제 — 절대 규칙】
    1. 출력(섹션 원문)의 모든 수치·고유 실적명을 기계 추출
    2. 입력 근거 블록에 존재하지 않는 수치가 출력에 있으면:
       근거를 찾아 입력에 추가하거나, 찾지 못하면 해당 샘플 폐기 (수치 마스킹 치환은 문체 왜곡 위험이 있어 폐기 우선)
    3. 정제 통과율·폐기 사유를 데이터 카드에 기록
 → (입력, 출력) 수백~수천 쌍 + 평가용 홀드아웃(사업 단위 분리 — 같은 사업의 섹션이 학습·평가에 갈리지 않게)
```

**예상 비용(추정)**: 35B(총)-A3B QLoRA, 수천 쌍 × 2~3 epoch — **Spark 1대 24~72 GPU-시간/이터레이션**, 3회 내외 반복 가정. 역구성(retro-fill) 배치의 LLM 비용이 별도(Spark 병렬 1~2일).

**평가 지표**:
- **수치 환각률**(생성 수치 중 입력 근거에 없는 것의 비율) — **0 수렴 필수**, 결정론적 대조기
- 평가지표 반영률(배점 검증기 로직) — 베이스 대비
- 문체·논리: 사람 블라인드 비교(베이스 vs LoRA, 담당자 평가) + DeepEval 로컬 저지 보조
- 부정 지표 감시: 근거 없는 섹션에서 "빈칸+표시" 규약을 지키는지(지어내지 않는지)

## 7.4 ZZAIMY-Extract-v1

| 항목 | 내용 |
|---|---|
| 베이스 후보 | **1안 Qwen3-4B**(Apache 2.0) / 대안 Mi:dm-2.0-Mini 2.3B(MIT), A.X-4.0-Light 7B(Apache 2.0) — 3후보 소규모 비교 후 확정 |
| 학습 프레임워크 | LLaMA-Factory 또는 Unsloth — 풀 SFT 또는 LoRA(소형이라 어느 쪽도 가능) |
| 학습 방식 | Distillation: 교사 = Qwen3.5-35B-A3B(+xgrammar 스키마 강제)의 추출 결과를 **사람이 검수·수정한 것**(수백 건)을 정답으로 SFT |

**학습 데이터 생성 파이프라인**
```
파일럿 결과보고서 → 교사 모델 추출(실적 카드 JSON + 원문 오프셋)
 → 사람 검수 3~500건 (LangExtract식 하이라이트 UI로 검수 효율화 — 01-I)
 → 검수 완료본으로 SFT (JSON 출력 형식 자체도 학습)
 → 서빙 시에도 xgrammar 스키마 강제 병행(형식은 이중 보증)
```

**예상 비용(추정)**: 4B급 SFT 수백~수천 샘플 — **Spark 1대 4~12 GPU-시간/이터레이션**. 사람 검수가 실질 병목(브리프 7.4의 "수백 건 한정" 준수).

**평가 지표**: 필드별 정확도/F1(사업명·연도·예산·인원·성과 등, 홀드아웃 검수본 대비), 교사 모델 대비 처리량 배수(Spark 1대 실측), 출처 오프셋 정확도.

## 학습 일정 스케치 (Phase 5, 브리프 10장 순서 준수)

```
Phase 3에서 확보되는 것: 자체 평가셋 + 베이스라인 수치(전 모델 공통 비교 기준)
Phase 5:
  주 1~2   ZZAIMY-Embed v0.1 학습·평가 → v0.2
  주 2~3   ZZAIMY-Rerank v0.1 (Embed 데이터 재활용) → 검색 스택 개선폭 확정
  주 3~6   ZZAIMY-Writer v0.1 (retro-fill 데이터) → 사람 평가 → v0.2
  주 6~8   ZZAIMY-Extract v0.1 (검수 데이터 축적과 병행) → 처리량 측정
  이후     각 모델 카드·평가 보고서 확정
```
*주 단위는 상대 순서 표기이며 절대 일정 아님. 사람 검수·평가 가용 시간에 종속.*

## 트랙 전체 위험

1. **합성 질의·retro-fill 품질이 4개 모델 중 3개의 상한을 결정** — 생성 프롬프트를 버전 관리하고 표본 사람 검수를 각 배치마다 수행.
2. MoE LoRA(Writer)의 프레임워크 성숙도 — dense 비교군(Mi:dm 11.5B) 병행으로 헤지(01-F).
3. 과거 계획서 20~30건의 양식 이질성이 크면 섹션 해체 매핑 비용 증가 — 99번 질문 13에 의존.
4. GPU-시간 추정치의 불확실성 — Spark의 BF16 실효 연산 성능·통합 메모리 대역 특성상 문헌치와 편차 가능. Phase 2 스모크 테스트(각 프레임워크 1시간 소형 잡)로 조기 보정.
